# Гайды Storybook: касание и клавиатура

Гайд для сценарных историй Tessera: как писать шаги, которые сами выполняют действия
пользователя в режимах touch и keyboard, сохраняют состояние при переходах и не меняют
вид таблицы визуализацией. Спецификации — ADR
[0117](../decisions/0117-story-controls.md),
[0086](../decisions/0086-touch-support.md),
[0231](../decisions/0231-touch-for-every-feature.md),
[0232](../decisions/0232-keyboard-for-every-feature.md).

## Инварианты

1. **Гайд выполняет шаги сам.** Не ждать действий пользователя. Первый шаг — только
   исходное состояние, без `enter`.
2. **Шаг атомарен.** Его `enter` выполняет только собственное событие, а не повторяет
   предыдущие. `atomicSteps` включается на уровне целого гайда и мигрируется поэтапно.
3. **Состояние восстанавливает навигатор.** При прямом переходе, откате или пометке
   «Таблица изменена» `GuideStory` молча проигрывает предыдущие шаги с их пропсами и
   `remount`, затем показывает действие только целевого шага. Не сериализовать таблицу и
   не переносить подготовку в `enter`.
4. **Асинхронное действие — `stepAction`.** Следующий шаг ждёт его `done`. Синхронный
   `enter` завершается после возврата. `play` нажимает только кнопки панели и проверяет.
5. **Тесты и живая история — разные уровни правды.** В тестах используем настоящий CDP-touch
   с `isTrusted`. Живой Storybook выполняет тот же сценарий автоматически: JS истории не
   создаёт trusted-события и не должен останавливаться из-за этого.

## Действие — полный жест

Не ограничиваться `pointerdown/up` и визуальной волной. Полный tap включает:

- `pointerdown` и `touchstart`;
- совместимый `mousedown` и фокус цели;
- `pointerup` и `touchend`;
- совместимый `mouseup` и `click`.

Используем готовые помощники `__mocks__/touchGuides.ts`:

```ts
const BUTTONS: readonly GuideStoryStep[] = [
  { title: both('Кнопки скрыты'), hint: both('Действия нет.') },
  {
    title: both('Касание ячейки'),
    hint: both('У ячейки появились кнопки.'),
    enter: realTapTarget(root => cellAt(root, 1)),
  },
  {
    title: both('Касание другой ячейки'),
    hint: both('Кнопки переехали к ней.'),
    enter: realTapTarget(root => cellAt(root, 4)),
  },
]

<GuideStory steps={BUTTONS} args={guideArgs(TOUCH_ARGS, args)} atomicSteps />
```

- `realTapTarget` сначала восстанавливает `touch`-модальность и раскрывает контролы, затем
  ждёт конца reveal-анимаций и вызывает CDP в тестах или автоматический tap в живом Storybook.
  Координатный tap идёт в безопасную точку внутри цели, а не в границу соседней ячейки.
- `realTouchDragTarget(target, destination)` делает то же до переноса: touch-модальность до
  `touchstart`, удержание 250 мс; третий аргумент `false` проверяет ранний сдвиг без переноса.
  В каталоге жест идёт через CDP, в живом Storybook — автоматически событиями touch. Не заменять
  его `dragHold(..., 'touch')`: события указателя пальца не проходят через `TouchSensor`.
- Ленивое меню открываем `openMenuBy`: оно ждёт `data-open`, а не просто факт нажатия. У ручек
  после tap дополнительно ждём фокус внутри меню, чтобы сторож гайда не закрыл его на `done`.
- `tapButton` — для кнопки, включая кебаб. Не добавлять после него ещё `.click()`: событие
  уже полное.
- Голый `.click()` — только если специально проверяется этот путь. Он не заменяет tap и
  может оставить режим `pointer` и лишний focus-visible.

## Touch и keyboard — не одно и то же

- `data-tsr-input` показывает последний ввод: `touch`, `pointer`, `keyboard`.
- В touch-заголовке при `headerActionMenu` постоянно видны кебаб и ручка переноса; остальные
  действия, включая активные, — в меню, активность показывает bubble. Не проверять инлайн-кнопку
  сортировки в такой истории: её там намеренно нет. Без `headerActionMenu` кнопки остаются инлайн.
- `data-touched` — только признак последней тронутой ячейки и строки для скрытых кнопок.
- `data-kn-active` — активная ячейка клавиатурной навигации; для неё нужен
  `enableKeyboardNavigation: true`.
- `data-cell-selected` — выделение `cellSelection`. Активная ячейка и выделение следуют
  строкой по `id`; не сбрасывать их при переносе.
- `data-touched` переносится на новую ячейку, снимается при перетаскивании и нажатии мимо.
  Это не отменяет выделение и активную ячейку.

Проверять нужный срез, а не всё сразу. Например, открытие меню не обязано выбирать ячейку,
но tap по ней самой при включённой навигации делает её активной.

## Визуализация не меняет таблицу

- Один жест — одна волна `data-guide-click`. `pointerdown`, `mousedown` и `click` не должны
  порождать отдельные волны. Считать дельту на каждом шаге, а не накопленную сумму.
- Для `[data-action-menu]` псевдоклассы `pseudo-hover` и `pseudo-active` не добавляются ни
  кнопке, ни её предкам. Фон кнопки, ячейки и строки остаётся прежним.
- Волна не заменяет событие. Проверяем итог: значения, атрибуты, меню, фокус и выделение.
- Не использовать `hasTouch: true` для всего каталога: это меняет CSS-режим других историй.
  CDP отправляет события только для tap и не переключает эмуляцию экрана или его
  медиа-признаки; мобильный контекст остаётся постоянным. Одновременный повтор того же
  жеста в StrictMode объединяется, разные касания выполняются последовательно.

## Переходы

- Обычный `N → N+1` выполняет только `enter` шага `N+1`.
- Прямой переход, назад, «Вернуть шаг» и переход после изменения человеком открывают свежую
  таблицу и молча восстанавливают шаги `1…N-1` с их накопленными пропсами и `remount`.
- Панель сразу показывает целевой шаг. Промежуточные действия не визуализируются и не
  пишутся в консоль.
- Новый переход отменяет прежнее восстановление и начинается из свежей таблицы. Ввод до
  завершения заблокирован.

Пример неправильного шага:

```ts
enter: afterRows(root => {
  tapTarget(cellAt(root, 1))
  tapTarget(cellAt(root, 4))
})
```

Правильно: второй шаг касает только `cellAt(root, 4)`; первое касание при необходимости
восстановит replay.

## Проверки

Сначала ADR и требование, затем красный тест, реализация и зелёный тест. Долгие прогоны —
только после явного OK пользователя.

### В `play`

- Нажимать панель только через `guideNext` и `stepDone`; события выполняет `enter`.
- Проверить итог каждой формулировки: `data-touched`, `data-kn-active`, `data-cell-selected`,
  `aria-*`, наличие меню, подписи словаря, фокус и волну.
- Для CDP-touch собрать `pointerdown` и убедиться, что события `isTrusted` и их достаточно.
  Не требовать фиксированное число при replay. Проверка доверенности относится к обычному
  последовательному проходу, а не к внутреннему восстановлению SN73/матрицы: там полный жест
  в элемент допустим и не требует trusted-событий.
- Пройти светлую и тёмную темы, обычный `play` и SN73 со свежей таблицей перед каждым шагом.

### В живом Storybook

- Открыть свежую страницу и пройти только кнопками панели: последовательно, напрямую и назад.
- Изменить таблицу человеком и нажать «Вернуть шаг»: восстановление проходит само.
- Убедиться, что на каждом шаге одна новая волна и нет второй накопленной.
- Проверить вычисленные стили: фон кнопки, ячейки и строки, `boxShadow`, псевдоклассы.
- Прочитать консоль браузера на новой загрузке. Не полагаться на скриншот без атрибутов.

## Частые ошибки

| Ошибка                                | Почему получается                          | Что делать                                           |
| ------------------------------------- | ------------------------------------------ | ---------------------------------------------------- |
| Шаг повторяет предыдущие              | Подготовка перенесена в `enter`            | Вынести её в replay через `atomicSteps`              |
| Волна есть, нажатия нет               | Только `pointerdown/up`                    | Полный tap с `mousedown/up`, `click` и фокусом       |
| Два действия вместо одного            | Подготовительный tap + кнопка              | Replay предыдущего шага, затем только цель           |
| Серая подложка                        | `pseudo-*` на кнопке или предках           | Для `[data-action-menu]` не добавлять их вовсе       |
| Прямоугольник фокуса                  | Голый `.click()` в режиме `pointer`        | Полный `tapButton`, затем проверить `data-tsr-input` |
| Кнопка остаётся после drag/клика мимо | Нет очистки `data-touched`                 | Снимать его, не сбрасывая выделение                  |
| Другие истории меняют вид             | Глобальный `hasTouch`                      | CDP-события только на tap, без смены медиа-признаков |
| Прямой переход требует действий       | Состояние пытаются получить из самого шага | Молчаливый replay предыдущих шагов                   |
| Тест зелёный, сценарий сломан         | Проверены только итоговые атрибуты         | Пройти живой Storybook кнопками панели и снять стили |
