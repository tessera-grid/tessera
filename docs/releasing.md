# Выпуск версии

Как выпустить новую версию Tessera ([ADR 0103](decisions/0103-ci-and-releases.md)). Когда
выходит версия и что в CHANGELOG — решает автор; поднимает версию, ставит тег и пушит
одна команда, остальное делает CI.

## Коротко

```bash
npm run release:draft
```

Правите раздел новой версии в `CHANGELOG.md` (на английском) и выпускаете:

```bash
npm run release
```

Через агента: «готовь релиз» — агент запускает `release:draft`, переводит черновик на
английский и показывает его; после вашего «выпускай» агент запускает
`npm run release -- <уровень> --yes`.

## Какой уровень

Команда сама предлагает уровень по сообщениям коммитов с прошлого тега и показывает, какие
коммиты его определили. Свой уровень — аргументом: `npm run release -- patch`.

| Что в коммитах                            | До 1.0 (`0.x`) | С 1.0 |
| ----------------------------------------- | -------------- | ----- |
| Ломающее: `feat(…)!:`, `BREAKING CHANGE:` | minor          | major |
| Новая возможность: `feat`                 | patch          | minor |
| Исправление, ускорение: `fix`, `perf`     | patch          | patch |

До 1.0 ломающее изменение поднимает minor, потому что `^0.1.0` у потребителя разрешает
только `0.1.x`: иначе оно приехало бы к нему само. Первый выпуск — `0.1.0`. Выпуск 1.0 —
решение автора («API устоялся»): `npm run release -- major` на версии `0.x`.

## Шаги

1. **Черновик.** `npm run release:draft [-- patch|minor|major]` вписывает в
   `CHANGELOG.md` раздел следующей версии из Conventional Commits: Breaking changes,
   Features, Fixes, Performance; `chore`, `test`, `docs`, `refactor`, `style`, `build`, `ci`
   не попадают. Ничего не коммитит. Повторный запуск готовый раздел не трогает.
2. **Правка.** Раздел пишется для потребителя: что изменилось для него, как обновиться при
   ломающем изменении. Лишние строки — удалить, связанные — объединить.
3. **Выпуск.** `npm run release [-- patch|minor|major]`:
   - отказывает, если в рабочей копии есть что-то кроме `CHANGELOG.md`, ветка не
     `master`, коммиты не запушены или не подтянуты, CI на последнем коммите не зелёный
     (нужен `gh`, вошедший в GitHub);
   - если раздела нет — собирает черновик и открывает его в редакторе git;
   - спрашивает подтверждение (`--yes` — без вопроса);
   - поднимает версию в `package.json` и `package-lock.json`, коммитит
     `chore(release): vX.Y.Z`, ставит тег `vX.Y.Z` и пушит их вместе.
4. **CI.** Тег запускает `release.yml`: барьер и шаги перед публикацией (`test:engines`,
   `test:react18`, `check:package`), затем черновик GitHub Release с текстом раздела.
   Проверьте черновик на GitHub и опубликуйте его.

Публикации в npm пока нет — она добавится в `release.yml` при открытии репозитория.

## Если что-то пошло не так

- **Команда отказала** — она пишет причины; устраните и запустите снова.
- **Отказались на вопросе** — раздел остаётся в `CHANGELOG.md`, версия и git не тронуты.
- **CI выпуска красный** — тег уже на GitHub, черновика Release нет. Исправьте, запушьте и
  выпустите следующую patch-версию; тег не переставляйте.
