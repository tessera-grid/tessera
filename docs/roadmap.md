# Roadmap

Планируемое направление развития Tessera. Это **намерение**, а не обязательство.
Принятые решения фиксируются как [ADR](decisions/README.md).

Здесь же ведётся список **известных проблем** — признанных краёв (непокрытых тестами
или нереализованных пробелов), которые относятся к проектной работе, а не к дефектам.

## На рассмотрении

- **Миграция на TanStack Table v9.** Стратегическое лечение ключевого ограничения v8:
  любое изменение состояния таблицы или данных пересчитывает **всю** модель таблицы —
  это архитектурный удар по производительности. Pub-Sub
  ([ADR 0007](decisions/0007-reactivity-pubsub.md)) смягчает его на v8, но не
  устраняет. Миграция оценивается, решение ещё не принято.

## Запланировано

- **Полная поддержка сводных таблиц (pivot).** Первоклассный режим pivot, со **всеми
  существующими плагинами, адаптированными** к работе под ним. Прорабатывается
  **отдельной сессией**: сквозной pivot-ADR фиксирует для каждого плагина строку
  матрицы «работает как есть / адаптирован (как) / недоступен (почему)», каждый
  статус — требование с префиксом `PV<n>`, покрытое тестом (для «недоступен» —
  «инертен + предупреждает», как в [ADR 0022](decisions/0022-plugin-compatibility-contract.md)).
  Pivot по своей природе даёт вложенные заголовки, поэтому вопрос drag/pin под
  многоуровневой шапкой решается **внутри** этого ADR (см. ниже).
- **Закрепление и слева, и справа в UI (двустороннее).** Сейчас кнопка пинит только
  влево, хотя рендер/состояние поддерживают обе стороны
  ([ADR 0011](decisions/0011-column-pinning.md)). Проработать правый пиннинг в UI
  **с нюансом `rowActions`**: столбец действий авто-закреплён справа всегда — надо
  решить, как пользовательский right-pin делит правую зону со служебным столбцом
  действий (порядок, приоритет, разделитель).
- **Debug-снимок активности плагинов.** API вроде `table.getPluginDiagnostics()`,
  считающий **eager** (не по мере рендера) статус каждого подключённого плагина:
  `active` / `inert` (+`reason` из тех же ключей, что уже шлёт `logWarn`,
  [ADR 0022](decisions/0022-plugin-compatibility-contract.md)). Это тот «снимок»,
  что ADR 0022 отложил. Первый шаг — **без статуса `error`**; полноценный
  error-статус (отлов падений/конфликтов плагина) — отдельно, см. «Известные
  проблемы».
- **Гибкий, настраиваемый внешний вид.** Развить тема-независимый слой CSS-переменных в
  по-настоящему настраиваемую визуальную систему.
- **Переход на последнюю версию dnd-kit для React.** Обновить DnD-фундамент
  ([ADR 0006](decisions/0006-dnd-with-dnd-kit.md)) до актуальной версии dnd-kit для
  React ради свежего API, исправлений и улучшений производительности.
- **Опыт разработчика (DX).** Постоянные улучшения DX по всему API и тулингу.
- **Тестирование сквозных (межплагинных) кейсов.** Слой заведён
  ([ADR 0023](decisions/0023-cross-plugin-interactions.md)): префикс `X<n>`, файл
  `visual/cross-plugin.test.tsx`, первое требование `X1` (выбор переживает
  перетаскивание — привязка к идентичности строки, а не к слоту). Дальше —
  наполнение сложными кейсами: как поддерживаемые комбинации, так и заведомо
  несовместимые (тогда требование — «недоступно вместе»), переиспользуя общую
  механику (напр. DnD-хореографию из `rowDragging.dnd.ts`) и читая состояние из
  контракта DOM.

## Известные проблемы

Признаны и относятся к greenfield — относитесь к ним как к проектной работе, а не к
дефектам, и не «чините» их походя (см. AGENTS.md §6 «Архитектурная дисциплина»).
Когда край закрыт или обнаружен новый — обновляйте этот список и соответствующий
`docs/architecture/*.md`, держа их синхронными.

- **Pub-Sub на масштабе** — fan-out не измерен на тысячах подписчиков.
- **Grouping + RowDragging** — перетаскивание при группировке **осознанно
  выключено** (не «пробел»): сгруппированная модель строк производна и пересобирается
  (`getGroupedRowModel`), slot-reorder в неё не мапится; раскладкой владеет
  rowGrouping (B2, [ADR 0022](decisions/0022-plugin-compatibility-contract.md)).
  Осмысленная интеграция потребовала бы отдельного устойчивого слоя порядка внутри
  группы или переклассификации строки — заводится отдельной потребностью, если
  появится.
- **Вложенные заголовки + ColumnDragging** — перетаскивание столбцов под
  многоуровневой шапкой не планируется (потребности нет); остаётся инертным с
  предупреждением ([ADR 0022](decisions/0022-plugin-compatibility-contract.md)).
  Пиннинг под вложенной шапкой, наоборот, **реализован**: групповой по умолчанию и
  reorder-out для листьев/групп любого уровня (`enableLeafPinning`, [ADR 0011](decisions/0011-column-pinning.md),
  CP17–CP19 / LP1–LP6).
- **Коллизия ключей `externalState`** — кастомные ключи `TState` вливаются в общий
  `table.getState()`; могут столкнуться с будущими полями TanStack.
- **`getRowId: row => row.id` захардкожен** — данные обязаны нести `id`.
- **Снимок плагинов — статус `error`** — базовый debug-снимок (`active`/`inert`)
  запланирован (см. «Запланировано»), но **без** статуса `error`: единого канала
  отлова падений/конфликтов плагина сейчас нет. Полноценный error-статус (что
  считаем ошибкой плагина и где её фиксировать) вернуть отдельно, когда появится
  реальный источник ошибок.
