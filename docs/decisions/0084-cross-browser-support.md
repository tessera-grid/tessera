## Контекст

Поддерживаемые браузеры нигде не названы: нет `browserslist`, цель сборки — умолчание
Vite. Барьер (`npm test`) гоняет все визуальные наборы в одном Chromium; в Firefox и
WebKit идут только сессии правки (ADR 0040) и вход с клавиатуры (KN32).

Фактический нижний порог уже задан зависимостями: Tailwind v4 требует Chrome 111,
Safari 16.4 и Firefox 128, цель сборки Vite 8 по умолчанию — Chrome и Edge 111,
Firefox 114, Safari 16.4.

### Аудит 2026-10-10

Разовый прогон всех 121 визуального набора в Firefox и WebKit:

- **~350 падений из-за инфраструктуры.** `vitest.browsers.config.ts` переопределяет
  `test` и теряет вспомогательные команды тестов (`reducedMotion`, `realDrag`,
  `realWheel`, `routeModule`…) — они зарегистрированы только у проекта `browser`.
- **52 падения с командами**, из них разобраны до причины:
  - **кольцо фокуса в Firefox — дефект (WCAG 2.4.7).** После клика мышью стрелки
    двигают фокус скриптом, Firefox не даёт ему `:focus-visible` — кольца нет совсем
    (CF2, DF12); WebKit и Chromium его рисуют;
  - **плавное раскрытие кнопок ячейки** держится на `interpolate-size`, которое есть
    только в Chromium: в Firefox и Safari ширина встаёт сразу (RW1, RW3);
  - **перетаскивание под вложенной шапкой в WebKit** не срабатывает, только если
    кнопку отпустить в том же кадре, что и последнее движение, — так делает тестовый
    `realDrag`, человек так не делает;
  - **W6, FO1, MO1** — гонки момента замера в тестах;
  - **AX1–AX7** — снимки дерева доступности через CDP, его нет вне Chromium.
- Около 20 одиночных падений не разобраны: меню, линии дерева по пикселям, раскладка
  в WebKit, тайминг.

Раньше в этой же сессии прогон трёх наборов в движках нашёл два дефекта тултипа
обрезанного текста (ADR 0083) и вход в грид с клавиатуры в Firefox (KN32).

### Как это сделано у других

- **AG Grid** поддерживает две последние мажорные версии Chrome, Firefox, Edge и Safari
  и мобильные Safari на iOS и Chrome на iOS и Android; остальное — «работает, но
  проверьте сами».
- **MUI** публиковала таблицу минимальных версий браузеров; для Data Grid отдельной
  таблицы нет.
- **Tailwind v4** фиксирует порог версиями, а не «двумя последними».

## Решение

### 1. Порог

Поддерживаются **Chrome и Edge ≥ 111, Firefox ≥ 128, Safari и iOS Safari ≥ 17.1,
Opera ≥ 97, Samsung Internet ≥ 22, Chrome и Opera на Android — последние**. Opera 97
и Samsung Internet 22 — тот же Chromium 111, что и порог Chrome: кода они не требуют,
только записи в пороге. У Samsung Internet нет цели сборки esbuild — его покрывает
`chrome111`. Chrome, Edge и Firefox — по Tailwind v4: ниже
библиотека всё равно не опустится. Safari строже Tailwind (16.4): строки шапки стоят
на `display: contents` (вложенные заголовки охватывают несколько строк одной сетки,
ADR 0049), а дерево доступности для таких строк WebKit дочинил в Safari 17.1. Порог
16.4 давал 89,05 % пользователей в мире, 17.1 — 88,58 % (caniuse, август 2026);
теряются в основном iPhone 8 и X, которые не обновляются выше iOS 16.7. С Opera и
Samsung Internet порог даёт 91,1 %. Для сравнения: MUI X — 88,34 % (Chrome 117,
Firefox 121, Safari 17.0), AG Grid, Handsontable и KendoReact — «две последние
версии», ≈ 74 %. Ниже Chrome 111 и Safari 16.4 не пускает Tailwind v4 (ADR 0003). Он записан в `browserslist` (`package.json`), `build.target`
сборки с ним совпадает; поднимается осознанно, вместе с зависимостями.

### 2. Порог держит статическая проверка CSS

Playwright даёт только свежие движки — Safari 17.1 или Firefox 128 тестами не
проверить. Поэтому после сборки `npm run check:browsers` сверяет `dist/style.css` с
порогом по данным caniuse: свойство или значение вне порога — красный, кроме списка
исключений с причиной. JS держит `build.target`.

Анализатор — `doiuse`. Новых возможностей CSS в его данных нет (`interpolate-size`,
`@starting-style`, `light-dark()`, `text-wrap`, anchor positioning и др.), поэтому
к нему добавлены свои правила с версиями появления (`scripts/browsers.ts`). Проверка
сразу нашла второе нарушение порога — `@starting-style` во вспышке ошибки кнопок
(Firefox 129+, Safari 17.5+); заливка вспышки переведена на `@keyframes`.

### 3. Поведение одинаково во всех движках

Функция, фокус, доступность и движение работают одинаково во всех поддерживаемых
движках: возможность, которой нет у части порога, не используется. Раскрытие кнопок
ячейки переходит на приём, работающий везде: обёртка кнопки — `grid` с колонкой
`0fr` → `1fr`, переход `grid-template-columns` в темпе токенов движения.

Тонкие линии (1px) не рисуются прямоугольником, тенью или стопом градиента: при
дробном масштабе (масштаб страницы, `transform` контейнера) Firefox и WebKit
привязывают их края к пикселям экрана и схлопывают в ноль. Линии дерева (ADR 0058)
переходят на маску — линия внутри изображения сглаживается. `overflow-clip-margin`
нет в Safari — ячейку дерева обрезает `clip-path`, правило добавлено в
`check:browsers`.

### 4. Кольцо фокуса не зависит от эвристики браузера

Грид сам отслеживает, с клавиатуры ли пришёл последний ввод: нажатие клавиши в гриде
включает признак клавиатуры на корне, нажатие указателя — снимает. Кольцо фокуса
ячейки и дня календаря рисуется по `:focus-visible` **или** по этому признаку — после
клика мышью стрелки показывают кольцо во всех движках.

### 5. Прогон в движках

- `npm run test:engines` — все визуальные наборы в Firefox и WebKit, кроме списка
  исключений; у каждого исключения есть причина (CDP, особенность движка). Команды
  тестов — общий объект для Chromium и движков.
- Проект мобильной эмуляции: iPhone (WebKit) и Pixel (Chromium) с касаниями. Жест
  пальцем Playwright умеет только через CDP Chromium: на Pixel прокрутка касанием
  проверяется настоящим жестом, на iPhone — что ни контейнер, ни ячейки не блокируют
  панорамирование (`touch-action`).
- Тестовая инфраструктура: `realDrag` выдерживает кадр перед отпусканием; гонки
  W6, FO1, MO1 — ожиданием; остальные падения аудита разобраны до вердикта
  (исправлено с тестом, исправлен тест или исключение с причиной).

### 6. Барьер

- Шаг 9 (`test:browsers` на своём наборе) остаётся обязательным при правках сессий
  правки и фокуса.
- Новый шаг `check:browsers` — обязательный после сборки.
- `test:engines` — **не барьер**: обязателен перед публикацией в npm; агент
  предлагает его при правках CSS-раскладки, фокуса и клавиатуры (~25 минут).

### 7. Аудит без исправлений

Три области в этом ADR только проверяются; каждый найденный пробел уходит в
«Известные проблемы» roadmap с планом, исправления — отдельными ADR с прожаркой:

- **мобильные с касаниями** — скрытые кнопки ячейки без наведения, тултипы, ресайз,
  перетаскивание;
- **режим высокой контрастности** (Windows `forced-colors`) — кольцо фокуса,
  выделение, подсветка;
- **масштаб 400% и окно 320px** (WCAG 1.4.10).

## Границы

- Проверка старых версий движков запуском — порог держит статическая проверка.
- Исправления касаний, высокой контрастности и масштаба — отдельные ADR по итогам
  аудита.
- React 18, StrictMode, SSR, RTL, пакет глазами потребителя, утечки памяти,
  скриншотная регрессия, живые скринридеры — roadmap «Не покрыто тестами».
- Перф в движках: троттлинг и замеры идут через CDP.

## Отвергнутые альтернативы

- **«Две последние версии»** (как AG Grid). Порог скользит сам, но CRM в
  корпоративной среде живёт на замороженных версиях (Firefox ESR); Tailwind и так
  задаёт фиксированный порог.
- **`test:engines` в обязательном барьере.** ~25 минут на каждое изменение; правки
  движко-зависимых мест и так ловит шаг 9.
- **Только отобранные наборы в движках.** Новый набор легко забыть добавить — так и
  пропустили найденное аудитом.
- **Мягкая деградация** (`interpolate-size` в Chromium, мгновенно в остальных).
  Отклонена: поведение должно быть одинаковым везде.
- **Только цель сборки без проверки CSS.** `interpolate-size` прошёл бы незамеченным.
- **Исправления касаний в этом ADR.** Решение «как показать кнопки без наведения»
  меняет UI и требует своей прожарки.

## Последствия

- **+** Поддерживаемые браузеры названы, порог проверяется автоматически.
- **+** Любой визуальный набор можно прогнать в Firefox и WebKit одной командой.
- **+** Кольцо фокуса видно при переходе с мыши на клавиатуру в Firefox.
- **−** Новая dev-зависимость — анализатор CSS по caniuse; ставится после одобрения.
- **−** Полный прогон в движках долгий и не входит в барьер — регрессия в движке
  может дожить до публикации.
- **−** Раскрытие кнопок ячейки — обёртка `grid` с колонкой `minmax(0, 0fr)` →
  `minmax(0, 1fr)`; перф прокрутки с ним перемеряется.
- **−** Порог Safari выше, чем у Tailwind v4: Safari 16.4–17.0 (≈ 0,47 % пользователей)
  не поддерживаются.
- Ломающих изменений публичного API нет; потребитель получает явный список браузеров.

## Разбор аудита (2026-10-10)

Итог шага 4: падения `test:engines` разобраны до причины.

**Дефекты библиотеки — исправлены:**

- **Линии дерева глубже второго уровня** пропадали в Firefox и WebKit (RE52, RE54).
  Тест-кадр снят в масштабе 0,8, и прямоугольник, тень или стоп градиента в 1px
  схлопываются при привязке к пикселям экрана. Так же будет при масштабе страницы
  67–90 %. Линии переведены на маску — слой на уровень (ADR 0058). Ячейку отступа
  обрезает `clip-path`: `overflow-clip-margin` нет в Safari, правило добавлено в
  `check:browsers`.
- **Скелет первой загрузки не держал места под вертикальную полосу прокрутки**
  (SL2): с видимой полосой (Windows, WebKit) правые закреплённые колонки сдвигались
  на её ширину при приходе данных. Теперь скелет держит полосу (`overflow-y: scroll`)
  и обрезает свою таблицу по высоте.
- **Отмена ожидания ленивого поповера** (LZ15) держалась на `Escape` и `blur` кнопки,
  а Safari не фокусирует кнопку по клику. Теперь отмену слушает документ: `Escape`,
  `Tab` и нажатие указателем.
- **Кнопка «наверх» в Safari** пряталась сразу после нажатия: без фокуса она не ждала
  его ухода (BT8–BT9). Теперь кнопка берёт фокус при нажатии сама.
- **Вспышка ошибки не гасла переходом** ни у одного носителя: правило фазы `off`
  было написано на класс, которого нет в разметке (BS17, ADR 0055).
- **Подсказка не открывалась**, если заголовок появлялся у триггера, уже стоящего под
  курсором (причина отказа пришла ответом). Теперь открывается — при появлении
  заголовка, но не при монтировании.
- **Короткая форма счётчика** нижней панели — отдельный узел `aria-hidden` вместо
  альтернативного текста `content: … / …` (Safari 17.4+); исключение
  `content-alt-text` в `check:browsers` снято.

**Тесты и инфраструктура:**

- Playwright запускает Chromium с `--hide-scrollbars`. Геометрию с видимой полосой
  прокрутки из основного прогона видит только WebKit в `test:engines`. SB3 учитывает
  горизонтальную полосу между футером и панелью.
- Команды перехвата загрузки модуля (`network.commands.ts`) держали один общий список
  на все браузеры. Firefox и WebKit идут параллельно, поэтому перехват одного движка
  доставался другому. Теперь список ведётся на страницу.
- CRS16 переведён с синтетических событий на настоящую мышь Playwright. HL10 получил
  свой тайм-аут — десятки снимков экрана. FL13 ждёт ухода меню «Колонки»: подложка
  выходящего меню съедает клик. NM24 уводит курсор с пункта и возвращает его:
  headless WebKit не шлёт наведение на элемент, появившийся под неподвижным курсором.
- BT9 входит в грид клавишей `Tab` с поля перед ним: обратный путь с кнопки в
  Playwright WebKit непредсказуем. Клик «как в Safari», без фокуса на кнопке,
  имитирует отменённый `mousedown`.

**Строки на `display: contents`.** Строка футера стала своим боксом (CB7). Строки шапки
так не переделать: вложенные заголовки охватывают несколько строк одной сетки
(`grid-row: … / span …`, ADR 0049). Дерево доступности для `display: contents` WebKit
чинил по частям, последнее — заголовки колонок у ячеек в `role="row"` на
`display: contents` — в Safari 17.1; порог Safari поднят до 17.1 (§1).

**Остаётся — в «Известных проблемах» roadmap:** закрытие модального меню отпусканием
кнопки в Firefox (MI24, NM19).
