# 0037 — Изоляция падений плагинов и статус `error` в снимке

- **Статус:** Принято
- **Дата:** 2026-09-30
- **Связано:**
  - [ADR 0022](0022-plugin-compatibility-contract.md) — логгер и снимок
    `getPluginDiagnostics()`; там статус `error` отложен до появления источника
    ошибок. Этот ADR даёт источник.
  - [ADR 0036](0036-plugin-contract-diagnostics-and-a11y.md) — контракт встроенного
    плагина (диагностика, доступность).
  - [ADR 0010](0010-invert-core-plugins-registry.md) — presence-based композиция:
    набор плагинов, в том числе сторонних, меняется в рантайме.

## Контекст

Ядро не перехватывает ошибки плагинов. Исключение в рендере компонента слота или
сервисной колонки всплывает до корня React и роняет **весь** грид — вместе с
данными и остальными плагинами. Исключение в `setup` прерывает сетап следующих
плагинов, в `diagnose` — вызов `getPluginDiagnostics()`. Снимок при этом знает
только `active` / `inert`: «плагин сломан» в нём не выразить.

Плагины бывают сторонними, и грид не должен зависеть от качества каждого из них.

## Решение

**Падение плагина изолируется в пределах этого плагина: его UI гаснет, грид и
остальные плагины продолжают работать. Ядро пишет ошибку в `logError` один раз на
плагин и отмечает плагин в снимке статусом `error`.**

### Где ядро ловит ошибки

- **Рендер.** Каждый компонент плагина — слот (`leftHeaderSlot` … `cellSlot`,
  `toolbarSlot`) и `cell`/`header` сервисной колонки — рендерится внутри error
  boundary, помеченной `id` плагина. Упавший компонент рисует пустое место (для
  `cellSlot` — собственный контент ячейки), соседние компоненты и ячейки не
  затрагиваются. Метку `id` ядро проставляет само при свёртке записей — автору
  плагина делать ничего не нужно.
- **Тип компонента обёртки стабилен.** Обёртка `cell`/`header` сервисной колонки
  кэшируется по паре (шаблон, `id` плагина): новая ссылка `columns` пересобирает
  колонки, но ячейки и заголовки служебных колонок остаются тем же компонентом и не
  перемонтируются. Иначе любая смена колонок сбрасывала бы фокус на ручке, открытое
  меню и локальное состояние, а нажатие, во время которого прошла перерисовка,
  теряло бы `click` (кнопка отсоединена до `mouseup`). Контракт L1 (потребитель
  мемоизирует `columns`) не меняется, но законная смена колонок служебные ячейки
  больше не задевает (PE7–PE8).
- **`setup`.** Каждый вызов обёрнут: исключение одного плагина не мешает `setup`
  остальных.
- **`diagnose`.** Исключение не выходит из `getPluginDiagnostics()`: этот плагин
  получает статус `error`, остальные считаются как обычно.

### Реестр ошибок и снимок

- У таблицы свой реестр ошибок плагинов (по `id`, первая ошибка). Он живёт, пока
  жива таблица.
- `getPluginDiagnostics()` для плагина с ошибкой возвращает
  `{ id, status: 'error', error }`, где `error` — сообщение исключения. `error`
  важнее `inert`: сломанный плагин сообщает о поломке, а не о неприменимости.
- Каждая пойманная ошибка идёт в `logError` с ключом `<id>:error` — один раз на
  плагин. Уровень `error` слышен и в проде, если потребитель не заглушил логгер
  (`logLevel: 'silent'`).

### Что вне этого среза

- **Обработчики событий** (`onSelect` действий, клавиатурные действия, пункты
  контекстного меню). Исключение в обработчике события React не роняет грид, поэтому
  изоляция здесь не нужна; статус `error` по ним пока не выставляется.
- **Код фич TanStack** плагина (методы на прототипах, `getCan*`). Он исполняется
  внутри row-моделей и рендера ядра; оборачивать каждый вызов слишком дорого.
- **Восстановление.** Упавший компонент не перерисовывается до пересоздания
  таблицы; повторной попытки нет.

## Последствия

- **+** Сломанный плагин не валит грид; причина видна в логе и в снимке.
- **+** Статус `error` из [roadmap](../roadmap.md) закрыт реальным источником.
- **−** Публичный тип `PluginDiagnostic` получает третий вариант
  (`status: 'error'`, поле `error`). Код потребителя, разбирающий снимок `switch`-ем
  по двум статусам, должен учесть третий.
- **−** Лишний уровень компонента вокруг каждого компонента плагина. Стоимость
  контролирует перф-матрица (P1–P8): она гоняется со всеми плагинами и обязана
  остаться в бюджете.
