# 0003 — Формализация технического стека

- **Статус:** Принято
- **Дата:** 2026-08-05

## Контекст

Ранние ADR фиксируют только _headless-ядро_: TanStack Table
([0004](0004-core-on-tanstack-table.md)), TanStack Virtual
([0005](0005-virtualization-tanstack-virtual.md)) и dnd-kit
([0006](0006-dnd-with-dnd-kit.md)). Рантайм-слой контролов и стилизации —
примитивы, утилитарный CSS, токены темы — сложился позже и **не зафиксирован ни в
одном ADR**, а `AGENTS.md` и `docs/**` не описывали его полно.

Нужен единый формальный источник правды о полном стеке, на который ссылаются
`AGENTS.md` и архитектурные документы, чтобы перечни библиотек не расходились с
`package.json` и кодом.

## Решение

Зафиксировать технический стек по состоянию на 2026-08-05 как перечислено ниже.
Внутри — несколько связанных решений, ранее нигде не записанных.

### Встроенные решения

1. **Примитивы контролов — Base UI.** Фундамент headless-примитивов (Button,
   Tooltip, Switch, Checkbox…) — `@base-ui/react`, база shadcn.
2. **Примитивы бандлятся, а не peer.** `@base-ui/react`, `cva`, `clsx`,
   `tailwind-merge`, `lucide-react` собираются **в `dist`** — пакет самодостаточен.
   `external` в `vite.config.ts` держит вынесенными **только** `react`,
   `react-dom`, `react/jsx-runtime`, `@tanstack/*`, `@dnd-kit/*`.
3. **Гибридная стилизация.** Tailwind-утилиты (shadcn-контролы) сосуществуют с
   CSS Modules (раскладка грида + тема `--tsr-comp-*`). Токены `--tsr-comp-*`
   выводятся из токенов shadcn (`--primary`, `--foreground`, `--muted`, `--border`,
   `--ring`, `--info`…) через `var()`/`color-mix()` в
   [`useThemeVariables`](../../src/lib/core/themeVariables/useThemeVariables.ts).
4. **Тема — токены shadcn.** Единый источник — `src/styles/global.css`
   (`@theme inline`, палитра «Vercel Inspired», класс `.dark`). Проп `colorMode`
   вешает класс `.dark` на обёртку грида (`DataGrid.tsx`); значения переменных
   одинаковы для light/dark — режим переключают токены.
5. **`cssFileName: 'style'`** в lib mode — чтобы сохранить экспорт `./style.css`
   (Vite 8/Rolldown иначе назвал бы файл по имени пакета).
6. **`cn` и `clsx` — не дубликаты, применяются по слою стилизации.** `cn`
   ([`src/lib/utils.ts`](../../src/lib/utils.ts)) — это `twMerge(clsx(...))`, то есть
   надстройка над `clsx`, а не замена (сам пакет `clsx` — транзитивная зависимость
   `cn` и остаётся в дереве в любом случае). `tailwind-merge` полезен **только** там,
   где конфликтующие Tailwind-утилиты могут переопределяться пропсом `className` —
   это shadcn-контролы на `cva`. Поэтому:
   - **`cn`** — в компонентах на Tailwind-утилитах (shadcn-примитивы, напр.
     [`ui/shadcn/button.tsx`](../../src/lib/ui/shadcn/button.tsx));
   - **`clsx` напрямую** — в компонентах грида и плагинах на CSS Modules + BEM, где
     конфликтующих Tailwind-классов нет и разруливать нечего.

   Массовая замена `clsx → cn` «для единообразия» **запрещена**: `twMerge` на каждый
   рендер прогоняет строку классов регэкспами, а в горячем пути рендера грида
   (CSS Modules, без Tailwind-утилит) это оверхед без пользы. И наоборот — `cn`
   держать только там, где реально мешаются Tailwind-утилиты.

## Следствия

- **+** Единый источник правды о стеке; `AGENTS.md` и `docs/**` ссылаются на него
  вместо дублирования перечней, которые устаревают.
- **+** `dist` самодостаточен — потребитель приносит только React, TanStack Table
  и (транзитивно) dnd-kit; примитивы и стили уже внутри.
- **+** Быстрое авторство контролов: shadcn + Tailwind v4 + cva дают вариантную
  стилизацию и токен-систему из коробки.
- **−** Больше размер бандла — примитивы Base UI и утилиты стилизации внутри `dist`.
- **−** Две ментальные модели стилизации (Tailwind-утилиты **и** CSS Modules);
  контрибьютор должен знать, где какая применяется.
- **−** Тема грида **жёстко зависит** от токенов shadcn/Tailwind: `--tsr-comp-*`
  без базовых токенов падают на «Vercel»-fallback'и, заданные в `var(--token, fallback)`.
- ADR **0004–0007 не отменяются** — ядро по-прежнему headless и компонуется, а не
  форкается; этот ADR лишь формализует рантайм-слой контролов и стилизации поверх него.

### Отвергнутые альтернативы

- **Сделать примитивы peer-зависимостями** — переложило бы установку небольшого
  набора библиотек на потребителя и усложнило бы DX ради спорной экономии размера.
  Выбран бандл в `dist`.
- **Стилизовать контролы на CSS Modules, а не на Tailwind** — потеряли бы
  токен-систему и скорость авторства shadcn-контролов. Гибрид оставляет CSS Modules
  там, где они сильны (раскладка грида), и берёт Tailwind там, где силён он (контролы).
- **Не объявлять `motion`** — оставлена как задел под запланированные анимации;
  додержать объявленной дешевле, чем вводить зависимость позже.
