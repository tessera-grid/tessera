# 0020 — Доступность (a11y): роли, имена, индексы, axe

- **Статус:** Принято
- **Дата:** 2026-09-06
- **Связано:**
  - [ADR 0004](0004-core-on-tanstack-table.md) — базовые роли таблицы
    (`table`/`rowgroup`/`row`/`columnheader`) и позиционные индексы заведены
    ядром; их требования (`R10`/`R11`, `R2`/`R3`) живут в `core-roles`/
    `core-structure`. Этот ADR **достраивает** контракт до валидной ARIA-таблицы
    и уточняет семантику индексов.
  - [ADR 0017](0017-ui-components.md) — UI-компоненты делегируют фокус/порталы
    Base UI, но **доступное имя** icon-кнопок и чекбоксов задаёт потребитель:
    тултип Base UI имя не проставляет. Этот ADR фиксирует, откуда имена берутся.
  - [ADR 0009](0009-test-coverage-visual-and-performance.md) — доступность
    проверяется визуальными тестами в реальном Chromium; каждое требование —
    отдельный именованный тест `A<n>`, состояние читается из контракта DOM/ARIA.
  - [ADR 0005](0005-virtualization-tanstack-virtual.md) — виртуализация держит в
    DOM лишь окно строк/колонок; отсюда потребность в `aria-rowcount`/
    `aria-colcount`, иначе позиционные индексы окна бессмысленны.

## Контекст

Библиотека рендерит `role="table"` и расставляла базовые роли, но контракт
доступности был неполон и местами невалиден по ARIA:

- **Ячейки тела и футера** несли `aria-colindex` на голом `<div>` без
  `role="cell"`. По ARIA `aria-colindex` валиден только на
  `cell`/`gridcell`/`columnheader`/`row`, а `table` обязана строиться как
  `table → rowgroup → row → cell`. Цепочка рвалась — скринридер не собирал
  таблицу.
- **Футер** рендерил `rowgroup → cell` **без** промежуточного `role="row"`
  (`rowgroup` обязан владеть `row`).
- **Индексы были 0-based**, тогда как ARIA `aria-rowindex`/`aria-colindex` —
  1-based; при этом **не было** `aria-rowcount`/`aria-colcount`, из-за чего под
  виртуализацией индексы окна не соотносились с полным размером таблицы.
- **Нет доступных имён** у icon-кнопок (сортировка/закрепление/группировка/
  раскрытие) и чекбоксов выбора: подписи жили только в тултипе Base UI, который
  имя триггеру не проставляет. Скринридер читал «button»/«checkbox».
- **Нет имени у самой таблицы** (`role="table"` без `aria-label`).

Требовался единый источник истины: что именно из a11y библиотека гарантирует,
чем это подтверждается и что осознанно отложено.

## Решение

### Семантика таблицы полностью замкнута

`table → rowgroup → row → cell/columnheader`:

- `BodyCell` и `FooterCell` несут `role="cell"`.
- Футер получает строку-обёртку `role="row"` со `style={{ display: 'contents' }}`
  — семантический `row` без собственного бокса, чтобы ячейки остались треками
  общей grid/flex-сетки (тот же приём, что в `HeadRow` для вложенных заголовков).
- Под вложенной шапкой (без виртуализации колонок) каждая строка заголовков
  `HeadRow` — такая же обёртка `role="row"` с `display: contents` и
  `aria-rowindex = headerGroup.depth + 1`; плоская шапка — обычный бокс-`row`.
- Выбор строк: в гриде (`keyboardNavigation`, `role="grid"`) с `rowSelection`
  выбираемая строка (`row.getCanSelect()`) несёт `aria-selected` — пара к
  `aria-multiselectable` на корне ([ADR 0021](0021-keyboard-navigation.md)).
  В `role="table"` атрибут не ставится: выбор там озвучивает чекбокс строки.

### Индексы — 1-based, плюс счётчики размера

- `aria-colindex` в `HeadCell`/`BodyCell`/`FooterCell` — 1-based позиция колонки
  в **порядке отображения**: start-закреплённые → центр → end-закреплённые
  (`core/displayColumns.ts`), тот же порядок, что у ячеек строки и заголовков.
  `column.getIndex()` не годится: он держит натуральный порядок, и колонка,
  закреплённая справа, визуально последняя, получала бы индекс «из середины».
  Спанящий групповой заголовок вложенной шапки несёт позицию своего первого
  листа.
- `aria-rowindex` — 1-based и **сквозной с учётом строк заголовка**: строка
  заголовка = `headerGroup.depth + 1`, строка данных =
  `headerRowCount + virtualRow.index + 1`. `headerRowCount` (= число
  header-групп) пробрасывается `DataGrid → Body → BodyRow`.
- На `role="table"` заведены `aria-rowcount = headerRowCount + rows.length` и
  `aria-colcount = leafColumns.length` — полный размер таблицы, невыводимый из
  DOM-окна под виртуализацией.
- **`data-index` остаётся 0-based** — это контракт виртуализации
  ([ADR 0005](0005-virtualization-tanstack-virtual.md)), а не ARIA-индекс; они
  сознательно разведены.

### Доступные имена — из локализации

Имена берутся из подписей `TableLabels` ([localization](../../src/lib/core/localization/localization.tsx)),
переопределяемых пропом `localization` у `DataGrid`:

- **Таблица** — `aria-label` из ключа `table` (дефолт `Data table`).
- **Icon-кнопки** — `aria-label` из существующих ключей (`sortAscending`/
  `sortDescending`/`clearSort`, `pin`/`unpin`, `group`/`ungroup`,
  `expand`/`collapse`, `editCell` — кнопка правки `cellEditing`), то есть тот же
  текст, что и в тултипе. Ячеечные кнопки (`CellButton`) ставят `aria-label` из
  той же подписи, что и тултип, — хардкод английского текста в плагинах недопустим.
- **Чекбоксы выбора** — `aria-label` из новых ключей `selectRow`/`selectAll`,
  проброшенных пропом `label` в `SelectCheckbox` (Base UI `Checkbox.Root`
  прокидывает `aria-label` на корневой контрол).

Новые ключи `TableLabels`: `table`, `selectRow`, `selectAll`, `editCell`.

### Enforcement — axe в реальном Chromium

Доступность закреплена прогоном `axe-core` в vitest-browser
([ADR 0009](0009-test-coverage-visual-and-performance.md)),
`stories/__tests__/visual/a11y.test.tsx`. Часть правил отключена как вне зоны
структурной доступности этого набора:

- `color-contrast` — зависит от токенов темы, покрыт тестами темизации
  ([ADR 0018](0018-external-theming.md), [ADR 0019](0019-token-architecture.md));
- `region` — документ-левел landmark-правило, неприменимо к встраиваемому гриду;
- `scrollable-region-focusable` — относится к отложенной клавиатурной области
  (см. ниже).

### Осознанно отложено (вне области ADR)

- **Клавиатурная навигация по ячейкам** — вынесена в **опциональный** плагин
  `keyboardNavigation` ([ADR 0021](0021-keyboard-navigation.md)): с ним грид
  получает `role="grid"`, roving tabindex, режим действия и один tab-stop, а
  правило `scrollable-region-focusable` (WCAG 2.1.1) проходит (A7). Без плагина
  грид остаётся `role="table"` (для чтения), и в общем наборе правило
  отключено — это осознанный контракт opt-in, а не маскировка. Поэтому WCAG
  2.1.1 заявляется **только с плагином** ([ADR 0031](0031-wcag-keyboard.md), KB9).
- **Ресайз-ручка** — фокусируемый `separator` с `aria-valuenow` и клавиатурным
  управлением вынесена в [ADR 0031](0031-wcag-keyboard.md) (KB2).

## Последствия

- **+** `role="table"` строится в валидное дерево — скринридер корректно
  озвучивает строки/ячейки, размер таблицы (`rowcount`/`colcount`) и позицию.
- **+** Все интерактивные контролы грида (кнопки действий, чекбоксы) и сама
  таблица имеют доступные имена, локализуемые через `localization`.
- **+** Регрессии доступности ловятся axe в реальном браузере, а не ревью.
- **−** Полное соответствие WCAG 2.1 AA **не** заявляется: WCAG 2.1.1 (Keyboard)
  закрыт [ADR 0031](0031-wcag-keyboard.md) только **с плагином**
  `keyboardNavigation` (кроме смены уровня вложенности строки — только
  указателем); вне области остаются live-объявления и проверка на реальных
  скринридерах.
- **−** Смена 0-based → 1-based ARIA-индексов **изменила контракт** тестов ядра:
  `core-structure` R2 (`aria-colindex` теперь `1..n`) и R3 (`aria-rowindex`
  теперь 1-based с учётом заголовка) обновлены; хелпер `renderedColumnIndexes`
  снимает 1 для 0-based смысла «индекса колонки».
- **−** Дополнительный `role="row"`-обёртка в футере — компромисс `display:
contents` (семантика без бокса); опирается на то, что современный Chromium
  держит такие элементы в дереве доступности.
