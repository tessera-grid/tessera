## Контекст

Поповер грида собирается по месту. Четырнадцать файлов — меню колонки и панель действий,
контекстное меню, меню ручек, «Колонки», выгрузка, сводка фильтров, выбор условия фильтра,
размер страницы, поповеры правки и редакторы вариантов, отметка ячейки, журнал отказов, пульт
черновиков — каждый сам берёт примитив Base UI (`Popover`, `Menu`, `Combobox`, `Select`), сам
ставит тему портала и зазор до якоря и сам подключает классы `ui/Popup/Popup.module.css` через
`composes`. Компонентами в ките оформлены только облачко записи `PopupEntry`, пункты меню
`MenuItems`, разделы `MenuSections` и меню ручек `HandleMenuPopup`; поверхность, пункт списка,
заголовок и кнопки панели — классы.

Следствия аудита поповеров 2026-11-04:

- раскладка разъехалась — четыре вида разделителя над кнопками, три поля у кнопок, два
  заголовка; единое правило PP11–PP13 держится только на дисциплине и тестах;
- поле ввода повторено в панели фильтра и «Колонках» копией `shared/field.module.css`;
- кнопка снятия фильтра в сводке была самописной и потеряла кольцо фокуса;
- ни один блок поповера нельзя посмотреть отдельно: историй у них нет, вид проверяется только
  внутри таблицы.

Поле ввода, список вариантов и календарь — визуальные части поповеров, но живут в `shared/`:
берут подписи из словаря таблицы и тип `ColumnOption` из ядра, поэтому кит их взять не может.

Аудит кита 2026-11-04 нашёл и контролы поповеров, собранные по месту:

- **поле поиска** (значок, поле, крестик) — трижды: быстрый поиск тулбара, поиск вариантов
  (крестик — самописная `<button>`), поиск «Колонок» (без крестика);
- **кнопка-триггер выпадающего списка** — дважды: выбор условия фильтра (класс `.trigger`) и
  размер страницы (`SizeTrigger` — самописная `<button>` со своими состояниями ожидания и
  отказа, исключение стража BN8);
- **радио** — классы `.radio` и `.dot` поверх Base UI в булевом фильтре и пресетах даты;
- **флажок** — в ките только `SelectCheckbox` выбора строк: список вариантов берёт его CSS-модуль
  и сам рисует Base UI `Checkbox`, редактор булевой ячейки — самописный `role="checkbox"` со
  своей клавиатурой, вопреки правилу «поведение — из Base UI»;
- **текст ошибки под полем** — свой класс в панели фильтра, инлайн-редакторе ячейки и списке
  вариантов;
- **значок состояния с причиной в тултипе** — отказ серверного фильтра колонки
  (`<span role="img" tabIndex={0}>`).

**Как у других.** MUI X Data Grid выносит части поповеров в подменяемые компоненты (слоты
`basePopper`, `baseTextField`, `baseSelect`) и показывает их в документации. AG Grid держит
поповеры, поля и календарь внутренними, отдельно их не показывает. Tessera берёт середину:
компоненты кита с историями, без публичного экспорта.

## Решение

### 1. Компоненты поповера в ките

- **`PopupSurface`** — поверхность и позиционер одним компонентом поверх любого попапа Base UI
  (`Popover`, `Menu`, `Combobox`, `Select`) через `render`: тема портала
  (`usePortalThemeClass`, `usePortalThemeData`), `POPUP_SIDE_OFFSET`, классы поверхности.
  Вне `ui/Popup` поверхность классом не подключают.
- **`PopupPanel`** — слоты `title`, содержимое и `footer`; раскладка — PP11–PP13 (ADR 0017),
  заголовок связан с поповером через `aria-labelledby`. Поповеры-панели — журнал, пульт,
  отметка ячейки, «Настройки вида», «Колонки», выгрузка, панель фильтра, поповеры правки —
  собираются на нём.
- **`PopupItem`** — пункт списка: иконка, подпись с переносом (ADR 0083), отметка, подсказка
  справа; состояния — покой, подсвечен, отмечен, выключен, ожидание и отказ (ADR 0078),
  блокировка с причиной в тултипе.
- **`PopupGroup`** — подпись группы и разделитель между группами пунктов. Подпись — стилем
  заголовка поповера: один заголовок на всё внутри поповера — у панели, раздела пульта и группы
  меню (решение автора 2026-11-04).

Существующие `MenuItems`, `MenuSections`, `PopupEntry` и меню ручек собираются из этих блоков.

### 2. Перенос из `shared/` в кит

- **`Field`** (`ui/Field`) — поле ввода: кольцо фокуса, ошибка (`aria-invalid` и текст под
  полем), крестик очистки при непустом значении (нынешний `OptionSearch`). Копии стилей поля в
  панели фильтра и «Колонках» уходят.
- **`Checklist`** (`ui/Checklist`, бывший `OptionChecklist`) — флажки, счётчики, виртуализация,
  ожидание и отказ загрузки. Варианты — своим типом кита `{ value, label, count? }`, тексты —
  пропами; импортов ядра нет.
- **`Calendar`** (`ui/Calendar`) — язык, пояс и подписи листания пропами. Остаётся в ленивых
  модулях фильтра и редактора даты.

### 2а. Контролы поповеров

- **Ошибка поля** — часть `Field`: текст под полем цветом ошибки, связан с полем через
  `aria-describedby`; у инлайн-редактора ячейки — объявлением (`role="alert"`), как сейчас.
- **`SearchField`** (`ui/Field`) — `Field` со значком лупы слева, крестиком очистки и
  необязательной кнопкой-подсказкой справа. Кнопки — `IconButton` кита; в тулбаре они остаются
  элементами композита тулбара через `render` (ADR 0035, ADR 0021).
- **`SelectTrigger`** — кнопка выпадающего списка: значение и шеврон, ожидание дугой и отказ
  (ADR 0127, ADR 0177), «стоп» отмены (ADR 0153). Триггер примитива (`Select.Trigger`) — через
  `render`.
- **`Radio`** — кружок с точкой поверх Base UI `Radio`: кольцо фокуса, выключенное, высокая
  контрастность. Строка с подписью — `PopupItem` (этап 1).
- **`Checkbox`** — флажок поверх Base UI `Checkbox`: отмечен, частично, выключен, ожидание
  (ADR 0176). `SelectCheckbox` собран на нём. Редактор булевой ячейки переходит на него без смены
  поведения: одно нажатие, `Space` и `Shift+Space`, вспышка и объявления — прежние (ADR 0175,
  ED5, ED20–ED21).
- **`StatusIcon`** — фокусируемый значок с причиной в тултипе: имя — причина, тон ошибки или
  обычный, кольцо фокуса.
- **`PopupNavItem`**, **`PopupLevels`** — пункт перехода и уровни поповера-панели со сдвигом
  (ADR 0215, §3): строка раздела, «назад» и заголовок уровня одним видом.
- **`PopupSkeletonRows`** — строки-скелеты высотой пункта: разделы меню, панель раздела «Настроек
  вида», список вариантов (`Checklist`).

### 3. Истории

- **Блоки.** У каждого компонента кита поповеров — история `Tessera/UI/Popup/<Компонент>`:
  первой `Playground` с контролами пропов, состояния — историями без контролов (ADR 0117,
  SN30–SN31). Поповер в истории открыт на холсте `UiCanvas`, без таблицы.
- **Собранные поповеры.** Раздел `Tessera/UI/Popup/Assembled`: `AssembledPlayground` — поповер
  на выбор контролом, открытый на маленькой таблице; гайд `PopupAssembled` — по шагу на каждый
  поповер грида и плагинов, пояснение шага называет блоки, из которых он собран. Матрица
  контраста проходит каждый шаг, у шага — близнец высокой контрастности (ADR 0130).
- **Публичности нет.** Компоненты не экспортируются из `/ui`; экспорт — отдельным решением.

## Границы

- **Тултип** — своё семейство (ADR 0017), не входит.
- **Вид поповеров не меняется**, кроме принятого в PP11–PP13 (ADR 0017, 2026-11-04).
- **Публичный экспорт** из `/ui` — не в этом ADR.
- **Инлайн-редактор ячейки** (`CellEditInput`) вписан в размер ячейки и остаётся в плагине;
  текст ошибки он берёт у `Field` (PK5).
- **Кнопки `/ui` в папках плагинов** (`SortButton`, `PinButton`, `ResizeHandler`,
  `ExpandButton`, `GroupButton`) — место файлов не меняется.

## Отвергнутые альтернативы

- **Только истории поверх нынешних классов** на демо-разметке: история проверяет копию
  разметки, а не то, что рисуют плагины, и PP11–PP13 по-прежнему держит дисциплина.
- **Публичный `/ui` сразу**: пропы становятся публичным API до того, как устоялись (решение автора
  2026-11-04).
- **Перенести только поле**, список вариантов и календарь оставить в `shared/`: их нельзя
  посмотреть отдельно от плагина (решение автора 2026-11-04 — перенести всё).

## Последствия

- **+** Каждый блок поповера виден и проверяется отдельно; раскладку PP11–PP13 держит код.
- **+** Новый поповер плагина собирается из готовых блоков, без своих отступов и тем портала.
- **−** Перевод четырнадцати поповеров и перенос трёх модулей задевают границы слоёв и
  ленивые модули; их сторожат `layerBoundaries`, `cssComposes`, `check:tree-shaking`.
- **−** Бюджет снимков Chromatic растёт: истории блоков с состояниями и шаги гайда с близнецами.
- **−** Этап 4 ломает `/ui`: экспорты `SelectCheckbox` и `CheckMark` заменяет `Checkbox`.
- **+** Исключение `SizeTrigger` стража BN8 и самописный `role="checkbox"` уходят; поведение
  контролов — из Base UI.

## Внедрение

Тесты каждого этапа пишутся после того, как автор примет вид в историях (ADR 0117, §6а;
`ui-kit.md`, §2). Вид принят 2026-11-06, тесты внедрены: визуальный `popup-kit`, модульный `popupKit`
(PK1, PK7), PK11 — `check:tree-shaking`, PK10 — кейс в `interaction`; предел 10 % к ревизии до кита
сверяет `npm run perf:compare -- <ref> --cases PK10`.

- **Этап 1** (PK1–PK4, PK10): `PopupSurface`, `PopupPanel`, `PopupItem`, `PopupGroup` и их
  истории; перевод четырнадцати поповеров грида и плагинов на эти компоненты; `MenuItems`,
  `MenuSections`, `PopupEntry`, меню ручек — из них же. Внедрён 2026-11-04, тесты — после
  того как автор примет вид. Ряд кнопок, который поповер собирает сам (поповеры правки, журнал,
  пульт), — `PopupFooter`. Подвалы панели фильтра колонки по виду уже PP12 и переходят на
  `PopupPanel` на этапе 2 вместе с полями ввода; песочница консоли историй
  (`stories/demos/ConsoleFilters`) — со своей темой, вне PK1.
- **Этап 2** (PK5–PK7, PK11–PK16): перенос `Field`, `Checklist`, `Calendar` из `shared/` в кит
  с историями; плагины передают тексты из словаря и варианты в типе кита;
  `shared/field.module.css`, копии стилей поля и классы текста ошибки уходят. Контролы
  поповеров — `SearchField`, `SelectTrigger`, `Radio`, `Checkbox`, `StatusIcon` — с историями
  `Tessera/UI/<Компонент>`; потребители переходят на них, подвалы панели фильтра — на
  `PopupPanel`, неиспользуемые классы `OptionFilterPanel.module.css` уходят. Внедрён 2026-11-04,
  тесты — после того как автор примет вид. Высота поля — токен `--tsr-comp-button-size`, как у
  быстрого поиска; текст ошибки — цветом текста ошибки `--tsr-comp-error-text-color`, а не
  цветом отметки ячейки; у поиска «Колонок» появился крестик очистки; у крестика и подсказки поля
  поиска — тултип базы `IconButton`; редактор булевой ячейки — `Checkbox` с кольцом фокуса кита
  вместо обводки ячейки; `SelectCheckbox` — обёртка `Checkbox` с прежним контрактом `/ui`.
  Блок отказа загрузки списка (`.error` у `Checklist`) — не текст ошибки поля и остаётся.
- **Этап 3** (PK8–PK9; S1): раздел `Tessera/UI/Popup/Assembled` с `AssembledPlayground` и гайдом
  `PopupAssembled`, близнецы шагов, стражи историй кита и шагов гайда, тесты PP11–PP13 ADR 0017
  на `PopupPanel`; бюджет снимков — с запасом. Гайд и стражи внедрены 2026-11-06, тесты PP11–PP13 —

  четырнадцати файлов — панели фильтра вариантов и даты, меню ручки и отметка ячейки, блоки которых
  иначе нигде не видны на таблице.
- **Этап 4** (PK18–PK20), по замечаниям автора 2026-11-04: один `Checkbox` вместо `CheckMark` и
  `SelectCheckbox` — ломающее изменение `/ui` до 1.0; списки месяца и года календаря из кита;

  записанное время, а не время отрисовки: иначе быстрый набор затирал предыдущий сегмент.
- **Этап 6** (PK27–PK30), по замечаниям автора 2026-11-06 к гайду `PopupAssembled`: облачко выбранного

- **Этап 7** (PK31), по замечанию автора 2026-11-09: затемнение краёв прокрутки в поповерах.
  Края ставит хук кита `useScrollFade` (`ui/Popup`), маску рисует класс `scrollFade`; список года
  календаря прокручивает `Select.List`, а не поповер, иначе маска погасила бы тень поверхности.
  Base UI ставит выбранный пункт списка к краю — под затемнение, поэтому год календаря и колонки
  времени открываются на выбранном посередине (`centerSelected`). Внедрён, вид принят автором
  2026-11-11; тест PK31 — в `popup-kit`: рост затемнения и края по вычисленной маске, полоса прокрутки
  без маски — в Firefox и WebKit (в headless Chromium полоса шириной 0), у поверхности маски нет;
  год календаря и обе колонки времени посередине — колонка минут без фокуса: Chromium сам ставит в
  центр невидимый элемент при фокусе, и колонка часов центрирование не доказывает; потребители — по
  исходникам. TQ1: затемнение без роста, нижний край всегда затемнён, маска на полосе, год и минуты
  без `centerSelected`. Там же PK32 — дефект, а не вид: поповер отметки ячейки монтировался сразу
  открытым и снимался из DOM при закрытии, поэтому не проигрывал ни появления, ни ухода; теперь
  он остаётся смонтированным после первого открытия, а первый кадр — закрытым. Тест внедрён.
- **Этап 8** (PK33–PK36), по замечаниям автора 2026-11-09 к галерее всех поповеров: поиск и кнопки

  Правило двух линий заменяет двойное поле панели PP13 ADR 0017: поле поповера — линия рамок,
  поле пункта сверх него — линия текста; токен поля пункта — `--tsr-comp-popup-item-padding-x`.

  рамки, а не от внешнего края) — исправлено. TQ1: старый отступ поля времени, без правила пункта с
  кнопкой, без левого поля записи.
