# 0073 — Экспорт в Excel: свой генератор `.xlsx`

- **Статус:** Принято (решения — по итогам прожарки 2026-10-09)
- **Дата:** 2026-10-09

- **Изменён:** 2026-10-31 — XL3: пояс выгрузки — `timeZone` таблицы ([ADR 0169](0169-data-mode.md)).
- **Изменён:** 2026-10-25 — сценарии с гайдами (ADR 0117); требования демо-историй проверяет `play` гайдов (решение пользователя).

## Контекст

`dataExport` выгружает только CSV. Excel может подключить приложение своим
`ExportFormat` поверх SheetJS или ExcelJS, но «из коробки» его нет. У конкурентов Excel
есть только в платных гридах, двумя путями: свой генератор (AG Grid Enterprise) или
ExcelJS (MUI X Premium, DevExtreme). ExcelJS — около мегабайта; SheetJS публикует
свежие версии вне npm.

`.xlsx` — zip-архив из нескольких XML-файлов. Для листа с типизированными ячейками,
шапкой, ширинами и закреплением хватает нескольких сотен строк кода без зависимостей.

Решено (прожарка 2026-10-09):

- свой генератор, типы ячеек по значению плюс даты колонок с `filter: 'date'` /
  `'datetime'`;
- шапка, ширины и закреплённые слева колонки; вложенная шапка и уровни дерева — позже;
- сжатие встроенным `CompressionStream`, `serialize` может вернуть `Promise`;
- формат подключает приложение (`exportFormats.xlsx()`), генератор грузится лениво;
- сборка на главном потоке кусками; воркер — вторым срезом по результатам замера;
- больше 1 048 576 строк — продолжение на следующих листах;
- пояс дат — как у фильтра;
- корректность файла проверяет независимый читатель (ExcelJS) в `devDependencies`.

## Решение

### 1. Подключение

```ts
dataExport({ formats: [exportFormats.csv(), exportFormats.xlsx({ timeZone?, sheetName? })] })
```

Без `exportFormats.xlsx()` всё как раньше. Формат — лёгкая запись; генератор листа —
отдельный модуль (отдельный чанк сборки приложения), который грузится при первой
выгрузке в `.xlsx` (как ленивые поповеры, ADR 0061).

### 2. Контракт формата

`serialize(data)` может вернуть `Promise<string | Uint8Array | Blob>`: выгрузка ждёт
его, кнопка «Экспорт» показывает ожидание, как в серверном режиме (EX28). Отказ
логируется (`logError`), кнопка вспыхивает, `onExported` не вызывается. Это расширение
контракта ADR 0044 — CSV не меняется.

`ExportColumn` получает поля, нужные листу: `size` (ширина колонки в гриде, px),
`pinned` (`'start' | 'end' | false`) и `filter` (поле `filter` описания колонки — тип и
`parse` дат). `ExportData` получает `timeZone` — пояс активного `columnFiltering`. Поля
добавлены — существующие форматы их игнорируют.

Кнопка показывает блик ожидания только у клиентской асинхронной выгрузки: она
блокирует повторный клик. Серверная выгрузка по-прежнему оставляет кнопку доступной —
пока сервер работает, можно выгрузить текущую страницу (EX28).

### 3. Ячейки

| Значение                                         | Ячейка Excel                                    |
| ------------------------------------------------ | ----------------------------------------------- |
| `number` (конечное)                              | число                                           |
| `boolean`                                        | логическое                                      |
| `Date`                                           | дата-время со стилем формата                    |
| строка в колонке `filter: 'date'` / `'datetime'` | дата по правилам фильтра дат (DF2), иначе текст |
| строка, прочее                                   | текст (`inlineStr`), объект — JSON, как в CSV   |
| `null`, `undefined`, `NaN`, бесконечность        | пустая ячейка                                   |

Текст пишется строковой ячейкой и формулой не становится: защита от формул, как у CSV,
не нужна. Спецсимволы XML экранируются, недопустимые в XML управляющие символы
удаляются.

**Даты.** В Excel нет поясов: пишется стенное время. `date` — календарный день без
сдвига; `datetime` и `Date` — стенное время пояса `timeZone` формата, по умолчанию
пояса активного `columnFiltering` (`columnFilteringTimeZone`), иначе браузера. Так в
файле то же время, что пользователь видит и фильтрует. Точность — секунды (фильтр
считает минутами). Разбор дат переезжает из плагина `columnFiltering` в общий код ядра,
чтобы экспорт не тянул фильтрацию.

### 4. Лист

- Первая строка — подписи листьев, жирным; закреплена при прокрутке; на ней автофильтр
  Excel.
- Ширины колонок — из `size` (px → ширина символа Excel).
- Колонки, закреплённые слева в гриде, закреплены и в Excel. Справа Excel закреплять не
  умеет — такие колонки идут обычными на своём месте.
- Больше 1 048 576 строк — данные продолжаются на листах 2, 3… с той же шапкой.
- Имя листа — `sheetName` (по умолчанию `Sheet1`; следующие — с номером).

### 5. Архив и объём

zip собирается своим кодом: записи, CRC-32, центральный каталог. Каждая часть сжимается
deflate через `CompressionStream('deflate-raw')`, который работает вне главного потока;
без него записи хранятся без сжатия. XML листа строится кусками строк с отдачей потока
между ними, чтобы выгрузка большого объёма не давала длинных задач.

Генератор — чистая функция без DOM (`buildXlsx(data, options)`): второй срез может
запускать её в воркере, который подключит приложение.

## Вне объёма

- Вложенная шапка (объединённые ячейки групп) и уровни дерева (группировка строк Excel)
  — следующим срезом после обсуждения.
- Стили ячеек из грида, числовые форматы колонок, формулы, несколько листов по выбору
  приложения.
- Воркер — вторым срезом, если замер XL11 покажет, что кусков не хватает.
- Серверный режим не меняется: сервер получает id формата.

## Последствия

- **+** Excel из коробки без зависимостей в `dist` и без платы за него у приложений,
  которые его не включили.
- **+** Ячейки типизированы: Excel сортирует, фильтрует и считает числа и даты.
- **−** Свой генератор — своя ответственность за корректность OOXML; страхует XL1 с
  независимым читателем в тестах.
- **−** Расширение публичного API: `exportFormats.xlsx`, поля `ExportColumn`,
  `serialize` с `Promise`.
- **−** Новая devDependency (ExcelJS) — только в тестах.
