# 0030 — Контекстное меню: плагин contextMenu (план)

- **Статус:** Предложено (не реализовано)
- **Дата:** 2026-09-22
- **Связано:**
  - [ADR 0024](0024-slot-action-descriptor-and-menu.md) — единый дескриптор
    `SlotAction<TCtx>` (иконка/подпись/`onSelect`/`visible`/`disabled`/`active`/
    `menuItems`) и движок меню на Base UI (`resolveMenuItems`, `ActionMenu`).
    Контекстное меню — **новая поверхность на том же движке**, не новый движок
    (принцип ADR 0024: «новая поверхность = новый плагин-меню»).
  - [ADR 0010](0010-invert-core-plugins-registry.md) — presence-based композиция;
    действия — декларативный канал записи, сворачиваемый ядром реактивно. Пункты
    контекстного меню собираются тем же способом (**инверсия**: плагины
    контрибьютят, ядро собирает).
  - [ADR 0017](0017-ui-components.md) — меню на Base UI `Menu`; здесь —
    **контекстный** триггер с виртуальным якорем у курсора.
  - [ADR 0029](0029-cell-range-selection.md) — cellSelection; первый контрибьютор
    (пункт «Копировать», позже «Вставить»); координация «правый клик по невыбранной
    ячейке» (см. Открытые вопросы).
  - [ADR 0020](0020-accessibility.md) — `role="menu"`, клавиатура/фокус меню (Base
    UI из коробки); контекстное меню наследует этот контракт.
  - [ADR 0009](0009-test-coverage-visual-and-performance.md) — три вида покрытия.

## Контекст

Правый клик по гриду сейчас даёт нативное меню браузера. Spreadsheet-UX (Excel/
Sheets/AG Grid) ожидает **своё контекстное меню**: «Копировать», позже «Вставить»,
действия строки/заголовка. Механика уже есть — «действие как данные»
([ADR 0024](0024-slot-action-descriptor-and-menu.md)) + Base UI `Menu`
([ADR 0017](0017-ui-components.md)); не хватает **поверхности** (триггер по правому
клику + позиционирование у курсора) и **канала контрибуции** пунктов от плагинов.

Держать меню внутри `cellSelection` нельзя: контекстное меню шире выделения ячеек
(строка, заголовок, грид в целом) — это отдельный сквозной концерн.

## Решение (предлагаемое)

Ввести плагин **`contextMenu()`** — presence-based запись `definePlugin`
([ADR 0010](0010-invert-core-plugins-registry.md)) **без сервисной колонки**,
переиспользующий дескриптор `SlotAction` и движок меню
([ADR 0024](0024-slot-action-descriptor-and-menu.md)).

### Канал контрибуции (требование 1)

Новый декларативный канал записи `RegistryEntry.contextMenuActions:
ContextMenuAction[]`, где `ContextMenuAction = SlotAction<ContextMenuContext>` —
**та же форма дескриптора**, что и у кнопок слота (иконка/подпись/`onSelect`/
`visible`/`disabled`/`active`/`menuItems`/`order`). Ядро сворачивает пункты
активных записей (как `slotActions`, реактивно по сигнатуре набора) и рендерит их
`resolveMenuItems` в Base UI `Menu`. Любой плагин добавляет пункт, объявив действие
данными; порядок — по `order`; группировка — `menuGroupLabel`/`menuItems`.

Первый контрибьютор — `cellSelection`: пункт «Копировать» (у него уже есть
`getSelectedCellRangesData` + сериализация, [ADR 0029](0029-cell-range-selection.md)),
позже «Вставить». `rowActions`/сортировка/пиннинг могут контрибьютить свои действия.

### Триггер и позиционирование (требование 2)

- Открытие по событию **`contextmenu`** (правый клик) внутри тела грида;
  `preventDefault` гасит нативное меню браузера.
- Base UI `Menu` с **виртуальным якорем** в точке курсора (`getBoundingClientRect`
  вокруг `clientX/clientY`); меню флипается у краёв вьюпорта штатно.
- Клавиатура/фокус/`Escape`/стрелки/`role="menu"` — из Base UI
  ([ADR 0017](0017-ui-components.md), [ADR 0020](0020-accessibility.md)).
- **Touch — вне первого среза** (long-press → меню) — отдельным шагом (см.
  Границы).

### Контекст и зависимость действий от выбора (требование 3)

**Решение: одно меню, пункты гейтятся контекстом — не два разных меню.**

Контекст пункта — `ContextMenuContext` = контекст ячейки под курсором
(`CellComponentProps`) + **сводка выделения**:

```ts
interface ContextMenuContext extends CellComponentProps {
  selection: {
    count: number        // сколько ячеек выделено
    isSingle: boolean    // ровно одна
    isMultiple: boolean  // > 1
    isInSelection: boolean // ячейка под курсором входит в выделение
  }
}
```

Каждый пункт сам решает применимость через уже существующие предикаты дескриптора:

- `visible(ctx)` — убрать пункт для неподходящего выбора (напр. гипотетическое
  «Объединить» — только `isMultiple`; «Редактировать» — только `isSingle`);
- `disabled(ctx)` — показать, но заблокировать.

Так «Копировать» доступно всегда (и для одной, и для многих), а специфичные
действия появляются/блокируются по `count`/`isSingle`/`isMultiple`. Это тот же
механизм, что гейтит кнопки слота в [ADR 0024](0024-slot-action-descriptor-and-menu.md)
(`visible`/`disabled`), — без развилки «меню A vs меню B».

## Границы

- **Touch (long-press)** — вне первого среза; отдельным шагом (жест + задержка +
  подавление native callout).
- **Клавиатурный вызов** (`Menu`-клавиша / `Shift+F10`) — вне первого среза;
  ложится на будущий `keyboardNavigation` ([ADR 0021](0021-keyboard-navigation.md)).
- **Вставка** как пункт — зависит от `cellEditing`/валидации
  ([ADR 0029](0029-cell-range-selection.md), роадмап), не входит сюда.
- **Вложенные подменю** — при необходимости, но не в первом срезе.

## Последствия

- **+** Единая модель действий: контекстное меню — ещё одна подача тех же
  `SlotAction`-дескрипторов; плагины контрибьютят данными, ядро собирает.
- **+** Отвязано от `cellSelection`: работает и без него (пункты дают другие
  плагины); `cellSelection` — просто первый контрибьютор.
- **+** Opt-in/tree-shakeable; без плагина — нативное меню браузера.
- **−** Новый контекст (`ContextMenuContext`) и канал (`contextMenuActions`) —
  небольшое расширение ядрового контракта поверх ADR 0024.
- **−** Координация «правый клик по невыбранной ячейке» вводит связь с
  `cellSelection` (см. Открытые вопросы).

## Открытые вопросы

- **Правый клик по ячейке ВНЕ выделения.** Spreadsheet-конвенция: сначала
  схлопнуть выделение на эту ячейку (или оставить, если она уже в выделении), потом
  открыть меню. Кто владеет этим — `contextMenu` зовёт публичный
  `setFocusedCell`/`selectCellRange` фичи, или `cellSelection` слушает `contextmenu`
  сам? Предпочтение: `contextMenu` перед открытием обеспечивает «target выбран»
  через публичный API фичи (по presence), не импортя плагин.
- **Канал: новый `contextMenuActions` vs новый `SlotName`.** Отдельный канал
  чище (свой контекст с выборкой), чем перегрузка `SlotName`/`slotActions`.
- **Пустое меню.** Если ни один активный плагин не дал применимого пункта — меню не
  открывать (уступить нативному), а не показывать пустое.
- **Скролл/ресайз при открытом меню** — закрывать или репозиционировать (Base UI
  политика).

## Требования (планируемые)

По конвенции ([ADR 0001](0001-spec-driven-development.md),
[ADR 0009](0009-test-coverage-visual-and-performance.md)) каждое требование —
именованный тест `CM<n>` в `visual/context-menu.test.tsx` (vitest-browser) и
unit-логика в `__tests__/contextMenu.test.ts`.

| ID  | Требование                                                                                     | Тест          |
| --- | --------------------------------------------------------------------------------------------- | ------------- |
| CM1 | Любой активный плагин добавляет пункт (`contextMenuActions`); собираются в одно меню по `order` | ☐ планируется |
| CM2 | Правый клик (`contextmenu`) в теле грида открывает меню у курсора; нативное меню подавлено      | ☐ планируется |
| CM3 | Пункты гейтятся контекстом выбора: `visible`/`disabled` по `isSingle`/`isMultiple`/`count`      | ☐ планируется |
| CM4 | `cellSelection` контрибьютит «Копировать»; выбор пункта кладёт выделение в буфер (TSV+HTML)     | ☐ планируется |
| CM5 | Пустое меню (нет применимых пунктов) не открывается — уступает нативному                        | ☐ планируется |
| CM6 | `Escape`/клик вне/выбор пункта закрывают меню; фокус/`role="menu"` (Base UI, a11y)              | ☐ планируется |
| CM7 | Правый клик по ячейке вне выделения выделяет её (target выбран) до открытия меню                | ☐ планируется |
| CM8 | Плагин инертен без импорта: правый клик даёт нативное меню браузера (tree-shaking)              | ☐ планируется |

**Перф.** Отдельного кейса не требует: свёртка `contextMenuActions` мемоизирована по
сигнатуре набора; меню Base UI монтируется лишь при открытии (как в
[ADR 0024](0024-slot-action-descriptor-and-menu.md)).

## План внедрения (предлагаемый)

- **Фаза 1 — канал + движок.** `contextMenuActions` в записи/`definePlugin`, фолд
  (по образцу `slotActions`), `ContextMenuContext` со сводкой выбора. Переиспользовать
  `resolveMenuItems`.
- **Фаза 2 — поверхность.** Плагин `contextMenu`: слушатель `contextmenu`,
  виртуальный якорь, Base UI `Menu`, подавление нативного меню; пустое меню не
  открывать (CM2/CM5/CM6/CM8).
- **Фаза 3 — контрибуция и контекст-гейтинг.** `cellSelection` даёт «Копировать»;
  правый-клик-вне-выделения выделяет target; `visible`/`disabled` по выборке
  (CM1/CM3/CM4/CM7).
- **Фаза 4 (позже).** Touch (long-press), клавиатурный вызов, «Вставить».

См. [ADR 0024](0024-slot-action-descriptor-and-menu.md) про дескриптор и движок
меню, [ADR 0029](0029-cell-range-selection.md) про cellSelection как первого
контрибьютора и [ADR 0010](0010-invert-core-plugins-registry.md) про инверсию
«плагины контрибьютят — ядро собирает».
