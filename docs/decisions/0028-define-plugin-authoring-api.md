# 0028 — `definePlugin`: эргономичный API написания плагина

- **Статус:** Принято.

## Контекст

После [ADR 0027](0027-plugin-hooks-in-factory-args.md) плагин — это запись
`TesseraFeatureEntry`, а фабрика вручную раскладывает плоские опции по полям. Авторская
поверхность оказалась низкоуровневой и «протекающей». Конкретные проблемы (из ревью API):

1. Слайс хуков собирается руками (`hookSlice = {}` + присваивания), иначе тип не сходится.
2. Нужны `if (opts.x)`-проверки, какие параметры переданы.
3. Из тела фабрики не видно разницы между `options` и `hooks` (почему одно живо, другое — нет).
4. Неясно, как расширять типизацию `options`/`hooks`/`state` для своего плагина.
5. Поле `slot` — непрозрачно (что это и почему объект).
6. `id` задаётся строкой в глобальном неймспейсе; коллизия между плагинами разных
   авторов разрешается молча («последний победил») — латентный баг.
7. Нет первоклассного способа завести **реактивное** или **мемоизированное** значение
   плагина, читаемое из его компонента (сейчас — руками писать v9-фичу, как
   `columnDraggingFeature`).
8. **Компонент плагина читает состояние/хуки через касты** (`(table.getHooks() as
RowSelectionPlugin).rowSelection`, `table.atoms.rowSelection as never`). Тип доступа не
   гарантирован компилятором — расхождение декларации и чтения всплывает в рантайме.

## Решение

Ввести хелпер-конструктор `definePlugin`, который принимает **декларации по именованным
полям**, а возвращает обычную фабрику `(opts?) => TesseraFeatureEntry`. Он прячет
раскладку, делает контракт «мемо/живо» явным и — ключевое для типобезопасности —
**связывает типы состояния/опций/хуков плагина с типами пропсов его слот-компонентов**.

Локальный канал плагина (`state`/`options`/`hooks`) **приходит в его слот-компоненты
пропсами** — как `row`/`table` сейчас. Компонент остаётся чистой функцией пропсов: **не
импортирует сам плагин**, не дёргает глобальных хелперов, не кастует. Токен identity
(ниже) используется **внутри** `definePlugin` для развязки локальных каналов в сторе;
автор его не видит.

### API

```ts
// Сигнатуры вынесены в именованные типы — объявляются один раз и переиспользуются.
type Favorites = Record<string, boolean>
type ToggleFavorite = (rowId: string, favorite: boolean) => void

interface FavoriteOptions {
  enabled?: boolean
  maxFavorites?: number
  favorites?: Favorites // ВНЕШНИЙ источник локального слайса (конвенция: favorites ↔ favorites)
  onFavoritesChange?: (next: Favorites) => void // запись назад (опц.)
  onToggleFavorite?: ToggleFavorite // бизнес-колбэк
}
interface FavoriteState {
  favorites: Favorites
}
interface FavoriteResolvedOptions {
  maxFavorites: number // дефолт применён — в компоненте не `| undefined`
}
interface FavoriteHooks {
  onToggleFavorite: ToggleFavorite // no-op применён — не опционально
}

// Пропсы слот-компонента = базовые (row/table) + локальный канал плагина.
// Порядок hooks-first; указываем только используемые каналы (rowFavorite читает все три).
type FavoriteCellProps = PluginCellProps<
  FavoriteHooks,
  FavoriteState,
  FavoriteResolvedOptions
>

// Никакого импорта rowFavorite. Компонент точно знает свой доступ из дженериков.
function FavoriteCell({
  row,
  state: [favorites, setFavorites],
  options,
  hooks,
}: FavoriteCellProps) {
  const isFav = favorites[row.id] ?? false
  const toggle = () => {
    if (!isFav && Object.keys(favorites).length >= options.maxFavorites) return
    const next = { ...favorites, [row.id]: !isFav }
    setFavorites(next) // локальная запись (роутинг внутр. стор / onChange — фреймворком)
    hooks.onToggleFavorite(row.id, next[row.id]) // живой колбэк, без каста
  }
  // ...
}

// TOptions (FavoriteOptions) задаётся ОДИН раз — явным дженериком; o в полях выводится.
export const rowFavorite = definePlugin<FavoriteOptions>()({
  id: 'rowFavorite', // debug-лейбл; identity локального скоупа — токен (внутр.)
  options: (o): FavoriteResolvedOptions => ({
    maxFavorites: o.maxFavorites ?? Infinity,
  }),
  hooks: (o): FavoriteHooks => ({
    onToggleFavorite: o.onToggleFavorite ?? (() => {}),
  }),
  // ЛОКАЛЬНЫЙ слайс: только ДЕФОЛТ (тип из аннотации возврата, без каста).
  // Внешний источник/запись — по конвенции из опций favorites / onFavoritesChange.
  state: (): FavoriteState => ({ favorites: {} }),
  // ↓ компонент КАЖДОГО слота констрейнится под FavoriteHooks/State/ResolvedOptions
  slots: [{ slot: 'rightCellSlot', component: FavoriteCell }],
})
```

> **Что такое поле `features` (бывший `slot`).** v9 — feature-based: таблица собирается из
> объектов-фич через `tableFeatures({ … })`, каждая фича учит инстанс своим методам/моделям
> (`rowSortingFeature` → `column.getToggleSortingHandler()`, `table.getSortedRowModel()`).
> `features` — это **фрагмент стоковых фич TanStack, который плагин вносит в набор**; ядро
> сливает `features` всех активных плагинов и прогоняет через `tableFeatures()`
> (`buildTesseraFeatures`). Пример у сортировки:
> `features: { rowSortingFeature, sortedRowModel, sortFns }`.
>
> Поле нужно только плагину, который **оборачивает встроенную фичу** (сортировка, пиннинг,
> выбор, раскрытие, ресайз, группировка). У полностью **кастомного** `rowFavorite`
> (собственное поведение + собственный `state`) стоковой фичи нет — поэтому в примере поля нет.
>
> `features` — это **v9-замена тому, что в v8 было всегда-доступными методами ядра**: в v8
> методы (`getToggleExpandedHandler` и пр.) присутствовали на инстансе всегда, а row-модель
> задавалась опцией (`getExpandedRowModel`); в v9 и методы, и модель приходят только через
> регистрацию фичи.
>
> **Не путать со `slots`** (мн.ч.): `features` — регистрация возможностей таблицы
> (методы/модели, заморожено на маунте); `slots` — куда рендерить UI плагина (чекбокс, кебаб),
> реактивно. Из-за этой путаницы `slot`→`features` и переименовано (DP10).

### Типобезопасность слот-компонентов (несущее требование)

`definePlugin` выводит дженерики из деклараций и **констрейнит ими каждый слот-компонент**.
У дженериков есть **дефолты**, чтобы плагин указывал только реально используемые каналы:
`state`/`options` по умолчанию — **нативные типы таблицы**, `hooks` — `never` (табличного
аналога нет). Порядок **hooks-first**, чтобы частый случай «только hooks» писался одним
аргументом:

```ts
export interface PluginCellProps<
  THooks = never, // нет hook-слайса → hooks недоступны (never)
  TState = TableState, // нет локального state → дефолт = состояние таблицы
  TOptions = TableOptions, // нет резолв-опций → дефолт = опции таблицы
> extends CellComponentProps {
  hooks: THooks
  state: [TState, (next: TState) => void]
  options: TOptions
}
type SlotDecl<TProps> = {
  slot: SlotName
  component: (props: TProps) => ReactNode
}

// TOptions — явным дженериком ОДИН раз (каррированная форма); TResolved/THooks/TState
// выводятся из деклараций конфига. `o` в options/hooks выводится как TOptions.
export function definePlugin<TOptions>(): <TResolved, THooks, TState>(config: {
  id: string
  options: (o: TOptions) => TResolved // o = TOptions по инференсу — без повторной аннотации
  hooks: (o: TOptions) => THooks
  state: () => TState
  // компонент констрейнится ВЫВЕДЕННЫМИ типами плагина (hooks-first):
  slots: SlotDecl<PluginCellProps<THooks, TState, TResolved>>[]
  // ...features/column/setup
}) => (opts?: TOptions) => TesseraFeatureEntry
```

Что это гарантирует:

1. **Указываешь только используемые каналы — без выдумывания несуществующих типов.**
   «Только hooks» (напр. `rowSelection`) — `PluginCellProps<RowSelectionHooks>`; неуказанные
   `state`/`options` берут дефолт от таблицы, `hooks` без слайса — `never`.
2. **Заявленный каналом тип — конкретный, этого плагина.** `THooks`/`TState`/`TResolved` TS
   выводит из `hooks`/`state`/`options` **того же** вызова `definePlugin`; поле `slots`
   констрейнит компонент этими типами.
3. **Расхождение или пропуск заявленного канала = ошибка компиляции на строке слота.**
   Компонент, чей тип канала разошёлся с декларацией (напр. `PluginCellProps<WrongHooks>`),
   **или** взявший табличный дефолт там, где плагин объявил свой `state`, не присваивается в
   `slots` → красное прямо в `definePlugin`, а не в рантайме (снимает проблему 8/8).

Слоты-шапки типизируются аналогично (`PluginHeaderProps<THooks, TState, TOptions>` — без
`row`). Инъекцию пропсов делает обёртка, которую генерит `definePlugin`: ядро по-прежнему
видит слот как `CellComponentProps => ReactNode`, а обёртка подмешивает `hooks`/`state`/
`options` из `getHooks()`/стора под токеном плагина (реактивно через `useSelector`).

### Три канала доступа

Пропсы слот-компонента разложены на три независимых канала. `PluginCellProps<H, S, O>`
**наследует** нативный `CellContext` (`table`, `row`, `column`, `cell`, `getValue`) —
поэтому доступ к таблице и её методам **сохраняется полностью**, новые пропсы лишь
добавляются сверху:

| Канал                                                       | Откуда                                           | Приватность                                                                                      |
| ----------------------------------------------------------- | ------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| Нативное состояние/методы (`getState`, `row.getIsSelected`) | пропсы `table` / `row` (`CellContext`)           | **общее** — по замыслу; читают все плагины                                                       |
| Бизнес-хуки плагина                                         | пропс `hooks` (обёртка читает `getHooks()[tok]`) | доставка **скоуплена** токеном и типизирована; но `table.getHooks()` **общий**, как `getState()` |
| Локальное состояние плагина                                 | пропс `state: [value, setter]`                   | **приватное** — токен-атом, символ не экспортируется, в `getState()` не попадает                 |

**`getHooks`/`getState` — публичные общие аксессоры (как в TanStack).** Пропс `hooks` — это
типизированный, скоупленный и без-кастовый **вид на свой слайс**, а не барьер: через
`table.getHooks()` по-прежнему видно всё (перекрёстное чтение чужих хуков допущено сознательно —
изоляция хуков не является целью). Приватным остаётся только локальный `state`.

#### Было → Стало (реальный код `rowSelection`)

Компонент — исчезают касты, доступ гарантируется дженериками пропсов:

```tsx
// БЫЛО: RowSelectionComponent
export const RowSelectionComponent = ({ row, table }: CellComponentProps) => {
  useSelector(
    (
      table as unknown as { atoms: { rowSelection: unknown } }
    ) // ← каст ради подписки
    .atoms.rowSelection as never,
  )
  const { isAllRowsSelected, onSelectRow } = (
    table.getHooks() as RowSelectionPlugin
  ).rowSelection // ← каст ради хуков
  // ...
}

// СТАЛО: тот же компонент под definePlugin.
// rowSelection использует ТОЛЬКО hooks (локального state нет, опции компонент не читает) →
// один аргумент; state/options берут дефолт от таблицы, ничего выдумывать не нужно.
const RowSelectionComponent = ({
  row,
  table,
  hooks,
}: PluginCellProps<RowSelectionHooks>) => {
  useSlice(table, 'rowSelection') // ← нативный слайс через table, типизировано, без каста
  const { isAllRowsSelected, onSelectRow } = hooks // ← пропс, типизировано, без каста
  // ...
}
```

Фабрика — исчезает ручная раскладка `hookSlice` и `if (opts.x)`; поля декларативны
(`state` у `rowSelection` нет — выбор это нативное состояние таблицы):

```ts
// БЫЛО: registry.ts
export const rowSelection = (opts: RowSelectionOptions = {}) => {
  const hookSlice: Partial<RowSelectionPluginParams> = {}
  if (opts.onSelectRow) hookSlice.onSelectRow = opts.onSelectRow
  if (opts.onSelectAllRowsOnPage)
    hookSlice.onSelectAllRowsOnPage = opts.onSelectAllRowsOnPage
  if (opts.isAllRowsSelected !== undefined)
    hookSlice.isAllRowsSelected = opts.isAllRowsSelected
  return {
    id: 'rowSelection',
    enabled: opts.enabled,
    slot: { rowSelectionFeature },
    hooks: { rowSelection: hookSlice },
    column: {/* … */},
    options: {
      enableRowSelection: opts.enabled === false ? false : enableRowSelection,
      enableSubRowSelection: opts.subRows ?? false,
      enableRowRangeSelection: false,
    },
  } satisfies TesseraFeatureEntry<{
    rowSelectionFeature: typeof rowSelectionFeature
  }>
}

// СТАЛО: definePlugin (TOptions задан ОДИН раз дженериком; o в полях выводится)
export const rowSelection = definePlugin<RowSelectionOptions>()({
  id: 'rowSelection',
  features: { rowSelectionFeature }, // фрагмент стоковой фичи v9
  options: o => ({
    enableRowSelection: o.enabled === false ? false : enableRowSelection,
    enableSubRowSelection: o.subRows ?? false,
    enableRowRangeSelection: false,
  }),
  hooks: o => ({
    onSelectRow: o.onSelectRow,
    onSelectAllRowsOnPage: o.onSelectAllRowsOnPage,
    isAllRowsSelected: o.isAllRowsSelected, // undefined-ключи отбросит definePlugin
  }),
  column: {/* … */},
})
```

### Куда протекают данные (сквозной дата-флоу)

От вызова фабрики потребителем — до пропсов авторского компонента:

```text
rowFavorite(opts)                 // opts — то, что потребитель передал фабрике
      │
definePlugin склеивает TesseraFeatureEntry из деклараций:
   options(opts) → резолвнутые опции
   hooks(opts)   → hook-слайс (undefined-ключи отброшены)
   state()       → seed (дефолт)
   features      → фрагмент фич v9
   slots         → { slot, component } + обёртка инъекции
      │
useCreateTable композирует набор (граница мемо/живо — по полю):
   features → tableFeatures() ................. заморожено на маунте
   options  → foldEntries (мемо по значению аргументов, ADR 0039) . живо
   hooks    → foldHooks КАЖДЫЙ рендер ......... живо → options.hooks → table.getHooks()
   state    → атом в Store под ТОКЕНОМ ........ seed один раз; внешний источник — опция `favorites`
   slots    → RenderSlots (обёртки) .......... реактивная сборка из активных плагинов
      │
Рендер слота: ядро зовёт обёртку с нативным CellContext (row, table, …).
Обёртка читает живьё и собирает PluginCellProps<H, S, O>:
   row, table          ← из CellContext (как есть; getState/getHooks — общие)
   options             ← резолвнутые опции (по значению аргументов)
   hooks               ← table.getHooks()[token]        (живой слайс своего токена)
   state: [value, set] ← useSelector(атом токена) + сеттер (реактивно)
      │
      └─→ авторский FavoriteCell(props)  // чистая функция пропсов, без импорта плагина
```

Куда пишет автор: `setFavorites(next)` — сеттер из пары `state` → внутренний атом токена или,
если задан `onFavoritesChange`, наружу потребителю (роутинг решает фреймворк). `hooks.*` —
только зов живого колбэка (побочный эффект), состояние им не хранят.

### Граница «мемоизируется / читается живо» — по полю

Ключевое решение: **где именно проходит граница, задаёт поле, а не автор per-параметр.**
Автор не рассуждает о мемоизации — он кладёт значение в поле с зафиксированной семантикой:

| Поле                             | Стратегия ядра                                                                 | В слот-компонент приходит                               |
| -------------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------- |
| `options`                        | живо по значению аргументов (ADR 0039); функции — стабильные обёртки           | пропс `options` (резолвнутый конфиг, дефолты применены) |
| `state` (локальный)              | дефолт стабилен (seed); внешний источник (опция) — живо; реактивно через Store | пропс `state: [value, setter]`                          |
| `slots` / `actionMenu` / `setup` | живо по значению аргументов (ADR 0039); `setup` перезапускается                | (структура/сайд-эффекты; в пропсы не идёт)              |
| `features` / `column`            | заморожено по составу набора                                                   | (структура; в пропсы не идёт)                           |
| `hooks`                          | **живо** (`foldHooks` каждый рендер)                                           | пропс `hooks` (свежие бизнес-колбэки)                   |

Обоснование, почему нельзя «просто всё сделать опциями»: внутри опций намешаны
значения-флаги (свежесть безразлична) и функции, кормящие мемоизированные row-модели
(`getSubRows`/`sortFns`/`getRowCanExpand` — им нужна стабильность), а колбэки, наоборот,
обязаны быть свежими. Различить их автоматически по параметру нельзя — поэтому граница
проведена явно по полю. `hooks` — и есть эта граница.

**Пересмотрено [ADR 0039](0039-reactive-plugin-arguments.md).** Заморозка `options`
по сигнатуре оказалась несовместима с ожиданием «аргументы фабрики — живые пропсы».
Конфликт снят без выбора поля автором: ядро пересобирает `options`/`slots`/
`actionMenu`/`setup` при смене **значения** аргументов, а функции из аргументов
подаёт стабильными обёртками на последнюю версию — ссылка для мемо row-моделей не
меняется. `slots` может быть функцией аргументов фабрики (DP15). Временное поле
`liveOptions` (прежний DP14) удалено как поглощённое этим механизмом.

### Identity: токен для локального, человеко-ключ для общего

`definePlugin` вызывается один раз на модуль → **identity привязана к определению, а не к
вызову фабрики** и стабильна. Он минтит **уникальный токен** (`Symbol`/объект).

- **Локальные каналы** (`hooks` и локальный `state`) неймспейсятся по **токену** — им
  адресуется обёртка `definePlugin` при инъекции пропсов в слот-компоненты. Токен даёт
  **типизированную и бесколлизийную** доставку своего слайса (без строковых scope и
  `as`-кастов). Это **удобство и защита от коллизий, не барьер изоляции**: локальный `state`
  живёт под токен-атомом (символ не экспортируется → снаружи не адресуется и не попадает в
  плоский `getState()`), а хуки дополнительно доступны через публичный `table.getHooks()` —
  он **общий, как `getState()`** (перекрёстное чтение допущено сознательно, см. «Три канала
  доступа»).
- **Общее (shared) состояние** живёт в общем `table.getState()` и **референсится снаружи**
  (`useCreateTable({ state })`), поэтому у него **человекочитаемый ключ** (как встроенные
  `rowSelection`/`expanded`). Общий неймспейс → коллизия возможна → ядро **дев-варнит**
  (замена нынешнего тихого «последний победил»).

Строковый `id` — опциональный человекочитаемый лейбл (дев-варнинги/отладка), а не
collision-prone ключ.

### Два уровня состояния: общее (shared) и локальное (plugin)

Ключевое различие, определяющее **куда писать** и **как типизировать**:

|                 | **Общее** (shared)                                             | **Локальное** (plugin)                                         |
| --------------- | -------------------------------------------------------------- | -------------------------------------------------------------- |
| Где задаётся    | `useCreateTable({ state, handlers })`                          | опции плагина: `rowFavorite({ favorites, onFavoritesChange })` |
| Где живёт       | `table.getState()` — общий плоский неймспейс                   | общий стор под ключом `plugin:<id>` (DP13)                     |
| Кто читает      | **любой** плагин (`useSlice(table, '…')`)                      | слот плагина с `state: true` — пропсом; снаружи — `onChange`   |
| Типизация       | **глобальная** (declaration merging `TableState`) — видна всем | **локальная** (инференс из декларации) — в `PluginCellProps`   |
| Ключ / identity | человекочитаемый → дев-варн на коллизию                        | `plugin:<id>` → не совпадает со стоковыми срезами (DP13)       |
| Когда           | нужно нескольким плагинам или потребителю снаружи              | приватно одному плагину                                        |

Это **не два способа одного и того же** (и не путаница «где писать»), а **выбор скоупа**:
«это состояние приватно моему плагину?» → опции плагина; «его читают другие плагины или
потребитель снаружи (тулбар над гридом)?» → `useCreateTable` (тогда это уже shared, и
читается через `useSlice`, а не пропсом слота).

**Локальное состояние** декларируется **одной функцией дефолтов** (`state: () => ({ … })`,
тип из аннотации возврата, без каста). Внешний источник и запись плагин объявляет **парой
своих опций** — как в самом TanStack (`rowSelection` ↔ `onRowSelectionChange`):
`controlled: { value: 'favorites', onChange: 'onFavoritesChange' }`. Тогда:

- не передал `favorites` → берётся дефолт (uncontrolled);
- передал новую ссылку `favorites` → срез принимает её до отрисовки кадра;
- передал и не меняешь → фактически initial: изменения изнутри не затираются (отдельного
  `initialFavorites` не нужно);
- каждое изменение среза изнутри приходит в `onFavoritesChange`; он **опционален**.

Это синхронизация по смене значения, а не строгий controlled React: без `onChange` срез
всё равно меняется изнутри. Опция значения исключена из ключа аргументов — новое значение
не пересобирает настройку плагина (опции, слоты, `setup`).

Плагин **агностичен**: читает эффективный слайс из пропса `state` (реактивно), пишет одним
сеттером из той же пары; роутинг (внутренний стор vs `onChange` потребителя) — фреймворком.

**Общее состояние** — модель TanStack controlled/uncontrolled: плагин объявляет слайс с
человеко-ключом (или пользуется встроенным, напр. `rowSelection`); потребитель контролирует
его через `state`/`handlers`; читают любые плагины через `useSlice`/`table.getState()`.
Правило пары `state.X` + `onXChange` — как в TanStack.

### Типизация: локальная (инференс) vs общая (declaration merging)

- **Локальное типизируется локально; общее — глобально** (главный водораздел). `hooks` и
  локальный `state` доступны и типизированы **только слот-компонентам плагина** — через
  дженерики `PluginCellProps` (hooks-first, с дефолтами от таблицы для `state`/`options` и
  `never` для `hooks`); тип выводится из деклараций плагина и связывается с пропсами
  констрейнтом на `slots` (см. «Типобезопасность слот-компонентов»). Ни глобальной
  аугментации, ни коллизий. Общее состояние/хендлеры
  читают **все** плагины, поэтому объявляются **глобально** (`TableState`/`TableOptions`
  через declaration merging) — как встроенные слайсы TanStack.
- Один входной тип на плагин (`TOptions`) — задаётся **один раз явным дженериком**
  (`definePlugin<TOptions>()(...)`, каррированная форма): `o` в `options`/`hooks` выводится
  как `TOptions`, повторная аннотация полей не нужна. TS не выводит общий входной тип из
  нескольких соседних полей-функций — отсюда явный дженерик (не декоративный, а несущий).
  Read-типы (резолвнутые `options`, `hooks`, `state`-value) **выводятся** из возвратов
  деклараций; расширение = дописать поле, места чтения перетипизируются сами.
- **Начальное состояние типобезопасно — проверяется, а не кастуется.** Тип слайса задаётся
  **аннотацией возврата** `state(): S` (или дженериком), поэтому `{}`-seed **валидируется**
  против `S`, а не утверждается. Каст `{} as Record<…>` — анти-паттерн (маскирует опечатку в
  форме состояния).

## Совместимость и миграция

- `definePlugin` **аддитивен**: цель компиляции — та же `TesseraFeatureEntry`, ручная
  форма записи остаётся валидной. Публичного слома для потребителя нет — сигнатуры
  плагинов те же.
- **Раскатано на все 11 плагинов (сделано).** `definePlugin`
  ([definePlugin](../../src/lib/core/definePlugin/index.ts)) — каррированный (DP12), поля
  `options`/`hooks`/`features`/`column`/`slots`/`slotActions`/`actionMenu`/`setup`; все
  реестры и плагины-меню на нём (ушла ручная раскладка hook-слайса, `satisfies`,
  boilerplate). row-модели создаются один раз (мемо per-table в v9).
- **Чтение хуков — без кастов (сделано).** Компоненты, читающие хуки
  (`RowSelectionComponent`/`HeadSelection`, `ColumnSizingComponent`,
  `RowExpandingComponent`), — на `PluginCellProps`/`PluginHeaderProps`; hooks приходят
  пропсом от `definePlugin` (слот — DP9, сервисная колонка — DP20); нативный срез
  — через `useSlice`. Дескрипторы действий (`sortHeaderAction`/`pinHeaderAction`) и
  императивные dnd-события (`getColumnDraggingEvents`) — не компоненты, читают свой слайс
  типизированным `readPluginHooks<XHooks>(table, 'x')`. В `src` не осталось ни `getHooks() as`,
  ни `atoms … as never`; публичный контракт хуков — единообразно интерфейсы `*Hooks` (Record-типы
  `*Plugin` удалены).
- **Канал локального `state` — реализован (сделано).** Поле `state` в `definePlugin`
  генерирует v9-фичу (`getInitialState` + `on<Key>Change` через `makeStateUpdater`),
  seed'ящую слайс под ключом `plugin:<id>` (DP13); слот с `state: true` получает пропсом (`PluginCellStateProps<THooks, TState>`) `state: [value, setter]` (реактивно, приватно от общего
  `getState`). Первый носитель — встроенный плагин `cellEditing` (слайс «редактируемая
  ячейка»), покрыт node-тестом. `TState` выводится из возврата `state`.
- **Канал замещения рендера ячейки (`cellSlot`) — реализован.** Обычные слоты
  аддитивны (рисуются рядом с `{render}`); чтобы плагин мог **заместить** контент ячейки
  (инлайн-редактор), добавлен слот-владелец `cellSlot`: ядро (`RenderCellSlot` в
  `BodyCell`) прокидывает собственный рендер ячейки компоненту пропсом `content`, тот
  рантайм отдаёт его как есть или замещает своим UI.
  `PluginCellOwnerProps<THooks, TState>` — типизированный доступ (`content` + hooks +
  локальный `state`), реактивность изолирована в компоненте-владельце (`useSlice`),
  `BodyCell` не перерисовывается. В сервисных колонках слоты не рендерятся → владелец там
  не сработает. Первый потребитель — `cellEditing`: кнопка в `rightCellSlot`, редактор во
  `cellSlot`. Сам инпут **сменный** (BYO) через опцию `editor` (дефолт — встроенный
  `CellEditInput`); `editor` живёт в hook-слайсе (читается живо, `undefined` → дефолт в
  компоненте). Покрыто node-тестами (владелец в `cellSlot`, passthrough `editor`) +
  визуальными (замещение контента, скрытие кнопки в правке).
  - **Несколько владельцев `cellSlot`.** Дедуп слота — по `id`: два владельца с
    одинаковым slot-`id` схлопываются (последний победил), конфликта нет. Разные id —
    **вкладываются** (`RenderCellSlot.reduceRight`: первый в массиве внешний, последний
    внутренний, каждый получает результат вложенного пропсом `content`). В покое контент
    проходит насквозь; активен один — он замещает, остальные пропускают. При
    **одновременной активности** внешний (первый) замещает контент, а внутренние **не
    рендерятся** — молчаливый конфликт. Ядру «активность» владельца непрозрачна (владелец
    вернул либо `content`, либо своё), поэтому рантайм-детект активного конфликта
    невозможен — ядро дев-варнит по **числу зарегистрированных владельцев** (после дедупа
    по id) в `useCreateTable`, как DP5. Владение ячейкой эксклюзивно, поэтому >1 владельца
    — почти всегда ошибка; сигнал покрыт node-тестом.
- **Поле записи `slot → features` — сделано (DP10).** Переименовано без алиаса (внешних
  потребителей нет).
- **Типы слот-компонентов (DP6, DP7, DP9) — сделано 2026-10-01.** До этого поле `slots`
  было `PluginSlot[]` без связи с плагином, а хуки подмешивались вручную
  `injectCellHooks(Компонент, 'id')` — расхождение хуков плагина и компонента
  компилировалось. Теперь `slots` типизирован `PluginSlotDecl<THooks, TState>`, каналы
  подмешивает `definePlugin` по своему `id` (`withPluginChannels`, обёртка кэшируется;
  пара `state` — только у слота с `state: true`, иначе каждая ячейка подписалась бы на
  весь срез — это поймал SS20), а
  вторая ступень фабрики — две сигнатуры: без `hooks` тип хуков пустой, с `hooks` —
  выведен. Вскрылось: `columnSizing` объявлял `onColumnResizeEnd` возможно `undefined`,
  а компонент ждал обязательный — дефолт перенесён в декларацию плагина.
- **Типы сервисной колонки (DP19, DP20) — сделано 2026-10-02.** `column` принимает
  `cell`/`header`, типизированные по `hooks` плагина; `definePlugin` подмешивает каналы
  по `id` и отдаёт обёрнутые компоненты в `make({ cell, header })`, результат
  `make` кэшируется (глубина шапки из сигнатуры убрана ADR 0049, HS14). `rowSelection` и `rowExpanding` больше не пишут
  `injectCellHooks(Компонент, 'id')`; сами инъекторы удалены (см. «Изменён»). Вскрылось: компоненты обоих плагинов ждали хуки обязательными, а
  плагины объявляют их необязательными — компоненты переведены на `Partial<…Hooks>`.
  В рантайме сбоя не было: ядро подставляет no-op дефолты встроенных scope
  (`createHooks.ts`).
- **Внешнее локальное состояние (DP8, DP17, DP18) — сделано 2026-10-01.** Плагин
  объявляет `controlled: { value, onChange }` — имена своих опций. Запись несёт
  `controlledState` (ключ среза, значение, колбэк); ядро в layout-эффекте переносит новую
  ссылку значения в атом мимо updater-опции (без эха в `onChange`), а каждое изменение
  изнутри — через updater-опцию фичи или `setPluginState` по обёртке `useTable` —
  сообщает в `onChange` (`pluginStateListeners`). Опция значения исключена из ключа
  аргументов. Носители: `cellEditing` (`editing`/`onEditingChange`, CE6) и
  `keyboardNavigation` (`activeCell`/`onActiveCellChange`, ADR 0021, KN31).
- **Резолвнутые `options`-как-пропс — не выделены.** Компонент-facing конфиг (напр.
  предикат `canEdit`) кладут в `hooks` (живой слайс) — отдельный options-канал требует
  различения «табличная опция» vs «конфиг плагина» и пока не нужен.
- **Дев-варн на коллизию `id` — сделано (DP5).** `id` — единый ключ scope (hooks,
  локальный state-слайс, генерируемая state-фича, id слотов), поэтому дубль молча
  перезаписывает их. `findDuplicatePluginIds` + эффект в `useCreateTable` дев-варнят один
  раз на набор (покрыто node-тестом). Коллизия ключей ОБЩЕГО состояния отдельно не
  проверяется — механизма декларации shared-state плагином нет (оно приходит от
  потребителя через `useCreateTable`).
- **Symbol-токен вместо `id`-скоупа — отклонён (не только отложен).** Локальный `state` в
  v9 — это срез табличного состояния со **строковым** ключом (в `getState`/`atoms`); ключ
  состояния Symbol'ом быть не может — «токен-приватный local state» в v9 невозможен, поэтому
  слайс живёт под строковым `id`. Для хуков токен потребовал бы переписать строково-ключевые
  `defaultHooks`/`resolveHooks` и держать ДВЕ identity (строковый `id` всё равно нужен для
  state/фичи/слотов/дебага) ради защиты от коллизии, которую у одного автора закрывает
  дешёвый дев-варн (выше). Итог: `id`-скоуп + дев-варн, без токена.
- **Ключ локального `state` — с пространством имён (DP13).** Строковый ключ неизбежен
  (Symbol в v9 невозможен, см. выше), но голый `id` совпадал со срезами TanStack: плагин
  с `id: 'sorting'` получал в свой слайс стоковую сортировку. Ключ — `plugin:<id>`
  (`pluginStateKey`), updater-опция — `on<Key>Change` от него. Для потребителя это не
  ломающее изменение: слайс читается только пропсом `state`, а не по ключу.
- Проверено на каждом шаге: `tsc`, node-набор (109), `eslint`, `prettier` — зелёные.

## Рассмотренные альтернативы

- **Оставить ручную `TesseraFeatureEntry`.** Отклонено: 8 проблем выше (бойлерплейт,
  непрозрачность «мемо/живо», риск коллизий, нет первоклассного state, касты в компоненте).
- **Token-хелперы `rowFavorite.useState()/useHooks()/useOptions()` в компоненте.**
  Отклонено: раздвоение identity (`rowFavorite` — и фабрика, и неймспейс), обязательный
  импорт плагина в его же компонент, потеря props-модели. Локальный канал доставляем
  **пропсами**; токен остаётся внутренней деталью обёртки.
- **`TableContext` + zero-arg хелперы для чтения вне ячейки.** Отклонено: чтение состояния
  плагина **вне его слотов** (тулбар над гридом) означает, что оно **общее** → идёт через
  `useCreateTable` + `useSlice`. Локальное состояние по определению приватно слотам плагина,
  которым `table`/канал уже приходят пропсами.
- **Все 3 дженерика `PluginCellProps` обязательны (без дефолтов).** Отклонено (пересмотрено
  на `rowSelection`): плагин, использующий подмножество каналов (напр. только `hooks`),
  вынужден называть несуществующий `state` и неиспользуемые `options` — «выдуманные» типы.
  Приняты **дефолты** (hooks-first): `state`/`options` ← нативные типы таблицы, `hooks` ←
  `never`; заявленные каналы по-прежнему констрейнятся выведенными типами плагина (DP7).
- **Схлопнуть `hooks` в живые `options`.** Отклонено: внутри опций есть функции,
  кормящие мемоизированные модели (нужна стабильность) — их нельзя автоматически отличить
  от колбэков; граница всё равно нужна и уходит на автора (та самая проблема 3/8).
- **Отдельная опция-seed `initialFavorites`.** Отклонено: дублирует дефолт + внешний
  источник — опция `favorites` (не меняешь → фактически initial) плюс дефолт в декларации.
- **Роутить controlled-состояние через фабрику в ОБЩИЙ `state`.** Отклонено: дублирует
  `useCreateTable({ state })` и путает «где писать». Резолюция — **два уровня**: приватное
  состояние → опции плагина (локальный токен-слайс), общее → `useCreateTable`.
- **Строковый `id` как единственная identity + dev-warn.** Частично: для **локальных**
  каналов берём токен (коллизий нет); человеко-ключ + dev-warn остаются только для **общего**
  состояния (его нужно референсить снаружи).
- **Обязательная глобальная аугментация `declare module`.** Отклонено как основной путь:
  типы держим локально в объекте плагина; аугментация — опциональный interop.

## Последствия

- **+** Плагин — самодостаточный типизированный модуль: без бойлерплейта, с явной
  семантикой полей, локальной композируемой типизацией и первоклассным реактивным `state`.
- **+** Слот-компонент — чистая функция пропсов: **без импорта плагина, без кастов**; тип
  доступа (`row`/`state`/`options`/`hooks`) **гарантирован компилятором** (DP7).
- **+** Чёткий водораздел **общее vs локальное** состояние: снят вопрос «где писать» и
  разведена типизация (глобальная для общего, локальная для приватного).
- **+** Для локальных каналов риск коллизий нулевой (токен); для общего — тихий баг
  «последний победил» становится дев-варном.
- **~** `getHooks`/`getState` остаются **публичными общими** аксессорами (как в TanStack):
  перекрёстное чтение чужих хуков возможно и допущено сознательно. Изоляция хуков — **не
  цель**; пропс `hooks` даёт лишь типизированный без-кастовый вид на свой слайс. Приватным
  остаётся только локальный `state` (токен-атом не попадает в плоский `getState`).
- **−** Новый слой абстракции (`definePlugin` + генерируемая обёртка инъекции пропсов +
  генератор state-фичи) — его надо сопровождать; переходный период с алиасом `slot`.
- **−** Автор должен осознанно выбрать скоуп состояния (общее/локальное); неверный выбор
  «прячет» состояние от других плагинов или, наоборот, засоряет общий неймспейс.
