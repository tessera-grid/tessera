# 0031 — Соответствие WCAG 2.1.1 (Keyboard)

- **Статус:** Принято (KB1–KB14 реализованы)
- **Дата:** 2026-09-25
- **Изменено:** [ADR 0220](0220-shortcuts-by-key-code.md) (2026-11-12) — буква и цифра в сочетаниях действий плагинов (`keys`, `keyComboOf`) — по коду клавиши, без учёта регистра в ключах (KC2).
- **Связано:**
  - [ADR 0020](0020-accessibility.md) — структурная доступность (роли, имена,
    индексы, axe); там же отложены ресайз с клавиатуры и клавиатурный DnD.
  - [ADR 0021](0021-keyboard-navigation.md) — плагин `keyboardNavigation`: roving
    tabindex, режим действия, один tab-stop, канал `keyboardActions`. Этот ADR
    опирается на него и закрывает то, что плагин оставил за бортом.
  - [ADR 0006](0006-dnd-with-dnd-kit.md) — перестановка строк и колонок
    перетаскиванием; [ADR 0013](0013-column-sizing.md) — изменение ширины;
    [ADR 0029](0029-cell-range-selection.md) — выделение диапазона ячеек.
  - [ADR 0009](0009-test-coverage-visual-and-performance.md) — один тест на
    требование; префикс требований этого ADR — `KB<n>`.

## Контекст

WCAG 2.1.1 (уровень A): вся функциональность, доступная указателем, доступна и
с клавиатуры — без требований к таймингу нажатий. Способ может отличаться
(перетаскивание можно заменить командами), но результат должен быть достижим.

После [ADR 0021](0021-keyboard-navigation.md) грид с `keyboardNavigation`
закрывает навигацию, действия плагинов (выбор, сортировка, раскрытие, правка),
контекстное меню и расширение выделения `Shift+стрелки`. Аудит выявил остаток:

- **Только указателем:** изменение ширины колонки (`onMouseDown`, сброс —
  `onDoubleClick`); перестановка колонок и строк (dnd-kit без клавиатурного
  сенсора); действия заголовков групп вложенной шапки (модель навигации знает
  только листовую строку заголовков); «выделить всё» для диапазона ячеек.
- **Формально достижимо, фактически нет:** hover-кнопки ячеек/заголовков/строк
  (`.cell__button--hidden`, `.row__button--hidden`) проявлялись только по
  `:hover` — в режиме действия фокус уходил на кнопку с `opacity: 0`.
- **Не проверено:** раскрытие групповых строк `rowGrouping` по `Enter`; отсутствие
  ловушки фокуса в редакторе, меню и тултипах (смежный критерий 2.1.2).
- **Без плагина** область прокрутки недостижима с клавиатуры — это осознанный
  opt-in-контракт [ADR 0020](0020-accessibility.md), но он не зафиксирован как
  граница заявляемого соответствия.

## Решение

Соответствие 2.1.1 заявляется **для грида с `keyboardNavigation`** и достигается
закрытием требований `KB1–KB10`. Для функций, основанных на перетаскивании,
принимается **командная альтернатива** (сочетания клавиш, KB3/KB4), а не
клавиатурный DnD:
критерий требует результата, а не жеста; клавиатурный сенсор dnd-kit остаётся
возможным улучшением отдельным ADR.

### KB1 — hover-кнопки видимы при клавиатурном фокусе

Контракт видимости (`grid/cellControls/buttonVisibility.css`) раскрывает
hidden-кнопки не только по `:hover`, но и когда ячейка заголовка/тела сама в
`:focus-visible` или содержит элемент в `:focus-visible` (`:has(:focus-visible)`);
для кнопок строки — когда строка содержит `:focus-visible`. Используется именно
`:focus-visible`, а не `:focus-within`: после клика мышью по ячейке кнопки не
остаются раскрытыми, когда указатель ушёл.

### KB6 — выделить всё и расширение до края

Клавиши обрабатывает `keyboardNavigation` (стоковая `cellSelectionFeature`
keydown не несёт) в режиме навигации, только при активном `cellSelection` с
`rangeSelection`:

- `Ctrl+A` (`Cmd+A`) — `table.selectAllCells()`, с `preventDefault`, чтобы
  браузер не выделил текст страницы. Без `cellSelection` клавиша остаётся
  браузеру. Активная ячейка не сдвигается.
- `Ctrl+Shift+стрелка` — фокус активного диапазона переносится на первую/
  последнюю строку модели или первую/последнюю выбираемую колонку в порядке
  отображения (column-level opt-out, как у стоковой фичи); якорь и активная
  ячейка остаются на месте — как у `Shift+стрелки` (KN19).

### KB5 — строки групп вложенной шапки в навигации

Строки шапки нумеруются снизу вверх: листовая — `-1`, верхняя — `-число строк`.
Позиция `(строка, колонка)` хранится как прежде (колонка — лист в порядке
отображения), а ячейку, которая активна, определяет **владелец** позиции —
заголовок, чей бокс её покрывает. Сетка владельцев строится по визуальной
раскладке шапки: заголовок владеет строками `headerGroup.depth …
headerGroup.depth + header.rowSpan − 1` (спаны TanStack v9,
[ADR 0049](0049-native-header-spans.md), HS10); заголовки с `rowSpan: 0` не
рисуются и ничем не владеют. Кэш — по идентичности `getHeaderGroups()`.

- Стрелки в шапке шагают **к следующему владельцу**: сквозь группу (несколько
  колонок) и растянутый бокс (несколько строк); за краем — на месте. Колонка при
  вертикальном ходе сохраняется: `↓` с группы — на лист той же колонки.
- Фокус/клик по заголовку делает активной позицию его верхней строки и первого
  листа; если он уже владеет активной позицией — она не меняется.
- Действия канала `keyboardActions` (scope `header`) и режим действия
  работают для любого владельца, в том числе группы.

### KB2 — ширина колонки с клавиатуры

Ручка `columnSizing` следует паттерну APG «Window Splitter»: `role="separator"`
получает `tabIndex=0`, `aria-orientation="vertical"`, доступное имя из
локализации (`resizeColumn`), `aria-valuenow` — текущую ширину,
`aria-valuemin`/`aria-valuemax` — `minSize`/`maxSize` колонки (без верхней
границы `aria-valuemax` не ставится). Клавиши на ручке:

- `←`/`→` — ширина −/+10px, с `Shift` — −/+50px, в пределах `minSize…maxSize`;
- `Home` — сброс к ширине колонки по умолчанию (как двойной клик).

Каждое нажатие — завершённый ресайз: `setColumnSizing` и бизнес-колбэк
`onColumnResizeEnd({ id, width })`, тот же, что после перетаскивания мышью.
Ручка — обычный виджет ячейки заголовка: с `keyboardNavigation` до неё доходят
режимом действия (`F2`, `Tab`), видима при фокусе по KB1. `Home` вместо
APG-«минимума» выбран ради паритета с двойным кликом.

### KB3, KB4 — перестановка колонок и строк сочетаниями клавиш

Канал `keyboardActions` принимает сочетания с `Alt` в форме `keyComboOf`
(`'Alt+Shift+ArrowUp'`: модификаторы Ctrl, Alt, Shift, Meta и `key`); без `Alt`
сочетания не проверяются — стрелки и `Shift+стрелки` остаются навигации и
выделению.

- **KB3, `columnDragging`:** `Alt+Shift+←/→` на листовом заголовке переставляет
  колонку с соседней перетаскиваемой незакреплённой — тем же `setColumnOrder` и
  `onColumnDragEnd({ dragIndex, hoverIndex })`, что у DnD. Ограничения — как у
  DnD: `getCanDrag` (плоская шапка), закреплённые колонки не участвуют.
- **KB4, `rowDragging`:** `Alt+Shift+↑/↓` на любой ячейке строки меняет её
  местами с соседней строкой того же уровня (корень или подстроки одной группы)
  через тот же `onRowOrderChange`; гейты — `row.getCanDrag()` (без сортировки и
  группировки) и наличие `onRowOrderChange`. Смену уровня вложенности
  (`Alt+Shift+→/←`) добавил [ADR 0032](0032-wcag-aa-remainder.md), W12.
- **Фокус следует за перемещённым:** перед действием навигация запоминает id
  строки и колонки активной ячейки и после перестановки переводит активную ячейку
  на их новую позицию — для колонки сразу, для строки — когда потребитель вернёт
  новые `data` (проверка на каждом рендере грида; намерение сбрасывается
  следующей клавишей или указателем).

Пункты меню «Сдвинуть …» — возможное улучшение видимости команд, не нужное для
2.1.1. На Windows `Alt+Shift` — системное переключение раскладки, но оно
срабатывает только без третьей клавиши: `Alt+Shift+стрелка` раскладку не
переключает (проверено вручную автором, 2026-09-26).

### KB7, KB8 — групповые строки и отсутствие ловушек фокуса

Аудит показал, что правок кода не нужно — требования закреплены тестами:

- **KB7:** групповая строка `rowGrouping` раскрывается кнопкой колонки
  `rowExpanding`, а значит — действием `Enter` канала `keyboardActions` на этой
  колонке (ADR 0021). Без `rowExpanding` групповая строка не раскрывается и
  указателем, так что пробела 2.1.1 нет.
- **KB8 (WCAG 2.1.2):** `Escape` закрывает редактор `cellEditing`, контекстное
  меню и поповер действия заголовка и возвращает фокус на ячейку; с ячейки `Tab`
  уводит фокус из грида. У поповера заголовка первый `Escape` возвращает фокус
  на кнопку-триггер, второй — на ячейку ([ADR 0032](0032-wcag-aa-remainder.md),
  W15). Тултипы фокус не забирают.

### KB9 — граница соответствия

README (блок «Доступность» в разделе плагинов) и [ADR 0020](0020-accessibility.md)
фиксируют: WCAG 2.1.1 выполняется только с `keyboardNavigation`; без плагина грид —
`role="table"` для чтения. В README же описаны клавиши KB2–KB6.

### KB10 — аудит

Структурный тест на грид со всеми совместимыми плагинами и `keyboardNavigation`:
каждый интерактивный контрол (кнопка, поле, `checkbox`/`switch`/`separator`,
ручка перетаскивания) не выключен из обхода `Tab` и лежит внутри ячейки
навигации — значит, достижим режимом действия. Скрытые зеркала под
`aria-hidden` (нативный `input` у Base UI Checkbox) и выключенные контролы не
учитываются. Тест ловит новый контрол, поставленный вне ячеек (футер, оверлей).

Функции, у которых указательный жест не повторяется нажатием на контрол, и их
клавиатурный путь:

| Жест указателем                            | Клавиатура                             | Требование     |
| ------------------------------------------ | -------------------------------------- | -------------- |
| Наведение — показ кнопок ячейки            | фокус на ячейке или кнопке             | KB1            |
| Перетаскивание ручки ширины, двойной клик  | `←`/`→`, `Home` на ручке               | KB2            |
| Перетаскивание колонки                     | `Alt+Shift+←/→` на заголовке           | KB3            |
| Перетаскивание строки (тот же уровень)     | `Alt+Shift+↑/↓` на ячейке              | KB4            |
| Перетаскивание строки в группу / из группы | `Alt+Shift+→/←` на ячейке              | W12 (ADR 0032) |
| Клик по кнопке заголовка группы            | стрелки в строки групп, режим действия | KB5            |
| Протяжка и Ctrl-клик по ячейкам            | `Shift`/`Ctrl+Shift`+стрелки, `Ctrl+A` | KB6, KN19      |
| Правый клик                                | `Shift+F10` / `ContextMenu`            | KN26           |

Исключений 2.1.1 не осталось: смену уровня вложенности закрыл W12
([ADR 0032](0032-wcag-aa-remainder.md)).

### KB11–KB14 — клавиатуры без F-ряда и блока навигации

На компактных клавиатурах (65 %, 60 %) нет F-ряда, `Home` / `End` /
`PageUp` / `PageDown` и клавиши `Menu`: они доступны только через слой `Fn`, а
часть сочетаний (`Shift+F10`) нажать неудобно или нельзя. Каждой такой клавише
добавлено сочетание из основного блока; прежние клавиши работают как раньше.
На macOS вместо `Ctrl` — `Cmd`.

| Было                     | Добавлено           | Что делает                                                             |
| ------------------------ | ------------------- | ---------------------------------------------------------------------- |
| `Home` / `End`           | `Ctrl+←` / `Ctrl+→` | первая / последняя ячейка строки (KB11)                                |
| `Ctrl+Home` / `Ctrl+End` | `Ctrl+↑` / `Ctrl+↓` | первая строка (верх шапки) / последняя строка в той же колонке (KB11)  |
| `F2`                     | `Ctrl+Enter`        | к кнопкам ячейки, даже если у неё есть своё действие на `Enter` (KB12) |
| `PageUp` / `PageDown`    | `Alt+↑` / `Alt+↓`   | на экран вверх / вниз (KB13)                                           |
| `Shift+F10`, `Menu`      | `Ctrl+Shift+Enter`  | контекстное меню активной ячейки (KB14)                                |

`Ctrl+стрелка` раньше работала как обычная стрелка; теперь — прыжок к краю, в паре
с `Ctrl+Shift+стрелкой` (расширить выделение до края, KB6), как в электронных
таблицах. `Alt+↑/↓` с `Alt+Shift+↑/↓` (перестановка строки, KB4) различает `Shift`.

## Последствия

- **+** Критерий 2.1.1 закрывается измеримо: каждое требование — тест.
- **+** Командная альтернатива DnD дешевле и понятнее скринридеру, чем
  клавиатурное перетаскивание с объявлениями.
- **−** Без `keyboardNavigation` соответствие не заявляется (KB9) — потребитель,
  которому нужен 2.1.1, обязан подключить плагин.
- **−** Фокус на виджете внутри ячейки раскрывает кнопки через `:has()` (Chromium
  105+, Safari 15.4+, Firefox 121+). Правила с `:has()` вынесены в отдельные
  блоки: в браузере без него не работает только это раскрытие, а раскрытие по
  наведению и по фокусу на самой ячейке остаётся.
