# 0027 — Бизнес-хуки в аргументах фабрики плагина (упразднение верхнего параметра `hooks`)

- **Статус:** Принято — реализовано для всех встроенных плагинов с hook-слайсами.
- **Дата:** 2026-09-20
- **Связано:**
  - [ADR 0001](0001-spec-driven-development.md) — spec-driven: требования (`H<n>`)
    живут здесь, а тесты их кодируют.
  - [ADR 0009](0009-test-coverage-visual-and-performance.md) — свёртка/разрешение
    хуков это **чистая логика**, поэтому закрывается **модульными** (headless)
    тестами (`src/lib/__tests__/rowSelection.test.ts`).
  - [ADR 0010](0010-invert-core-plugins-registry.md) — presence-based композиция:
    именно там `hooks` был вынесен **отдельным always-on контрактом** (тогда его тип
    шёл через дженерик `THooks`). Этот ADR переносит авторскую поверхность обратно в
    сами фабрики.
  - [ADR 0026](0026-migrate-to-tanstack-v9.md) — v9 фиксирует набор фич на маунте и
    держит состояние в Store; композиция мемоизируется по сигнатуре набора — отсюда
    требование «живого» канала для колбэков.

## Контекст

Бизнес-логику плагина потребитель задаёт через **верхний параметр** `hooks`
(`useCreateTable({ hooks })`), отдельно от включения самого плагина в `plugins`.
Возникают два канала для одного плагина: конфигурация — в аргументах фабрики
(`rowSelection({ subRows })`), а колбэки — в параллельном объекте `hooks`. Это
неочевидно и требует трюка типизации `useCreateHooks<RowSelectionPlugin & MyHooks>`.

Почему `hooks` вообще отделён от аргументов фабрики — у конфигурации и у колбэков
**противоположные жизненные циклы**:

|                            | Аргументы плагина (конфиг)                           | Бизнес-колбэки                  |
| -------------------------- | ---------------------------------------------------- | ------------------------------- |
| Когда нужны                | один раз при композиции                              | всегда свежие, на момент вызова |
| Мемоизация                 | `useMemo` по `signature` (id + enabled) — заморожены | должны обходить мемо            |
| Новый объект каждый рендер | игнорируется (тот же id)                             | обязан подхватываться           |

`features`/`foldEntries` в [useCreateTable](../../src/lib/core/useCreateTable.ts)
мемоизированы по `signature`. Если положить колбэк в **то же** свёрнутое-и-замороженное
место, инлайн-стрелка каждого рендера будет проигнорирована → **устаревшее
замыкание**. Убрать мемоизацию нельзя: v9 фиксирует фичи на маунте, плюс перф-регресс.
Поэтому `hooks` читается **живо** — `commonFeature` определяет
`table.getHooks() = () => options().hooks` ([commonFeature.ts](../../src/lib/core/commonFeature.ts)),
а `options` пересобирается каждый рендер.

Вывод: несущим является **механизм** (живой `getHooks()`, развязанный с мемо-композицией),
а не верхний параметр `hooks` как способ его задать.

## Решение

Перенести авторскую поверхность бизнес-логики в **аргументы фабрики плагина**,
сохранив живой канал чтения:

1. Запись фичи получает поле `hooks?: Record<string, unknown>` — слайс(ы) плагина по
   его scope ([features.ts](../../src/lib/core/features.ts)).
2. Фабрика принимает колбэки и кладёт их в этот слайс:
   `rowSelection({ onSelectRow, onSelectAllRowsOnPage, isAllRowsSelected })`.
3. Новая **живая** свёртка `foldHooks(plugins)` собирает слайсы активных записей
   **каждый рендер** (в отличие от `foldEntries`, мемоизированного по сигнатуре).
4. `resolveHooks` ([createHooks.ts](../../src/lib/core/createHooks.ts)) сливает слайсы
   с no-op дефолтами **по scope** (а не поверхностно сверху), поэтому частичный набор
   (только `onSelectRow`) дополняется дефолтами остальных ключей, а не затирает их.
5. `table.getHooks()` не меняется — компоненты читают живо, как и раньше
   (`(table.getHooks() as RowSelectionPlugin).rowSelection`).
6. Верхний параметр `hooks` и `useCreateHooks` **удалены** из публичного API
   (пакет ещё `0.0.1`, внешних потребителей нет — поэтапный депрекейт не нужен).
   Единственный способ задать бизнес-логику — hook-слайс записи плагина: у
   встроенных — аргументы фабрики; у пользовательских — поле `hooks` записи
   (для «живого» колбэка запись создаётся инлайн в массиве `plugins`).
   Низкоуровневая табличная опция `options.hooks` (её читает `commonFeature.getHooks`)
   сохраняется — именно её теперь наполняет `resolveHooks(foldHooks(plugins))`.

Перф-модель цела: тяжёлое (фичи/колонки/слоты/setup) остаётся мемоизированным по
`signature`; живо пересобирается только дешёвый объект колбэков — что и требуется.

### DX-выигрыш

- Параметры колбэков типизируются нативно из сигнатуры фабрики — исчезает
  `useCreateHooks<RowSelectionPlugin & MyHooks>`.
- Логика ко-локирована с включением плагина; один канал вместо двух.

## Требования

| ID   | Требование                                                                                                                                       | Тест                                                        |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------- |
| `H1` | Колбэк, заданный в аргументах фабрики, доступен через `table.getHooks()`                                                                         | `rowSelection.test.ts` — `H1:`                              |
| `H2` | Частичный слайс дополняется no-op дефолтами по scope (не затирает соседние ключи)                                                                | `rowSelection.test.ts` — `H2:`                              |

| `H6` | Каждый плагин с hook-слайсом принимает свой колбэк в аргументах фабрики                                                                          | `plugin-hooks.test.ts` — `H6 <плагин>:`, по кейсу на плагин |
| `H7` | Новый бизнес-колбэк в аргументах фабрики на каждом рендере приложения (тот же смысл, новая функция) не перерисовывает строк, ячеек и шапки грида | `work-counters.test.tsx` — `H7:`                            |

## Миграция

- **Сделано (все 7 плагинов с hook-слайсами):** `rowSelection`, `columnSorting`,
  `columnPinning`, `columnSizing`, `columnDragging`, `rowExpanding`, `rowDragging` —
  фабрики принимают свои колбэки; ядро (`features.foldHooks`, `createHooks.resolveHooks`,
  `useCreateTable`) поддерживает живой канал. Тесты `H1–H3` + `H5`/`H6` зелёные;
  `tsc`, node-набор и lint зелёные. Плагины без бизнес-хуков (`rowGrouping`,
  `rowActions`, `headerActionMenu`, `rowActionMenu`) — не затронуты.
- **Удаление верхнего `hooks` (сделано сразу):** параметр `hooks` в `useCreateTable`
  и экспорт `useCreateHooks`/`PluginsHooks` убраны из публичного API; демо-сторис
  переведены на hook-слайс записи (`{ id: 'demoHooks', slot: {}, hooks: … }`); гайды
  README переписаны на колбэки в аргументах фабрики.

## Последствия

- **+** Один канал бизнес-логики, нативная типизация, ко-локация, перф без изменений.
- **−** Пользовательский плагин с «живым» колбэком обязан создавать свою запись
  инлайн в массиве `plugins` (модульная const заморозит колбэк).
- **−** Незаданные значения-флаги (`isAllRowsSelected`) при переезде становятся
  «живыми» из аргументов; для динамики по-прежнему предпочтителен `state`.
