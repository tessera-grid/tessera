## Контекст

Тип значения колонки знают по кусочкам. `dataType` колонки (ADR 0139) — пять типов и только
разбор ввода правки. Вид фильтра задаёт отдельное поле колонки `filter` (ADR 0045, 0047, 0048),
варианты с подписями — третье место, `options` и `getOptionLabel` (ADR 0048, 0063), стенное время
дат — четвёртое (`wallTime`, ADR 0047). Ячейка показывает значение как есть: число без
форматирования, `true`/`false` текстом, `Date` — строкой `Date.toString()`. Сортировка текста —
по кодам символов, пустые значения — где придётся. Выгрузка в xlsx угадывает тип ячейки по
`filter`. Поиск ищет по сырым значениям, а не по тому, что видит человек.

Цель автора — всё в таблице подстраивается под тип колонки, в том числе интерфейс и фичи, и
плагины, в том числе чужие, узнают тип из одного места.

### Как у других

- **AG Grid** — `cellDataType` колонки (вывод из данных, отключаемый), встроенные `text`,
  `number`, `boolean`, `date`, `dateString`, `object`; свои типы — `dataTypeDefinitions` с
  `extendsDataType`, у типа — `valueFormatter`, `valueParser`, фильтр и выгрузка. Даты по
  умолчанию — `YYYY-MM-DD`, булево — неактивный флажок.
- **MUI X** — `type` колонки: `string`, `number`, `date`, `dateTime`, `boolean`, `singleSelect`
  с `valueOptions`, `actions`; свои типы — объект колонки, который разворачивают в описание.
  Формат — `valueFormatter`, выравнивание числа — вправо.

## Решение

### 1. Встроенные типы и реестр

Девять встроенных типов: `text`, `number`, `boolean`, `date`, `dateTime` (объект `Date`),
`dateString` (`YYYY-MM-DD`), `dateTimeString` (ISO со временем), `select` (значение варианта),
`multiSelect` (массив значений). Свои типы — реестр `dataTypes` в `useCreateTable`: запись с
`extends` наследует непереопределённые поля, запись с именем встроенного типа меняет все его
колонки, поле колонки главнее поля типа. Тип задаётся только у колонки, не у ячейки: вид по
строке — `formatValue(value, row)` и своя ячейка; таблицы свойств с разными типами в одной
колонке — отдельный сценарий потом.

### 2. Одно место для типа

Тип разрешается один раз на описание колонки и реестр. `column.getDataType()` отдаёт имя,
базовый тип и итоговое определение; ячейка, плагины и плагин автора узнают тип только так.

### 3. Вид

Умолчания нейтральны к языку, как у AG Grid: число как есть, дата `2026-10-31`, дата со временем
`2026-10-31 14:05` в поясе таблицы, варианты — подписи, булево — неинтерактивный значок флажка.
`format` — опции `Intl` на языке таблицы, `formatValue` главнее. Число выровнено вправо, цифры
одной ширины. Текст по типу видят ячейка, строка группы, агрегат, тултип и сводка фильтров.
Колонка без типа выглядит как сейчас; `Date` без типа — как `dateTime`.

### 4. Фичи по типу

Сортировка, фильтр, разбор ввода, поиск и выгрузка берут базовый тип колонки. Поля `filter` у
колонки нет: при подключённом фильтре он есть у каждой колонки с данными, его вид — от типа,
выключатель — стоковое `enableColumnFilter`.

### 5. Этапы

1. Система типов и вид: DT1–DT9, DT18, DT20; сценарии S3, S4.
2. Сортировка, фильтр, разбор ввода и выгрузка: DT10–DT14, DT17, DT19, DT21; сценарии S1, S2,
   S6, S7, S8.
3. Поиск: DT15–DT16; сценарий S5.

## Границы

- Редакторы по типу и вид ячейки по типу — следующие два ADR: они добавят в определение типа
  поля `editor` и `cell`. Туда же тип «чеклист» — список пунктов с отметками в ячейке.
- Перенос `format` в числовой формат Excel — вне объёма: xlsx получает тип ячейки, а не формат.
- Вывода типа из данных нет, кроме `Date`.
- Тип у отдельной ячейки — вне объёма.

## Отвергнутые альтернативы

- **Тип у ячейки** — сортировка и фильтр смешанных типов без ясного правила и разрешение типа на
  каждую ячейку при прокрутке.
- **Вывод типа из данных, как у AG Grid** — по первой строке тип ошибается на пустых и
  смешанных колонках, а явный тип короче отладить.
- **Оставить поле `filter`** — второй источник типа, который расходится с `dataType`.
- **Булево флажком выбора `SelectCheckbox` только для чтения** — интерактивный контрол, чью роль
  и фокус пришлось бы гасить, а вид данных смешался бы с видом выбора.
- **Форматы по языку по умолчанию** — таблица меняла бы вид данных от языка интерфейса без
  просьбы приложения; язык включается `format`.

## Последствия

- **+** Один источник типа для показа, сортировки, фильтра, поиска, выгрузки и правки, в том
  числе для плагинов авторов.
- **+** Свои типы и смена вида всех колонок типа — в одном месте.
- **−** Ломающие изменения: поля колонки `filter` нет, колонки без него теперь фильтруются;
  `ExportColumn.filter` заменяется типом; меняется вид — числа вправо, булево значком, `Date` без
  типа в формате `dateTime`. `BREAKING CHANGE` в коммитах этапов.
- **−** Около 110 мест с `filter:` в историях и тестах.
- **−** Сортировка 100 000 строк через `Intl.Collator` и поиск по показанному тексту уже сейчас
  вне INP — перф-гейты DT11 и DT16.
- **−** Заголовок числа, выровненный вправо, рядом с кнопками колонки — вид показывается до
  тестов.

## Внедрение

- **Этап 1** (DT1–DT9, DT18, DT20; S3, S4): типы и реестр — `core/dataTypes.ts`
  (`resolveDataType`: тип колонки раз на описание колонки и реестр, неизвестное имя и цикл
  `extends` — предупреждение в dev), текст по типу и выравнивание — `core/dataTypeFormat.ts`
  (форматтеры `Intl` — раз на язык, пояс и объект опций). `column.getDataType()` — API колонки
  `commonFeature`, опция таблицы `dataTypes` — в `CoreOptions`. Ячейку по умолчанию рисует
  ядро (`defaultCell`); значок булева грид подставляет в ячейку ядра (`grid/cellContent.tsx`):
  ядро кит не импортирует. Агрегат группы рисует та же ячейка ядра — грид не берёт
  `aggregatedCell`. Выравнивание — атрибуты `data-align` и `data-numeric` у ячейки и заголовка,
  правила — в обёртке текста `CellWrapperTitle`. Разбор правки берёт тип через
  `getDataType()`: `dateTime` — как `date`, прочие новые типы — текстом до этапа 2. Правки
  требований при внедрении (решение автора 2026-11-01): DT19 — в этап 2 (порядок сортировки
  появляется там); DT8 — в сводке фильтров по типу числа, даты остаются в виде календаря
  фильтра; из DT8 убран агрегат футера — футер колонки рисует `footer` приложения; DT18 —
  галочка одной иконкой `checkboxChecked`; из DT4 «фильтр текстовый» перенесён в DT12: до
  этапа 2 вид фильтра от типа не зависит; у DT20 — цена 30 % или 4 мс. Бюджет снимков
  Chromatic — 1050. Тесты: модульный `dataTypes` (DT1–DT3, DT7), визуальный `data-types`
  (DT4–DT6, DT8, DT9, DT18), перф DT20 — в `scroll`.
- **Этап 2** (DT10–DT14, DT17, DT19, DT21; S1, S2, S6, S7, S8): поля типа `parseDate`
  (значение даты-строки в `DateCellValue` для своего формата — им пользуются показ, фильтр,
  сортировка и выгрузка) и `loadOptions` (справочник фильтра у типа; у колонки — поле
  `ColumnOptionsDef.loadOptions`). Сортировка по типу — `columnSortingModel/typedSort.ts`:
  ставится колонке без своего `sortFn` и без вариантов (их сортирует подпись, ADR 0063);
  `Intl.Collator` с числами по значению — раз на язык; пустые — в конце при обоих
  направлениях. Своя модель сортировки (ADR 0064) держит в памяти язык и реестр типов: их
  смена пересчитывает порядок без пересоздания таблицы (DT19). Вид фильтра выводит
  `columnFilterDefOf` (`columnFilteringModel/conditions.ts`) из базового типа через
  `filterTypeOfBase` — ею же пользуются «серверы» историй. Выгрузка: `ExportColumn.dataType`
  (`{ name, base, parseDate? }`) вместо `filter`, вид ячейки xlsx — по базовому типу. Разбор
  числа по языку — `util/parseNumber.ts` (`parseLocaleNumber`): у поля числа панели фильтра и у
  правки в серверной модели; там же разбор `dateTime`, `dateTimeString` и `select` по подписи.
  В клиентском режиме правка отдаёт приложению набранный текст: разбор — его дело (EW6).
  Решения автора 2026-11-01: DT17 и S6 — в этап 2; свой формат даты-строки — полем
  `parseDate`; требования фильтрации, сменившие смысл с уходом поля `filter`, переписаны —
  FL3, FL8 (ADR 0045), DF1, DF2 (ADR 0047), SF1 (ADR 0048), XL3 (ADR 0073); числа моков
  историй — тип `number`. Около 44 файлов историй и тестов переведены с `filter` на
  `dataType` и `loadOptions`. Тесты: модульные `dataTypes` (DT10, DT13, DT17) и
  `cellEditWrite.dom` (DT14), визуальный `data-types` (DT12, DT19, DT21), перф DT11 — в
  `interaction`.
- **Этап 3** (DT15–DT16; S5): быстрый поиск ищет по показанному тексту —
  `formatDataTypeValue` колонки (`quickSearchModel/search.ts`): формат типа, подписи вариантов,
  даты в нейтральном виде в поясе таблицы; колонка без типа — по строке, числу или дате, булево
  вне поиска (значок, а не текст). Текст кешируется в `WeakMap` по объекту строки и колонке;
  смена данных строки, описания колонки, языка, пояса или реестра типов его сбрасывает.
  Требования, сменившие смысл, переписаны (как в этапе 2): FL14 (ADR 0045), DF18 (ADR 0047) —
  даты ищутся в показанном виде, QS3 (ADR 0053) — колонки дат в подсказке. Серверный поиск
  ищет как решит сервер: колонки поиска уходят ему в `columnIds` (ADR 0053). Тесты: модульный
  `dataTypes` (DT15), перф DT16 — в `interaction`, гайд S5 `DataTypesSearch`.
