# 0021 — Клавиатурная навигация: плагин keyboardNavigation (план)

- **Статус:** Предложено (не реализовано)
- **Дата:** 2026-09-06
- **Связано:**
  - [ADR 0020](0020-accessibility.md) — доступность: экран-ридер-семантика и имена
    сделаны, но **WCAG 2.1.1 (Keyboard)** явно отложен; правило axe
    `scrollable-region-focusable` отключено до реализации этого плагина. Данный
    ADR закрывает именно этот пробел.
  - [ADR 0004](0004-core-on-tanstack-table.md) — роли ядра: сейчас контейнер
    несёт `role="table"` (для чтения). Плагин переводит его в `role="grid"`
    (интерактивный композит) по наличию.
  - [ADR 0005](0005-virtualization-tanstack-virtual.md) — виртуализация держит в
    DOM лишь окно; сфокусированная ячейка при прокрутке размонтируется. Это
    центральное ограничение плагина; решается «пиновкой» активной строки/колонки в
    `rangeExtractor` (тот же приём, что для перетаскиваемой строки).
  - [ADR 0007](0007-reactivity-pubsub.md) — ячейки читают «я активна?» гранулярно
    через `useSubscribeStore`, а не глобальным ре-рендером.
  - [ADR 0010](0010-invert-core-plugins-registry.md) — форма плагина
    (`RegistryEntry`, presence-based). Плагин **сознательно расширяет** контракт:
    он не выразим одной сервисной колонкой и требует новых швов ядра (см. ниже).
  - [ADR 0017](0017-ui-components.md) — интерактивный контент ячеек
    (`IconButton`/`Checkbox`) участвует в «actionable»-режиме композита.

## Контекст

По [ADR 0020](0020-accessibility.md) грид пригоден для экран-ридеров, но не для
работы **только с клавиатуры**: нет навигации по ячейкам (стрелки), контейнер
прокрутки не фокусируем, `role="table"` не предполагает клавиатурного управления.
Это нарушает **WCAG 2.1.1 (A)** и не даёт дотянуть до AA.

Целевой паттерн — **WAI-ARIA APG «Grid»**: сетка — один tab-stop, внутри — свой
фокус-менеджмент (roving tabindex), стрелки двигают активную ячейку, а
интерактивное содержимое ячейки достижимо во «входном» режиме. Это сквозная
механика: фокус — свойство самого DOM-узла ячейки и контейнера, поэтому её нельзя
внести только сервисной колонкой, как делают прочие плагины
([ADR 0010](0010-invert-core-plugins-registry.md)).

Почему **плагин**, а не всегда-вкл ядро:

- клавиатурный композит имеет цену (обработчики, ре-рендер активной ячейки,
  пиновка в виртуализаторе) — не всем потребителям он нужен;
- presence-based-композиция ([ADR 0010](0010-invert-core-plugins-registry.md))
  делает его tree-shakeable и opt-in;
- держит `role="grid"`-семантику и её обязательства (полная клавиатура)
  ограниченными теми, кто явно её включил.

## Решение (предлагаемое)

Ввести плагин **`keyboardNavigation()`** — presence-based `RegistryEntry`
([ADR 0010](0010-invert-core-plugins-registry.md)) **без сервисной колонки**, но с
несколькими новыми, минимальными швами ядра (раздел «Новые швы ядра»).

### Модель фокуса — roving tabindex

- Плагин владеет срезом состояния `keyboardNavigation: { row: number; col: number
  } | null` — **активная ячейка в модельных индексах** (не виртуальных): устойчива
  к прокрутке и переупорядочиванию окна.
- **Один tab-stop:** активная ячейка несёт `tabindex="0"`, все прочие — `-1`
  (`HeadCell`/`BodyCell` читают «я активна?» через `useSubscribeStore`). Tab уводит
  фокус из грида целиком; вход в грид ставит активной последнюю (или первую)
  ячейку.
- Отвергнуто: `aria-activedescendant` как основной механизм — под виртуализацией
  референс всё равно требует существования узла в DOM, т.е. пиновку; roving +
  пиновка проще и не плодит id-менеджмент. (Оставлено как открытый вопрос на случай
  проблем с AT.)

### Два режима (композит APG Grid)

- **Навигация** (по умолчанию): стрелки/Home/End/PageUp-Down двигают активную
  ячейку; фокус на самой ячейке.
- **Действие** (`Enter`/`F2` на ячейке с интерактивным контентом): фокус уходит на
  виджет внутри ячейки (кнопка/чекбокс/ссылка); `Escape` возвращает в навигацию на
  ту же ячейку. Ячейка без интерактива режим не меняет.

### Клавиатурная карта

| Клавиша | Действие |
| --- | --- |
| `←`/`→`/`↑`/`↓` | Соседняя ячейка (кламп на краях) |
| `Home` / `End` | Первая / последняя ячейка строки |
| `Ctrl+Home` / `Ctrl+End` | Первая ячейка первой / последняя ячейка последней строки |
| `PageUp` / `PageDown` | На страницу (высота вьюпорта в строках) вверх/вниз |
| `Enter` / `F2` | Войти в «режим действия» (если в ячейке есть виджет) |
| `Escape` | Выйти из «режима действия» → навигация |
| `Space` | Переключить выбор строки (**если активен `rowSelection`**) |
| `Tab` / `Shift+Tab` | Выйти из грида (сетка — один tab-stop) |

Координация с плагинами (без конфликтов клавиш): `Space` → `rowSelection`
([ADR 0014](0014-row-selection.md)); `Enter` на `columnheader` →
`columnSorting` ([ADR 0012](0012-column-sorting.md)); `Enter`/`→` на строке-группе
→ `rowExpanding` ([ADR 0015](0015-row-expanding.md)). Клавиши разрешаются плагином
навигации и делегируются штатным хендлерам через существующие хуки/`table`-методы.

### Роль и ARIA

- Контейнер получает `role="grid"` **по наличию плагина** (аналогично реактивной
  сборке слотов из активного набора, [ADR 0010](0010-invert-core-plugins-registry.md));
  без плагина остаётся `role="table"` ([ADR 0020](0020-accessibility.md)).
- При активном `rowSelection` — `aria-multiselectable="true"` на сетке.
- `aria-rowcount`/`aria-colcount`/`aria-rowindex`/`aria-colindex` уже заведены
  ([ADR 0020](0020-accessibility.md)) и переиспользуются как есть.

### Взаимодействие с виртуализацией (центральное)

- Активная ячейка хранится в **модельных** индексах, поэтому переживает
  анмаунт/маунт окна.
- **Пиновка от анмаунта:** активные строка и колонка добавляются в
  `rangeExtractor` строкового/колоночного виртуализатора — ровно тем же приёмом,
  каким уже пинуется перетаскиваемая строка (`useRowRangeExtractor` +
  `rowDraggingIndex`, [ADR 0005](0005-virtualization-tanstack-virtual.md)). Так
  сфокусированный DOM-узел не исчезает даже вне вьюпорта.
- **Довод в вид:** при переходе за пределы окна плагин зовёт
  `virtualizer.scrollToIndex(row/col)` (сейчас наружу не отдаётся — см. швы), затем
  фокус ставится после маунта.
- **Восстановление фокуса:** ячейка на маунте, если она активная и грид в фокусе,
  забирает фокус на себя (эффект в `BodyCell`/`HeadCell` через тот же
  active-подписчик).

## Новые швы ядра (главное в этом плане)

Плагин нарушает инвариант «ноль правок ядра» ([ADR 0010](0010-invert-core-plugins-registry.md))
— осознанно, т.к. фокус/роль/пиновка не выразимы сервисной колонкой. Требуемые
минимальные швы:

1. **Виртуализатор наружу отдаёт `scrollToIndex`** (`useRowVirtualizer` /
   `useColumnVirtualizer` сейчас возвращают только `virtualRows`/`bodyHeight`/
   `measureElement`). Аддитивно, не ломает потребителей.
2. **`rangeExtractor` учитывает активный индекс** — обобщить текущую пиновку
   drag-строки до «пин-сет индексов» (drag ∪ active). Строково и колоночно.
3. **`DataGrid` берёт `role` из активного набора** — presence плагина флипает
   `table`→`grid` (реактивно, как слоты), а не хардкодит `role="table"`.
4. **Ячейки читают active-состояние** — тонкий opt-in-хук `useIsActiveCell(row,
   col)` поверх `useSubscribeStore`, **no-op без плагина** (среза нет — `?.`, как у
   `rowDragging`). Ставит `tabindex` и владеет refocus-эффектом.
5. **Фокусируемость области** — контейнер прокрутки получает управляемый фокус
   (грид как один tab-stop), закрывая `scrollable-region-focusable`.

Все швы **аддитивны и инертны** без плагина: ядро не импортит плагин (R1 ADR 0010
сохраняется — швы читают presence через состояние/активный набор, не пофамильно).

## Область и границы

- **Вне области:** RTL-раскладка; выделение диапазона ячеек мышью/`Shift+стрелки`;
  typeahead-поиск по колонке; редактирование ячеек (нет фичи редактирования);
  клавиатурный drag&drop строк/колонок (отдельная задача поверх dnd-kit,
  [ADR 0006](0006-dnd-with-dnd-kit.md)).
- **Заголовки и футер** входят в модель навигации (строки заголовка — первые
  `aria-rowindex`); действия заголовка доступны через «режим действия».

## Последствия

- **+** Закрывает **WCAG 2.1.1**: грид управляем только с клавиатуры; можно
  включить правило axe `scrollable-region-focusable` и заявить AA-намерение
  (см. [ADR 0020](0020-accessibility.md)).
- **+** Opt-in и tree-shakeable: цену платит лишь тот, кому нужен grid-режим.
- **+** Реактивность гранулярна: ре-рендерятся только прежняя и новая активные
  ячейки (подписка на срез), не вся сетка.
- **+** Пиновка активной ячейки переиспользует уже существующий механизм
  `rangeExtractor` — не изобретаем удержание узла в DOM.
- **−** Первый плагин, которому нужны **швы ядра** (роль, виртуализатор,
  active-подписка) — точечная связность в обмен на невыразимую иначе механику.
  Инвариант ADR 0010 ослабляется явно и ограниченно.
- **−** Сложность refocus под виртуализацией: гонки маунта/скролла, `PageUp/Down`
  по переменной высоте вьюпорта, восстановление фокуса после внешнего сброса
  состояния — основной источник багов; требует отдельного покрытия.
- **−** Координация клавиш с плагинами (`Space`/`Enter`) вводит межплагинную
  зависимость по клавиатурному контракту — держать в одном месте (резолвер клавиш
  плагина навигации).

## Открытые вопросы

- **`aria-activedescendant` vs roving под AT.** Если roving+пиновка дают проблемы
  в конкретных скринридерах (потеря фокуса при быстром скролле), рассмотреть
  гибрид: постоянный `tabindex=0` на сетке + `aria-activedescendant` на
  запинованную ячейку.
- **Обнаружение «режима действия».** Как ячейка декларирует наличие
  интерактивного виджета (через слот/`renderComponent`-мету или запрос DOM в
  момент `Enter`).
- **Семантика `PageUp/Down`** при переменной высоте строк (оценка виртуализатора
  vs измеренная высота).
- **Включение заголовков** в roving: всегда или опцией фабрики
  (`keyboardNavigation({ headers: false })`).
- **Клавиатурный DnD** — отдельным ADR поверх [ADR 0006](0006-dnd-with-dnd-kit.md).

## План внедрения (предлагаемый)

Инвариант: **существующий набор тестов и axe-набор ([ADR 0020](0020-accessibility.md))
остаются зелёными на каждом шаге**; правило `scrollable-region-focusable`
включается только в финале.

- **Фаза 1 — швы ядра (аддитивно).** Отдать `scrollToIndex` из виртуализаторов;
  обобщить `rangeExtractor` до пин-сета; ввести no-op `useIsActiveCell`; `DataGrid`
  берёт `role` из активного набора. Без плагина поведение не меняется; `tsc` и
  существующие тесты зелёные.
- **Фаза 2 — срез и фокус-модель.** Плагин + срез `keyboardNavigation`; roving
  `tabindex` и refocus-эффект в ячейках; вход/выход из грида (KN1–KN3, KN7).
- **Фаза 3 — навигация без виртуализации-крайних случаев.** Стрелки/Home/End/Page
  на помещающейся в экран сетке (KN4–KN6).
- **Фаза 4 — виртуализация.** Пиновка + `scrollToIndex` + восстановление фокуса на
  большой выборке (KN8–KN10); перф-кейс навигации в общей матрице
  ([ADR 0009](0009-test-coverage-visual-and-performance.md)).
- **Фаза 5 — режим действия и координация.** `Enter`/`F2`/`Escape`, делегирование
  `Space`/`Enter` в `rowSelection`/`columnSorting`/`rowExpanding` (KN11–KN13).
- **Фаза 6 — затянуть a11y-гейт.** Включить `scrollable-region-focusable` в
  `a11y.test.tsx`; обновить [ADR 0020](0020-accessibility.md) (2.1.1 закрыт) и
  статус этого ADR на «Принято».

См. [ADR 0020](0020-accessibility.md) про текущее состояние доступности,
[ADR 0005](0005-virtualization-tanstack-virtual.md) про `rangeExtractor`-пиновку и
[ADR 0010](0010-invert-core-plugins-registry.md) про форму плагина и инвариант
«ноль правок ядра», который этот план осознанно ослабляет.
