# 0237 — Переиспользование отфильтрованных строк для счётчиков фасета

- **Статус:** Принято.
- **Дата:** 2026-11-25
- **Слой:** плагин `columnFilteringModel` — получение строк для счётчиков фасета из клиентской стадии фильтрации.
- **Связано:** [ADR 0048](0048-option-filtering.md), [ADR 0200](0200-own-row-engine.md), [ADR 0234](0234-filter-tree-and-optional-acceleration.md).

## Контекст

Счётчики вариантов используют выборку без фильтра своей колонки. Пока в
этой колонке нет фильтра, встроенная клиентская стадия уже вычислила
нужный набор. Штатный фасет строит его ещё одним обходом.

В целевом эксперименте на гриде SF25 при Chromium ×4 участвовало
126 668 входных узлов. Три запроса к другой колонке давали 2 541,
12 124 и 17 466 узлов. Выполнено девять измерений на вариант.

| Метрика, медиана              | Штатный путь | Переиспользование |
| ----------------------------- | -----------: | ----------------: |
| Получение модели              |      96,5 мс |           <0,1 мс |
| Получение модели и счётчиков  |     101,7 мс |            9,3 мс |
| Самая длинная задача сценария |       332 мс |            325 мс |

Счётчики и порядок их ключей совпали на всех запусках. Заметный эффект
подтвердился для операции фасета. Устойчивого сокращения самой длинной
задачи всего сценария этим прогоном не установлено.

В отдельном холодном замере удаление временных массивов и повторного
определения типа для скалярных значений дало 84,6 → 85,1 мс. Этот
вариант в решение не входит. Сырые данные — `performance-results/facet-research.json`
и `performance-results/facet-research-cold.json`.

## Предлагаемое решение

Переиспользовать `flatRows` выхода встроенной клиентской стадии для
счётчиков вариантов, когда у колонки нет собственного условия и набор
эффективных условий у фасета совпадает с набором стадии. Ограничить
быстрый путь известными встроенными моделями с совпадающей семантикой
дерева и поиска. При собственном условии, пользовательской модели,
ручном или смешанном серверном режиме применять штатное вычисление.
Публичный контракт модели фасета сохраняется.

Кэш счётчиков привязан к снимку строк и колонке. При смене определения
типа или правил получения значения проверить, что счётчики обновляются
вместе с правилами.

## Требования

| ID  | Требование                                                                                                                    | Проверка |
| --- | ----------------------------------------------------------------------------------------------------------------------------- | -------- |
| FC1 | При фильтре только другой колонки встроенные счётчики переиспользуют строки выхода стадии и совпадают со штатными счётчиками. | unit     |
| FC2 | При собственном условии счётчики исключают его и учитывают остальные условия.                                                 | unit     |
| FC3 | Переиспользование сохраняет счётчики дерева при отборе от листьев и от корней.                                                | unit     |
| FC4 | Пользовательская модель фасетов остаётся источником счётчиков.                                                                | unit     |
| FC5 | Серверные счётчики по-прежнему берутся из ответа приложения.                                                                  | unit     |
| FC6 | Изменение типа данных или ключа варианта обновляет счётчики для актуальной колонки.                                           | unit     |

## Последствия

Первый этап закрывает подтверждённое повторное построение модели без
Worker или Wasm. Перед расширением быстрого пути измерить открытие
реальной панели, собственный фильтр, смену другого фильтра и холодный
подсчёт по типам колонок.
