# 0115 — Движение колонок

- **Статус:** Принято (решения — по итогам прожарки 2026-10-14)
- **Дата:** 2026-10-14
- **Связано:**
  - [ADR 0107](0107-row-motion.md) — движение строк: тот же механизм FLIP, здесь — по
    горизонтали для колонок.
  - [ADR 0114](0114-async-column-moves.md) — откат колонки после отказа сервера: теперь
    она едет назад, а не прыгает.
  - [ADR 0006](0006-dnd-with-dnd-kit.md),
    [ADR 0052](0052-dnd-under-nested-headers.md) — перенос колонок и узлов вложенной шапки.
  - [ADR 0034](0034-wcag-22-dragging-and-target-size.md) — меню ручки «Move left / right».
  - [ADR 0080](0080-highlight-api.md) — подсветка колонки едет вместе с ней.
  - [ADR 0011](0011-column-pinning.md) — закреплённые колонки не ездят.

## Контекст

Строки переезжают на новые места плавно (ADR 0107), колонки — нет. Перенос мышью выглядит
плавным только потому, что соседей во время сессии двигает dnd-kit. Остальные смены
порядка колонок мгновенны: откат после отказа сервера (ADR 0114), `Alt+Shift+←/→`, пункты
меню ручки, программный `setColumnOrder`. Колонка прыгает, и не видно, куда она делась —
особенно при откате, когда пользователь ждёт подтверждения.

### Как это сделано у других

- **AG Grid** — колонки ездят при переносе мышью, через меню и API
  (`suppressColumnMoveAnimation` выключает); показ и скрытие не анимируются.
- **MUI X, Mantine React Table, TanStack Table** — движения нет; колонка встаёт сразу.

## Решение

### 1. Механизм — FLIP по горизонтали

Тот же, что у строк (ADR 0107, §1). Перед коммитом новой раскладки колонок грид
запоминает **видимые** позиции колонок: левый край ячейки шапки с её текущим `transform`
и идущей анимацией. После коммита каждая ячейка колонки, сменившей позицию, — шапки, тела
и футера — получает обратный сдвиг `translate` по X и уезжает на место анимацией Web
Animations. Покадровой перерисовки React нет.

Видимые позиции, а не логические: после броска мышью колонки уже стоят на местах — сдвиг
нулевой, повторного переезда нет.

Под вложенной шапкой у каждой ячейки группы — свой сдвиг по своему `id`: группа и её
листья едут одним блоком.

### 2. Когда колонки двигаются

Анимируется смена **порядка** видимых колонок при том же их наборе и том же закреплении:
откат, клавиатура, меню ручки, `setColumnOrder`, новые `columns` с теми же `id`.

Не анимируются — колонка встаёт сразу:

- показ и скрытие колонки (набор видимых колонок сменился);
- закрепление и открепление;
- смена ширины, прокрутка.

Закреплённые колонки не ездят никогда: они липкие и стоят у края.

### 3. Колонка издалека и вдаль

При горизонтальной виртуализации колонка, которая до смены стояла далеко за краем окна,
въезжает от края окна с нужной стороны: стартовая позиция — прежняя, но не дальше края.
Колонка, которая после смены уходит далеко, уезжает к краю **призраком**: копии её ячеек
на прежних местах уезжают к новому месту, но не дальше края, и уходят из DOM. Призраки вне
доступности и ввода: `inert`, `aria-hidden`, без ролей и `id`. Двигаются только колонки,
путь которых задевает видимую часть грида.

### 4. Тема, флаг, уменьшенное движение

- Длительность — токен движения строк `--tsr-comp-row-motion-duration`, кривая —
  `--tsr-comp-motion-easing`. Своего токена нет: строки и колонки ездят одним темпом.
- Флаг ядра `enableColumnAnimation` в `useCreateTable`, по умолчанию `true`; `false` —
  мгновенно, как раньше.
- `prefers-reduced-motion: reduce` и нулевая длительность в теме — без движения.

### 5. Посреди анимации

- Прокрутка доводит движение до конца за кадр.
- Новая смена порядка во время движения стартует с текущего видимого положения, без
  скачка.
- Движение не меняет фокус (ADR 0021): активная ячейка после смены там же, где без
  движения.

## Отвергнутые альтернативы

- **Анимация переходом `left` или `transform` в CSS.** Ячейки виртуальных колонок стоят
  по `left`; переход по нему пересчитывает раскладку каждый кадр, а `transform` занят
  dnd-kit. Web Animations по свойству `translate` не мешают ни тому, ни другому.
- **Общий флаг с `enableRowAnimation` или переименование в `enableAnimation`.** Одно имя
  для строк и колонок вводит в заблуждение, переименование ломает API.
- **Анимация показа, скрытия и закрепления.** Нужны призраки колонок при каждом показе и
  движение липкой зоны; выигрыш меньше риска.
- **Без призраков: уходящая далеко колонка просто пропадает.** Не видно, куда она делась —
  ровно то, что решает этот ADR.

## Границы

- Движение под вложенной шапкой — без призраков: там нет горизонтальной виртуализации,
  все колонки смонтированы.
- Скелет первой загрузки (ADR 0060) не ездит.
- Узкий грид: перенос с клавиатуры к краю прокручивает грид к фокусу (ADR 0021), и
  прокрутка обрывает движение (§5) — колонка встаёт сразу. Так же, как у строк (ADR 0107,
  §7).
- Порядок колонок, общий с приложением, меняется и без грида — движение то же, что от
  `setColumnOrder`.

## Последствия

- **Публичный API:** новый флаг ядра `enableColumnAnimation` (по умолчанию `true`).
  Смена порядка колонок теперь видна движением; прежнее поведение — `false`.
- **Перф:** анимируются только ячейки видимых строк у колонок, сменивших место; строки
  запаса виртуализации не едут — слой композитора на каждую ячейку дорог. После коммита —
  одно чтение раскладки шапки (ширины ячеек не всегда равны размерам колонок), замеры
  до анимаций: `animate()` сбрасывает стили. Замер CN13 на 1000×1000: перенос —
  около +5 мс без троттлинга, кадры движения — в бюджете кадра.
- **Рендер-слой:** класс `ColumnMotion` вокруг шапки, тела и футера (`getSnapshotBeforeUpdate`
  видит DOM до коммита), чистый план `planColumnMotion`.
