## Контекст

Пункт меню действий описывается дескриптором (ADR 0024): `disabled(ctx)` и
`visible(ctx)` синхронны, `onSelect` ничего не возвращает. Поэтому:

- доступность, которую решает сервер (права, состояние записи), выразить нельзя:
  грид не узнает об ответе, открытое меню не обновится;
- долгое действие (удаление строки на сервере) после клика не видно — ни ожидания,
  ни отказа;
- заблокированный пункт просто серый: почему — не сказано.

Кебаб целиком не блокируется никогда; ожидание на нём бывает только при загрузке
модуля панели (ADR 0061).

## Решение

### 1. Блокируются пункты, а не кебаб

Меню открывается сразу. Готовые пункты доступны; пункт, чья доступность ещё
проверяется, — в ожидании. Кебаб не ждёт самой медленной проверки и не блокируется,
даже если заблокированы все пункты: человек должен увидеть причины.

### 2. Асинхронная проверка доступности

`disabled` может вернуть промис: `(ctx, signal: AbortSignal) => DisabledResult |
Promise<DisabledResult>` (причина — §3).

- **Сессия проверки.** Проверки запускаются при наведении и фокусе на кебабе
  (как `preload`, ADR 0061) или при открытии меню, если сессии ещё нет, и
  переиспользуются при открытии. Пока меню открыто, не повторяются. Уход указателя
  или фокуса без открытия и закрытие меню прерывают сессию (`signal.aborted`), поздние
  ответы отбрасываются. Результат живёт только в сессии — кеширует приложение, оно
  знает инвалидацию. Контекстное меню начинает сессию при открытии.
- **Вид.** Проверяемый пункт заблокирован, у правого края, на месте галочки, горит
  маленький лоадер — спиннер из пятен света (ADR 0095); описание
  для скринридера — «Проверка доступности». Блик по контуру пункта отвергнут: на
  строке меню он шумнее и читается хуже лоадера на привычном месте состояния.
- **Закрытие.** Прерванная сессия оставляет свои итоги, а увиденные отказы убираются
  по окончании закрытия: закрывающееся меню не мигает ожиданием и не теряет иконку.
- **Проверка не удалась** (промис отклонён) — это не запрет: ответа просто нет. Пункт
  доступен, у правого края — иконка ошибки, текст — в тултипе и `aria-describedby`
  (`errorMessage`, иначе текст ошибки, иначе «Не удалось проверить доступность»).
  Нажатие не закрывает меню и проверяет заново (лоадер): «можно» — действие сразу
  выполняется и меню закрывается, намерение уже выражено; «нельзя» — значок причины,
  действие не выполняется; новая ошибка — иконка ошибки остаётся. Пропустить проверку
  и сразу запустить действие отвергнуто: проверку тогда незачем было делать.
- **`visible` остаётся синхронным**: пункты не появляются и не исчезают под
  указателем. Высота пунктов от ответа проверки не меняется: все состояния пункта —
  значок фиксированной колонки у правого края.
- **Вне меню** (инлайн-кнопка) асинхронный `disabled` не поддержан: кнопка
  заблокирована, ядро пишет dev-предупреждение. Проверка при наведении на каждую
  строку — шквал запросов; это отдельная задача (roadmap).

Ядро зовёт `disabled` и в рендере — для синхронных значений. Дескриптор, однажды
вернувший промис, помечается асинхронным, и рендер его больше не вызывает: запрос
идёт только из сессии. Пробный вызов в рендере получает уже прерванный `signal`.

### 3. Причина блокировки

Причину чаще всего знает только ответ сервера («уже в архиве», «нет прав»), поэтому её
возвращает сам `disabled`:

```ts
type DisabledResult = boolean | { kind: 'done' | 'forbidden'; reason?: string }
disabled?: (ctx, signal) => DisabledResult | Promise<DisabledResult>
```

Причины различаются значком у правого края пункта — в той же колонке, что галочка
включённого состояния, лоадер и иконка ошибки:

| Причина                  | Пример              | Значок                                            | Выбрать |
| ------------------------ | ------------------- | ------------------------------------------------- | ------- |
| `done` — уже сделано     | строка уже в архиве | галочка цветом акцента                            | нельзя  |
| `forbidden` или `true`   | нет прав            | замок (`icons.actionBlocked`), если есть `reason` | нельзя  |
| проверка не удалась (§2) | сервис недоступен   | иконка ошибки (`icons.actionFailed`)              | можно   |

Запрет без текста (`true` или `forbidden` без `reason`) только гасит пункт, без значка:
замок без причины ничего не объясняет. `reason` — полный текст в тултипе (наведение
и переход стрелками) и в `aria-describedby`; без него описания нет. Чтобы тултип открывался, заблокированный
пункт с текстом принимает наведение; выбрать его по-прежнему нельзя.

Отвергнуто:

- **Вторая строка мелким текстом под подписью** — появляется в момент ответа проверки и
  сдвигает пункты под курсором.
- **Отдельная функция `disabledReason`** — не видит ответа сервера, из которого
  причина и известна.
- **Тултип недоступен с тач-устройства** — принято: он открывается касанием
  заблокированного пункта.

### 4. Долгое действие

`onSelect` может вернуть промис.

- Меню закрывается сразу.
- **Ожидание** привязано к паре «действие + цель» (колонка заголовка, ячейка строки
  или ячейка контекстного меню) и хранится в срезе `actionStatus` (TanStack Store): оно
  переживает уход строки из окна виртуализации, сортировку и смену страницы. Пока
  действие ждёт, этот пункт в этой цели заблокирован (защита от двойного «Удалить»);
  остальные пункты и то же действие в другой цели работают.
- **Кебаб** бликует, пока ждёт хотя бы одно его действие. Тултип и доступное имя
  перечисляют ждущие: «Row options. Running: Delete, Export». Несколько действий
  одновременно разрешены — источник виден без открытия меню.
- **Объявления** с именем действия: «Delete: done», «Delete failed: <текст>».
- **Инлайн-кнопка** с промисом `onSelect` показывает ожидание своим кольцом
  (`pending`) и отказ — вспышкой (`errorFlash`) с объявлением; отметки ошибки у неё
  нет — открывать нечего.

### 5. Ошибка действия

- На кебабе вспыхивает `errorFlash` и **остаётся отметка ошибки** — точка цветом
  ошибки на месте точки включённых действий (ADR 0062). Кебаб с отметкой виден без
  наведения; тултип и имя: «Failed: Delete».
- Открытие меню помечает ошибку увиденной (отметка снимается), по окончании закрытия
  меню она убирается. Повторный запуск действия заменяет её ожиданием.
- **В меню** у упавшего пункта у правого края, на месте галочки, — иконка ошибки
  (`icons.actionFailed`). Полный текст — в тултипе (наведение и переход стрелками) и в
  описании пункта (`aria-describedby`). Пункт доступен — можно повторить.
- **Текст ошибки:** `errorMessage?.(ctx, error, labels)`, иначе `rejectionText`
  (`Error.message` или строка), иначе подпись `actionFailedFallback`.
- Цвет — токен `--tsr-comp-action-error-color` (от `--tsr-sys-danger`).

### 6. Где действует

Кебаб заголовка, кебаб строки, контекстное меню (кебаба нет: ожидание и ошибки видны в
пунктах при следующем открытии, объявления те же) и инлайн-кнопки (§4). Мини-меню
инлайн-кнопки (`inlineAsMenu`) не затронуто: его пункты — `menuItems`, они синхронны
по контракту.

### 7. Блик стоит во время прокрутки

Блик кнопки (ADR 0055) вращает угол градиента — каждое кольцо перерисовывается на
каждом кадре. Когда ждут сотни действий (массовое удаление), кебабы в окне прокрутки
удорожали кадр прокрутки по Y с ~17 до 24–32 мс (MI23). Пока у контейнера грида стоит
`data-scrolling` (ADR 0076, RW3), анимация блика кнопок на паузе
(`animation-play-state: paused`): пятно видно, но не бежит; после остановки бежит
дальше. Блик ячейки в правке (ADR 0057) идёт на компоновщике — его пауза не касается.

### 8. Совместимость

Синхронный `disabled` и `onSelect`, ничего не возвращающий, ведут себя как прежде.
Новые поля необязательны — изменение не ломающее.

## Границы

- **Асинхронный `visible`** — нет (§2).
- **Асинхронная проверка у инлайн-кнопок** — нет, в roadmap.
- **Свои пункты кебаба у приложения без плагина** — нет, в roadmap.
- **Список пунктов с сервера** («Переместить в…») — вложенные разделы меню, отдельный
  ADR.
- **Отмена идущего действия** из меню — нет.

## Отвергнутые альтернативы

- **Кебаб ждёт все проверки** — одна медленная проверка задерживает все действия.
- **Одно ждущее действие на кебаб** (остальные заблокированы) — медленное действие
  отнимает несвязанные.
- **Меню остаётся открытым до конца действия** — мешает работать с гридом,
  расходится с ADR 0041/0061.
- **Ожидание в состоянии компонента кебаба** — пропадает при уходе строки из окна
  виртуализации.
- **Отдельное поле `checkDisabled`** вместо промиса из `disabled` — два источника
  одного признака; синхронный и асинхронный случаи различает тип результата.

## Последствия

- Новый always-on срез `actionStatus` ядра (`actionStatusFeature`).
- `MenuAction` получает `errorMessage`; `disabled` возвращает причину (`DisabledResult`) и
  может вернуть промис, `onSelect` —
  расширяют тип результата.
- Новые подписи `localization`, иконки `actionFailed` и `actionBlocked`, токен
  `--tsr-comp-action-error-color`, тон `error` у внутреннего `Bubble`.
- Пункты обоих меню рисует один компонент `ActionMenuItems`.

## План внедрения

1. Типы дескриптора, срез `actionStatus`, `runMenuAction`, сессия проверок.
2. `ActionMenuItems` для кебаба и контекстного меню; кебаб и инлайн-кнопка читают срез.
3. Подписи, иконка, токен, тон `Bubble`.
4. Тесты, истории, документация.
