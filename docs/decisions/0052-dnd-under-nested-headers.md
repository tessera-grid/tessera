# 0052 — Перетаскивание под вложенной шапкой: колонки по уровням и строки

## Контекст

Под вложенной шапкой оба плагина перетаскивания инертны с причиной
`multiLevelHeader`: `column.getCanDrag()` ложен при числе строк шапки больше одной,
`rowDragging` гасит себя тем же условием. ADR 0022 записал это контрактом «потребности
нет». Потребность появилась: колонки в многоуровневой шапке нужно переставлять так же,
как в плоской.

Что задаёт форму решения:

- **Порядок колонок в TanStack — порядок листьев** (`columnOrder`). Шапка строится из
  него: если листья группы перестают идти подряд, группа режется на сегменты (так
  работает reorder-out пиннинга). Значит, перенос листа в чужую группу меняет
  структуру шапки — это решение приложения, а не жест пользователя.
- **Механика DnD колонок** — один горизонтальный `SortableContext` по листьям, соседи
  расступаются `translateX`, призрак — клон ячейки, фиксация — `setColumnOrder`.
  Под вложенной шапкой нет колоночной виртуализации, шапка — CSS grid.
- **`onColumnDragEnd({ dragIndex, hoverIndex })`** — индексы среди перемещаемых листьев;
  для группы они ничего не значат.
- **Строки.** Гейт `rowDragging` пришёл из времени, когда колонка-ручка оборачивалась
  в группы-прокладки. После ADR 0049 это обычный лист на всю высоту шапки, и гейт
  устарел.

## Решение

### 1. Единица перетаскивания — узел дерева колонок (ND1–ND3)

- **Лист** переставляется среди соседей **внутри своей группы**.
- **Группа** переставляется среди соседей **своего уровня** целиком: её листья едут
  одним блоком и остаются подряд.
- **Вынос за пределы родителя запрещён**: бросок за границу группы прижимает узел к
  её краю. Структура шапки при перетаскивании не меняется.
- Колонка верхнего уровня без группы — узел верхнего уровня, соседи — группы и колонки
  верхнего уровня.

Перетаскиваемость задаёт флаг `enableDragging` в описании узла (у группы — в её
`columnDef`), как у листьев сейчас; листья внутри группы следуют своим флагам (ND6).

### 2. Отрисовка (ND4)

Пока узел тащат, расступается **вся колонка заголовков** узла — его ячейка и все
ячейки под ним; исходный блок скрыт (`opacity: 0`), призрак — клон ячейки узла
шириной блока. Узлы и соседи — `core/columnNodes.ts`: узел — нарисованный заголовок
(не покрытый спаном), ключ соседей — родитель + зона закрепления. Сортируемый id —
`header.id`: у сегментов одной группы id колонки совпадает. Во вложенной шапке
`HeadRow` оборачивает каждую серию соседей строки в свой `SortableContext` (без DOM —
порядок ячеек в CSS grid не меняется), столкновения считаются только с соседями
активного узла. Ячейки под группой — в других строках сетки, поэтому сдвиг и скрытие
они берут у предка из маленького стора (`grid/dnd/nodeShift.ts`). Плоская шапка —
одна серия, как раньше. Призрак (`OverlayHeadCell`) — `inert`: визуальный клон не
попадает ни в дерево доступности, ни в фокус.

### 3. Клавиатура и меню (ND5)

`Alt+Shift+←/→` и меню ручки «Move left / Move right» двигают узел к соседнему
перемещаемому узлу того же родителя; у края группы пункт недоступен. Ручка — в
ячейке узла (группы или листа), как сейчас у листа.

### 4. Пиннинг (ND7)

Закреплённые колонки и группы не перетаскиваются (D29). При reorder-out (`leafPinning`)
сегмент разрезанной группы двигается только внутри своей зоны; через границу
закрепления узел не переносится — бросок прижимается к краю зоны.

### 5. Колбэки (ND8–ND9)

`onColumnDragEnd` получает вдобавок `columnId` (лист или группа) и `columnOrder` —
новый порядок листьев. `dragIndex` / `hoverIndex` остаются: для листа — как сейчас,
для группы — индексы первого листа её блока и первого листа цели, по порядку до
переноса. `onColumnDragCancel`
получает `columnId` узла. Форма расширяется, ломающих изменений нет.

### 6. Строки под вложенной шапкой (ND10)

Гейт `multiLevelHeader` у `rowDragging` снимается: ручка строки — лист служебной
колонки на всю высоту шапки, перетаскивание и меню ручки работают как в плоской
шапке.

## Границы

- **Перенос листа между группами** не поддерживается — меняет структуру шапки.
  Приложение может сделать это само, поменяв `columns`.
- **Перенос в зону закрепления** не закрепляет колонку — пиннинг и перетаскивание
  остаются независимыми.
- Колоночная виртуализация под вложенной шапкой по-прежнему выключена (ADR 0049).

## Отвергнутые альтернативы

- **Только верхний уровень** (как групповой пиннинг): проще, но перестановка внутри
  группы недоступна.
- **Перенос между группами**: TanStack режет группы на сегменты — шапка становится
  нечитаемой, а смысл группы теряется.
- **Перенос в зону закрепления закрепляет** (как AG Grid): смешивает два плагина и их
  колбэки.
- **Отдельный `onGroupDragEnd`**: два канала одного события.
- **Замена формы колбэка** на `{ columnId, columnOrder }`: чище, но ломает потребителей.

## Последствия

- **+** Перетаскивание колонок и строк работает под любой шапкой.
- **+** Структура шапки не может сломаться от жеста пользователя.
- **−** Сортируемых контекстов в шапке становится несколько (по группе соседей) —
  перф-требование ND14.
- **Публичный API:** `onColumnDragEnd` и `onColumnDragCancel` получают новые поля;
  `enableDragging` начинает действовать в описании группы. ADR 0022 (B4) отменяется
  в части drag; ADR 0006 — раздел «Известные ограничения» обновляется.

## План внедрения

1. `columnDraggingFeature`: узел дерева вместо листа — `getCanDrag` для групп,
   соседи по родителю, снятие гейта `multiLevelHeader`.
2. Рендер: сортируемые контексты по группам соседей в `DndHeadWrapper`, сдвиг блока
   ячеек, призрак группы.
3. `moveColumn` и меню ручки — по соседям родителя; колбэки с новыми полями.
4. `rowDragging`: снять гейт, проверить ручку на всю высоту.
5. Тесты, история, документация (`dnd.md`, ADR 0006 «Известные ограничения»,
   ADR 0022 B4, roadmap).
