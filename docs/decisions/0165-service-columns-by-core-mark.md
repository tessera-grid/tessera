# 0165 — Служебные колонки по метке ядра

- **Статус:** Принято (решения — по итогам прожарки 2026-10-31)
- **Дата:** 2026-10-31

  колонок в записи `ServiceColumn`; грид читает сведения, а не имена плагинов.

## Контекст

Ядро узнаёт служебную колонку по подстроке id: `columnId.includes('actionColumn')`. Колонка
приложения с таким id становится служебной: теряет шапку, сортировку и поиск. Отдельный метод
`getIsRowActionsColumn` назван по одному плагину и проверяет его id. Описание колонки несёт
поля, которые ставят только встроенные плагины: `serviceLabel` — союз из трёх ключей
подписей, `controlSized`. Грид ищет колонку раскрытия по `serviceLabel === 'expandColumn'`,
чтобы нарисовать в скелете дерева переключатель. `columnPinning` кладёт `pinSides` в
`ColumnMeta` — пространство приложения.

### Как у других

- **AG Grid** — служебное поведение колонки задают флаги её описания (`checkboxSelection`,
  `rowDrag`), а не id.
- **MUI X** — свои служебные колонки помечены типом (`type: 'checkboxSelection'`,
  `'actions'`).

## Решение

### 1. Метка ядра

`injectServiceColumns` метит каждую вставленную служебную колонку внутренним полем описания
(символ, не часть публичного `ColumnDef`); метка переживает слияние с `defaultColumn`.
`column.getIsActionsColumn()` читает метку. Новый `column.getServiceColumn()` отдаёт сведения
служебной колонки или `undefined`: `id`, `pluginId`, `label`, `controlSized`, `fill`.
`getActionColumnId` остаётся — по нему плагин даёт колонке стабильный id.

### 2. Свойства — в записи `ServiceColumn`

Запись `ServiceColumn` плагина получает поля:

- `label` — ключ `localization` для скрытой подписи шапки (любой ключ словаря, не три
  встроенных);
- `controlSized` — ширина по кнопке грида из темы (ADR 0135);
- `fill` — зона действий строки (ADR 0025): колонка забирает свободное место строки, а её
  ячейки рисуют действия слота `actionRowSlot` (инлайн-кнопки и кебаб).

Поля `serviceLabel` и `controlSized` уходят из описания колонки, `getIsRowActionsColumn` — из API
колонки; `ROW_ACTIONS_COLUMN_ID` переезжает из ядра в плагин `rowActions`.

### 3. Переключатель в скелете

Вид ячейки скелета `skeletonCell` получает значение `'toggle'`: на строках плана с детьми
колонка рисует переключатель, на прочих — пусто. Колонка раскрытия объявляет его сама; грид
не ищет её по подписи.

### 4. `pinSides`

`pinSides` — поле описания колонки в карте фичи `columnPinning`, рядом со стоковым
`enablePinning`: `{ accessorKey: 'name', pinSides: 'start' }`. Библиотека не дополняет
`ColumnMeta`; база LB7 пуста.

## Границы

- Знание грида о самих плагинах (флаги перетаскивания, линий дерева, липких строк) — находки 2 и 3,
  шаги 5 и 7 аудита.

## Отвергнутые альтернативы

- **Только метка вместо подстроки** — меньше правок, но `serviceLabel`, `controlSized` и
  `getIsRowActionsColumn` держали бы имена плагинов в ядре и гриде; решено на прожарке.
- **Метка полем описания с именем** — стала бы публичным полем `ColumnDef` и строкой снимка LB8;
  символ виден только ядру.

## Последствия

- Колонка приложения с любым id — колонка данных.
- Сторонний плагин объявляет подпись, ширину по кнопке и захват места своей служебной колонки
  так же, как встроенный.
- **Ломающие изменения публичного API (до 1.0):** удалены поля описания колонки `serviceLabel`,
  `controlSized` и метод `getIsRowActionsColumn`; `meta.pinSides` → `pinSides`.

## Сценарии

Нет: служебные колонки выглядят и работают как прежде, нового сценария нет.

## Внедрение

Внедрён 2026-10-31.

- **Метка** — символ `SERVICE_COLUMN` и `serviceColumnOf` в `core/createColumns`;
  `column.getServiceColumn()` от `commonFeature`; `checkIsActionColumn` удалён,
  `ROW_ACTIONS_COLUMN_ID` — в `plugins/rowActions` (и в корне пакета, как id других служебных
  колонок).
- **Грид** читает `getServiceColumn()`: `HeadCell` (подпись, ширина), `BodyCell` (зона действий),
  `layout.ts` (дорожка `1fr`), `useControlColumnSizes` (ширина по кнопке), `SkeletonBody`
  (переключатель по `skeletonCell: 'toggle'`). Лишняя проверка `getIsRowActionsColumn` в
  `cellEditing` и `cellSelectionModel` снята: колонка действий строки и так служебная.
- **`pinSides`** — фича `columnPinSidesFeature` плагина `columnPinning`; база LB7 пуста.
- **Тесты** — модульный `serviceColumns` (SX1, SX2, SX4), визуальный `skeleton-toggle` (SX3).
  TQ1: признак по подстроке id (SX1), запись `rowActions` без `fill` (SX2), `'toggle'` без
  отрисовки (SX3), чтение `meta.pinSides` (SX4).
