# 0040 — Сессии действий: черновик, причины завершения, потеря фокуса

- **Статус:** Принято (реализовано)
- **Дата:** 2026-09-30
- **Изменён:** 2026-10-25 — сценарий S4: колбэки перетаскивания — гайд «Plugin API — Drag & resize callbacks».
- **Связано:**
  - [ADR 0039](0039-reactive-plugin-arguments.md) — запрет идущего действия отменяет
    его как Escape (§5, RX14–RX16); этот ADR определяет, что при этом получает
    приложение и что происходит с черновиком правки.
  - [ADR 0027](0027-plugin-hooks-in-factory-args.md) — бизнес-колбэки в аргументах
    фабрики, читаются живо.
  - [ADR 0021](0021-keyboard-navigation.md), [ADR 0031](0031-wcag-keyboard.md) —
    клавиши входа в правку (`Enter`/`F2`) и выхода (`Escape`).
  - [ADR 0006](0006-dnd-with-dnd-kit.md), [ADR 0013](0013-column-sizing.md) —
    перетаскивание строк и колонок, ресайз.
  - Асинхронный контракт бизнес-колбэков (отказ сервера, ожидание) — отдельный ADR.

## Контекст

У части плагинов есть **сессия действия**: у неё есть начало, промежуточное
состояние и конец.

| Плагин                          | Сессия         | Промежуточное состояние    |
| ------------------------------- | -------------- | -------------------------- |
| `cellEditing`                   | правка ячейки  | черновик — введённый текст |
| `rowDragging`, `columnDragging` | перетаскивание | позиция над целью          |
| `columnSizing`                  | ресайз колонки | ширина под указателем      |

Сейчас сессии устроены так, что пользователь и приложение теряют информацию:

1. **Черновик живёт в компоненте редактора.** Прокрутка, увёл строку из окна
   виртуализации, смена страницы, сортировка — компонент размонтирован, текст
   потерян. Вернулся к ячейке — редактор открыт, но с исходным значением.
2. **Потеря фокуса отменяет правку.** Клик мимо ячейки или `Tab` выбрасывают
   введённое. На рынке наоборот: в AG Grid переход на другую ячейку и в MUI X клик
   мимо **сохраняют**, а отмена — только `Escape`.
3. **Приложение не знает, чем кончилась сессия.** Бизнес-колбэки зовутся только при
   успехе (`onCellEdit`, `onRowDragEnd`, `onColumnDragEnd`, `onColumnResizeEnd`).
   Отмена пользователем, запрет на лету (ADR 0039), исчезновение строки из данных
   проходят молча — а при правке с ними молча пропадает черновик.
4. **Конфликт не отслеживается.** Если значение ячейки обновилось извне во время
   правки (данные в реальном времени), сохранение черновика молча затирает новое
   значение.
5. **Ресайз нельзя отменить.** У перетаскивания `Escape` отменяет, у ресайза отмены
   нет.

## Решение

### 1. Причины завершения сессии (SS1–SS2)

У любой сессии одна из причин завершения, единый словарь для всех плагинов:

| Причина       | Когда                                                                                     |
| ------------- | ----------------------------------------------------------------------------------------- |
| `commit`      | результат применён: значение сохранено, строка брошена, ширина зафиксирована              |
| `cancel`      | пользователь отменил: `Escape`, кнопка отмены                                             |
| `revoke`      | действие запретили на лету: предикат, опция, выключенный плагин (ADR 0039, §5)            |
| `unavailable` | цель исчезла: строка или колонка ушли из данных                                           |
| `conflict`    | только правка в строгом режиме: значение ячейки изменилось извне после начала сессии (§4) |

Бизнес-колбэки успеха остаются как есть и зовутся только на `commit`. Остальные
причины приходят в **новый колбэк отмены** плагина — по одному на плагин с сессией:

```ts
cellEditing({
  onEditCancel?: (end: {
    rowId: string
    columnId: string
    reason: 'cancel' | 'revoke' | 'unavailable' | 'conflict'
    draft: string // введённый текст — не теряется молча
    original: unknown // значение ячейки на начало сессии
    current?: unknown // значение сейчас (для 'conflict')
  }) => void,
})
rowDragging({ onRowDragCancel?: (end: { rowId: string; reason }) => void })
columnDragging({ onColumnDragCancel?: (end: { columnId: string; reason }) => void })
columnSizing({ onColumnResizeCancel?: (end: { columnId: string; reason }) => void })
```

У перетаскивания и ресайза `reason` — `'cancel' | 'revoke' | 'unavailable'`.
Колбэк отмены — бизнес-колбэк (ADR 0027): читается живо, не рендерит.

- **Бросок без перестановки** — мимо цели, на то же место, на недопустимую
  глубину — тоже `cancel`: результат не применён.
- **Плагин выключили посреди сессии** — выключенный плагин свой слайс хуков уже не
  отдаёт, поэтому хуки запоминаются на начало сессии и отмена с `revoke` доходит.
- Причина от ядра к колбэку идёт через механизм отмены «как Escape» (ADR 0039, §5):
  у перетаскивания — синхронно вокруг синтетического `Escape`, у ресайза — меткой
  на событии конца протяжки.
- **Колбэк успеха перетаскивания строки** `rowDragging({ onRowDragEnd })` был
  объявлен, но не вызывался. Он зовётся при успешном броске и при перестановке
  соседей с клавиатуры или из меню ручки (SS14):
  `{ rowId, dragIndex, hoverIndex }`, где индексы — позиции в показанных строках до
  перестановки: исходная и целевая. `rowId` добавлен, потому что при вложенности
  одних индексов мало. Смена вложенности с клавиатуры (`nest`/`unnest`) —
  не перестановка: о ней сообщает только `onRowOrderChange`.

### 2. Черновик правки — в состоянии плагина (SS3–SS6)

Локальный срез `cellEditing` хранит не только «какая ячейка редактируется», но и
черновик: `{ cell, draft, original } | null`.

- **Черновик переживает размонтирование**: прокрутку виртуализации, смену страницы,
  сортировку, скрытие колонки. Вернулся к ячейке — редактор с тем же текстом и тем же
  текстом ошибки `validate`, если она была (SS21).
- Размонтирование редактора **не завершает** сессию: ячейка просто не на экране.
- Строка ушла из данных — сессия завершается с `unavailable`, черновик уходит в
  `onEditCancel`.
- Контракт редактора (BYO, `editor`) получает `setDraft(value)`: редактор сообщает
  введённое, чтобы черновик жил в срезе, и `value` — черновик, а не значение ячейки.
  Редактор, который `setDraft` не зовёт, работает как раньше, но его черновик не
  переживает размонтирование.

**Согласование сессии.** Редактор может быть размонтирован, поэтому сессию правки
ведёт не он, а плагин. Запись плагина получает поле `reconcile(table, { enabled,
hooks })`: ядро зовёт его после каждого рендера таблицы для всех присутствующих
записей, включая выключенные, — с живой таблицей и хуками записи. `cellEditing`
сверяет в нём открытую сессию с таблицей:

| Что с ячейкой сессии                                | Итог                          |
| --------------------------------------------------- | ----------------------------- |
| строки нет в данных, колонки нет в описании         | завершение с `unavailable`    |
| плагин выключили или убрали из набора               | завершение с `revoke`         |
| `canEdit` запрещает ячейку, даже вне экрана         | завершение с `revoke`         |
| ячейка вне окна, на другой странице, колонка скрыта | сессия жива, черновик в срезе |

Причина `revoke` на лету теперь проверяется здесь, а не в смонтированном редакторе:
запрет доходит и до ячейки, которую увели прокруткой.

- **Серверная пагинация.** В данных только текущая страница: строка другой страницы
  для грида неотличима от удалённой. Правка при уходе на другую серверную страницу
  завершается `unavailable`, черновик приходит в `onEditCancel`.
- **Смена страницы и сортировка кликом** уводят фокус из редактора — это потеря
  фокуса (§3), и она завершает сессию. Черновик переживает смену, пришедшую не через
  фокус: прокрутку, смену данных, программную смену страницы или сортировки.
- Ячейки подписаны на проекцию среза «редактируется ли эта ячейка»
  (`useSliceProjection`): ввод черновика сетку не перерисовывает.

### 3. Потеря фокуса сохраняет (SS7–SS9)

- **Потеря фокуса — `commit`** через `validate`, как в AG Grid и MUI X.
- **Отмена — только явная**: `Escape` (и кнопка отмены, если редактор её рисует).
- Потеря фокуса с **недопустимым** значением сессию не завершает: редактор остаётся
  открытым с текстом ошибки, черновик цел — пользователь вернётся и исправит.
- Размонтирование редактора (прокрутка) — не потеря фокуса и не `commit` (§2).
- Потеря фокуса после `Enter` или `Escape` ничего не делает: сессия уже закрыта,
  повторного сохранения нет.
- **Значение не изменилось** (черновик совпадает с исходным значением ячейки) —
  сохранение просто закрывает правку: без `onCellEdit`, без `onEditCancel` и без
  `validate` (SS18). Как в AG Grid: событие изменения без изменения не шлётся.
  Иначе клик в ячейку и уход из неё отправляли бы приложению пустое сохранение, а
  при недопустимом по `validate` исходном значении редактор нельзя было бы закрыть.
  Сравнение — с исходным значением, а не с текущим: если значение изменилось извне,
  а пользователь ничего не вводил, новое значение остаётся.
- **Открытие правки другой ячейки** при открытой сессии (недопустимое значение после
  потери фокуса) завершает прежнюю с `cancel`, её черновик уходит в `onEditCancel`
  (SS17). Одновременно открыта одна сессия правки.
- BYO-редактор сам решает, что считать потерей фокуса, и зовёт `commit` — как
  дефолтный на `blur`.
- Текущее значение для конфликта (§4) читается из таблицы в момент сохранения, а не
  из отрисованной строки.

### 4. Конфликт (SS10)

Ни AG Grid, ни MUI X не обнаруживают конфликт сами: они отдают приложению исходное
и новое значение (у MUI — `processRowUpdate(newRow, oldRow)`, где `oldRow` — строка
на начало правки), а конфликт решает приложение, обычно на сервере через версию
записи. Грид сравнивает только значение одной ячейки, а настоящий конфликт —
понятие домена. Поэтому:

- **По умолчанию сохранение проходит.** На начало сессии запоминается исходное
  значение ячейки. В `onCellEdit` дополнительно приходят `original` (значение на
  начало сессии) и `current` — значение сейчас, если оно изменилось извне. Приложение
  само решает, конфликт ли это.

  ```ts
  onCellEdit: (commit: {
    rowId: string
    columnId: string
    value: string
    original: unknown // значение на начало сессии
    current?: unknown // есть, только если значение изменилось извне
  }) => void
  ```

- **Строгий режим — по выбору:** `cellEditing({ onConflict: 'block' })`. Если значение
  изменилось извне, грид не сохраняет: сессия завершается с `conflict`, в
  `onEditCancel` уходят черновик, исходное и текущее значение. Для приложений без
  серверной проверки версии.
- **Отказ сервера** с возвратом в правку — асинхронный контракт (отдельный ADR).

### 5. Запрет и отмена ресайза (SS11–SS13)

- Запрет на лету (ADR 0039, §5) — причина `revoke` у всех сессий. Для правки это
  закрывает долг RX16: черновик больше не теряется, он уходит в `onEditCancel`.
- **`Escape` во время ресайза отменяет его**, как у перетаскивания: ширины
  возвращаются к стартовым, `onColumnResizeEnd` не зовётся, `onColumnResizeCancel` —
  с `cancel`.
- Строка или колонка ушла из данных посреди перетаскивания или ресайза — отмена с
  `unavailable` (SS15). Скрытая колонка для ресайза тоже недоступна: ручки больше
  нет на экране. Шапка на время протяжки заморожена memo-компаратором, поэтому
  исчезновение колонки проверяет `DataGrid`.

## Границы

- **Асинхронное сохранение** (промис, ожидание, отказ сервера с возвратом в правку)
  — отдельный ADR об асинхронном контракте.
- **Массовая правка, вставка из буфера, правка строки целиком** — своими ADR поверх
  этой модели сессий.
- **`Tab` в режиме правки** — сохраняет по §3 (это потеря фокуса); переход с
  открытием редактора в соседней ячейке — позже.
- **Показ конфликта в UI** (подсветка, диалог) — решает приложение по колбэку.

## Последствия

- **+** Пользователь не теряет введённое: ни при прокрутке, ни при клике мимо, ни при
  отзыве права на правку.
- **+** Приложение узнаёт о каждом завершении сессии, а не только об успехе.
- **+** Поведение потери фокуса совпадает с рынком.
- **−** **Ломающее изменение поведения:** клик мимо ячейки теперь сохраняет, а не
  отменяет.
- **−** Расширение публичного API: четыре колбэка отмены, `setDraft` у редактора,
  поля `original`/`current` у `onCellEdit`, опция `onConflict`, форма локального среза
  `cellEditing`.
- **−** BYO-редакторы без `setDraft` не получают живучести черновика.
- **−** Расширение контракта записи плагина: поле `reconcile` — ядро зовёт его на
  каждый рендер таблицы, поэтому оно обязано быть дешёвым при отсутствии сессии.
- **−** Ломающее для тех, кто читал срез `cellEditing` напрямую: был ключ
  `rowId:columnId`, стал объект сессии.
