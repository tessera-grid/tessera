# 0180 — Единая форма диапазона выделения: индексы во всех режимах

- **Статус:** Принято (решения — по итогам прожарки 2026-11-03)
- **Дата:** 2026-11-03
- **Слой:** плагин `cellSelectionModel` — выделение по индексам становится единственной
  реализацией методов поверх стоковой фичи; ядро `core/highlights` — форма цели `range`
  подсветки и вспышки. Новых модулей ядра нет: диапазон выделения — модель плагина, цель
  подсветки уже в ядре.

    стоковой фиче» в «Границах» снимается.
  - [ADR 0152](0152-menu-action-outcome-on-target.md) §4 — цель `range` — той же формы, что
    диапазон выделения.
- **Связано:**
  - [ADR 0029](0029-cell-range-selection.md) — выделение ячеек и копирование.
  - [ADR 0178](0178-drafts.md) §7 — при строках до сохранения выделение уже идёт по индексам
    видимого списка.
  - [ADR 0080](0080-highlight-api.md) — API подсветки.

## Контекст

Срез `cellSelection` в разных режимах устроен по-разному:

| Режим                             | Углы строк в срезе                        | Реализация методов              |
| --------------------------------- | ----------------------------------------- | ------------------------------- |
| Клиентские данные                 | `anchorRowId`, `focusRowId`               | стоковая `cellSelectionFeature` |
| Клиент со строками до сохранения  | индексы видимого списка и `id` (ADR 0178) | своя, по индексам               |
| Серверная модель строк (ADR 0146) | `anchorRowIndex`, `focusRowIndex`         | своя, по индексам               |

Приложение, которое читает или задаёт срез, ветвится по режиму. Цель `range` подсветки
(ADR 0152) принимает обе формы, но своим синтаксисом: `rows: [from, to]` или
`rows: { indexes }`. Две реализации геометрии выделения держат паритет тестами (ADR 0146,
«Последствия»).

Стоковая фича TanStack v9 хранит углы диапазона как `id` строк и переводит их в места через
`getRowsInDisplayOrder()`; при смене `data` она сбрасывает выделение
(`autoResetCellSelection`). Методы фичи подменяет своя фича поверх стоковой — так уже
сделано в серверной модели строк.

### Как у других

- **AG Grid** — диапазон задаётся индексом строки во всех моделях строк.
- **MUI X** — выделение — словарь «`id` строки → поле → флаг».
- **Excel, Google Sheets** — диапазон — координаты.

## Решение

### 1. Срез — индексы, `id` углов — рядом

Диапазон во всех режимах — `anchorRowIndex`, `focusRowIndex`, `anchorColumnId`,
`focusColumnId` и `operation`. Грид дописывает `anchorRowId` и `focusRowId`, где строка
известна: в клиентском режиме — всегда, в серверной модели — у загруженных строк. Тип среза
Tessera `CellSelectionState` по-прежнему расширяет тип TanStack.

### 2. Одна реализация

Фича выделения по индексам (`indexCellSelectionFeature`) подменяет методы стоковой фичи во
всех режимах: `getIsSelected`, `getSelectionEdges`, `getIsFocused`, обработчики мыши,
`setFocusedCell`, `selectCellRange`, `extendCellSelection`, `moveCellSelection`,
`selectAllCells`, `getFocusedCell`, `getSelectedCellRangesData`, `getSelectedCellCount`.
Стоковая фича остаётся в наборе: её срез, опции и сброс при смене `data`. На тех же действиях
итог прежний.

### 3. Клиент: выделение едет с углами

Смена сортировки или фильтра на клиенте пересчитывает индексы по `id` углов: прямоугольник
стоит между теми же строками на их новых местах. Угол скрыт фильтром — диапазон не показан и
остаётся в срезе; снятие фильтра его возвращает. Перевод — по одной карте «`id` → место» на
порядок строк. В серверной модели новая выборка сбрасывает выделение, как прежде (ADR 0146,
§6).

### 4. Диапазон от приложения

Приложение задаёт диапазон индексами в любом режиме или `id` на клиенте. Диапазон только с
`id` в серверной модели применяется, если строки загружены; иначе не применяется — одно
dev-предупреждение.

### 5. Чтение без режима

`table.getCellSelectionRanges()` — диапазоны одной формой во всех режимах: границы строк
индексами (`minRowIndex`, `maxRowIndex`), `id` углов, где известны, колонки по `id` в
порядке отображения, операция. Для панелей и массовых действий приложения.

### 6. Цель `range` подсветки

Цель `range` подсветки и вспышки — той же формы, что диапазон выделения: углы строк
`anchorRowIndex`/`focusRowIndex` или `anchorRowId`/`focusRowId`, колонки
`anchorColumnId`/`focusColumnId`. Прежняя форма `rows: [from, to]` / `{ indexes }` и
`columns` удаляется.

## Границы

- Вставка из буфера — вне объёма (ADR 0029).
- Закреплённые строки в выделении серверной модели — по ADR 0146, «Границы».
- Порядок колонок в диапазоне — по-прежнему `id` колонок: колонки гриду известны всегда.

## Отвергнутые альтернативы

- **Обе формы со стоковой фичей на клиенте.** Без ломки, но две реализации геометрии
  остаются, и форма среза зависит от режима.
- **Индексы без `id` углов.** На клиенте выделение не поедет со строками при сортировке —
  решение автора: едет, как сейчас.
- **Сброс выделения при сортировке на клиенте**, как в серверной модели. Проще, но меняет
  привычное поведение клиента.
- **Оставить формы как есть.** Приложение по-прежнему ветвится по режиму.

## Последствия

- **Ломающие изменения:** главная часть диапазона в срезе — индексы, на клиенте их пишет и
  ждёт грид; `anchorRowId`/`focusRowId` на клиенте остаются. Форма цели `range` подсветки
  меняется. На клиенте стоковая геометрия TanStack не используется — паритет доказывает UR2.
- **+** Одна реализация геометрии выделения вместо двух; один код приложения для всех режимов.
- **−** На каждую смену порядка строк клиента — карта «`id` → место» (UR8).
- Тесты цели `range` (ADR 0152, TG1, TG8, TG12) и истории подсветки переходят на новую форму.

## Внедрение

1. **Этап 1.** UR1–UR8, S1–S2: одна реализация по индексам, пересчёт по `id` углов на
   клиенте, `getCellSelectionRanges`, новая форма цели `range`. Внедрён 2026-11-03:
   - Путь по индексам (`indexCellSelectionFeature`) подменяет методы стоковой фичи всегда.
     На клиенте место угла — по его `id` (`resolve`), запись грида дописывает `id` углов
     (`withIds`), смена порядка строк пересчитывает индексы в срезе (`followClientOrder`).
   - Клиентский источник ищет место строки по карте «`id` → место» на список
     (`createClientRowSource`): после сортировки — без прохода по строкам.
   - Цель `range` хранится в срезе подсветки прежним ключом (`RangeSpan`): заданы оба `id`
     углов — по ним, иначе по индексам.
   - UR8 — 20 % вместо 10 % по решению автора 2026-11-06: по X выделение стоит 16–20 %, в коде
     горячего места нет, цена — в стилях выделенных ячеек.
   - XC1 ADR 0146 — с `id` загруженных углов в срезе и диапазоном по `id` загруженных строк.
   - S1 — в разделе выделения серверной модели: режим данных — договор на время жизни
     таблицы, и гайд не переключает его шагом; ту же форму на клиенте доказывает UR6.
