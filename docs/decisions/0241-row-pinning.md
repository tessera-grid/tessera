## Контекст

Человек, который разбирает данные, хочет сравнивать строки: держать одну-две строки на виду и
прокручивать к другим. Сейчас для этого приложение строит свою панель над гридом. Запрос частый:
MUI #10057, идея TanStack «Row Pinning с серверной пагинацией» (исследование
`docs/research/user-needs-2026-11-13.md`), пункт «Закрепление строк» в roadmap.

В Tessera свой движок строк ([ADR 0200](0200-own-row-engine.md)): стоковой
`rowPinningFeature` TanStack в нём нет, просто включить её нельзя. У грида уже есть две «липкие»
механики — строки групп под шапкой (ADR 0160) и футер у низа области (ADR 0118); закреплённые
строки должны встать с ними в один порядок, а не спорить за край.

### Как это сделано у других (по документации, проверено 2026-11-28)

- **TanStack Table** — `rowPinningFeature`: модель делится на `getTopRows()`, `getCenterRows()`,
  `getBottomRows()`; закреплённая строка уходит из центра. `keepPinnedRows` (по умолчанию `true`)
  держит закреплённые на виду при фильтре и пагинации, `false` — показывает, только пока строка в
  отфильтрованной странице; один флаг на оба случая. `row.pin(position, includeLeafRows?,
includeParentRows?)`. Документация прямо говорит: состояние закрепления ничего не ставит на экран,
  `position: sticky` — забота приложения.
- **AG Grid** — ручное закрепление: `enableRowPinning: true | 'top' | 'bottom'`, подменю «Pin Rows»
  в контекстном меню, `isRowPinnable(row)`, начальное `isRowPinned(row)`, событие
  `pinnedRowsChanged`. Закреплённая вручную строка остаётся и в теле (выгрузка предлагает
  `skipPinnedRowDuplicates`). Сортировка и фильтр применяются к закреплённым. Закрепить можно и
  строку общего итога.
- **MUI X Pro** — отдельный проп `pinnedRows`, строки из `rows` убирает приложение; кнопки — свои у
  приложения в колонке `actions`. Сортировка, фильтр и пагинация закреплённые не трогают.
  Не поддерживаются вместе: выбор, группировка, дерево, перестановка, master-detail.
- **Material React Table** — режимы `rowPinningDisplayMode`: `sticky` (по умолчанию), `top`,
  `bottom`, `top-and-bottom`, `select-*`. Документация: «Sticky Row Pinning is not currently
  compatible with row virtualization».

Предела числа закреплённых, асинхронного закрепления с ожиданием и отказом и закрепления в
группах и дереве нет ни у кого.

## Решение

### 1. Закрепление — вид, а не данные

Закреплённая строка уходит из прокручиваемого списка в область у края: верхнюю — между шапкой и
списком, нижнюю — между списком и футером. Дублей нет: строка видна в одном месте. Режима
«липкой» строки нет: строки виртуализированы всегда, а копия, появляющаяся по уходу строки из
окна, превращает закрепление в плавающий элемент.

Закрепление не меняет данные: итоги колонок, число строк группы и её агрегаты, «выбрать всё»,
счётчики «Показано N из M» и выгрузка считают закреплённую строку на её месте в данных, как без
плагина. Выгрузка идёт в порядке данных, без отдельного раздела закреплённых.

### 2. Плагины и срез

`rowPinningModel` — модель: срез `rowPinning` формы TanStack `{ top: string[]; bottom: string[] }`
(id строк в порядке закрепления), аргументы `rowPinning`, `initialRowPinning`,
`onRowPinningChange` (ADR 0120), стадия движка, области, `table.pinRow(id, position)`,
`row.getIsPinned()` (`'top' | 'bottom' | false`). Без интерфейса модель показывает срез, заданный
приложением или из кода.

`rowPinning` — интерфейс: пункты меню (§4), перестановка в области (§7), подписи. Аргументы:

| Аргумент        | Значение                                                                                           |
| --------------- | -------------------------------------------------------------------------------------------------- |
| `enabled`       | `false` — пунктов нет, модель и её срез продолжают действовать                                     |
| `maxPinnedRows` | предел закреплённых строк в обеих областях вместе, по умолчанию 5                                  |
| `sides`         | `['top', 'bottom']` по умолчанию; `['top']` или `['bottom']` — только один край                    |
| `visibility`    | `'hide'` (по умолчанию) или `'keep'` — §3                                                          |
| `canPinRow`     | `(row) => boolean \| string \| Promise<…>`: `false` или причина — пункты выключены с этой причиной |
| `onRowPin`      | бизнес-колбэк `({ rowId, position, index, previous, signal })`, может вернуть промис — §5          |

Аргументы `visibility` и `maxPinnedRows` нужны и модели: интерфейс передаёт их модели, как
аргументы модели от интерфейса в ADR 0120 (MP16).

### 3. Фильтр, поиск и страница

Один режим `visibility` на фильтр, поиск и страницу:

- **`'hide'`** — закреплённая строка видна, только пока она в отфильтрованной выборке и на
  текущей странице. Скрытая не открепляется: вернётся, когда фильтр снимут или откроют её
  страницу. Так закреплённые колонки подчиняются видимости колонок.
- **`'keep'`** — закреплённая строка видна всегда, при любом фильтре и на любой странице.

В обоих режимах закреплённые строки не входят в размер страницы: страница из 20 строк показывает 20
строк списка. Внутри области строки идут по текущей сортировке; без сортировки — в порядке
закрепления. Сворачивание группы закреплённую строку не скрывает: это не фильтр.

### 4. Пункты меню

Плагин кладёт в `actionRowSlot` (ADR 0024) пункты «Закрепить сверху» и «Закрепить снизу»; у
закреплённой строки пункт её края заменяет «Открепить», пункт другого края переносит её туда. С
плагином `contextMenu` те же пункты — в контекстном меню строки. Пункты выключены с причиной в
подсказке, когда:

- достигнут предел `maxPinnedRows` («Закреплено строк: N из N»); прежние закрепления сами не
  вытесняются;
- у строки есть вложенные строки (§6);
- `canPinRow` ответил `false` или причиной; промис — ожидание доступности по ADR 0078.

### 5. Асинхронное закрепление

`onRowPin` вызывается на закрепление, открепление, перенос на другой край и перестановку в
области. Без промиса срез меняется сразу. С промисом срез меняется сразу, строка в ожидании
(ADR 0177): волна на строке, пункт меню занят; ответ — вспышка `accepted` (ADR 0134); отказ —
откат среза, вспышка `danger` на строке на её прежнем месте, запись в журнале отказов и
объявление. Новое действие над той же строкой отменяет прежнее (`signal`).

### 6. Группы и дерево

Закрепить можно только строку без вложенных строк: обычную строку и лист группы или дерева. У
строки-группы, родителя дерева и строки с `hasChildren` (ленивые дети, ADR 0054) пункты выключены
с причиной «У строки есть вложенные строки»: ушедший из списка родитель унёс бы доступ к своим
детям, а дети в области ломают предел. Строка, у которой появились дети (смена `data`,
транзакция), открепляется с объявлением.

Закреплённый лист в области — без отступа, линий дерева и предков; путь к нему (значения групп или
подписи предков) — в подсказке строки.

### 7. Перестановка в области

С плагином `rowDragging` закреплённые строки переставляются перетаскиванием внутри своей области:
меняется порядок закрепления, а не данных; итог уходит в `onRowPin` с новым `index`. При активной
сортировке перестановка в области выключена с причиной, как перестановка строк при сортировке.
Перетаскивания между областью и списком и между областями нет: для этого есть пункты меню.

### 8. Отрисовка

Ядро получает обёртку `bodyEdges`: плагин отдаёт строки верхнего и нижнего края, ядро рисует их
`BodyRow` в двух блоках `position: sticky` внутри области прокрутки, в окне колонок. Поэтому
закреплённые колонки, виртуализация колонок, ширины, горизонтальная прокрутка, перенос текста и
высота по содержимому работают в областях как в списке.

Порядок у краёв: шапка → верхняя область → липкие строки групп (ADR 0160) → список → нижняя
область → футер `pinned` (ADR 0118). Область не выше трети высоты области прокрутки; больше —
прокручивается внутри себя. Строки областей не виртуализируются: их немного по пределу, при
`maxPinnedRows` больше 20 — предупреждение разработчику. Граница области и списка — линия токена
`--tsr-comp-pinned-row-divider`; тон строк — как у строк списка.

Закрепление и открепление переносят строку движением (ADR 0107) на токенах движения; уменьшенное
движение — без движения.

### 9. Клавиатура и доступность

Строки областей — в порядке клавиатуры: стрелки переходят из верхней области в список и из списка
в нижнюю, Ctrl+Home и Ctrl+End — к первой и последней показанной строке. `aria-rowindex` —
по порядку на экране, `aria-rowcount` считает каждую строку один раз. Строка области несёт
описание «Закреплена сверху» или «Закреплена снизу» из словаря. Выделение диапазона ячеек не
переходит между областью и списком.

### 10. Серверная модель

С плагином `serverRowModel` колбэк `getPinnedRows` обязателен; без него плагины инертны с
причиной `serverRowModel` (как SD26), пункты меню не появляются, разработчик получает
предупреждение.

```ts
getPinnedRows: ({ ids, request, visibility, signal }) =>
  Promise<{ rows: TData[]; filteredOut?: string[] }>
```

`request` — текущая выборка (сортировка, фильтр, поиск, группировка). Серверная модель зовёт
колбэк при восстановлении среза по id, на каждую новую выборку и на `refreshRows`. Ответ:

- строка в `rows` — новые значения;
- id в `filteredOut` — строка есть, но не проходит выборку: в режиме `'hide'` скрыта и остаётся
  закреплённой; в режиме `'keep'` сервер присылает строку в `rows`;
- id нет ни там, ни там — строки больше нет: открепляется с объявлением и причиной `removed` в
  канале действий.

Данные закреплённых строк плагин держит отдельно от кэша блоков: сворачивание группы, вытеснение
блока и новая выборка их не трогают. Между вызовами строку обновляют `setRowData`, транзакции
(ADR 0157), сохранённая строка правки (ADR 0139) и та же строка в любом пришедшем блоке. До ответа
строка области — скелет; отказ — строка ошибки с повтором (как SD11), прежние значения не
показываются как текущие. На клиенте строка, ушедшая из `data`, открепляется так же.

С серверной пагинацией в режиме `'hide'` строка видна, пока она среди загруженных строк текущей
страницы.

## Границы

- Закрепление групп, родителей дерева и строк вместе с предками или детьми — нет (§6).
- Дубль строки в списке и «липкий» режим — нет (§1).
- Перетаскивание между областью и списком и между областями — нет (§7).
- Выделение диапазона через границу области — нет (§9).
- Отдельные режимы для фильтра и для страницы — нет: один `visibility` (§3).
- Закрепление в истории отмены (ADR 0222) — нет: это вид, а не правка данных.
- Строки общего итога в областях, как в AG Grid, — нет: итоги — футер (ADR 0118).
- Выгрузка с разделом закреплённых — нет (§1).

## Отвергнутые альтернативы

- **Копия строки в области, оригинал в списке (AG Grid).** Строка видна дважды, считается дважды в
  глазах человека; закрепление колонок так не работает.
- **«Липкая» строка — копия, только пока оригинал вне окна (`sticky` у Material React Table).**
  Закрепление теряет смысл: строка — плавающий элемент; у MRT режим несовместим с виртуализацией.
- **Области вне области прокрутки — отдельные панели.** Горизонтальную прокрутку и закреплённые
  колонки пришлось бы синхронизировать между тремя областями вручную — дрожание и дубль раскладки
  шапки.
- **Стоковая `rowPinningFeature`.** Движок строк свой (ADR 0200); стадия плагина даёт то же и не
  тянет опор TanStack.
- **Один флаг `keepPinnedRows`, как у TanStack.** Это и есть `visibility`; строковое значение
  читается яснее и оставляет место для режима.
- **Закреплённая строка без проверки сервером.** Устаревшая копия жила бы до ручного открепления.
- **Вытеснять старейшее закрепление при пределе.** Строка пропала бы без действия человека.

## Последствия

- Ядро: обёртка `bodyEdges` и факт «строки краёв» — рост `DataGrid` без плагинов в пределе 1 %
  (LB4).
- Движок: стадия `pinned`; паритет без закреплений — модель та же, что без плагина.
- Новый обязательный колбэк сервера при закреплении в серверной модели.
- Новые строки реестров касаний и клавиатуры (ADR 0231, ADR 0232) и базы паритета моделей
  (ADR 0187).

## План внедрения

1. Ядро: обёртка `bodyEdges`, факт «строки краёв» для клавиатуры, `aria-*` и липких строк групп.
   Модель: срез, стадия `pinned`, области, режимы, открепление ушедших строк (RPN1–RPN7,
   RPN11–RPN15, RPN22, RPN24–RPN25, RPN36).
2. Интерфейс: пункты меню, предел, `canPinRow`, `onRowPin` с ожиданием и отказом, движение,
   словарь и действия, a11y и перф (RPN8–RPN10, RPN16–RPN19, RPN32–RPN35).
3. Группы, дерево и перестановка в области (RPN20–RPN21, RPN23).
4. Серверная модель: `getPinnedRows`, данные вне кэша, обновления (RPN26–RPN31).
5. Истории S1–S14 с гайдами и близнецами высокой контрастности; строки реестров касаний,
   клавиатуры, исходов и паритета моделей.
