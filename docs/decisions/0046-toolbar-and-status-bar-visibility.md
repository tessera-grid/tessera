# 0046 — Включение тулбара и нижней панели: по слотам, флаг — явное переопределение

- **Статус:** Принято (реализовано 2026-10-03; решения — по итогам прожарки 2026-10-03)
- **Дата:** 2026-10-03
- **Изменён:** 2026-10-25 — PB12 доказывает гайд «Panels/Pagination — Own pager» (S2 [ADR 0120](0120-model-and-interface-plugins.md)): история «Panels/Status bar — Off (own pager)» удалена как дубль.
- **Связано:**
  - [ADR 0035](0035-toolbar-and-column-visibility.md) — тулбар, `toolbarSlot`, флаг
    `enableToolbar`; здесь меняется условие показа (TB3–TB4) и условие инертности
    `columnVisibility` (CV19).
  - [ADR 0038](0038-pagination-and-status-bar.md) — нижняя панель и `statusBarSlot`;
    здесь к правилу «по наличию слота» (SB1) добавляется флаг `enableStatusBar`.
  - [ADR 0044](0044-export.md), [ADR 0045](0045-filtering.md) — `dataExport` и
    `quickSearch` перестают быть инертными без флага (EX2, FL15, FL18).
  - [ADR 0010](0010-invert-core-plugins-registry.md) — presence-based композиция:
    плагин приносит свой UI.
  - [ADR 0036](0036-plugin-contract-diagnostics-and-a11y.md) — `diagnose` и причины
    инертности.
  - [ADR 0009](0009-test-coverage-visual-and-performance.md),
    [ADR 0043](0043-honest-test-coverage.md) — покрытие тестами.

## Контекст

У грида две панели вне скролл-контейнера: тулбар сверху (контролы) и нижняя панель
(сведения о данных и позиция в них). Включались они по-разному:

- **Тулбар** — только ядровым флагом `enableToolbar` (ADR 0035). Плагины, чья кнопка
  живёт в тулбаре (`columnVisibility`, `dataExport`, `quickSearch`), без флага
  инертны с причиной `'noToolbar'`.
- **Нижняя панель** — по наличию активного `statusBarSlot`, флага нет (ADR 0038).
  `pagination` и счётчики сами вызывают панель.

Для потребителя это читается как «одни плагины приносят свою панель, другие требуют
флаг»: `pagination` работает сразу, `dataExport` без `enableToolbar` молча
бездействует. Причина асимметрии — в доводах ADR 0035, которые сегодня не держатся:

1. **«Раскладка не прыгает при подключении плагинов».** ADR 0038 закрыл этот довод для
   нижней панели иначе: слот присутствует, пока плагин активен, даже если показывать
   нечего. Тот же приём годится тулбару.
2. **Левая часть тулбара под контент потребителя.** API для неё нет; пустой тулбар
   сегодня ничему не служит, а явный `enableToolbar: true` его сохраняет.
3. **Ленивый чанк тулбара.** Грузить его можно по наличию слота так же, как по флагу.
4. **`columnVisibility` без тулбара: скрыл — не вернёшь.** Если плагин сам вызывает
   тулбар, проблема возникает только при явном запрете тулбара.

## Решение

### 1. Панель — по наличию слотов; флаг — явное переопределение (PB1–PB6)

Оба ядровых флага `useCreateTable` — `boolean | undefined`:

| Значение             | Тулбар (`enableToolbar`)               | Нижняя панель (`enableStatusBar`)        |
| -------------------- | -------------------------------------- | ---------------------------------------- |
| не задан (умолчание) | есть, если есть активный `toolbarSlot` | есть, если есть активный `statusBarSlot` |
| `true`               | есть всегда, в том числе без слотов    | есть всегда, в том числе без слотов      |
| `false`              | нет никогда                            | нет никогда                              |

Правило одно на обе панели: `flag ?? slotCount > 0`. Слот присутствует, пока плагин
активен (`enabled !== false`), даже когда его компонент ничего не показывает, —
поэтому панель не появляется и не пропадает от смены данных, поиска или выбора, а
переключение `enabled` на лету её показывает или убирает. Чанк тулбара по-прежнему
грузится лениво — только когда тулбар показывается.

Имя `enableStatusBar` совпадает со слотом `statusBarSlot` и токенами
`--tsr-comp-status-bar-*`.

### 2. Панель запрещена — скрыт встроенный UI, API работает (PB7–PB11)

При `false` плагин теряет свой контрол на этой панели, но не перестаёт работать:

- **`dataExport`** — кнопки нет, `table.exportData()` выгружает как раньше; `diagnose`
  не называет `'noToolbar'` (остаётся `'noOnExport'` серверного режима, EX29).
- **`quickSearch`** — поля нет, программная смена `globalFilter` фильтрует строки;
  `diagnose` активен (кроме `'noOnSearchChange'`, FL31).
- **`pagination`** — переключателя нет, строки по-прежнему делятся на страницы,
  `setPageIndex` / `setPageSize` работают: приложение рисует свой пейджер.
- **Счётчики** (`rowSelection` `selectedCount`, `filteredCount` фильтрации) — не
  рисуются, плагины активны.
- **`columnVisibility`** — единственное исключение: при `enableToolbar: false` он
  инертен (`'noToolbar'`, dev-warn ядра при монтировании), «Скрыть колонку» в кебабе
  нет. Иначе колонку можно скрыть, но вернуть нечем.

Причина `'noToolbar'` теперь означает «тулбар явно запрещён», а не «флаг не задан».

### 3. Что меняется в принятых ADR

- **ADR 0035:** TB3 — тулбар размечен и стоит над таблицей; когда он есть, решают
  PB1–PB2. TB4 — пустой тулбар (`enableToolbar: true`) той же высоты. CV19 → PB7.
- **ADR 0038:** SB1 — правило по умолчанию; `enableStatusBar` — PB3.
- **ADR 0044:** EX2 → PB8.
- **ADR 0045:** FL15 — только поле поиска с очисткой; инертность без тулбара снята
  (PB9). FL18 — фильтры колонок работают при `enableToolbar: false`.

## Границы

- **Контент потребителя в левой части тулбара** — по-прежнему вне объёма; `true`
  оставляет под него место.
- **Готовый внешний пейджер** — не входит: при `enableStatusBar: false` приложение
  собирает его на API пагинации.
- **`enableFooter`** (футер колонок внутри таблицы) не меняется: это часть таблицы, а
  не панель вне скролла.

## Последствия

- **+** Одно правило на обе панели: плагин приносит свой UI, флаг нужен только чтобы
  оставить пустую панель или запретить её.
- **+** `dataExport`, `quickSearch` и `columnVisibility` работают без дополнительной
  настройки; `pagination` можно встроить в свой пейджер.
- **−** Ломающее изменение (до 1.0): грид с `columnVisibility`, `dataExport`,
  `quickSearch` или `columnFiltering` без `enableToolbar` раньше обходился без тулбара,
  теперь тулбар появится. Вернуть прежний вид — `enableToolbar: false` (у
  `columnVisibility` это делает его инертным, как раньше).
- **−** `diagnose` трёх плагинов меняет ответ: без флага они активны; `'noToolbar'`
  возникает только при явном `false`.
- **−** Новый флаг `enableStatusBar` в публичном API.

## План внедрения

- **Ядро.** `resolvePanelVisible(flag, slots)` в `core/panels.ts`; `DataGrid` решает
  показ обеих панелей им; флаг `enableStatusBar` в `useCreateTable`,
  `CreateDataGridOptions` и аугментации опций.
- **Плагины.** `diagnose` `columnVisibility` — `'noToolbar'` только при `false`;
  `dataExport` и `quickSearch` — без условия тулбара.
- **Тесты.** `visual/panels` (PB1–PB5, PB10–PB11), `visual/toolbar-chunk` (PB6 —
  отдельный файл: модуль грузится один раз на документ), модульные PB7–PB9 в
  `columnVisibility`, `export`, `filtering`. Переписаны TB3, TB4, SB1, FL15, FL18.
- **Истории.** `enableToolbar` / `enableStatusBar` — тройной выбор «auto / on / off»;
  группа Panels: «Panels/Presence — Playground» и «Panels/Status bar — Off (own
  pager)» (дымовой `visual/panels-stories`, PB12); явные `enableToolbar: true`
  в историях, где тулбар и так вызывают плагины, убраны.
