# 0217 — Автоподбор ширины колонки по содержимому

- **Статус:** Принято (прожарка 2026-11-12)
- **Дата:** 2026-11-12
- **Слой:** плагин `columnSizing` — двойной клик по грипу, пункты меню ручки и кебаба, API
  `table.autosizeColumns`, опция `autosizeOnData` и замер содержимого (`measureColumns`: ячейки в
  области прокрутки грида, которую ядро отдаёт через `viewportOf`); ядро — набор измеряемых колонок
  (`core/autosize.ts`), его читает экстрактор окна колонок: колонки вне окна на время замера
  отрисовываются. Не в гриде: без плагина замер не нужен, а вес `DataGrid` без плагинов не растёт.
- **Изменяет:** [ADR 0111](0111-resize-grip-on-column-border.md), «Границы» — двойной клик по грипу
  подгоняет ширину по содержимому.
- **Связано:**
  - [ADR 0013](0013-column-sizing.md) — срез `columnSizing`, `onColumnResizeEnd`, сброс ширины.
  - [ADR 0216](0216-flex-columns.md) — подгонка флекс-колонки ставит ей нижнюю границу по содержимому.
  - [ADR 0034](0034-wcag-22-dragging-and-target-size.md) — меню ручки грипа вместо перетаскивания.
  - [ADR 0125](0125-debug-actions.md) — канал действий.
  - [ADR 0024](0024-slot-action-descriptor-and-menu.md) — пункты кебаба заголовка.

## Контекст

Ширину по содержимому приходится подбирать протяжкой. AG Grid (двойной клик по грипу, «Autosize
This Column» / «Autosize All Columns», `autoSizeStrategy: fitCellContents`) и MUI (двойной клик,
`autosizeColumns`, `autosizeOnMount`) подбирают её сами — по отрисованным строкам и шапке.

## Решение

### 1. Что измеряется

Ширина колонки — наибольшая из ширины заголовка (подпись и кнопки шапки) и ширин ячеек строк в
окне виртуализации: подпись ячейки целиком, без многоточия, плюс поля, отступ дерева и кнопки
ячейки. Строки вне окна не меряются: полного обхода данных нет ни у AG Grid, ни у MUI, а у
серверной модели строк вне окна нет. Итог — в пределах `minSize`/`maxSize`.

Колонки вне окна виртуализации колонок («Подогнать все» на 1000 колонок) на время замера
отрисовываются вне видимой части на строках окна пачками по 20 колонок на кадр и сразу уходят:
пачка — одна задача главного потока, а не тысяча колонок разом. Подпись меряется одним диапазоном
на весь замер — тысячи живых диапазонов браузер правил бы при каждом удалении узла.

### 2. Чем запускается

- **Двойной клик по грипу** — колонка. Первый клик открывает меню ручки (ADR 0034); двойной его
  закрывает и подгоняет.
- **Меню ручки грипа** и **кебаб заголовка** — пункты «Подогнать ширину» и «Подогнать все колонки».
- **API** `table.autosizeColumns(columnIds?)` — промис, `true` — подогнано; без аргумента — все
  колонки данных. Автор зовёт его, когда сам обновил содержимое.
- **Опция** `columnSizing({ autosizeOnData: true })` — подгонка на приходе данных и на каждой новой
  ссылке `data`; колонки, протянутые или подогнанные пользователем, она не трогает. У серверной
  модели `data` не меняется — пересчёт по API.

### 3. Результат

Ширина нефлекс-колонки — как протяжка: в пользовательский срез `columnSizing`,
`onColumnResizeEnd({ id, width })` по каждой такой колонке, сброс ширины возвращает `size`. Флекс-колонка
остаётся флекс (решение автора 2026-11-12): ширина содержимого — её нижняя граница, свободную ширину
она делит по весу, таблица остаётся на всю ширину (ADR 0216, §3); `onColumnResizeEnd` у неё не
зовётся — её ширина не пользовательская; сброс ширины снимает границу. Флекс-колонка, уже протянутая
пользователем, подгоняется как нефлекс. Действие `autosize` в канале действий — одно на подгонку, с
источником. Служебные колонки не подгоняются. Подгонка по опции `autosizeOnData` пишет ширины в тот же срез, но `onColumnResizeEnd` не
зовёт и действие сообщает с источником `auto`; плагин помнит поставленные им ширины, и следующая
подгонка по данным берёт колонку, только если её ширина с тех пор не менялась.

## Границы

- Строки вне окна виртуализации не меряются.
- Своя функция замера у колонки — нет (этап 2 по запросу).
- Клавиша на разделителе для подгонки — нет: с клавиатуры — пункт меню ручки и кебаба.

## Отвергнутые альтернативы

- **Подгонка снимает флекс (AG Grid).** Растянутая таблица после «Подогнать все» переставала бы
  заполнять ширину.
- **По содержимому, остаток — всем поровну (`expand` у MUI).** Перекраивала бы раскладку, которую задал
  разработчик: фиксированные колонки тоже растягивались бы.

- **Замер по данным без отрисовки (canvas и формат значения).** Не видит своих ячеек
  (`cell`, кнопки, отступ дерева) и шрифта темы.
- **Двойной клик без меню ручки.** Меню ручки — замена перетаскиванию (ADR 0034), убрать его нельзя.
- **Подгонять только видимые колонки при «Подогнать все».** Колонки за краем остались бы прежними,
  хотя пользователь просил все.

## Последствия

- **+** Ширина по содержимому одним действием; автор пересчитывает её сам через API или опцию.
- **−** Подгонка «всех» на 1000 колонок отрисовывает их на строках окна: на ×4 троттлинге — около
  50 задач по ~250 мс, всего ~13 с (AZ10). Страница отвечает между пачками.
- **±** Двойной клик по грипу на мгновение открывает меню ручки.
