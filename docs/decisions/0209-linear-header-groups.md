# 0209 — Линейная сборка групп шапки

- **Статус:** Принято (решение автора 2026-11-11)
- **Дата:** 2026-11-11
- **Слой:** ядро — сборка групп шапки (`core/headerGroups.ts`), подключённая фичей
  `commonFeature`. Не плагин: группы шапки нужны любой таблице, их читают шапка, футер, навигация и
  спаны.
- **Связано:**
  - [ADR 0004](0004-core-on-tanstack-table.md) — ядро на TanStack Table: компоновать, не форкать.
  - [ADR 0200](0200-own-row-engine.md) — свой движок строк поверх публичных точек TanStack с
    паритетом против стоковых моделей; здесь тот же приём для групп шапки.
  - [ADR 0207](0207-one-head-layout.md) — одна раскладка шапки.
  - Замер `docs/research/tessera-vs-ag-grid-2026-11-09.md`.

## Контекст

Профиль монтирования 1000 × 1000 на стенде против AG Grid (2026-11-10, ×4 CPU): сборка групп шапки
TanStack — ~14–20 мс, из них ~7 мс — собственное время `countPendingHeadersForColumn`. Разбор
исходников TanStack 9.3.1 (`core/headers/buildHeaderGroups.js`):

- `constructHeaderGroup` на каждом уровне строит заголовки уровня выше. На нижней ступени (уровень 0)
  он строит их тоже — для плоской шапки из N колонок это N заглушек — и выбрасывает: рекурсия на
  уровне 0 останавливается;
- номер заглушки (`placeholderId`) считает `countPendingHeadersForColumn` перебором всех уже созданных
  заголовков уровня — квадратично: на 1000 колонок ~500 000 сравнений ради поля выброшенных
  заглушек.

`getHeaderGroups` мемоизирован, поэтому цена — раз на смену структуры колонок: монтирование, порядок,
видимость, закрепление, группировка, смена `columns`. На десятках колонок её не видно; на тысяче —
5–10 % монтирования.

## Решение

### 1. Своя сборка

`buildHeaderGroupsLinear` (`core/headerGroups.ts`) повторяет `buildHeaderGroups` TanStack с двумя
отличиями: номер заглушки — из счётчика по колонке (`Map`), а не перебором; заголовки уровня выше на
нижней ступени не строятся. Заголовки создаёт экспортированный `constructHeader` TanStack: прототип,
поля и `initHeaderInstanceData` фич — стоковые. Порядок листьев — как у `table_getHeaderGroups`:
видимые листья в порядке закрепления (`_orderByColumnPinning`).

### 2. Подключение — фичей, без форка

`commonFeature` в `constructTableAPIs` назначает своё тело `table_getHeaderGroups` через публичную
`assignTableAPIs` — тем же механизмом, каким его назначает `coreHeadersFeature`; фичи Tessera идут
после стоковых, поэтому назначение Tessera — последнее. Зависимости мемо — те же, что у TanStack.
Пакет TanStack не меняется; снять назначение — вернуть стоковую сборку.

### 3. Обновления TanStack

Два стража падают, когда TanStack меняет сборку:

- **паритет** (HG1–HG2): группы шапки Tessera совпадают с экспортированным `buildHeaderGroups` на
  плоской и вложенной шапке, с закреплением групп и листьев, скрытыми колонками и после смены каждого
  среза;
- **зависимости мемо** (HG3): список зависимостей `table_getHeaderGroups` в `coreHeadersFeature`
  TanStack совпадает со списком Tessera.

Упал страж при обновлении — сборку сверяют с новой версией TanStack и правят здесь же. Если TanStack
исправит квадратичный подсчёт у себя, своя сборка удаляется вместе со стражами.

## Отвергнутые альтернативы

- **Патч TanStack** (`patch-package`, вендор) — против ADR 0004: TanStack Table — зависимость, а
  не вендоренный код.
- **Только issue в TanStack** — выигрыш пришёл бы с их релизом; issue можно открыть и теперь, решение
  от него не зависит.
- **Своя модель шапки целиком** — без нужды: стоковые заголовки и их API подходят, дорог только
  порядок сборки.

## Последствия

- **+** Сборка групп шапки линейна и не строит выброшенных заголовков: на плоской шапке — N
  заголовков вместо 2N.
- **−** Своя копия ~80 строк логики TanStack с опорой на внутренние `_orderByColumnPinning` и
  `_headerGroupInstanceInitFns`; расхождение с новой версией ловят стражи HG1–HG3.
- **Публичный API** не меняется.

## План внедрения

Один этап: §1–§3, HG1–HG4; HG5 — `perf:compare` по команде автора.

## Внедрение

2026-11-11. HG1–HG4 — красные мутацией (ширина листа, уровень над нижней ступенью). Мутация номера
заглушки (`placeholderId` всегда `'0'`) эквивалентна: при сборке TanStack две заглушки одной колонки
на одном уровне не встречаются. HG5 — `perf:compare` против `a92bdd52` вместе с ADR 0208 (см. его
«Внедрение»): монтирование 1000 × 1000 P3 — 0,854, P6 — 0,910, регрессий нет; доли двух ADR замер
не разделяет.
