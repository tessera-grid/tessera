## Контекст

Потребителю нужно группировать строки по значению колонки: свести плоский набор
к строкам-группам (одна на различное значение) с агрегатами (сумма, счётчик), и
переключать группировку прямо из шапки колонки. Афорданс должен быть виден в
шапке groupable-колонки, отражать текущее состояние (сгруппировано / нет) и не
загромождать шапку в покое.

TanStack Table v9 несёт готовую модель группировки: срез `grouping`, встроенные
`columnGroupingFeature`/`rowAggregationFeature` + `createGroupedRowModel()`, методы колонки (`toggleGrouping`, `getIsGrouped`,
`getCanGroup`), строки (`getIsGrouped`), агрегацию (`aggregationFn`,
`aggregatedCell`) и опцию `groupedColumnMode`. Но она про **состояние
группировки и модель сгруппированных строк**, а не про рендер: саму
кнопку-переключатель в шапке, её видимость и активное состояние надо построить
поверх.

Этот ADR — единый источник истины по группировке строк в Tessera. Он фиксирует и
**решение** (что группировку строим на штатной модели TanStack, а не на своей), и
**как** оно реализовано плагином `rowGrouping`: слот-кнопку в шапке, опору на
`toggleGrouping` / `getIsGrouped` / `getCanGroup`, режим `groupedColumnMode:
false` и контракт DOM, — плюс таблицу требований (RG1–RG11) со ссылками на тесты.

## Решение

### Опора на штатную модель TanStack

Группировка опирается на встроенную модель TanStack Table
([ADR 0004](0004-core-on-tanstack-table.md)). Плагин не хранит собственного
состояния группировки — он читает `column.getIsGrouped()` / `getCanGroup()` и
делегирует переключение `column.toggleGrouping()`. Группировка возвращается в
дерево через штатный срез `grouping`, сгруппированные строки даёт
`getGroupedRowModel()`, агрегаты — `aggregationFn` колонок (`sum`, `count`). Значение агрегата
в строке группы рисует `cell` колонки: `aggregatedCell` TanStack грид не рисует ни в одной
модели ([ADR 0144](0144-server-side-grouping.md), §2).

Опции таблицы (`core/useCreateTable.ts`):

- **`enableGrouping`** — включает группировку (по умолчанию `false`); участвует в
  `getCanGroup()` колонки.
- **`groupedColumnMode: false`** — сгруппированная колонка **остаётся на своём
  месте**, а не выносится в начало и не прячется; лесенка групп идёт по
  раскрытию строк ([ADR 0015](0015-row-expanding.md)), а не по перестановке
  колонок.

### Форма плагина

`rowGrouping` (`src/lib/plugins/rowGrouping/registry.ts`) — фабрика записи
`TesseraFeatureEntry`. Поведение дают встроенные `columnGroupingFeature` +
`rowAggregationFeature` + слот-модель `createGroupedRowModel()`. В отличие от
пиннинга / сортировки / выбора / раскрытия, плагин **не инъектирует служебный
столбец** — афорданс группировки объявляется **дескриптором** `slotActions`
(`groupHeaderAction`, [ADR 0024](0024-slot-action-descriptor-and-menu.md)) в
`rightHeaderSlot` (`order: 2`):

```ts
slotActions: [groupHeaderAction] // ядро подаёт инлайн-кнопкой или строкой кебаб-меню
```

Дескриптор виден только на группируемой колонке (`visible: ({ column }) =>
column.getCanGroup()`; на служебной, при `enableGrouping: false` или выключенной
группировке `getCanGroup()` = `false` — кнопки нет). Инлайн ядро рендерит его
кнопкой-тумблером `GroupButton`, `onSelect` зовёт `column.toggleGrouping()`;
реактивность на срез `grouping` обеспечивает грид (`useSelector`, TanStack Store).

### Кнопка группировки

`GroupButton` (`GroupButton.tsx`) — общий `IconButton` (иконка `group` через
`useIcons` — переопределяема) в `Tooltip` (`group` / `ungroup` из локализации).
Видимость подчинена общему контракту hoverable-кнопок шапки
(`grid/cellControls/buttonVisibility.css`, общий с сортировкой/пиннингом): кнопка
скрыта (`opacity: 0`) в покое и появляется при наведении на шапку; когда колонка
сгруппирована (`data-button-active='true'`), кнопка **остаётся видимой** без
наведения.

### Контракт DOM

Состояние группировки выражено в разметке — seam, за который цепляются тесты (см.
[ADR 0009](0009-test-coverage-visual-and-performance.md) про запрет хардкода
мок-данных: состояние читается из атрибутов, а не из литералов мока):

- **`.column-group__button`** — стабильный класс кнопки группировки (на
  `GroupButton`), за который цепляются тесты и потребитель.
- **`data-button-active` на обёртке кнопки** (`.cell__button`) —
  `column.getIsGrouped()`: активна ли группировка по этой колонке (и, как
  следствие, видима ли кнопка без наведения).
- **`data-group-row` на `role="row"`** (`BodyRow.tsx`) — `row.getIsGrouped()`:
  является ли строка агрегированной строкой-группой.

Служебные (`data-actions-column-cell='true'`) колонки слотов шапки не рендерят
(`HeadCell`), поэтому кнопки группировки у них нет.

### Точки расширения

Отдельного hook у плагина нет: переключение идёт через штатный
`column.toggleGrouping()`, а состояние группировки потребитель читает/контролирует
через срез `grouping` и `onGroupingChange`
([ADR 0004](0004-core-on-tanstack-table.md)). Иконка кнопки переопределяема через
`useIcons`.

## Последствия

- **+** Группировка опирается на штатную, проверенную модель TanStack — свой
  «источник истины» по группировке, агрегации и модели сгруппированных строк не
  заводится.
- **+** Афорданс — слот шапки, а не служебный столбец: группировка не тратит
  ведущую колонку и переиспользует общий контракт видимости hoverable-кнопок.
- **+** Реактивность гранулярна: кнопка подписана на состояние группировки
  колонки через `useSelector` (TanStack Store), а не перерисовывается глобально.
- **+** `groupedColumnMode: false` сохраняет раскладку колонок при группировке —
  никакого скачка/выноса колонки.
- **−** Раскрытие групп (открыть строку-группу и увидеть её членов) обеспечивает
  плагин раскрытия ([ADR 0015](0015-row-expanding.md)); без него группы видны, но
  не раскрываются. Покрытие связки group + expand — предмет сквозного ADR
  взаимодействий, а не набора RG.
- **−** Совмещение с перетаскиванием строк (`Grouping + RowDragging`) пока не
  реализовано (см. «Известные проблемы» в [roadmap](../roadmap.md)).

## Требования и покрытие тестами

Критерии приёмки, которые кодируют тесты. По конвенции проекта
([ADR 0001](0001-spec-driven-development.md),
[ADR 0009](0009-test-coverage-visual-and-performance.md)) каждое требование —
**отдельный именованный тест** с ID-префиксом `RG<n>:`, совпадающим с ID из
таблиц ниже. Визуальные тесты живут в
`stories/__tests__/visual/row-grouping.test.tsx` (vitest-browser, реальный
Chromium) и гоняют историю `RowGrouping` (плоский детерминированный набор из
генератора, стартует без группировки). Перформанс-покрытие даёт кейс группировки
в общей перф-матрице (`stories/__tests__/performance/`, см.
[ADR 0009](0009-test-coverage-visual-and-performance.md)).
