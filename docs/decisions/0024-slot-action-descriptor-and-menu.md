# 0024 — Единый дескриптор действия слота + схлопывание в кебаб-меню (AM1–AM19)

- **Статус:** Принято
- **Дата:** 2026-09-10
- **Связано:**
  - [ADR 0010](0010-invert-core-plugins-registry.md) — presence-based композиция и
    декларативные `slots`. Действия-дескрипторы — **сестринский декларативный
    канал** (`RegistryEntry.slotActions`), свёрнутый ядром так же реактивно.
  - [ADR 0011](0011-column-pinning.md), [ADR 0012](0012-column-sorting.md),
    [ADR 0016](0016-row-grouping.md) — плагины, чьи кнопки заголовка переведены с
    опаковых слот-компонентов на дескрипторы (см. правки в этих ADR).
  - [ADR 0013](0013-column-sizing.md) — `columnSizing` **остаётся опаковым**
    (resize-грип — аффорданс) и помечен `countsAsHeaderAction: false`.
  - [ADR 0017](0017-ui-components.md) — меню строится на Base UI `Menu`.
  - [ADR 0009](0009-test-coverage-visual-and-performance.md) — три вида покрытия.

## Контекст

Кнопки в заголовках (пиннинг/сортировка/группировка) и в строках (действия строки)
исторически рендерились как **опаковые слот-компоненты**: плагин отдавал готовый
JSX (`ColumnPinningComponent` → `PinButton` и т. п.), где видимость (`getCanPin`),
состояние, `onClick` и подпись запечены внутри. Наружу — только ReactNode.

Из этого вытекали две потребности, неразрешимые «сбоку»:

1. **Схлопывание в кебаб-меню.** Когда действий в слоте много, их нужно сложить в
   одну кнопку «⋮» с раскрывающимся меню. Но меню хочет действие **как данные**
   (иконка + подпись + `onSelect` + `disabled`), а опаковая иконка-кнопка их не
   выдаёт: её нельзя ни переозаглавить строкой меню, ни посчитать.
2. **Порог «больше N кнопок».** Решение о схлопывании требует знать число
   **применимых** кнопок в слоте до отрисовки. Видимость же вычислялась рантайм-
   логикой внутри каждого компонента — снаружи её не видно.

То есть «регистрировать пункты меню с признаками» — это перевод кнопок на
**декларативный дескриптор действия**, а ядро уже решает подачу.

## Решение

Вводим **единый дескриптор `SlotAction<TCtx>`** — единственный источник правды для
кнопки слота. Плагин объявляет действия данными в `RegistryEntry.slotActions`; ядро
сворачивает их реактивно (как `slots`, маршрутизируя по `slot`) в
`table.options.slotActions` и **само решает подачу**: инлайн иконка-кнопка или
строка кебаб-меню.

- **Дженерик по контексту.** `SlotAction<TCtx, TSlot>` абстрагирует контекст:
  `HeaderAction = SlotAction<HeaderComponentProps, …>` (шапка),
  `RowAction = SlotAction<CellComponentProps, 'actionRowSlot'>` (строка). Один
  движок и рендереры (`resolveActionLayout`, `ActionButton`, `ActionMenu`,
  `ActionsZone`) обслуживают оба.
- **Порог, all-or-nothing.** Плагин-меню объявляет `actionMenu` (`{ slots, mode,
threshold }`); ядро сворачивает декларации в карту `actionMenu` **по слотам**
  (реактивно, не shallow-spread опций — иначе разные плагины-меню затирали бы чужие
  слоты, а отключение оставляло бы устаревший конфиг). `resolveActionLayout` для
  слота: применимые действия (`visible(ctx) !== false`) либо **все** инлайн, либо
  схлопнутые — **все** в кебаб. Форс `mode: 'always'` схлопывает независимо от
  счётчика.
- **Смешанное состояние.** Опаковые слот-компоненты (ещё не мигрированные плагины)
  схлопнуть нельзя — они всегда инлайн, но **учитываются в пороге** (занимают место
  в ряду). Исключение — аффордансы (`countsAsHeaderAction: false`, resize-грип): не
  считаются кнопкой.
- **Подгруппы меню.** Каждое действие — своя секция (`Menu.Group`) с разделителем;
  `menuItems` разворачивает одно действие в несколько пунктов (сортировка →
  asc/desc/сброс). Инлайн-подача и вклад в порог при этом — одно действие.
- **Реактивность и локализация.** Признаки перечитываются реактивно через
  `useSelector` (TanStack Store, `table.atoms`; [ADR 0026](0026-migrate-to-tanstack-v9.md)).
  Ядро UI-агностично: подпись
  инъектируется (`label(ctx, labels)`), иконка возвращается компонентом (доступ к
  `useIcons`/локализации — только из React-дерева).
- **Поверхности.** `headerActionMenu` (слоты шапки, порог 3 по умолчанию) и
  `rowActionMenu` (`actionRowSlot`, порог 2 — overflow-меню строки) — отдельные
  плагины на общем движке. Кебаб строки ревилится по hover строки (`row__button`) и
  остаётся видимым, пока меню открыто (состояние из Base UI `onOpenChange`, не CSS
  `:has`), и до завершения закрытия (AM26). Кебаб заголовка — по тому же правилу, что остальные кнопки заголовка
  (`cell__button`): появляется по наведению или клавиатурному фокусу и остаётся
  видимым, пока меню открыто (AM24), и до завершения закрытия — Base UI
  `onOpenChangeComplete`, после которого фокус уже на кебабе (AM25). Так же держится
  инлайн-действие, поданное мини-меню (`inlineAsMenu`, AM27). Открытие триггер
  запоминает сам: `onOpenChangeComplete(true)` Base UI приходит не всегда. Ширина служебной колонки действий
  (`rowActions`, сам плагин колонки — [ADR 0025](0025-row-actions.md)) сужается,
  когда `rowActionMenu` схлопывает `actionRowSlot` (владелец ширины — плагин
  колонки, читает лишь факт схлопывания из `actionMenu`; при live-переключении меню
  ширина следует без перезагрузки).

- **Действие с панелью** (`panel`, [ADR 0045](0045-filtering.md), FL9): содержимое
  поповера вместо обработчика — инлайн-кнопка и пункт кебаба открывают одну и ту же
  панель; из кебаба она встаёт у его кнопки, и кебаб остаётся видимым, пока панель
  открыта.

Ячейки (`left/rightCellSlot`) обобщением контракта уже покрыты, но встраивание зоны
в обычные cell-слоты отложено до появления нужды.

## Требования и покрытие тестами

По конвенции ([ADR 0001](0001-spec-driven-development.md),
[ADR 0009](0009-test-coverage-visual-and-performance.md)) каждое требование — один
именованный тест с ID-префиксом `AM<n>:`. Модульные (`__tests__/slots.test.ts`, где тестируется `resolveActionLayout`)
и визуальные (`visual/action-menu.test.tsx`); межплагинные — `X<n>` в
`cross-plugin.test.tsx` ([ADR 0023](0023-cross-plugin-interactions.md)).

| ID   | Требование                                                                                                                                                                                 | Вид    |

| AM2  | `auto`: применимых < порога → все инлайн                                                                                                                                                   | unit   |
| AM3  | `auto`: применимых ≥ порога → все схлопываемые в кебаб                                                                                                                                     | unit   |
| AM4  | Опаковые компоненты добивают счётчик до порога, но сами в кебаб не уезжают                                                                                                                 | unit   |
| AM5  | `mode: 'always'` схлопывает независимо от счётчика (при ≥1 схлопываемом)                                                                                                                   | unit   |

**Межплагинный кейс.** «Кебаб заголовка и кебаб строки схлопываются независимо,
поведение обоих сохраняется» — это требование **связки** плагинов, поэтому по
[ADR 0023](0023-cross-plugin-interactions.md) живёт как **`X2`** в
`cross-plugin.test.tsx`, а не как отдельный `AM`.

**Перформанс.** Отдельного перф-кейса фича не заводит: свёртка `slotActions`/
`actionMenu` мемоизирована по сигнатуре активного набора (нет работы на кадр),
инлайн-рендер идёт по видимым ячейкам как у прочих слотов, а меню Base UI монтируется
лишь при открытии. Куб 2×2×2 ([ADR 0004](0004-core-on-tanstack-table.md)) покрывает
режим «все плагины» без нового измерения.

## Последствия

- **+** Один источник правды на кнопку: видимость/состояние/подпись/обработчик —
  данными; конец рассинхрону «кнопка vs пункт меню».
- **+** Движок context-agnostic: заголовки и строки (и в перспективе ячейки) — на
  одном контракте; новая поверхность = новый плагин-меню, не новый движок.
- **+** Per-slot конфиг реактивной свёрткой чинит клоббер нескольких плагинов-меню и
  устаревание конфига при live-выключении.
- **−** Кнопки заголовков стали данными: плагин больше не отдаёт произвольный JSX
  напрямую (для нестандартной подачи есть `component`/`render`-слоты и `adornment`/
  `className`-escape). Публичные примитивы (`PinButton`/`SortButton`/`GroupButton`)
  сохранены для потребителей и theming-тестов.
- **−** Общий hover-джиттер кебаба при соседстве с растягивающимся аффордансом
  (resize-грип) — открытый вопрос, вынесен в [ADR 0013](0013-column-sizing.md).
