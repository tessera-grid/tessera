## Контекст

Слева в тулбаре — поле поиска (`align: 'start'`), справа — две группы: `view`
(«Колонки», `order: 0`; «Фильтры», `order: 1`) и `data` («Экспорт», `order: 0`).
Порядок групп по TB9 — по наименьшему `order` среди их кнопок. У обеих групп он 0,
поэтому порядок решает регистрация плагинов: при `[dataExport(), columnFiltering(), …]`
получается «Экспорт | Колонки · Фильтры», и «Фильтры» оказываются в конце.

Порядок должен отражать важность и частоту: сужение данных (поиск, фильтры) — чаще и
важнее настройки вида (колонки) и выгрузки (экспорт). «Фильтры» — кнопка-сводка
активных фильтров (сами фильтры ставятся из шапки колонки), её место — рядом с
поиском: вместе они отвечают на вопрос «что сейчас сужает данные».

## Решение

Раскладка по умолчанию:

```
[Поиск] [Фильтры] ……………………………… [Колонки] | [Экспорт]
```

- **«Фильтры» — слева, в группе поиска.** Слот `filterSummaryButton` получает
  `align: 'start'`, `group: 'search'`, `order: 1`: сразу после поля поиска, без
  разделителя; без поиска — первыми слева.
- **Ранги групп — фиксированные в ядре.** `resolveToolbarGroups` упорядочивает
  встроенные группы по рангу: `search` → `view` → `data`. Группы без ранга (свои
  группы потребителя и `default`) идут после встроенных, между собой — по наименьшему
  `order`, при равенстве — в порядке регистрации. Внутри группы — по `order`, как в
  TB9. Порядок плагинов в `plugins` на раскладку больше не влияет.
- **Узкий тулбар.** Левая группа сжимается за счёт поля поиска (`min-width: 0`), между
  сторонами — зазор `--tsr-comp-toolbar-gap`: «Фильтры» не наезжают на правую сторону.
- **Кнопки потребителя** без `group`/`order` — группа `default`, в конце правой
  стороны, как сейчас.
- **Переопределять порядок встроенных кнопок** приложению не даём: свои кнопки оно
  ставит через `group`/`order` слота. Отдельный проп порядка — отдельной потребностью.

## Границы

- Ранги — только для встроенных групп; новую встроенную группу добавляют в таблицу
  рангов ядра вместе с её ADR.
- Набор кнопок, их вид и поведение не меняются.

## Отвергнутые альтернативы

- **Только стабилизировать порядок** («Колонки · Фильтры | Экспорт» независимо от
  регистрации): убирает случайность, но оставляет сводку фильтров вдали от поиска.
- **«Фильтры» первыми справа** («Фильтры · Колонки | Экспорт»): разносит поиск и
  фильтры по разным краям.
- **Ранг через большие `order`** (`order: 100` у экспорта): неявно и ломается у первого
  потребителя со своим `order`.
- **Проп порядка `toolbarOrder`**: новый публичный API без запроса на него.

## Последствия

- **+** Раскладка предсказуема и не зависит от порядка плагинов.
- **+** Инструменты сужения данных собраны слева.
- **−** Меняется вид тулбара у всех потребителей с фильтрами: кнопка переезжает влево.
  Ломающим изменением API это не является, но называется в отчёте.
