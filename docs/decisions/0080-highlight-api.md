## Контекст

Код вне грида — внешний плагин или приложение — не может выделить строку, ячейку
или колонку. Типичные сценарии:

- плагин удаления строк подсвечивает строку, пока человек подтверждает удаление;
- поиск отмечает совпадения;
- приложение показывает ячейку с ошибкой валидации или мигает строкой, которую
  изменил другой пользователь.

Внутри грида подсветки уже есть, но закрытые: приход ленивых детей (ADR 0056,
срез `rowArrivals`) и сохранение ячейки (ADR 0057, срез `cellSaved`). Публичного
способа нет, как нет `rowClassName`/`getRowProps`.

### Палитра состояний тела грида

Подсветка ложится на ячейки, у которых уже есть состояния. Разбор темы
(`core/themeVariables/theme.css`) и CSS строки и ячейки:

| Состояние                                  | Чем рисуется                                                               | Ось     |
| ------------------------------------------ | -------------------------------------------------------------------------- | ------- |
| Строка в покое, нечётная                   | `surface`, `bg`                                                            | яркость |
| Ховер строки                               | чернила 4% поверх фона строки                                              | яркость |
| Выбранная строка, с ховером                | чернила 6% и 10%                                                           | яркость |
| Закреплённые ячейки                        | непрозрачная подложка: surface + чернила 3/7/9/13%, `!important`           | яркость |
| Выделение ячеек (`cellSelection`)          | синий `info` 14% слоем `background-image`, синие кромки 2px (`box-shadow`) | синий   |
| Приход строк, сохранение ячейки            | синий (`loader-bar` = `info`) 16% слоем `::after` поверх содержимого       | синий   |
| Ожидание, полоса загрузки                  | синий                                                                      | синий   |
| Отказ: вспышка, метка ошибки, DnD «нельзя» | красный `danger` (у DnD — сплошной фон на время перетаскивания)            | красный |
| Фокус-кольцо, контур ячейки при ховере     | `ring`/`accent`, нейтральные                                               | контур  |

Состояния взаимодействия живут только на оси яркости и красятся нейтральными
чернилами. Цвет занят двумя тонами: синий — системные состояния, красный — отказ.
Палитра `ref` знает только neutral, blue и red.

Отсюда конфликты, которые решение обязано обойти:

1. Синий тон подсветки не отличить от выделения ячеек и подсветки прихода.
2. Слой поверх строки (как у прихода) тонирует текст, фокус-кольцо и кромки
   выделения; чтобы покрыть закреплённые ячейки (`z-index` 2), его пришлось бы класть
   поверх всего содержимого.
3. `background-color` строки не доходит до закреплённых ячеек: их подложка
   непрозрачна и перебивает его с `!important` — полоса подсветки вышла бы дырявой.

## Решение

### 1. API на экземпляре таблицы

```ts
type HighlightTarget =
  | { row: string }
  | { cell: readonly [rowId: string, columnId: string] }
  | { column: string }

interface HighlightOptions {
  /** Встроенный или свой тон (§4). По умолчанию `warning`. */
  tone?: 'danger' | 'warning' | 'success' | (string & {})
  /** Держать столько миллисекунд, затем погасить. Без него — до снятия. */
  duration?: number
  /** Снять, когда промис выполнится или будет отклонён. */
  until?: PromiseLike<unknown>
  /** Группа подсветок; по умолчанию `'default'`. */
  key?: string
  /** Текст для скринридера (§6). */
  label?: string
}

table.highlight(target, options?): { clear(): void }
table.clearHighlights(key?: string): void
```

- Подсветка — ядровая фича, всегда включена, как `actionStatus` (ADR 0078): API
  доступно приложению и любому плагину через `table` без отдельного плагина.
- Под API — срез `highlights` в TanStack Store: подсветка реактивна, переживает
  размонтирование строки виртуализацией и не зависит от смонтированного грида. Форма
  среза — внутренняя; управлять подсветкой через `state` нельзя: в ней живут промисы
  и таймеры.
- **Ключ.** Повторная подсветка той же цели с тем же ключом заменяет прежнюю. Две
  подсветки одной цели с разными ключами хранятся обе, видна последняя; снятие
  последней открывает предыдущую. `clearHighlights(key)` снимает группу,
  `clearHighlights()` — все.
- **Время жизни.** `duration`, `until` и `clear()` действуют вместе: подсветка
  снимается первым из них. Повторный `clear()` и `clear()` снятой подсветки ничего
  не делают.
- **Цель ушла.** Строка, которой больше нет в данных (core-модель), и колонка, которой
  нет в `columns`, теряют подсветку. Строка, скрытая фильтром, страницей или
  свёрнутым родителем, подсветку сохраняет и показывает её при возвращении.

### 2. Заливка — слой фона ячейки, а не слой поверх строки

Подсветка меняет только **тон**; состояния взаимодействия по-прежнему меняют только
**яркость**. Заливка полупрозрачна, поэтому разница ховера и выбора под ней видна
(при альфе _a_ от неё остаётся доля 1 − _a_).

Порядок слоёв ячейки, снизу вверх:

1. `background-color` — фон строки и её состояний, у закреплённых — непрозрачная
   подложка;
2. **заливка подсветки** — слои `background-image`: строки, колонки, ячейки;
   на пересечении они складываются;
3. тинт `cellSelection` — верхний слой `background-image`;
4. содержимое, кромки выделения (`box-shadow`) и фокус-кольцо (`outline`).

Заливка **никогда не лежит поверх текста и индикаторов**.

Подсветку строки рисует слой фона самой строки: обычные ячейки прозрачны и пропускают
его. Ячейки с непрозрачной подложкой закрепления повторяют тот же слой по
унаследованной CSS-переменной `--tsr-highlight-row` — полоса сплошная, а подложка
по-прежнему маскирует прокручиваемое содержимое. Прозрачные закреплённые ячейки
(колонка действий без своей подложки) слоя строки не получают: они лежат поверх
прокрученных ячеек той же строки, и второй слой удвоил бы тон. Тот же приём
(`background-image` поверх `background-color`) уже держит тинт `cellSelection` над
закреплёнными ячейками.

Подсветка колонки ложится на её заголовок, ячейки тела и футер. Под вложенной шапкой
подсветка листа группу над ним не заливает; цель — группа — заливает только заголовок
группы (ячеек и футера у неё нет).

Слой прихода строк (ADR 0056) остаётся поверх: он короткий и сообщает о другом.

### 3. Цвет передаётся переменной с именем тона

Элемент цели получает атрибут `data-highlight="<tone>"` и инлайн-переменную слоя
(`--tsr-highlight-row`, `--tsr-highlight-column`, `--tsr-highlight-cell`) со
значением `var(--tsr-comp-highlight-<tone>-bg)`. Это кастомное свойство в `style`, а
не CSS-in-JS: цвет по-прежнему определяет тема.

### 4. Тоны

Встроенные тоны — только не занятые системой:

| Тон       | Роль                        | Смысл                                      |
| --------- | --------------------------- | ------------------------------------------ |
| `danger`  | `--tsr-sys-danger`          | разрушительное действие, ошибка данных     |
| `warning` | `--tsr-sys-warning` (новая) | внимание, совпадения поиска (как `<mark>`) |
| `success` | `--tsr-sys-success` (новая) | подтверждение, удачное изменение           |

- **Синего встроенного тона нет:** синий закреплён за выделением ячеек, приходом и
  загрузкой.
- `danger` отличается от отказов формой: вспышка отказа — контур, метка ошибки —
  значок, DnD «нельзя» — сплошной фон только во время перетаскивания.
- Новые роли с мостом к токенам потребителя: `--tsr-sys-warning: var(--warning,
var(--tsr-ref-amber-500))`, `--tsr-sys-success: var(--success,
var(--tsr-ref-green-500))`; в тёмной теме — ступень 400, как у `danger` и `info`.
- Токены заливки: `--tsr-comp-highlight-<tone>-bg` — `color-mix` роли с прозрачностью.
  Альфа подбирается тестами HL10, HL13 и HL14, а не на глаз.
- **Свой тон.** Имя из `[a-z0-9-]`; приложение определяет токен
  `--tsr-comp-highlight-<tone>-bg` в своей теме и при желании стилизует
  `[data-highlight="<tone>"]`. Без токена заливки нет. В документации — предупреждение
  не брать синий и нейтральный: они конфликтуют с состояниями. Недопустимое имя тона —
  dev-предупреждение, подсветка не ставится.

### 5. Блик

> **Снято [ADR 0101](0101-static-highlight.md):** бегущая полоса читалась как загрузка;
> опции `shimmer`, её токенов и синхронизации фазы больше нет. Раздел — запись прежнего
> решения.

`shimmer` добавляет к заливке более плотную полосу того же тона, которая проходит по
цели слева направо. Светлая полоса не годится: в тёмной теме «светлое» — это цвет
текста, и полоса читалась бы как засвет, а не блик тона.

- `repeat` — число проходов: `1` по умолчанию, `N` или `'infinite'` до снятия
  подсветки; `period` — длительность прохода, по умолчанию токен
  `--tsr-comp-highlight-shimmer-period`, в вызове переопределяется инлайн-переменной.
- После последнего прохода остаётся заливка.
- Полоса — отдельный псевдоэлемент, сдвигается `transform` (работа компоновщика, без
  перерисовки): у строки — `::before` с `z-index` 3 (выше закреплённых ячеек, ниже
  слоя прихода), у ячейки и колонки — `::after` ячейки (`::before` занят линиями
  дерева, ADR 0058); заголовок — `::before` (`::after` занят фокус-кольцом). Ширина
  — `--tsr-comp-highlight-shimmer-width`, но не больше 60 % цели: полоса шире узкой
  ячейки проскакивала её за мгновение. Путь — ширина цели (`container-type` на время
  блика). Это единственная часть, которая на время ложится на текст, поэтому полоса
  узкая и полупрозрачная: `--tsr-comp-highlight-<tone>-shimmer`, у своего тона без
  такого токена — его заливка.
- **Одна фаза.** Ячейки колонки, её заголовок и футер — отдельные анимации, и
  монтируются они в разное время (виртуализация ещё и пересоздаёт ячейки): каждая
  полоса бежала бы со своего момента. Поэтому каждая анимация блика при старте
  получает начало — момент постановки подсветки (`data-highlight-start`, обработчик
  `animationstart` на контейнере грида задаёт `startTime`). Все элементы цели идут в
  одной фазе, а ячейка, вернувшаяся в окно, подхватывает текущую фазу, а не начинает
  сначала.
- Окончание блика — таймер в срезе: после последнего прохода атрибут блика снимается.
- Пока грид прокручивается (`data-scrolling`), полосы нет (`content: none`).
  Заливка прокрутке ничего не стоит, а бесконечный блик колонки добавлял ~4 мс к кадру
  вертикальной прокрутки 1000×1000 (HL19): каждая новая ячейка колонки приходила с
  бегущей полосой. Пауза (`animation-play-state`, как MI25) не годится: ячейки,
  появившиеся во время прокрутки, отставали бы по фазе от старых. После остановки
  полосы стартуют заново и выравниваются по общему началу.

### 6. Движение и доступность

- Гаснущая подсветка (`duration`, `until`, `clear()`) уходит переходом
  `--tsr-comp-highlight-fade-duration` на кривой токенов движения. Тем же переходом
  подсветка и проявляется ([ADR 0101](0101-static-highlight.md), HL26).
- `prefers-reduced-motion`: заливка видна, затухание мгновенное — общим
  правилом темы.
- Цвет не может быть единственным сигналом (WCAG 1.4.1). `label` при постановке
  объявляется через live region (`table.announce`) и, пока подсветка держится, висит
  `aria-description` на цели: на строке, на ячейке, у колонки — на её заголовке. Без
  `label` подсветка чисто визуальна, `aria-*` не меняются — это решение автора.

### 7. Подписки

- Строка читает свою подсветку в подписке `useRowStateSubscription`, которая у неё
  уже есть.
- Ячейка тела читает подсветку своей колонки и свою собственную в той же подписке,
  что и форма колонок; ячейки заголовка и футера — подсветку колонки. Селектор
  возвращает объекты среза, которые не меняются, пока не изменилась их цель.
- Подсветка одной строки перерисовывает только эту строку, ячейки — только эту
  ячейку, колонки — только ячейки этой колонки.

## Границы

- **Обводка** (`emphasis: 'outline'`) — нет; только заливка.
- **Докрутка к цели** — есть с [ADR 0104](0104-scroll-to-row.md): `reveal: true`
  докручивает к строке, ячейке или колонке через `table.scrollToRow`.
- **Перевод подсветки прихода (0056) и сохранения (0057)** на новый механизм — нет:
  свои токены и тесты, отдельный рефакторинг (roadmap). API не мешает переезду.
- **Управление через `state`** — нет (§1).
- **Правые закреплённые ячейки не реагируют на ховер и выбор строки** — найденный по
  пути баг ADR 0011, чинится отдельно; заливка подсветки от него не зависит (§2).

## Отвергнутые альтернативы

- **Слой поверх строки, как у прихода.** Тонирует текст, фокус-кольцо и кромки
  выделения; выше закреплённых ячеек он ложится на всё содержимое.
- **`background-color` строки.** Не доходит до непрозрачной подложки закреплённых
  ячеек — полоса с дырами.
- **Произвольный цвет пропом.** Ломает тему, тёмный режим и контраст; свой тон —
  токеном (§4).
- **Синий тон `info`.** Неотличим от выделения ячеек и прихода.
- **Только управляемый срез `state.highlights`.** Честнее для TanStack, но промисы и
  таймеры в нём не живут, а плагину неудобно.
- **Бегущее пятно по контуру (ADR 0057) как блик.** Это обводка, от которой отказались.

## Последствия

- Новые роли `--tsr-sys-warning`, `--tsr-sys-success` и примитивы `ref` amber и green —
  первые цвета палитры помимо синего и красного.
- Слой `background-image` ячейки теперь общий для подсветки и `cellSelection`:
  правило собирается из переменных, а не задаётся одним градиентом.
- Публичная поверхность растёт на `table.highlight`/`table.clearHighlights` и типы
  `HighlightTarget`, `HighlightOptions`; ломающих изменений нет.
