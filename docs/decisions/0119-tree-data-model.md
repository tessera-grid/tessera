# 0119 — Дерево: модель `rowExpandingModel` отдельно от переключателя, линии — плагином `treeLines`

## Контекст

Показ иерархии и интерфейс её изменения сейчас — один плагин `rowExpanding`. Модель
раскрытия (`rowExpandingFeature` и `expandedRowModel`) приходит только с ним, а с ним —
служебная колонка с переключателем. Отсюда:

- приложение, которое передало вложенные данные и `expanded: true`, без плагина получает
  одни корни: срез `expanded` не входит в набор фич и молча игнорируется;
- дерево без кнопок невозможно: режимов колонки два — `'auto'` и `'always'` (ADR 0050);
- линии дерева — опция `rowExpanding({ treeLines })`: их нельзя показать без колонки
  переключателя, хотя рисуются они в отступе первой колонки данных, а не в ней;
- скелет первой загрузки рисует дерево по отдельной опции `skeletonOptions.tree`, никак не
  связанной с тем, придут ли данные деревом.

Прожарка 2026-10-16 разобрала, кто чем владеет. Состояние колонок (порядок, видимость,
закрепление, ширины) живёт в ядре — без него нет раскладки, а плагины колонок добавляют
только интерфейс. Модели строк живут в плагинах, чтобы плоский грид не платил за них.
Решено сохранить это и разделить плагин дерева на модель и интерфейс, а не переносить
модель в ядро. Тот же вопрос для сортировки, страниц, фильтров, группировки и выбора —
отдельная прожарка.

### Как это сделано у других

- **AG Grid** — иерархию включает флаг `treeData` (путь строки — `getDataPath`), что
  раскрыто по умолчанию — `groupDefaultExpanded` или `isGroupOpenByDefault`. Переключатель
  живёт в колонке группы и настраивается её рендерером.
- **MUI X** — `treeData` и `getTreeDataPath`, раскрытие по умолчанию —
  `defaultGroupingExpansionDepth`; переключатель — в колонке группировки.

У обоих иерархия — свойство данных, а переключатель — свойство колонки. Отдельного режима
«дерево без переключателя» нет: кнопки прячут своим рендерером ячейки.

## Решение

### 1. `rowExpandingModel({ enabled })` — модель дерева

Новый плагин без интерфейса. Приносит фичи модели: `rowExpandingFeature` и
инкрементальную модель раскрытия (ADR 0070). Строки раскрыты по состоянию `expanded`
приложения (`state`/`initialState`, `true` — все): подстроки видны, первая колонка данных
получает отступ по ADR 0059. Раскрываемость — по наличию подстрок, без ограничения
глубины. Пустой `expanded` — одни корни.

Колонки переключателя нет. Пользователь раскрытие не меняет: у строк нет `aria-expanded`,
←/→ только двигают фокус, в меню строки нет пункта раскрытия. С клавиатурной навигацией
грид — `treegrid` с `aria-level`, `aria-setsize`, `aria-posinset` (W10, W16), без неё —
`table`.

Код модели живёт вне папки плагина: его делят `rowExpandingModel` и `rowExpanding` (сборка с
`preserveModules`, IV3).

### 2. `rowExpanding()` — модель и интерфейс

`rowExpanding` приносит те же фичи модели, что `rowExpandingModel`, и добавляет интерфейс: колонку
переключателя, ←/→ и пункт меню, `aria-expanded`, `onExpandRow`, ленивые дети (ADR 0054).
Подключать `rowExpandingModel` рядом не нужно; подключённый — не мешает: фичи сливаются по ключу,
модель в наборе одна.

**Выключение.** `rowExpanding({ enabled: false })` убирает только свой интерфейс. Сейчас
`foldEntries` сливает опции записей по порядку, и `enableExpanding: false` выключенной
записи погасил бы дерево `rowExpandingModel`. Опции модели (`enableExpanding`) выводятся из всех
записей, несущих модель: модель включена, если включена хоть одна из них, — порядок
плагинов не важен.

**`maxDepth` — предел модели `rowExpanding`.** Как и раньше, строка глубже предела не
раскрывается — ни переключателем, ни состоянием `expanded`, ни ←/→, ни прокруткой к строке
(RX8, SV5), — и рядом с `rowExpandingModel` тоже: `rowExpanding` — это модель с пределом и
интерфейс. У `rowExpandingModel` в одиночку предела нет. Выключенный `rowExpanding` предела не
задаёт.

**Раскрытие пользователем — только с `rowExpanding`.** Ядро раскрывает строку по ←/→ и
ставит строке `aria-expanded`, только когда переключатель есть: `rowExpanding` включён.

### 3. Группы

Строки-группы `rowGrouping` раскрываются той же моделью. С `rowExpandingModel` без `rowExpanding`
группы раскрыты по `expanded`, колонки переключателя нет. С `rowExpanding` — как сейчас.

### 4. `treeLines({ enabled })` — линии

Новый плагин без модели: рисует линии ADR 0102 у любой видимой иерархии — дерева
`rowExpandingModel` или `rowExpanding` и групп `rowGrouping`. Сам ничего не раскрывает: без плагина
модели и без раскрытых строк линий нет. `enabled: false` гасит линии на лету, без
перемонтирования. Опция `rowExpanding({ treeLines })` удаляется.

### 5. Скелет первой загрузки

`skeletonOptions.tree` удаляется. Скелет рисует подстроки по плану SL22, когда в наборе
есть модель дерева (`rowExpandingModel` или `rowExpanding`) и `expanded === true`: тогда дерево
придёт развёрнутым. Иначе скелет плоский. Линии в скелете — при `treeLines`. Квадраты
переключателя — только с колонкой `rowExpanding`: у строк с подстроками в плане дерева, у
части строк по номеру — в плоском (SL25).

Ограничение: при `expanded: true` и плоских данных скелет нарисует дерево, а данные
придут плоскими. До данных структура неизвестна; `expanded: true` — единственный сигнал
приложения.

### 6. Имена и истории

По ADR 0106: фабрики `rowExpandingModel` и `treeLines` с `enabled`, аргументы историй
`enableRowExpandingModel` и `enableTreeLines`; аргумент `rowExpandingTreeLines` удаляется.

## Отвергнутые альтернативы

- **Модель раскрытия в ядре.** Ядро показывает дерево по `expanded` без плагинов. Модель и
  её проход по строкам вошли бы в каждый грид, в том числе плоский, против ADR 0010.
- **`rowExpanding({ column: 'none' })`.** Режим без колонки у плагина интерфейса: плагин
  объявлен, но ничего не рисует и ничего не даёт пользователю — путает ответственность.
- **Параметр `lines` у модели дерева.** Линии — оформление любой иерархии, включая группы;
  плагин модели ими не владеет.
- **`rowExpandingModel` раскрывает всё сам.** Присутствие плагина не должно менять состояние:
  раскрытие задаёт приложение.
- **`skeletonOptions.tree` с умолчанием от плагина.** Вторая настройка того же факта;
  `expanded` уже говорит, придёт ли дерево развёрнутым.

## Границы

- Ленивые дети (`hasChildren`/`loadChildren`) — только с `rowExpanding`: раскрытая в
  `expanded` ленивая строка без него ничего не грузит.
- Путь строки вместо `getSubRows` (`getDataPath` AG Grid) — вне объёма.
- Разделение на модель и интерфейс у сортировки, страниц, фильтров, группировки, выбора
  строк и экспорта — отдельная прожарка.

## Последствия

- **Публичный API:** новые фабрики `rowExpandingModel`, `treeLines`. **Ломающие изменения:**
  удалены `rowExpanding({ treeLines })` и `skeletonOptions.tree`. Выключенная модель дерева показывает одни корни: раньше `rowExpanding({ enabled: false })` при сохранённом `expanded` показывал раскрытые строки без переключателя (сужение `narrowExpandingOff`). Отмечаются в
  `CHANGELOG.md`.
- **ADR 0015:** модель дерева — у `rowExpandingModel`, `rowExpanding` приносит её с пределом
  `maxDepth` и переключателем (§2).
- **ADR 0058, 0102:** формулировки RE53–RE58 и TL1–TL8 — про `treeLines()`, ID остаются.
- **ADR 0060:** SL22–SL25 — правило по `expanded` (§5); сценарий S1 «Получение данных»
  проигрывает шаги «Иерархия данных» (`rowExpandingModel`, `expanded: true`) → «Линии дерева»
  (`treeLines`) → «Раскрытие строк» (`rowExpanding`) → «Данные получены».
- **Ядро:** `foldEntries` выводит опции модели из всех её записей (§2); `isTreeGrid` и
  `aria-expanded` строк — от модели и колонки, а не от одной опции `enableExpanding`.
- **Документация:** `docs/architecture/plugins-and-slots.md` (плагин модели и плагин
  интерфейса), `rendering.md` (линии, скелет), roadmap.
