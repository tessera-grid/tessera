# 0221 — Вспышка при смене значения извне

- **Статус:** Принято (прожарка 2026-11-13, решения автора — рекомендованные варианты целиком и
  непрозрачная вспышка поверх любых заливок)
- **Дата:** 2026-11-13
- **Изменён:** 2026-11-15 — §9: итог колонки в футере вспыхивает при смене значений строк, не
  при смене набора строк (VC21–VC24, S6); значения строк-групп остаются в «Границах» и roadmap.
- **Слой:** плагин `valueChangeFlash` — сравнивает значения и зовёт `flashOutcome` ядра. Ядро —
  поле `watch` у вклада ячейки в тело (ADR 0170): ячейка уже перерисовывается с новой строкой и
  держит значение, поэтому она и зовёт вкладчика после коммита — без компонента на ячейку; без
  вкладчика с `watch` значение не читается. Ядро — новые итоги `changed`, `up`, `down` во
  вспышке итога (ADR 0134): тон, стрелка направления и непрозрачный слой нужны и вспышкам
  приложения через `table.flashOutcome`, поэтому живут рядом с прежними итогами. Отметка «своей
  записи» — `shared/ownWrites.ts`: её пишет плагин правки, читает плагин вспышки, а плагин не
  импортирует другой плагин ([ADR 0163](0163-layer-boundaries-and-guards.md)).
- **Изменяет:**
  - [ADR 0170](0170-body-contribution-channel.md) — у вклада ячейки поле `watch`: смена значения
    смонтированной ячейки после коммита.
  - [ADR 0134](0134-outcome-flash.md) — §2 и §3: у `FlashOutcome` три новых итога; §5: заливка
    вспышки непрозрачна и лежит над подсветкой приложения, тинтом диапазона и заливкой выбора, не
    смешиваясь с ними (§6 этого ADR); OF8 переписан, «Границы»: изменения `data` извне закрыты.
  - [ADR 0126](0126-cell-fill-precedence.md) — §5: вспышка — верхний слой фона ячейки, над тинтом
    выделения.
- **Связано:**
  - [ADR 0194](0194-incremental-data-changes-and-client-transactions.md),
    [ADR 0199](0199-row-shifts-in-the-middle-of-data.md) — смена `data` из прежней модели,
    вспышка добавленных строк.
  - [ADR 0157](0157-ssrm-row-transactions.md) — транзакции SSRM, `setRowData`.
  - [ADR 0139](0139-saved-row-and-column-data-type.md) — сохранённая строка из ответа
    `onCellEdit`.
  - [ADR 0219](0219-paste-fill-and-bulk-edit.md) — запись в ячейки: вставка, протяжка, очистка.
  - [ADR 0172](0172-column-data-type.md) — тип колонки, ключ записи `object`.
  - [ADR 0080](0080-highlight-api.md), [ADR 0101](0101-static-highlight.md) — подсветка.
  - [ADR 0087](0087-forced-colors.md) — высокая контрастность.
  - [ADR 0195](0195-node-subscriptions-by-declared-slices.md) — перерисовка только затронутых
    ячеек.

## Контекст

Вспышки грида отмечают итоги своих действий (ADR 0134) и приход строк (ADR 0056, ADR 0199).
Значение, которое изменилось с новыми данными — сокет CRM, котировка, правка другого
пользователя, — меняется молча: в таблице на тысячи строк глаз его не замечает. ADR 0134 вынес
это в «Границы» как отдельную фичу подсветки изменений.

### Как у других

- **AG Grid** — `enableCellChangeFlash` у колонки (обычно в `defaultColDef`),
  `cellFlashDuration` 500 мс и `cellFadeDuration` 1000 мс, `api.flashCells`. Сравниваются
  значения до форматирования. Вспыхивают отрисованные ячейки: ячейка вне окна при прокрутке не
  вспыхивает. `rowNode.setData` не вспыхивает, `updateData` и `setDataValue` вспыхивают; смена
  из-за фильтра — нет (`allowShowChangeAfterFilter`). Направление — отдельные рендереры:
  `agAnimateShowChangeCellRenderer` (дельта со стрелкой) и `agAnimateSlideCellRenderer`.
- **MUI X**, **Handsontable** — встроенной вспышки нет, только свой рендерер ячейки.

## Решение

### 1. Источники

Вспыхивает ячейка, чьё значение изменилось, пока она смонтирована, а смену не сделал человек в
этой таблице:

- новый `data` приложения — ссылкой или через `applyRowTransaction` (ADR 0194);
- серверная модель строк — `update` транзакции, `setRowData` приложения, `refreshRows` без
  `purge` (ADR 0138, ADR 0157).

Не вспыхивают:

- **запись человека** — правка ячейки (`onCellEdit`), пакет `onCommitEdits` ручного сохранения и
  операций записи (вставка, протяжка, заполнение, очистка, вырезание — ADR 0219), сохранённая
  строка из ответа `onCellEdit` (ADR 0139). Плагин правки перед вызовом колбэка отмечает
  ячейки записи «своими» (`shared/ownWrites.ts`); отметка гасит ближайшую смену значения ячейки
  при любом новом значении — нормализованное сервером значение не мигает, итог уже показала
  вспышка `accepted`. Отметка живёт, пока ждёт ответ колбэка, и `OWN_WRITE_GRACE` (2 с) после
  него: приложение успевает положить новый `data`, а поздняя смена извне всё же вспыхнет;
- первая отрисовка ячейки — монтирование, въезд в окно, новая страница, раскрытие, конец
  быстрой прокрутки: прежнего значения в окне не было;
- новые строки — у них вспышка `arrived` всей строки (ADR 0199, ADR 0157);
- смена порядка и отбора без смены значения — сортировка, фильтр, поиск, группировка;
- смена описания колонки, языка, формата: значение то же;
- строки-группы (агрегаты) — «Границы»; итоги футера — §9.

### 2. Включение

```ts
valueChangeFlash({
  enabled?: boolean
  /** Вид колонок без своего `changeFlash`; по умолчанию `true`. */
  columnDefault?: boolean | 'direction'
})

interface ValueChangeFlashColumnDef {
  /** `false` — колонка не вспыхивает; `'direction'` — тон и стрелка роста или падения. */
  changeFlash?: boolean | 'direction'
}
```

Плагин presence-based (ADR 0010): с ним вспыхивают все колонки данных, кроме `changeFlash:
false`; служебные колонки не вспыхивают. Умолчание для колонок без своего поля — аргумент
`columnDefault`, как `defaultColDef` у AG Grid: `columnDefault: false` и `changeFlash: true` у
нужных колонок — вспышка только у них. `defaultColumn` таблицы (ADR 0077) для этого не годится:
он несёт только размеры колонки. Тип данных вспышку не включает: в CRM меняются и статус, и
ответственный.

### 3. Сравнение и направление

- Значение ячейки — `getValue` колонки, до форматирования. Равенство — по типу колонки
  (ADR 0172): даты по моменту (`dateTypeInstant`), `multiSelect` поэлементно, `object` — по
  ключу записи (`getKey`), прочее — `Object.is`. Новый объект строки с тем же значением ячейки
  не вспыхивает. По показанному тексту не сравнивается: это форматирование на каждую ячейку, а
  1.004 → 1.005 при показе «1.00» скрыл бы настоящую смену.
- `changeFlash: 'direction'` у колонок `number`, `numberString` (`compareDecimal`) и дат: рост —
  `up`, падение — `down`. Пусто, не число или равенство порядка (тот же момент, другой объект) —
  `changed`. У прочих типов `'direction'` — как `true`.

### 4. Цена

Сравнивает ячейка тела: прежнее значение — в её ref, смена — в layout-эффекте, который идёт при
смене объекта ячейки (новой строки), а не на каждую отрисовку; вкладчик с `watch` получает новое
и прежнее значение. Цена — по числу ячеек в окне, а не строк в данных: на 100 000 строк смена
`data` сравнивает только ячейки окна изменённых строк (ячейка неизменённой строки не
перерисовывается — ADR 0195).

Невидимый компонент правого слота на каждую ячейку отвергнут замером VC18: четыре лишних
компонента на ячейку (слот, граница ошибок плагина, обёртка, сторож) — 930 отрисовок на тик вместо 342.

Вспышки одного коммита собираются и пишутся в срез одной записью на итог — **в следующем кадре**:
новые значения красятся сразу, а перерисовка вспыхнувших ячеек идёт отдельной короткой задачей и
не удлиняет задачу смены данных. Чтобы запись вспышки не будила весь грид, корень `DataGrid` на
срез `flashes` не подписан — его читают ячейки, строки, шапка и футер своими подписками (было:
каждая вспышка любого итога перерисовывала корень). Время вспышки ядро читает из темы один раз и
перечитывает после кадра: чтение токена сразу после коммита пересчитывало стили всего грида.

### 5. Частые обновления, окно и перестановки

- Смена той же ячейки до конца вспышки перезапускает время (OF3), итог — по последней смене:
  ячейка, которая меняется чаще удержания и угасания, горит непрерывно, как у AG Grid. Склейки
  во времени нет: смены одного рендера React склеивает сам.
- Ячейка вне окна в момент смены не вспыхивает и при прокрутке к ней. Вспыхнувшая ячейка, ушедшая
  из окна и вернувшаяся до истечения, залита сразу (OF6).
- Строку, переставленную сменой внутри окна (сортировка по изменённой колонке), отметка ведёт по
  id: ячейка вспыхивает на новом месте. Строку, которую смена увела из окна или из отбора, не
  видно. Строка, въехавшая в окно той же сменой, не вспыхивает — край в «Известных проблемах».

### 6. Вид: непрозрачный слой поверх любых заливок

- Итоги ADR 0134 дополняются тремя:

  | Итог      | Тон                                        | Смысл                    |
  | --------- | ------------------------------------------ | ------------------------ |
  | `changed` | фиолетовый (`--tsr-comp-flash-changed-bg`) | значение сменилось извне |
  | `up`      | зелёный (`--tsr-comp-flash-up-bg`)         | значение выросло         |
  | `down`    | красный (`--tsr-comp-flash-down-bg`)       | значение упало           |

  Фиолетовый — новая роль `--tsr-sys-changed`: синий занят приходом и тинтом выделения, янтарь —
  подсветкой «внимание» и черновиками (ADR 0178), зелёный и красный — `accepted` и `reverted`.
  На подсвеченной янтарём строке янтарная вспышка была бы не видна. Тона `up` и `down` — свои
  токены, а не `accepted`/`reverted`: смысл другой, и тема переворачивает их там, где рост
  красный.

- **Вспышка не смешивается с заливкой цели** (решение автора). Тон каждого итога — непрозрачный:
  оттенок, заранее смешанный с фоном строк (`--tsr-comp-row-bg`). Слой вспышки — верхний слой фона
  ячейки и строки: над подсветкой приложения, тинтом диапазона, заливкой выбора, наведения и
  закрепления. Пока вспышка держится, видна только она; угасая, она открывает прежнюю заливку, и
  после угасания цель залита как до вспышки. Срез подсветки и выбора вспышка не трогает. Вспышка
  строки в ячейке с подсветкой или тинтом рисуется и слоем ячейки — иначе их полупрозрачный тон
  лёг бы поверх. Среди вспышек одной ячейки главнее ячейка, затем колонка, затем строка. Текст,
  кромки диапазона, кольцо фокуса и отметки углов лежат выше фона и не тонируются. Это меняет вид
  и прежних итогов `arrived`, `accepted`, `reverted`.
- `up` и `down` ещё несут стрелку: треугольник `--tsr-comp-flash-direction-size` (6 px) у
  начального края ячейки посередине высоты, в отступе содержимого, цветом
  `--tsr-comp-flash-up-color` и `--tsr-comp-flash-down-color`; без стрелки направление
  передавал бы только цвет (WCAG 1.4.1). Стрелка — элемент ячейки с `aria-hidden`, раскладку не
  меняет, гаснет вместе с заливкой. Её рисует ядро на любой вспышке `up` и `down`, в том числе от
  приложения.
- Текст на каждом тоне держит 4.5:1, стрелка на своём тоне — 3:1, в обеих темах.
- Время — общие токены вспышки (ADR 0134, §4): 300 + 500 мс.

### 7. Режимы и доступность

- Вспышка ничего не объявляет и не меняет `aria-*`: тикер утопил бы скринридер. Приложение,
  которому нужно объявление, зовёт `table.announce`.
- **Высокая контрастность:** `changed`, `up` и `down` не заливаются, как `arrived` и `accepted`
  (ADR 0134, §7); стрелка рисуется цветом `CanvasText` — направление видно и в режиме.
- **Уменьшенное движение:** то же время без угасания (MO3).

### 8. Публичный API

- Плагин `valueChangeFlash` с аргументом `columnDefault`, поле колонки `changeFlash`, типы
  `ValueChangeFlashOptions`, `ValueChangeFlashColumnDef`, `ValueChangeFlashHooks` — из `/plugins`.
- Итоги `changed`, `up`, `down` в `FlashOutcome` — `table.flashOutcome(cell, 'up')` у приложения
  (аналог `api.flashCells`).
- Роль `--tsr-sys-changed`, токены `--tsr-comp-flash-changed-bg`, `--tsr-comp-flash-up-bg`,
  `--tsr-comp-flash-down-bg`,
  `--tsr-comp-flash-up-color`, `--tsr-comp-flash-down-color`, `--tsr-comp-flash-direction-size`.
- **Изменение вида темы:** токены `--tsr-comp-flash-<итог>-bg` по умолчанию непрозрачны; тема,
  задавшая полупрозрачный тон, снова смешает его с заливкой под ним.

### 9. Итог колонки в футере

Итог колонки (ADR 0184) вспыхивает по правилам своей колонки: с плагином и без
`changeFlash: false`; при `'direction'` у числового итога — тон роста или падения и стрелка.

- **Смена значений — вспышка:** новый `data`, клиентская транзакция, `update` и `setRowData`
  серверной модели, новые `totals` той же выборки, новый аргумент `columnTotals({ totals })` —
  и своя правка человека: итог стоит в другом месте таблицы, следствие правки легко пропустить.
- **Смена режима `aggregationScope` — вспышка:** итог считает те же строки шире или уже — верхний
  уровень или все узлы дерева (ADR 0229), величина та же, и рост виден стрелкой. В серверной модели
  смена режима начинает новую выборку — её итог вспыхивает, если отбор и группировка прежние.
- **Смена набора строк — без вспышки:** поиск, фильтр, группировка, смена `aggregationFn`, новая выборка
  серверной модели. Сторож помнит набор строк итога и сравнивает
  его с прежним.
- **Без вспышки и** первое появление итога (было пусто — стало число) и его уход; строка итогов
  за краем области (`inline`) — и при прокрутке к ней, как ячейка вне окна.
- Равенство — по значению: числа, даты по моменту, итоги-списки (`extent`, `unique`) и объекты
  (`aggregationFn` списком) — по элементам. Направление — только у конечных чисел, иначе `changed`.
- Вспышка — цель итога колонки в срезе `flashes` (ключ `f` по колонке) и слой ячейки футера
  поверх вспышки колонки; стрелка — та же, что у ячейки тела. Ячейка футера зовёт сторожа опции
  ядра `watchColumnTotal` при монтировании и при смене итога; сторожа ставит плагин. Вспышки
  кадра пишутся одной записью в следующем кадре, как у ячеек.
- Отдельного перф-требования нет: сторож работает только при смене итога, по одному сравнению
  на видимую колонку итога.

## Отвергнутые альтернативы

- **Сброс подсветки на время вспышки и возврат после.** Тот же вид, но вспышка писала бы в срез
  подсветки приложения (ADR 0110 отверг именно это) и делила бы с приложением время возврата.
  Непрозрачный слой даёт то же без записи в чужой срез.
- **Сравнение всех строк данных на смене `data`.** Дало бы вспышку и вне окна, но стоит
  O(строк × колонок) на каждом тике и растит срез вспышек до размера данных; AG Grid тоже
  вспыхивает только отрисованные ячейки.
- **Сравнение по показанному тексту** (§3).
- **Включение по типу данных.** Числа не единственное, что меняется извне.
- **Направление только тоном.** Цвет — единственный носитель смысла (WCAG 1.4.1).
- **Дельта числом и съезжающее значение** (рендереры AG Grid) — другой вид ячейки, «Границы».
- **Вспышка своей записи.** Две вспышки подряд (`accepted`, затем смена) путают; человек и так
  видит, что записал.

## Границы

- Агрегаты строк-групп (ADR 0184) не вспыхивают: нужен проход по затронутым группам — в roadmap.
  Итоги футера — §9.
- Дельта числом в ячейке и съезжающее значение — не делаются.
- Вспышка всей строки при смене любой её ячейки — не делается: приложение зовёт
  `table.flashOutcome({ row }, 'changed')`.
- Строка, въехавшая в окно той же сменой, не вспыхивает (§5) — «Известные проблемы».

## Последствия

- **+** Потоковые обновления видны: ячейка мигает, направление цены — тоном и стрелкой.
- **+** Цена — по окну, не по данным; без плагина — ноль.
- **+** Вспышка любого итога читается на любой заливке: тон не смешивается с подсветкой и
  выделением.
- **−** Пока вспышка держится, подсветка и тинт диапазона под ней не видны (кромки и выбор других
  ячеек строки видны).
- **−** Снимки Chromatic всех вспышек меняют цвет: тон стал непрозрачным.
