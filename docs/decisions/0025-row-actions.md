# 0025 — Действия строки: плагин rowActions

- **Статус:** Принято
- **Дата:** 2026-09-12
- **Связано:**
  - [ADR 0010](0010-invert-core-plugins-registry.md) — presence-based композиция:
    плагин `rowActions` владеет служебной колонкой, её опциями и автосайзом; в ядре
    остаётся лишь id колонки (`ROW_ACTIONS_COLUMN_ID`) и предикаты, которые
    безусловно читает grid.
  - [ADR 0011](0011-column-pinning.md) — авто-закрепление колонки действий вправо
    (`pin: { side: 'right', when: 'always' }`) и её поведение в двустороннем
    пиннинге: подложка/разделитель, sticky-шапка, стык с пользовательскими правыми
    пинами и reorder-out (CP14/CP23/CP24/CP25, LP7/LP10).
  - [ADR 0024](0024-slot-action-descriptor-and-menu.md) — сами ДЕЙСТВИЯ подаются
    как дескрипторы `RowAction` в слоте `actionRowSlot` и при `rowActionMenu`
    схлопываются в per-row кебаб; оттуда же — `collapsedWidth` (AM15–AM19).
  - [ADR 0009](0009-test-coverage-visual-and-performance.md) — покрытие визуальными
    тестами; собственные требования кодируются префиксом `RA<n>`, состояние
    читается из контракта DOM.

## Контекст

Потребителю нужен ряд действий над строкой (редактировать / дублировать /
удалить …) в **фиксированном замыкающем столбце**, всегда видимом при прокрутке.
Столбец — **служебный**: без данных, с пустым заголовком; конкретные же действия
задаёт потребитель дескрипторами `RowAction` в слоте `actionRowSlot`
([ADR 0024](0024-slot-action-descriptor-and-menu.md)). Плагин `rowActions`
отвечает только за **колонку**: её инъекцию, позицию (замыкающая), ширину и
авто-закрепление вправо.

Исторически требования к этой колонке разошлись по соседним ADR (композиция
служебных колонок — [0010](0010-invert-core-plugins-registry.md); пиннинг —
[0011](0011-column-pinning.md); подача действий и кебаб —
[0024](0024-slot-action-descriptor-and-menu.md)), и отдельного источника истины у
неё не было. Этот ADR консолидирует поведение колонки действий: замыкающая
позиция, авто-пин вправо, ширина «следует за подачей», поведение под вложенной
шапкой и в двустороннем пиннинге, — плюс таблицу требований, где собственные
`RA<n>` дополняют перекрёстные ссылки на существующие наборы.

## Решение

### Форма плагина

`rowActions(opts)` (`src/lib/plugins/rowActions/registry.ts`) возвращает
`RegistryEntry` без собственной фичи (`feature: {}` — поведение выражено
композицией ядра) и объявляет служебную колонку записью:

```ts
column: {
  id: ROW_ACTIONS_COLUMN_ID,
  make: getRowActionsColumn,
  side: 'trailing',
  order: 0,
  pin: { side: 'right', when: 'always' },
}
```

Presence-based ([ADR 0010](0010-invert-core-plugins-registry.md)): включается
фабрикой `rowActions({ width, collapsedWidth })` в массиве `plugins`; вне набора —
колонки нет (gate наличием фичи, `service-columns` R8).

### Служебная колонка

`getRowActionsColumn(depth)` (`rowActionsColumn.ts`) строит колонку: **пустой
заголовок** (`header: undefined`), `enablePinning`/`enableSorting`/
`enableResizing`/`enableDragging` = `false`, `size`/`minSize` = 0 (реальную ширину
задаёт автосайз, ниже). Под **вложенной шапкой** (`depth > 1`) колонка
оборачивается в служебные группы (`${ROW_ACTIONS_COLUMN_ID}-group-level-N`), чтобы
замыкать ряд на всех уровнях шапки (RA1).

### Позиция и авто-закрепление

`side: 'trailing'`, `order: 0` → колонка **последняя** в ряду. `pin: { side:
'right', when: 'always' }` → закреплена вправо **всегда** — даже без
`enableColumnPinning` и без пользовательских пинов (CP14). Стык с **двусторонним
пиннингом** ([ADR 0011](0011-column-pinning.md)): по умолчанию колонка **без
подложки**; при появлении пользовательского правого пина её тело и заголовок
получают ту же подложку, заголовок становится `sticky`, выравнивается с телом и
остаётся без контента (CP23), пользовательский right-pin встаёт **левее** неё
(CP24), разделитель у неё не рисуется никогда, а reorder-out её не трогает
(LP7/LP10).

### Ширина «следует за подачей»

`width` (по умолчанию **120**) — когда действия показаны инлайн рядом кнопок;
`collapsedWidth` (по умолчанию **56**) — когда `rowActionMenu` схлопывает
`actionRowSlot` в один ⋮ (иначе фиксированная ширина под ряд кнопок оставляла бы
пустоту). Ширина применяется через generic-механизм ядра
`table.setColumnAutoSizing` в хуке `setup` (обобщённый escape для императивного
сетапа, [ADR 0010](0010-invert-core-plugins-registry.md)); `setup`
перезапускается при смене активного набора плагинов, поэтому toggle меню меняет
ширину без перезагрузки (RA2). Владелец ширины — плагин колонки; факт «слот
схлопнут» читается из общей опции `actionMenu.actionRowSlot`, не из внутренностей
соседа.

### Подача действий (перекрёстно, ADR 0024)

Сами действия — дескрипторы `RowAction` в `actionRowSlot`, их даёт потребитель
(демо — `rowActionsDemo`). Инлайн они рисуются рядом **row-кнопок-чипов** (ревил
по hover строки; каждая кнопка — непрозрачный чип с тенью, чтобы читаться поверх
прокручиваемого контента под sticky-прозрачной колонкой, CP25); при
`rowActionMenu` схлопываются в per-row overflow-кебаб (AM15–AM19).

### Контракт DOM

- **`data-column-id` = `actionColumn__rowActions`** и **`data-actions-column-cell`
  = `true`** на ячейках колонки (маркер служебной; тем же атрибутом помечены и
  ведущие служебные столбцы — селектор именно rowActions фильтрует по
  `data-column-id`).
- **`data-cell-pinned='right'`** — авто-закрепление.
- **пустой заголовок** — контентом колонку наполняют только `actionRowSlot`.

## Последствия

- **+** Колонка переиспользует общий механизм служебных колонок
  ([ADR 0010](0010-invert-core-plugins-registry.md)) и авто-пиннинга
  ([ADR 0011](0011-column-pinning.md)) — своего «источника истины» по позиции и
  закреплению не заводит.
- **+** Действия развязаны с колонкой: плагин даёт **место**, потребитель —
  **дескрипторы** ([ADR 0024](0024-slot-action-descriptor-and-menu.md)).
- **+** Ширина следует за подачей автоматически (инлайн ↔ кебаб) без перезагрузки.
- **−** Требования исторически размазаны по R/CP/AM/LP; этот ADR консолидирует их
  ссылками, а `RA<n>` добивает не покрытые общими наборами пробелы.
- **±** Колонка помечена `data-actions-column-cell` как все служебные столбцы,
  поэтому селекторы, адресующие именно rowActions, обязаны фильтровать по
  `data-column-id` (иначе цепляют ведущие служебные).
