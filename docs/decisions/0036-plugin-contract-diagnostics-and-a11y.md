# 0036 — Контракт встроенного плагина: диагностика и доступность

- **Статус:** Принято
- **Дата:** 2026-09-29
- **Связано:**
  - [ADR 0022](0022-plugin-compatibility-contract.md) — логгер, dev-warn'ы
    инертности из гейтов `getCan*` (PC1–PC6, PC11) и снимок
    `getPluginDiagnostics()` (PC12–PC14). Этот ADR делает их обязательными для
    каждого встроенного плагина.
  - [ADR 0028](0028-define-plugin-authoring-api.md) — `definePlugin`, поле
    `diagnose`.
  - [ADR 0020](0020-accessibility.md), [ADR 0031](0031-wcag-keyboard.md),
    [ADR 0032](0032-wcag-aa-remainder.md), [ADR 0034](0034-wcag-22-dragging-and-target-size.md)
    — требования доступности, которые плагин обязан соблюдать.
  - [ADR 0035](0035-toolbar-and-column-visibility.md) — columnVisibility без
    тулбара (CV19).

## Контекст

ADR 0022 сделал слышимыми инертные состояния пяти плагинов, но правило
действовало точечно: остальные плагины в нём не упоминались. Аудит нашёл ещё
случаи «подключён, но без эффекта», о которых никто не сообщал:

- `columnVisibility` без `enableToolbar` — нет кнопки «Колонки», а скрытую из
  кебаба колонку нечем вернуть;
- `headerActionMenu` / `rowActionMenu` без единого действия в своих слотах —
  схлопывать нечего;
- `contextMenu` без пунктов — правый клик ничего не открывает;
- `rowActions` без действий строки — пустая колонка.

Доступность тоже проверялась выборочно: axe гонялся на наборах фич (A5, A7), а не
на каждом плагине. Новый плагин мог не попасть ни в один прогон.

## Решение

**Каждый встроенный плагин обязан сообщать о своей инертности и проходить axe.
Оба правила проверяются тестами, которые перечисляют плагины из
`@tessera-grid/tessera/plugins` автоматически: новый плагин без диагностики или без
axe-прогона роняет сборку.**

### Диагностика

- **`diagnose` обязателен.** Плагин, у которого нет условий инертности, объявляет
  это явно общей константой `neverInert` из `core/pluginDiagnostics.ts`. Так
  «не подумали» отличимо от «инертным не бывает».
- **Причина — одна функция.** Гейт `getCan*`, `diagnose` и предупреждение
  берут причину из одного места, чтобы снимок и лог не расходились (как в
  ADR 0022).
- **Статические причины ядро предупреждает само.** При монтировании и при смене
  набора плагинов ядро проходит по `getPluginDiagnostics()` и для каждой инертной
  записи (кроме `enabled: false` — это намеренное отключение) печатает dev-warn с
  ключом `<id>:<reason>`. Так плагину без своих гейтов (меню, тулбарные кнопки)
  не нужно искать место для вызова логгера.
- **Причины, зависящие от состояния** (активная группировка, сортировка),
  по-прежнему предупреждают лениво из гейтов (ADR 0022): при монтировании их может
  ещё не быть. Ключ тот же, поэтому повтор не печатается.
- **Поверхности без содержимого инертны** с причиной `'noActions'`: плагин-меню,
  контекстное меню и колонка действий, которым нечего показать.

### Доступность

- **Каждый встроенный плагин проходит axe** в гриде, где он включён (с
  минимальным окружением, без которого у плагина нет UI: тулбар для
  `columnVisibility`, действия для меню).
- **Клавиатура и размер целей** — по [ADR 0031](0031-wcag-keyboard.md) и
  [ADR 0034](0034-wcag-22-dragging-and-target-size.md): плагин с интерактивным UI
  заводит свои требования клавиатурного доступа там же (как KB/DA), а не
  отдельно. Этот ADR не дублирует их.
- **Подписи — из `localization`, иконки — из `icons`** (жёсткий инвариант
  AGENTS.md); axe `button-name` проверяет, что имя у контрола есть.

## Последствия

- **+** «Плагин подключён, но не работает» слышно для каждого встроенного плагина,
  а снимок `getPluginDiagnostics()` показывает причину.
- **+** Новый плагин не может тихо пропустить диагностику или axe: тесты
  перечисляют плагины сами.
- **−** Больше предупреждений в dev-консоли: сторис и приложения с неполной
  конфигурацией (меню без действий, `columnVisibility` без тулбара) теперь
  предупреждают. Это и есть цель; в проде логгер молчит.
- **−** Поведение `columnVisibility` без тулбара меняется: «Скрыть колонку» из
  кебаба пропадает (CV19).

## Требования

По конвенции ([ADR 0001](0001-spec-driven-development.md),
[ADR 0009](0009-test-coverage-visual-and-performance.md)) каждое требование — один
тест с префиксом `PQ<n>:`.

| ID  | Требование                                                                                                                                                                                      | Тест                                           |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| PQ1 | Каждый встроенный плагин (все фабрики `@tessera-grid/tessera/plugins`) объявляет `diagnose`; плагин без условий инертности — константой `neverInert`                                            | `__tests__/pluginContract.test.ts` `PQ1:`      |
| PQ2 | При монтировании ядро печатает dev-warn для каждой активной записи, чей `diagnose` вернул причину, — один раз на `<id>:<reason>`; `enabled: false` и работающие плагины молчат                  | `__tests__/pluginContract.dom.test.tsx` `PQ2:` |
| PQ3 | Поверхности без содержимого инертны с причиной `'noActions'`: `headerActionMenu` (нет действий в его слотах), `rowActionMenu` и `rowActions` (нет действий строки), `contextMenu` (нет пунктов) | `__tests__/pluginContract.test.ts` `PQ3:`      |
| PQ4 | Каждый встроенный плагин, включённый в гриде, проходит axe без нарушений; набор проверенных плагинов совпадает с набором встроенных                                                             | `visual/plugin-a11y.test.tsx` `PQ4:`           |

Инертность конкретных плагинов по-прежнему закрыта их собственными требованиями:
PC1–PC6, PC11 ([ADR 0022](0022-plugin-compatibility-contract.md)), CV19
([ADR 0035](0035-toolbar-and-column-visibility.md)).
