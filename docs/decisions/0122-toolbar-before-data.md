# 0122 — Тулбар до прихода данных

- **Статус:** Принято (реализовано 2026-10-17; решения — по итогам прожарки 2026-10-17)
- **Дата:** 2026-10-17
- **Связано:**
  - [ADR 0060](0060-initial-loading-skeleton.md) — скелет первой загрузки: компоненты
    слотов решают сами через `isSkeletonShown(table)` (§4, SL21); **изменяется** здесь:
    кнопки тулбара больше не «не меняются» все — клиентский экспорт и контролы без колонок
    показывают скелет (SL11); шапка без кнопок плагинов (SL4) и `inert` скелета (SL12)
    не меняются.
  - [ADR 0121](0121-shared-skeleton-wave.md) — общая волна скелетов рамки, панели в ней.
  - [ADR 0035](0035-toolbar-and-column-visibility.md), [ADR 0051](0051-toolbar-button-order.md)
    — тулбар, меню «Колонки», порядок кнопок.
  - [ADR 0044](0044-export.md), [ADR 0073](0073-xlsx-export.md) — экспорт: оси, серверная
    выгрузка `onExport`, `table.exportData`.
  - [ADR 0045](0045-filtering.md), [ADR 0048](0048-option-filtering.md) — сводка фильтров
    в тулбаре, фильтр вариантов.
  - [ADR 0053](0053-quick-search-columns-hint.md) — подсказка колонок поиска, выключенное
    поле без колонок поиска.
  - [ADR 0116](0116-async-server-actions.md) — серверные действия, `signal` и замена
    ожидающего действия.
  - [ADR 0120](0120-model-and-interface-plugins.md) — `server` у `quickSearchModel`,
    `columnFilteringModel`.

## Контекст

Во время первой загрузки (`loading: 'initial'`) грид рисует скелет по раскладке таблицы, а
тулбар — как после загрузки: ADR 0060 (§4, SL11) записал, что кнопки тулбара «от данных не
зависят и не меняются». Это верно не для всех:

- **клиентский экспорт** до данных выгружает файл с одной шапкой — выглядит как
  выгрузка, а данных в нём нет;
- **без колонок** (`columns: []` — приложение получает колонки с сервера, ADR 0060 SL9)
  меню «Колонки» пустое, поле поиска выключено, хотя колонки вот-вот придут.

При этом поиск, сводка фильтров и экспорт бывают и клиентскими, и серверными: серверному
режиму данные на клиенте не нужны, и блокировать его по признаку «данных нет» нельзя.

Панели фильтров колонок, включая фильтр вариантов, до данных не открыть: кнопок плагинов в
шапке скелета нет (SL4), сам скелет `inert` (SL12), а сводка «Фильтры» панели колонки не
открывает. Пустой список вариантов до данных пользователь не увидит.

### Как это сделано у других

- **AG Grid** — экспорт (`exportDataAsCsv`, `exportDataAsExcel`) на время загрузки не
  блокируется: строк нет — файл с шапкой. Тулбара нет, кнопки — у приложения.
- **MUI X** — `GridToolbarExport` и quick filter во время `loading` доступны; выгрузка без
  строк — файл с шапкой.
- **TanStack Table** — тулбара нет, решает приложение.

Встроенного ответа на «что в тулбаре до данных» ни у кого нет; у Tessera тулбар свой,
поэтому отвечает плагин — хозяин компонента слота.

## Решение

### 1. Принцип и ответственность

Что показать до прихода данных, решает компонент слота плагина через `isSkeletonShown(table)`
(ADR 0060 §4). Функция тулбара **доступна**, если её результат — изменение запроса или
состояния:

- в клиентском режиме состояние применяется к пришедшим строкам;
- в серверном приложение получает колбэк и перезапрашивает данные; отменить или заменить
  первый запрос — договор приложения (как с `signal` в ADR 0116).

На месте контрола — **скелет**, если результат вычисляется из строк на клиенте или если
колонок, над которыми работает функция, ещё нет. «Колонки известны» — у таблицы есть
листовые колонки данных; служебные колонки (выбор, раскрытие, ручка, действия) не
считаются.

### 2. Функции тулбара

| Функция   | Клиентский режим                                 | Серверный режим                  | До данных                                                  |
| --------- | ------------------------------------------------ | -------------------------------- | ---------------------------------------------------------- |
| Поиск     | Запрос в `globalFilter`, применяется к пришедшим | `onSearchChange` сразу           | Доступен; без колонок — скелет поля                        |
| «Фильтры» | Фильтры начального состояния видны и снимаются   | Снятие — колбэк приложению       | Как после загрузки; без фильтров или без колонок выключена |
| «Колонки» | Меню по описанию колонок                         | Режима нет: видимость клиентская | Доступна; без колонок — скелет кнопки                      |
| «Экспорт» | Выгрузка из строк модели                         | `onExport` приложения            | Клиентский — скелет кнопки; с серверным вариантом доступен |

- **Скелет на месте контрола** — примитив `Skeleton` кита по видимой части контрола, а
  место — как у контрола. У кнопки тулбара фон прозрачный и видна только иконка: скелет —
  квадрат иконки `--tsr-comp-button-icon-size` со скруглением скелета
  `--tsr-comp-skeleton-radius` в центре места кнопки `--tsr-comp-toolbar-button-size`. У
  поля поиска видна рамка: скелет — `--tsr-comp-quick-search-width` ×
  `--tsr-comp-toolbar-button-size` со скруглением `--tsr-comp-control-radius`. Данные или
  колонки пришли — контрол встаёт на то же место, соседи не сдвигаются.
- **Экспорт с серверным вариантом.** Кнопка настоящая. Одна комбинация, и она серверная, —
  клик выгружает сразу через `onExport`. В панели клиентские значения оси «Строки»
  недоступны до данных, выбрано первое доступное — тем же механизмом, каким сейчас
  пропадает «выбранные» без выбора.
- **Пустой результат после загрузки** не меняется: обычная кнопка, файл с шапкой — честный
  итог, как у AG Grid и MUI X. Блокировка — только по `isSkeletonShown`.
- **Поле поиска после загрузки** без колонок поиска остаётся выключенным с подсказкой
  (ADR 0053); скелет — только во время первой загрузки.

### 3. Вид и доступность скелетов

Скелеты тулбара — в общей волне рамки (ADR 0121): при уменьшенном движении без волны, в
`forced-colors` — `GrayText`, как остальные скелеты. Скелет не фокусируется и скрыт от
скринридера; roving-фокус тулбара (Base UI Toolbar) его пропускает, после загрузки контрол
встаёт в порядок на своё место (ADR 0051).

### 4. `table.exportData()`

Вызов из кода приложения во время первой загрузки не блокируется: это явное решение
приложения. Клиентская выгрузка в это время в dev предупреждает, что данных ещё нет и файл
выйдет с одной шапкой.

## Отвергнутые альтернативы

- **Скелет во весь квадрат кнопки тулбара.** Фон кнопки прозрачный, видна только иконка:
  квадрат `--tsr-comp-toolbar-button-size` выглядел крупнее самой кнопки.
- **Выключенная кнопка экспорта с причиной в тултипе** (как заблокированный пункт меню,
  ADR 0078). Скелет повторяет вид остальной рамки во время загрузки и не требует подписи;
  причина «данные загружаются» и так видна по скелету таблицы.
- **Скрыть кнопку до данных.** Соседи в тулбаре сдвигаются при приходе данных — ломает
  «ничего не сдвигается» ADR 0060.
- **Блокировать весь экспорт, включая серверный.** У сервера данные есть; запрет без
  причины.
- **Блокировать поиск и сводку фильтров до данных.** Их результат — состояние запроса, а не
  производная строк; серверному режиму данные на клиенте не нужны.
- **Блокировать клиентский экспорт и при пустом результате после загрузки.** Файл с шапкой
  после загрузки — честный итог; до загрузки — нет.
- **Состояние «загрузка» в панели фильтра вариантов.** Панель до данных не открыть (SL4,
  SL12); защита от недостижимого состояния.

## Границы

- Панели фильтров колонок и фильтр вариантов — вне объёма (см. «Контекст»).
- Нижняя панель не меняется: её числа уже скелеты (ADR 0060, SL11).
- Свой компонент слота приложения или автора плагина решает сам через `isSkeletonShown`
  (SL21); грид чужие контролы не подменяет.

## Последствия

- **Публичный API** не меняется; ломающих изменений нет.
- **ADR 0060:** §4 и SL11 — кнопки тулбара по этому ADR; пункт «Скелеты кнопок тулбара —
  не входят» снят.
- **Плагины:** `dataExport`, `columnVisibility`, `quickSearch` читают `isSkeletonShown`
  и известность колонок; `columnFiltering` (сводка) — без изменений.
- **Локализация:** новых подписей нет.
- **Документация:** `docs/architecture/rendering.md` — каталог видов скелетов дополняется
  скелетами тулбара.
- **Перф (TQ6)** неприменим: новое состояние — до трёх контролов тулбара, а не массовое.
- **Договор с приложением:** ввод запроса или снятие фильтра до данных в серверном режиме
  даёт второй запрос; гонку ответов разрешает приложение.
