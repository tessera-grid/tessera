## Контекст

Раскрываема только строка с `subRows`: раскрыть строку без детей, чтобы догрузить их с
сервера, нельзя, а колонка раскрытия на таких данных скрыта (roadmap, «Известные
проблемы»). Для highload-деревьев — справочники, оргструктуры, иерархии счетов — это
основной режим: дети узла приходят по запросу.

Ожидание уже есть: промис от `onExpandRow` переводит тоггл в ожидание, отказ
сворачивает строку (ADR 0041, §3). Но приложение само должно вставить детей в своё
дерево (поиск родителя и иммутабельное обновление), грид не знает ни о пустом ответе,
ни об ошибке, а ошибку пользователь не видит вовсе.

Это первый срез серверной модели строк (roadmap, «Server-Side Row Model»): грид
впервые владеет частью данных — последним ответом сервера на «дети узла».

## Решение

### 1. API: `hasChildren` и `loadChildren`

```ts
rowExpanding({
  hasChildren: row => row.original.childCount > 0,
  loadChildren: row => api.children(row.id), // TData[] | Promise<TData[]>
})
```

- **`hasChildren(row)`** — у строки есть дети, которых нет в `subRows`. Строка
  раскрываема, если `subRows.length > 0` или `hasChildren(row)`; `maxDepth` действует
  одинаково. При активной группировке `hasChildren` не вызывается — раскрытием
  владеет `rowGrouping` (ADR 0022).
- **`loadChildren(row)`** — загрузка детей; вызывается на **каждое** раскрытие
  строки без `subRows` в данных. Возвращает массив (применяется сразу, без ожидания)
  или промис. Кэш, свежесть, дедупликация и отмена запросов — на приложении.
- Строка, у которой `subRows` уже есть в данных, — обычная: `loadChildren` не
  вызывается.
- `onExpandRow(row, expanded)` по-прежнему уведомляет о переключении. Если задан
  `loadChildren`, ожидание ведёт его промис, а промис `onExpandRow` игнорируется.
- Оба аргумента живые (ADR 0039).

### 2. Последний ответ держит грид

Ответ — срез плагина `loadedChildren: Record<rowId, TData[]>`; исходная модель берёт
детей строки из `subRows` данных, иначе — из среза. Грид держит **последний ответ**,
чтобы его показывать; политика свежести — у приложения. Правила:

- **Первое раскрытие** — `loadChildren(row)`; ответ кладётся в срез и показывается.
- **Повторное раскрытие** сразу показывает сохранённых детей и одновременно зовёт
  `loadChildren`; новый ответ заменяет детей (stale-while-revalidate).
- **Сворачивание** ответ не трогает.
- **Пустой ответ** (`[]`) — строка становится листом (тоггла нет) до следующей смены
  `data`: ответ сервера свежее, чем `hasChildren`.
- **Смена `data`** — ответ остаётся по `id` строки: серверная сортировка соседей не
  схлопывает раскрытую строку.
- **Строка ушла из `data`** — её ответ удаляется (согласование, ADR 0040).
- **Поздний ответ** прежней попытки игнорируется (номер попытки, как у AS11).
- **`table.setLoadedChildren(rowId, rows | updater)`** — приложение заменяет
  сохранённый ответ строки, раскрытой или свёрнутой: после правки ребёнка
  (`onCellEdit` получает строку ребёнка, а данные ребёнка — у грида), по фоновой
  инвалидации кэша или push с сервера. Для строки без ответа вызов игнорируется.
- **`table.resetLoadedChildren(rowId?)`** — удаляет ответ строки (без аргумента — все
  ответы); раскрытая строка без ответа сворачивается.

Пример с TanStack Query — свежий кэш отдаётся синхронно, без ожидания:

```ts
rowExpanding({
  hasChildren: row => row.original.childCount > 0,
  loadChildren: row =>
    queryClient.getQueryData(childrenKey(row.id)) ??
    queryClient.fetchQuery({
      queryKey: childrenKey(row.id),
      queryFn: () => api.children(row.id),
    }),
})
// фоновое обновление кэша Query → table.setLoadedChildren(rowId, rows)
```

Приход ответа пересобирает исходную модель строк — тот же радиус, что смена `data`
(в v9 исходная модель зависит только от входа данных). Цена замеряется (RE38).

### 3. Ожидание — на тогле

Общий паттерн ожидания Tessera: его показывает контрол, запустивший запрос (ADR 0055).
Тоггл остаётся тем же, с шевроном; пока промис `loadChildren` (или `onExpandRow`) не
выполнен, он в состоянии `pending` базовой кнопки — блик бежит по контуру,
`aria-busy`, повторное нажатие игнорируется. Строка раскрывается сразу и несёт
`aria-busy="true"` (как AS11). Строка-скелетон под раскрытой строкой отвергнута (см.
ниже).

### 4. Ошибка: вспышка и объявление

Отказ промиса (`loadChildren` или `onExpandRow`):

- **Нет сохранённого ответа** — строка сворачивается обратно.
- **Есть сохранённый ответ** — строка остаётся раскрытой со старыми детьми.
- В обоих случаях контур тоггла **вспыхивает** цветом ошибки — блик заливает контур
  с места, где стоял (`errorFlash` базовой кнопки, ADR 0055), а отказ **объявляется** в live-области: `announceExpandFailed(error)`
  («Couldn't load: …»). Текст ошибки — по правилу AS10: `Error.message`, строка как
  есть, иначе подпись `loadChildrenFailed`. Цвет — не единственный носитель сигнала
  (WCAG 1.4.1, 4.1.3).
- Следующая попытка — повторный клик; стойкой метки ошибки нет.

Это меняет ADR 0041, §3 («сообщение об ошибке показывает приложение»): вспышка и
объявление — для любого отказа раскрытия, в том числе от `onExpandRow` без
`loadChildren`.

### 5. Раскрытое без действия пользователя

`expanded: true`, начальное состояние и «раскрыть всё» `loadChildren` не вызывают:
загрузку начинает только действие пользователя. Ленивая строка с сохранённым ответом
показана раскрытой с ним; без ответа и без ожидания — в эффективном состоянии
свёрнута (сужение `expanded`, ADR 0039), сохранённый срез не меняется.

### 6. Сочетания с плагинами

- **`rowSelection`** — дети выбранного родителя приходят невыбранными (выбор — по
  `id`, их в нём не было); выбор родителя не меняется: грид срез выбора не трогает.
  «Частично выбран» TanStack показывает только при выбранном ребёнке, поэтому родитель
  остаётся отмеченным.
- **Сортировка, фильтр, экспорт** (клиент) — работают по загруженным детям; экспорт
  `all` выгружает только загруженное.
- **Пагинация** — страницы по верхнему уровню (ADR 0038), приход детей страницы не
  сдвигает.
- **`keyboardNavigation`** — `Enter` на ячейке колонки раскрытия тем же путём;
  активная ячейка — по индексам (осознанный контракт ADR 0021).
- **Колонка** при `column: 'auto'` видна, если `hasChildren` истинно хоть у одного
  корня исходных данных.

## Границы

- **Строка-заглушка «нет данных»** для пустого ответа — не входит: строка становится
  листом.
- **Число детей и скелетон** под строкой — не входит (см. «Отвергнутые альтернативы»).
- **Отмена запроса** (`AbortSignal`), таймауты, повторы, кэш и его свежесть — на
  приложении.
- **Блочная подгрузка детей** (тысячи детей одного узла кусками) — часть SSRM, не здесь.
- **Ленивые дети под группировкой** — не входит: строки-группы синтетические.

## Отвергнутые альтернативы

- **Дети в `data` приложения** (`onExpandRow` вставляет их в дерево). Чистая модель
  владения, но хирургия дерева в каждом приложении, грид не видит пустой ответ и
  ошибку; SSRM всё равно приведёт к кэшу у грида.
- **Удалять ответ при сворачивании.** Каждое повторное раскрытие проходило бы через
  ожидание и пустой кадр даже при свежем кэше приложения.
- **Свой кэш грида с политикой свежести.** Свежесть — бизнес-решение приложения; грид
  держит только последний ответ.
- **Строка-скелетон под раскрытой строкой.** Синтетическая строка в модели:
  виртуализация, `aria-setsize`/`posinset`, навигация, «выбрать всё», экспорт и
  пагинация должны её пропускать — много межплагинных требований ради вида.
- **Отдельная иконка загрузки вместо шеврона.** Тоггл менял бы вид; блик по контуру
  кнопки — общий паттерн (ADR 0055).
- **Грузить детей всех раскрытых строк** при `expanded: true` — сотни запросов разом.
- **Стойкая метка ошибки** на тогле — в строке нет места для текста, а повтор — тот же
  клик.
- **Поле в данных** (`row.original.hasChildren`) — диктует форму `TData`.

## Последствия

- **+** Ленивое дерево — двумя аргументами фабрики, без хирургии данных в приложении;
  кэш приложения (TanStack Query и т. п.) работает без ожидания.
- **+** Пустой ответ и ошибка видны пользователю; паттерн ожидания один на весь грид.
- **+** Модель «грид держит ответ сервера по узлу» — заготовка кэша SSRM.
- **−** Грид впервые владеет частью данных: правка ребёнка и фоновое обновление кэша
  требуют `table.setLoadedChildren`.
- **−** Ответы живут, пока строка есть в `data`; память освобождает
  `table.resetLoadedChildren`.
- **−** Приход ответа на 100 000 корней — ~215–225 мс под ×4 CPU: известный недостиг
  RE38 с регресс-потолком 300 мс (roadmap, «Известные проблемы»). Модель собирается из
  прежней — пересобираются только изменённые поддеревья
  ([ADR 0067](0067-incremental-lazy-core-row-model.md)); асинхронные ответы, пришедшие
  до кадра, применяются пачкой ([ADR 0066](0066-lazy-children-answer-batching.md));
  фильтрация и группировка без работы не обходят строки
  ([ADR 0068](0068-idle-filter-and-group-passes.md)); словарь `rowsById` переходит
  новой модели без копии ([ADR 0069](0069-rowsbyid-handover.md)); модель раскрытия
  обходит заново только затронутые корни
  ([ADR 0070](0070-incremental-expanded-row-model.md)).
- **Публичный API:** аргументы `hasChildren`, `loadChildren`; методы
  `table.setLoadedChildren`, `table.resetLoadedChildren`; ключи локализации
  `announceExpandFailed`, `loadChildrenFailed`. Ломающих изменений нет; поведение
  отказа `onExpandRow` меняется с молчаливого на вспышку и объявление.
