## Контекст

Строки тела стоят абсолютно по `top: virtualRow.start`. При раскрытии, сворачивании,
сортировке и фильтре строки меняют `top` мгновенно, новые появляются и уходящие исчезают
за кадр: глаз теряет, куда делась строка. Плавно поворачивается только шеврон (RE41).

При перетаскивании строки соседи сдвигаются `transform` от dnd-kit без перехода —
прыжком на высоту строки, — и слот-заливка прыгает вместе с ними. При броске облако
гаснет со сдвигом на 5px, а не приземляется в слот.

После броска колонки сосед переезжал обратно, потому что переход `transform` снимал сдвиг
уже после смены порядка (ADR 0006, D38). У строк та же ловушка: анимировать нужно видимое
положение, а не логическое.

### Как это сделано у других

- **AG Grid** (`animateRows`, включено по умолчанию) — строки ездят `translateY` с
  переходом при раскрытии, сортировке, фильтре и перестановке; новые проявляются,
  уходящие живут в DOM и гаснут; около 400 мс.
- **MUI X, Mantine React Table, TanStack Table** — движения строк нет; перестановка в
  MUI X — призрак без сдвига соседей.
- **Notion, Linear, Finder** — плавное раскрытие, при перетаскивании соседи
  раздвигаются вживую.

## Решение

### 1. Механизм — FLIP в рендер-слое

Перед коммитом грид запоминает **видимые** позиции смонтированных строк — с их текущим
`transform`. После коммита строка, сменившая позицию, получает обратный сдвиг
`translateY` без перехода и в следующем кадре уезжает на место CSS-переходом. Видимые
позиции, а не логические: после броска строки уже стоят на месте, и сдвиг равен нулю —
повторного переезда нет (урок D38).

Двигаются только строки окна виртуализации. Анимация — CSS-переходы, а не
`element.animate`: уменьшенное движение гасит их общее правило темы (MO3). Покадровой
перерисовки React нет — в коммите ставятся стартовый сдвиг и класс перехода.

### 2. Когда строки двигаются

Анимируется любая смена **модели строк** — порядка или состава: раскрытие и
сворачивание (дерево и группы), приход ленивых детей и пачки ответов, сортировка,
фильтр и поиск, перестановка мышью, с клавиатуры и из меню, новые `data` с теми же `id`,
включение и снятие группировки.

Геометрия без смены модели не анимируется: смена `rowHeight`, ширины контейнера,
прокрутка.

**Замена целиком — без анимации.** Если из строк окна после смены не уцелела ни одна
(смена страницы, первая загрузка, скелет → данные, новый набор с другими `id`), всё
встаёт сразу: иначе мигало бы всё окно.

### 3. Появление и уход

- Строка, которой не было в модели, проявляется (`opacity`) на своём месте.
- Строка, ушедшая из модели, гаснет **призраком** на своём старом месте одну
  длительность и уходит из DOM. Призрак строится из строки прошлой модели, он вне
  доступности и ввода: `inert`, `aria-hidden`, не в `aria-rowcount`, не цель клика,
  выбора, навигации и DnD.
- При сворачивании дети гаснут призраками, а строки ниже поднимаются на их место.

### 4. Строка издалека

Строка, которая до смены стояла далеко за краем окна (сортировка), въезжает от края окна
с нужной стороны: стартовая позиция — старая, но не дальше края. Направление движения
читается, темп тот же.

### 5. Перетаскивание

- Соседи и слот-заливка сдвигаются переходом только на время сессии перетаскивания.
- При броске облако долетает до места слота (анимация броска dnd-kit), слот плавно
  становится строкой.
- После броска ни одна строка не переезжает повторно (видимые позиции, §1).

### 6. Тема, флаг, уменьшенное движение

- Токен `--tsr-comp-row-motion-duration` — 250 мс, выведен из базового:
  `calc(var(--tsr-comp-motion-duration) * 5 / 3)`; кривая — общая
  `--tsr-comp-motion-easing`.
- Флаг ядра `enableRowAnimation` в `useCreateTable`, по умолчанию `true`; `false` —
  мгновенно, как раньше.
- `prefers-reduced-motion: reduce` — без движения и проявления, сразу конечное
  состояние.

### 7. Посреди анимации

- Прокрутка, быстрая прокрутка (ADR 0008) и `scrollToRow` (ADR 0104) доводят анимацию до
  конца за кадр.
- Новая смена модели во время анимации стартует с текущего видимого положения, без
  скачка.
- Контракт активной ячейки не меняется (ADR 0021): она по индексам, после смены модели
  фокус на ячейке той же позиции; клавиатурный фокус не теряется и не уходит из грида,
  призраки его не получают.

### 8. Совместимость

- Механизм работает на React 18 и всех 19.x одинаково: нужны только layout-эффекты и
  CSS-переходы (ADR 0091).
- Переходы и `transform` есть во всём пороге браузеров (ADR 0084).
- Грид не мешает View Transitions приложения: не зовёт `document.startViewTransition` и
  не ставит строкам `view-transition-name`. Обёртка приложения `<ViewTransition>` вокруг
  грида анимирует его целиком, движение строк внутри работает по-прежнему.

## Отвергнутые альтернативы

- **View Transitions (`<ViewTransition>` React 19.3, `document.startViewTransition`).**
  Задача та же — переезд, появление и уход, и уходящие элементы браузер рисует сам (не
  нужны призраки). Отвергнуто:
  - React запускает переход только для обновлений-переходов (`startTransition`,
    `Suspense`, `useDeferredValue`). Состояние грида живёт в TanStack Store и читается
    через `useSyncExternalStore` (ADR 0026), а изменения внешнего хранилища React
    выполняет как блокирующие — переход не начнётся даже внутри `startTransition`.
  - Снимки рисуются в верхнем слое поверх страницы и по умолчанию не обрезаются
    прокручиваемым телом, липкими шапкой и футером — строки летали бы поверх них.
    Обрезку дают вложенные группы (`view-transition-group`), их нет во всём пороге.
  - Переходы внутри документа есть с Chrome и Edge 111, Safari 18, Firefox 144; порог
    грида — Safari 17.1 и Firefox 128 (ADR 0084).
  - `ViewTransition` стабилен только с React 19.3; пакет обещает `react ^18 || ^19` —
    второй механизм для старых версий всё равно нужен.
  - Переход один на документ: грид прерывал бы переходы маршрутов приложения и наоборот.
  - Перетаскивание идёт за указателем каждый кадр — это не переход между состояниями.

  Пересмотр — в [roadmap](../roadmap.md#запланировано).

- **Только явные действия** (раскрытие, бросок, перестановка) — предсказуемее и дешевле,
  но сортировка и фильтр остались бы прыжком; выбрана любая смена модели, как в AG Grid.
- **Переход по `top`** — каждый кадр перекладывает раскладку всех двигающихся строк;
  `transform` — только композиция.
- **Дети исчезают сразу при сворачивании** — проще (без призраков), но на кадр виден
  пустой промежуток; несимметрично раскрытию.

## Границы

- Колонки не двигаются этим механизмом: порядок — ADR 0006, ширина — ADR 0013.
- Прокрутки к раскрытым детям, ушедшим ниже окна, нет.
- Строки, не попавшие в окно ни до, ни после смены, не анимируются.

## Последствия

- Поведение по умолчанию меняется: смены модели плавные. API не ломается; вернуть
  мгновенное — `enableRowAnimation: false`.
- На смену модели нужна карта «`id` → старая позиция» для строк окна. Строится только
  когда в окне есть уцелевшие строки; цена — в RM20.
- Призраки — строки прошлой модели в DOM на одну длительность: навигация, выбор,
  `aria-*` и DnD их пропускают (RM3).
