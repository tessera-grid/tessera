# 0211 — Отложенная запись мест сдвинутых строк

- **Статус:** Принято (решение автора 2026-11-11)
- **Дата:** 2026-11-11
- **Слой:** ядро — места строк (`core/rowPosition.ts`) и смена `data` (`core/dataChanges.ts`); плагин
  модели сортировки — поиск уходящей строки (`plugins/columnSortingModel/sortedRowModel.ts`). Места
  строк — факт хранилища ядра, его читают модели плагинов и перетаскивание.
- **Дополняет:** [ADR 0200](0200-own-row-engine.md) §5 — место строки у хранилища;
  [ADR 0199](0199-row-shifts-in-the-middle-of-data.md) — сдвиги в середине `data`, перф MS9–MS11.
- **Связано:** [ADR 0210](0210-positions-by-shift.md) — пересчёт позиций виртуализатора сдвигом.

## Контекст

После ADR 0210 удаление 100 строк из середины 100 000 при сортировке (MS10) — 54 мс против 33,5 мс у
дописывания в конец (×1,6 при пороге ADR 0199 ×1,3). Профиль модели строк без React (2026-11-11, без
троттлинга, мс на смену):

| Работа                                              | Удаление | Дописывание |
| --------------------------------------------------- | -------- | ----------- |
| запись мест ~50 000 сдвинутых строк (`setPosition`) | 2,0      | —           |
| правка уровня сортировки (`patchLevel`)             | 2,2      | 0,9         |
| всего                                               | ~9,6     | ~5,7        |

Место сдвинутой строки пишется в `WeakMap` при каждой смене, хотя в этом пути его никто не читает.
Сортировка ищет уходящую строку двоичным поиском с правилом «по месту» при равных значениях — это
единственное чтение, и оно вынуждает запись всех мест. Уровень без уходящих строк собирается
`filter` с `Set.has` на каждую строку.

### Как у других

- **AG Grid** — `rowIndex` у узла переписывается проходом после каждой смены модели.
- **MUI X** — место строки — индекс в массиве id, пересчёт — новым массивом.

## Решение

### 1. Места сдвига — при первом обращении

Смена `data` сдвигом (`patchShifted`) не пишет места строк середины и конца: она откладывает
запись «строки нового списка с индекса начала сдвига стоят на своих индексах». Отложенное
хранится у таблицы (ключ — хранилище таблицы), одно на таблицу, вместе со сдвигом конца списка.
Чтение места (`positionOf`) проверяет строку в новом списке: на прежнем месте или на прежнем со
сдвигом конца — это её место, запись не нужна. Иначе, при записи места (`setPosition`,
`copyPosition`) и в простое браузера отложенное дописывается целиком. Место подтверждает тождество
строки в списке, поэтому строки других моделей той же таблицы (строки-группы) и вложенные строки
проверку не проходят и получают прежнюю запись.

Следующая смена сдвигом из того же списка сливается с отложенным: начало нового списка до места
сдвига — те же строки на тех же местах, отложенное начинается с меньшего из двух мест, сдвиги конца
складываются. Смена другим
путём (сборка по уровням, полная сборка) сначала дописывает отложенное: прежний список не держится
в памяти, а запись мест сборкой не перекрывается старой.

### 2. Поиск уходящей строки — по значениям

Сортировка ищет уходящую строку двоичным поиском по значениям колонок без правила «по месту», затем
перебирает блок равных значений по тождеству — до 256 строк. Блок больше — прежний поиск с правилом
по месту. Значения строк у обоих сравнений общие. Уровень без уходящих строк — копией отрезков между
ними.

## Отвергнутые альтернативы

- **Журнал сдвигов с применением на чтении** (место = прежнее место + сумма сдвигов) — нужна версия
  создания у каждой новой строки и отличение строк ядра от строк-групп той же таблицы; сложнее при
  том же выигрыше для MS10.
- **Поле места в объекте строки** вместо `WeakMap` — замер ADR 0199: запись быстрее на четверть, но
  меняет форму строки TanStack.

## Последствия

- **+** Удаление, вставка и перенос в середине `data` не пишут мест хвоста: начало и конец списка
  читаются проверкой по индексу, запись идёт в простое.
- **−** Чтение места строки из середины переноса платит отложенную запись целиком.
- **−** Чтение места при отложенном у таблицы — поиск таблицы строки и проверка по индексу; без
  отложенного — как прежде.
- **Публичный API** не меняется.

## План внедрения

Один этап: §1–§2, PD1–PD4, затем PD5.

## Внедрение

2026-11-11. PD1–PD4 — красные мутацией (отложенное теряется или пишется сразу, запись места без
дописывания, чтение без проверки по индексу или без сдвига конца, промах без дописывания, поиск
уходящей строки по местам). PD3 был красным и на первой версии: `patchFlat` и полная сборка не
дописывали отложенное, и прежний список строк держался в памяти — поправлено переносом
отложенного на новый список и дописыванием в `buildCoreModel`.

Первый замер показал регрессию полной сборки MS11-base (×1,45): таблица, ушедшая с отложенными
местами, заставляла каждое чтение места искать таблицу строки. Поправлено дописыванием в простое,
запоминанием таблицы без отложенного и проверкой места по индексу в новом списке.

PD5 — `perf:compare` против `a92bdd52` (рабочая копия с ADR 0208–0210), 5–15 раундов, ×4 CPU:

| MS9-base — дописывание в конец        | 40,3  | 31,5  | 0,782     | улучшение     |
| MS10 — удаление 100 строк из середины | 68,1  | 31,4  | 0,461     | улучшение     |
| MS10-base — дописывание в конец       | 40,2  | 30,5  | 0,757     | улучшение     |
| MS11 — перенос строки                 | 48,5  | 33,8  | 0,698     | улучшение     |

MS9 и MS10 — ×1,03 к дописыванию при пороге ADR 0199 ×1,3. Против ревизии с ADR 0210 отдельно не
