# 0171 — Эффективное состояние без сборки в рендере

- **Статус:** Принято (решения — по итогам прожарки 2026-10-31)
- **Дата:** 2026-10-31
- **Слой:** `core/` — сужение срезов (`effectiveState`), хранилище аргументов плагинов
  (`pluginArgs`), каналы локального состояния `definePlugin`, сборка `useCreateTable`. Это
  сборка ядра: плагину её не передать. В плагинах меняется только форма среза правки
  `cellEditing`; запись навигации ядра получает `initialActiveCell`.
- **Изменяет:**
  - [ADR 0039](0039-reactive-plugin-arguments.md), §4 «Как это устроено» — сужение считают
    атомы, а не рендер; §1 — хранилище аргументов обновляется в эффекте коммита (RX2 держится
    до кадра, а не в том же рендере).
  - [ADR 0028](0028-define-plugin-authoring-api.md), DP8 — канала `controlled` у
    `definePlugin` нет: локальный срез плагина объявляется формой срезов.
  - [ADR 0120](0120-model-and-interface-plugins.md), §4 — форма `<срез>`, `on<Срез>Change`,
    `initial<Срез>` становится единственной формой внешнего состояния плагинов.
  - [ADR 0160](0160-expand-all-and-sticky-rows.md) — опции `refreshNarrowing` нет: пересчёт
    сужения после прихода ленивых детей идёт сам.
  - [ADR 0170](0170-body-contribution-channel.md), §1 — активная ячейка получает
    `initialActiveCell`.
- **Связано:**
  - [Аудит архитектуры 2026-10-31](../research/architecture-audit-2026-10-31.md), находки 7
    и 11, шаг 8 порядка работ; известный край «Сборка ядра в рендере».
  - [ADR 0164](0164-core-options-and-public-plugin-entry.md) — слияние `controlled` со срезами
    перенесено сюда со шага 2.
  - [ADR 0091](0091-environment-compatibility.md) — записи атомов и `setState` на React 18.
  - [ADR 0026](0026-migrate-to-tanstack-v9.md) — реакция на состояние только через TanStack
    Store.

## Контекст

Сужение срезов (ADR 0039, §4) считается в рендере хоста `useCreateTable`:
`useEffectiveState` кэширует результат в ref, а сужению, которому нужны строки с текущими
данными, не хватает свежей таблицы — оно откладывается до двух принудительных перерисовок.
Хранилище аргументов плагинов тоже пишется в рендере — так новая функция-предикат видна уже в
этом рендере. Ради обоих для `useCreateTable` и `useEffectiveState` отключено правило линта
`react-hooks/refs`, а прерванный конкурентный рендер может оставить в ref и хранилище значение,
которое так и не закоммитилось.

Пересчёт сужения привязан к смене сохранённого среза, данных и колонок. Что ещё читает
сужение, ядро не знает: ответ ленивой строки, уже числящейся раскрытой, остаётся невидимым до
смены данных (известная проблема), а для «раскрыть всё» плагин просит пересчёт опцией
`refreshNarrowing` (ADR 0160) — заплатка поверх, а не общий механизм.

Внешнее состояние плагинов приходит двумя каналами, делающими одно и то же: срезы
аргументами фабрик (`<срез>`, `on<Срез>Change`, `initial<Срез>`, ADR 0120) и канал
`controlled` у `definePlugin` (ADR 0028, DP8) — у `cellEditing` и активной ячейки навигации, без
`initial`.

TanStack Table v9 собирает срез таблицы производным атомом `table.atoms[key]`; внешний атом
`options.atoms[key]` главнее `options.state[key]`, а функции обновления фич пишут в него.

### Как у других

- **AG Grid** — состояние живёт внутри грида; параметры меняются через API
  (`setGridOption`), ограничения применяются при чтении; React-обёртка состояние в рендере не
  собирает.
- **MUI X** — состояние в хранилище `apiRef`; контролируемые пропсы (`sortModel`,
  `filterModel`…) переносятся в хранилище эффектом при смене, производное считают
  мемоизированные селекторы хранилища.

## Решение

### 1. Сужение — атомы-линзы

Для каждого суженного среза ядро отдаёт TanStack внешний атом в `options.atoms`: чтение —
эффективное значение («сохранённое ∩ допустимое»), запись — в сохранённое. Сохранённое —
свой атом-источник ядра (неконтролируемый срез) или значение приложения из опций рендера
(контролируемый, §2). Эффективное значение — производный атом от источника и всего, что читает
сужение: аргументов плагинов, данных, колонок, состояния плагинов вроде пришедших ленивых
детей. Пересчёт идёт по зависимостям атома, а не по рендеру хоста: кэша в ref и
принудительных перерисовок нет, `refreshNarrowing` не нужен. Гарантии ADR 0039 §4 прежние:
сохранённое не переписывается, контролируемому потребителю `on*Change` из-за сужения не
приходит, сужение собирается со всех записей набора, срезы ядра (закрепление) только сужаются.

Пересчёт с тем же сохранённым значением, чей итог по полям равен прежнему, отдаёт прежний
объект: таблица не видит смены там, где её нет. Вычисляемый атом без подписчиков
пересчитывается заново — StrictMode отписывается и подписывается, — и новый объект сужения
перерисовывал бы хост. Отсюда правило для сужений: значение, чей смысл не в его полях (прокси,
ключи-символы, ссылка как ключ `WeakMap`), — один объект на одно сохранённое значение, как у
«всё, кроме» выбора строк (ADR 0138). От другого сохранённого значения прежний объект не
берётся.

### 2. Контролируемый срез — из опций рендера

Значение контролируемого среза — `state` ядра и аргумент среза плагина — линза читает из
опций текущего рендера, как TanStack читает `state` несуженных срезов; так же — сужения
среза и свёртку набора (`pluginNarrows`, `pluginNarrowContext`). Рендер атомы не пишет:
атом-источник хранит только то, что сохраняет ядро (неконтролируемый срез), его меняют
события. Новое значение видит весь коммит, лишней отрисовки нет.

Прожарка решила переносить значение приложения в атом в layout-эффекте коммита, как у MUI X.
Внедрение показало гонку: layout-эффекты дочерних компонентов — грида и dnd-kit — React
выполняет раньше эффекта хоста `useCreateTable`, и в том же коммите они видели прежнее
значение. Бросок в свёрнутую группу с раскрытием в `useState` приложения запоминал уровень по
ещё свёрнутой группе (NX1, NX3). Решение пересмотрено с автором 2026-10-31.

### 3. Аргументы плагинов — в эффекте коммита

Хранилище аргументов обновляется в layout-эффекте. Функции аргументов — по-прежнему
стабильные обёртки на последнюю закоммиченную версию. Предикат, прочитанный в самом рендере,
один рендер видит прежнюю версию; версия отрисовки (ADR 0039, RX2) поднимается в том же
эффекте и перерисовывает ячейки до кадра. Исключение `react-hooks/refs` для сборки ядра
снимается.

### 4. Один канал внешнего состояния плагина

Канала `controlled` у `definePlugin` нет. Локальный срез плагина (`state`) объявляет имя
среза, и `definePlugin` берёт из аргументов `<срез>`, `on<Срез>Change` и `initial<Срез>` — как
срезы TanStack у плагинов модели (ADR 0120, §4). `cellEditing`: `editing`, `onEditingChange`,
`initialEditing`; ядро: `activeCell`, `onActiveCellChange`, `initialActiveCell`.

### 5. Этапы

1. §1–§2: атомы-линзы, контролируемые срезы из опций рендера, без `refreshNarrowing` — EF1–EF6,
   EF11;
   `perf:compare`.
2. §3: аргументы плагинов в эффекте, без исключения линта — EF7–EF8; `perf:compare`.
3. §4: один канал внешнего состояния — EF9–EF10.

`perf:compare` против ревизии до этапа — по P1, P3, P12 и I1–I3; новых перф-требований нет:
видимой работы не прибавляется.

## Границы

- Публичного API эффективного состояния («что скрыто сужением») нет, как и в ADR 0039.
- Договоры на время жизни (режим данных, `initialPageSize`) — прежние.
- Видимое поведение прежнее, кроме закрытой известной проблемы с ответом ленивой строки:
  своей таблицы сценариев и новых историй нет.

## Отвергнутые альтернативы

- **Чистая функция в рендере** (`useMemo` по входам, без записи ref) — дешевле, но
  перерисовки ради строк с текущими данными и `refreshNarrowing` остаются, а ядро по-прежнему
  не знает, что читает сужение.
- **Запись атома-источника в рендере при смене пропа** — без лишней отрисовки, но побочный
  эффект рендера остаётся, и прерванный конкурентный рендер оставляет незакоммиченное значение.
- **Значение приложения в атом в эффекте коммита** (решение прожарки) — layout-эффекты дочерних
  компонентов идут раньше эффекта хоста и в том же коммите видят прежнее значение: скрытая
  гонка у всех, кто читает состояние в эффектах (перетаскивание — первый случай).
- **Хранилище аргументов в рендере** — новая функция видна в том же рендере, но исключение
  линта и риск прерванного рендера остаются.
- **Оставить `controlled`** — ничего не ломает, но два канала одного смысла остаются, и у
  локального среза нет `initial`.

## Последствия

- **+** Рендер сборки ядра без побочных эффектов: корректность при прерванном конкурентном
  рендере, путь к React Compiler.
- **+** Сужение следует всему, что читает, — заплатки вроде `refreshNarrowing` не нужны.
- **+** Одна форма внешнего состояния у всех плагинов.
- **−** Срез приложения читается из рендера: прерванный конкурентный переход краткое время
  виден чтению, как у TanStack для любого `state`.
- **−** Ломающее изменение API авторов плагинов: поля `controlled` у `definePlugin` нет —
  `BREAKING CHANGE` в коммите и CHANGELOG.
- **−** Сужение, читающее строки внутри атома, — риск цикла зависимостей (модель раскрытия
  читает `expanded`, сужение `expanded` — строки ядра): проверяется первым на этапе 1.

## Внедрение

- **Этап 1** (EF1–EF6): хранилище срезов — `createSliceStore` в `core/effectiveState.ts`,
  одно на таблицу. Линзы лежат в одном объекте `options.atoms`: TanStack фиксирует его при
  создании таблицы, поэтому срезы, появившиеся и снятые на лету, ядро добавляет и удаляет в
  нём самом, в эффекте коммита. Таблицу хранилище узнаёт фичей набора в
  `constructTableAPIs`: StrictMode создаёт таблицу дважды, React оставляет первую — её и
  берём. Значение приложения линза читает из `options.state` рендера; сужения и свёртка
  набора — новые опции таблицы `pluginNarrows` и `pluginNarrowContext`. Опции React-адаптера —
  простые данные, производный атом их не видит: при смене таблицы, данных, колонок, значения
  приложения, сужений или свёртки берётся новый производный атом. Пересчёт с тем же значением
  и поверхностно равным итогом отдаёт прежнюю ссылку: атом без подписчиков пересчитывается
  заново (StrictMode отписывается и подписывается снова), и новый объект сужения перерисовал бы
  хост (EF4). Обработчик `on<Срез>Change` один на ключ и для снятых сужений пишет в атом
  TanStack. Опции `refreshNarrowing` и принудительных перерисовок нет; цикла зависимостей
  у сужения `expanded`, читающего строки ядра, нет. Тесты: модульный `effectiveSlices.dom`
  (EF1–EF2, EF5–EF6, EF11), визуальный `effective-state` (EF3–EF4).
