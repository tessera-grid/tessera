## Контекст

Быстрый поиск ищет «содержит» по видимым колонкам со строкой или числом; исключены
служебные колонки, `enableGlobalFilter: false` и колонки дат, у колонок с вариантами
ищется подпись. Набор живой: скрыли колонку — она выпала из поиска. Булевы колонки
(`filter: 'boolean'`) поиск тоже не обходит: значение не строка и совпасть не может,
а в подсказке они вводили бы в заблуждение. Пользователь об
этом не знает — поле подписано просто «Search». Почему строка нашлась или не нашлась,
не видно.

В серверном режиме грид не знает, где ищет сервер: `onSearchChange(search)` получает
только строку, и любая подсказка грида могла бы разойтись с сервером.

## Решение

### 1. Иконка «и» с тултипом (QS1–QS4)

- В поле поиска справа (перед кнопкой очистки) — иконка-кнопка `info` (новая иконка в
  `icons`). Наведение или фокус показывает тултип грида: «Search in columns: Name, Country,
  Visits» — подписи колонок (`header`), в порядке отображения, переносом строк при
  длинном списке.
- Тот же текст — доступное описание поля (`aria-describedby`): скринридер слышит его
  при входе в поле, без похода на иконку.
- Список живой: скрыли колонку, исключили её или добавили — тултип и описание
  меняются сразу.
- Подписи — из `localization`: `searchColumnsHint(columns)` и `searchNoColumns`.

### 2. Искать не по чему (QS5)

Когда ни одна видимая колонка не ищется, поле недоступно — как остальные контролы
тулбара, оно остаётся фокусируемым и помечено `aria-disabled` (Base UI); описание и
тултип — «No columns to search». Введённый поиск не стирается: без колонок поиска
TanStack его просто не применяет (сужение среза не нужно), строки не фильтруются —
вернули колонку, поиск снова работает.

### 3. Колонки для сервера (QS6–QS7)

`onSearchChange(search, { columnIds })` получает вторым аргументом id колонок, по
которым ищет грид, — сервер ищет по тем же, и подсказка остаётся честной. Смена набора
колонок при непустом поиске тоже вызывает колбэк (с прежней строкой). Первый аргумент
не меняется.

### 4. Скрытые колонки

Поиск по-прежнему идёт только по видимым колонкам («ищу то, что вижу»): строка не
должна находиться по невидимому тексту. Теперь это видно в подсказке.

## Границы

- **Подсветка совпадений** в ячейках — не входит (ADR 0045).
- **Выбор колонок поиска пользователем** — не входит; тултип не интерактивный.
- **Список колонок в плейсхолдере** — не делаем: поле узкое, список мешает вводу.

## Отвергнутые альтернативы

- **Плейсхолдер со списком** — не помещается и исчезает при вводе.
- **Поповер по клику** — лишний клик ради справки; место для выбора колонок не нужно.
- **Метки в шапках колонок** — шумно, новое состояние шапки.
- **Список от приложения** (`searchColumns`) — подсказка и сервер синхронизировались бы
  вручную.
- **Поиск и по скрытым колонкам** — строки находились бы по невидимому.

## Последствия

- **+** Пользователь видит, по каким колонкам ищет; в серверном режиме — те же колонки.
- **+** Пустой набор не выглядит как «ничего не нашлось».
- **−** Ещё одна кнопка в поле поиска и новая иконка.
- **Публичный API:** второй аргумент `onSearchChange`, иконка `info`, ключи
  локализации `searchColumnsHint`, `searchNoColumns`. Ломающих изменений нет.

## План внедрения

1. `quickSearch`: список колонок поиска (`canSearchColumn` + видимость), подпись — из
   `header`; `SearchField` — иконка, тултип, `aria-describedby`, `disabled`.
2. Булевы колонки исключены из поиска (как даты).
3. `onSearchChange(search, { columnIds })` и вызов при смене набора в серверном режиме.
4. Иконка `info`, ключи локализации.
5. Тесты, истории, документация (ADR 0045 §6, `theming-and-overrides.md`).
