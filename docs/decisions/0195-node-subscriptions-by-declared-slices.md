# 0195 — Подписки узла ячейки и строки по объявленным срезам

- **Статус:** Принято (прожарка 2026-11-07), внедрено 2026-11-08
- **Дата:** 2026-11-07
- **Слой:** `core/bodyContributions` — подписка узла цели на атомы срезов и dev-проверка
  необъявленных; `core/definePlugin` — обязательное поле `slices` у вклада автора; грид
  (`BodyCell`, `BodyRow`) объявляет срезы своего выбора. Не в плагине: подписка узла — договор
  канала вклада в тело для всех вкладчиков, плагины только объявляют срезы.
- **Изменяет:**
  - [ADR 0170](0170-body-contribution-channel.md) — узел цели подписан не на всё хранилище, а на
    атомы срезов ядра и вкладчиков.
  - [ADR 0173](0173-body-channel-for-plugin-authors.md) — у вклада автора в ячейку и строку обязательное
    поле `slices`; ломающее изменение авторского API до 1.0.
- **Связано:**
  - [ADR 0193](0193-predicate-result-subscription.md) — узел подписан и на версию отрисовки
    предикатов, она остаётся.
  - [ADR 0149](0149-plugin-cost-on-scroll.md), [ADR 0099](0099-perf-gates-and-ab-compare.md) —
    счётчики работы и сравнение ревизий.
  - [ADR 0185](0185-selection-with-client-grouping.md) — выбор строки-группы выводится из строк
    группы.

## Контекст

Ячейка и строка тела читают состояние одним узлом (ADR 0170): выбор ядра и выборы вкладчиков
под одной подпиской. Подписка — на всё хранилище таблицы. Любая смена состояния — выбор строки,
ввод в поиск, раскрытие, подсветка — заставляет каждую смонтированную ячейку и строку
пересчитать свой выбор и выборы всех вкладчиков и сравнить итог с прежним. Перерисовывается
только та цель, чей итог изменился, но сами пересчёты идут всегда.

Профиль клика выбора строки под ×4 CPU (10 кликов, все плагины, 30×500 и 1000×1000): около
55 мс на клик, из них 15–19 % — источник узла, сравнение итогов и выборы ячеек и навигации.
Клику выбора строки ячейки не нужны вовсе: от выбора строки зависят только строки.

Выбор вкладчика может читать срез неявно: выделение ячеек спрашивает `cell.getIsSelected()`,
а тот читает атом сам. По коду выбора зависимость не вывести.

### Как у других

- **AG Grid** — ячейка подписана на конкретные события сервиса событий (`cellChanged`,
  `rowSelected`, `cellFocused`); чужое событие ячейку не будит.
- **MUI X Data Grid** — компоненты читают состояние гранулярными селекторами
  (`useGridSelector`); селектор пересчитывается на каждую смену общего состояния, мемоизация
  отсекает перерисовку.
- **TanStack Table v9** — состояние лежит атомами по срезам; подписка на атом не будит на смене
  другого.

Tessera берёт явные зависимости, как AG Grid, на атомах TanStack: узел подписан только на атомы
своих срезов.

## Решение

### 1. Узел подписан на атомы своих срезов

Узел цели подписан на атомы срезов, от которых зависит его выбор, и на версию отрисовки
предикатов (ADR 0193). Срезы ядра объявляет грид:

- **ячейка** — закрепление, ширины, порядок и видимость колонок, подсветка, вспышки, статус
  действий, отказы, активная ячейка;
- **строка** — выбор строк, раскрытие, группировка, ожидание раскрытия, переносы строк,
  подсветка, вспышки, статус действий.

Смена среза, которого нет ни у ядра, ни у вкладчиков цели, её выборы не пересчитывает. Новая
отрисовка цели (новая строка, ячейка, контекст) пересчитывает выборы, как прежде.

Цели с одинаковым набором срезов и версией отрисовки внутри одной таблицы берут общий
снимок. Источник подписывается на атомы при подключении первой цели и отписывается
после отключения последней. Селектор и сравнение результата остаются у каждой цели.

### 2. Вкладчик объявляет срезы

Вклад в ячейку и строку несёт поле `slices` — ключи состояния таблицы, которые читает его выбор
прямо или через методы строки и ячейки. Поле обязательное у встроенных вкладчиков и у плагинов
авторов: без него — ошибка типов и dev-ошибка при сборке записи. Собственный срез плагина автора
входит в подписку его вклада без объявления.

Строка-группа клиентской группировки подписана на выбор строк, её состояние выводится из строк
группы (ADR 0185). Срез — один атом на все строки: на смену выбора пересчитываются узлы всех
строк, перерисовывается только та, чей итог изменился.

### 3. Dev-проверка необъявленных срезов

В dev и тестах узел пересчитывает выборы и при смене необъявленного среза. Если итог вкладчика
изменился — предупреждение с id вкладчика и ключом среза, одно на такую пару. В
production-сборке проверки нет: узел подписан только на объявленное.

## Границы

- Перерисовка `DataGrid` целиком, тулбара и кнопок шапки на клике выбора строки (ещё 20–25 %
  клика) — отдельная задача: причина другая, хост и контролируемый срез.
- Шапка и футер — не узлы канала вклада, не меняются.
- Срезы из аргументов предикатов (`refreshOn`) — по-прежнему через версию отрисовки (ADR 0193).

## Отвергнутые альтернативы

- **Поле `slices` необязательное, без него — подписка на всё хранилище.** Авторский API не
  ломается, но вклад без поля возвращает узел к нынешней цене, и грид не знает, что автор забыл.
- **Вывод зависимостей автоматически** — запись чтений атомов во время выбора. Чтения через
  методы TanStack идут мимо обёртки атома; перехват всех атомов стоит на каждом выборе дороже,
  чем выигрыш.
- **Только тесты вместо dev-проверки.** Встроенные вкладчики покрыты, плагины авторов — нет:
  забытый срез молча оставляет ячейку старой.
- **Мемоизация выборов, как у MUI X.** Пересчёт на каждую смену остаётся, сокращается лишь
  сравнение.

## Последствия

- Клик выбора строки не будит ячейки; любая смена среза будит только зависящие от него узлы.
- Автор плагина объявляет срезы вклада; забытый срез виден в dev предупреждением.
- В production неявная зависимость без объявления — ячейка не перерисуется: цена отказа от
  проверки в production.
- **Ломающее изменение** авторского API (ADR 0173) до 1.0: у `body.cell` и `body.row` обязательное
  поле `slices`.
