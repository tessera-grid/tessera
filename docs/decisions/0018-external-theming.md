# 0018. Внешняя темизация: переопределяемый слой токенов

Статус: Принято (2026-09-04; дополнено 2026-09-05 — самодостаточная палитра light+dark + фикс шиппинга)

> **Архитектура токенов вынесена в [ADR 0019](0019-token-architecture.md)
> (2026-09-05):** введена трёхуровневая система `--tsr-ref/sys/comp`; component-токены
> называются `--tsr-comp-*`. Этот ADR отвечает за механику слоя, шиппинг (глобальный
> импорт вместо `@import` в модуль) и контракт colorMode; уровни, префикс и мост к
> shadcn — в 0019.

## Контекст

Тема грида — набор CSS-переменных `--tsr-comp-*` (цвета строк/ячеек/пиннинга,
hover, выделение, checkbox/switch, skeleton, loader, фокус-ринг, радиусы, шрифт),
выведенных из апстрим-токенов shadcn (`--primary`, `--foreground`, `--muted`,
`--info`, `--border`, `--ring`, `--destructive`…) через `var()`/`color-mix()`
(см. [design.md](../design.md), [global.css](../../src/styles/global.css)).

Раньше весь набор `--tsr-comp-*` вешался **инлайн-стилем** на обёртку грида
(хук `useThemeVariables`). Из-за этого потребитель НЕ мог переопределить
конкретный токен обычным CSS-правилом: инлайн-стиль бьёт любой внешний селектор
(кроме `!important`), а установка того же токена на предке маскировалась
собственным инлайн-объявлением обёртки. Единственным рабочим рычагом оставались
апстрим-токены shadcn (напр. `--info` перекрашивал лоадер) — то есть «поменять
цвет только прогресс-бара, не трогая палитру» было нельзя. При этом JSDoc хука
обещал обратное («любой токен можно переопределить на контейнере») — расхождение
кода и обещания.

## Решение

**Дефолты токенов вынесены в низкоспецифичный CSS-слой.**
[`theme.css`](../../src/lib/core/themeVariables/theme.css) объявляет все
статические `--tsr-comp-*` на классе `.data-grid-theme` через `:where()`
(нулевая специфичность). Обёртка грида несёт стабильный класс
`DATA_GRID_THEME_CLASS = 'data-grid-theme'`. Значения — те же `var()`/
`color-mix()`-производные от палитры, что и раньше (фолбэки «Vercel» сохранены,
тёмный режим — через класс `.dark`, переопределяющий апстрим-токены).

Два рычага переопределения, оба ergonomic:

- **Глобально / по селектору — обычным CSS.** Любое правило потребителя
  (`.data-grid-theme { --tsr-comp-loader-bar: … }` или свой контейнер) бьёт слой
  `:where(...)` нулевой специфичности — без `!important`.
- **Пер-инстансно — инлайн.** `DataGrid` принимает `style` (и `className`),
  которые кладутся на обёртку: `style={{ '--tsr-comp-loader-bar': '#f00' }}`
  переопределяет токен для одного инстанса, а инлайн бьёт дефолт слоя.

Правка **апстрим-палитры** (`--primary`/`--foreground`/`--info`…) по-прежнему
согласованно меняет ВСЕ производные `--tsr-comp-*` — теперь это осознанный
верхний рычаг, а не единственный.

Инлайн на обёртке остаются только РАНТАЙМ-переменные (высоты шапки/тела,
drag-офсеты, ширина скроллбара) — они вычисляются на рендере и токенами темы не
являются. `useThemeVariables`/`cellContentVariables` удалены (мёртвый код после
переноса дефолтов в CSS); публично экспортированы `DATA_GRID_THEME_CLASS` и тип
`ColorMode`.

Витрина — история `Tessera/Theming` (`Theming.stories.tsx`) с color-контролами на
КАЖДЫЙ токен, сгруппированными по поверхностям переопределения (shadcn-мост →
semantic → component; см. ADR 0019); значения собираются в инлайн-`style`.

## Последствия

- **+ Настоящая внешняя кастомизация** любого токена обычным CSS или пропом
  `style`; JSDoc-обещание теперь истинно.
- **+ Единый источник дефолтов** — CSS-файл (а не JS-объект); нет риска дрейфа
  между JS и CSS.
- **+ Тени токенизированы** — `box-shadow` больше не хардкод: цвет основных
  теней (шапка/футер/drag-оверлеи) — единый `--tsr-comp-shadow-color`, полные
  значения по поверхностям (`--tsr-comp-shadow-head`/`-footer`/`-drag`/
  `-drop-bubble`/`-action`) переопределяемы целиком. Раньше в шапке/футере/
  оверлеях/actions стоял захардкоженный `rgba(0,0,0,…)`.
- **+ Заглушка `stub` теперь внутри темы** — ветка no-data тоже несёт
  `.data-grid-theme` (+ `dark`, `style`), так что `--tsr-comp-*` и тёмный режим
  доступны и в кастомной заглушке (раньше не были).
- **− Ломающее изменение (pre-1.0 допустимо):** удалён внутренний хук
  `useThemeVariables`. Публичный API грида не затронут (хук не экспортировался).

## Дополнение (2026-09-05): самодостаточная палитра (light+dark) + фикс шиппинга

Исходная редакция оставляла два дефекта, всплывших при проверке бандла:

1. **Тёмный режим не работал из коробки.** Токены грида читали апстрим с
   ЛИТЕРАЛЬНЫМ светлым фолбэком (`var(--foreground, #171717)`), а сами
   апстрим-`:root`/`.dark`-токены жили только в `global.css`, который импортит
   лишь Storybook. В бандл они не попадали → `colorMode="dark"` вешал класс
   `.dark`, но флипать было нечего → грид оставался светлым.
2. **Слой темы вообще не шиппился с рабочими классами.** `theme.css`
   подключался через CSS `@import` внутрь `DataGrid.module.css` (CSS Module),
   из-за чего Vite СКОУПИЛ глобальные классы: в `dist/style.css` оказывался
   `:where(._data-grid-theme_hash)` вместо `:where(.data-grid-theme)`. Класс
   `data-grid-theme` на обёртке не матчил ничего → у потребителя пакета не
   применялась и СВЕТЛАЯ тема. Прежняя проверка `grep -c data-grid-theme`
   давала ложный плюс (совпадение с подстрокой в хеше).

**Решение — самодостаточные дефолты (light+dark) + глобальный шиппинг.**

- Каждый цветовой токен грида получил самодостаточный дефолт, не зависящий от
  `global.css`, объявленный для **light** (`:where(.data-grid-theme)`) и **dark**
  (`:where(.data-grid-theme.dark), :where(.dark .data-grid-theme)`). Апстрим-палитра
  потребителя, если задана, по-прежнему побеждает (мост к shadcn). Конкретная
  трёхуровневая реализация этой цепочки (`--tsr-comp-*` → `--tsr-sys-*` → `--tsr-ref-*`,
  мост к shadcn в semantic) описана в [ADR 0019](0019-token-architecture.md).
- Дженерик-имена (`--foreground`/`--card`…) в глобальный скоуп НЕ выносятся — грид
  не засоряет документ и не мешает чужому UI-фреймворку. `:where()` держит нулевую
  специфичность, поэтому реальная `.dark {…}`/`:root {…}` палитра потребителя
  (спец. ≥ 0,1,0) перебивает дефолт.
- **Фикс шиппинга:** `@import "theme.css"` убран из `DataGrid.module.css`;
  `theme.css` импортируется как ГЛОБАЛЬНЫЙ (не-модульный) CSS side-effect из
  `DataGrid.tsx` (удерживается в графе → не режется tree-shaking'ом; плоский CSS →
  классы не хешируются). Проверка теперь строгая:
  `grep -c '_data-grid-theme_' dist/style.css` = 0 И присутствует литеральный
  `:where(.data-grid-theme)`.

**Контракт colorMode.** Для потребителя со своим shadcn (плоский `.dark {…}`)
`colorMode="dark"` вешает `.dark` на обёртку → его же правило матчит её и флипает
и апстрим-токены. Ниша: если его dark-токены заданы только как `html.dark`/
`:root.dark` (не матчат обёртку) и приложение в light — грид возьмёт свои тёмные
дефолты структурно, а апстрим-цвета останутся светлыми; детерминированный путь на
этот случай — прокинуть значения через `style` по своей mode-логике.

Пять требований потребителя (все покрыты): (1) без темизации — shadcn + своя
тема; (2) литералы извне (`style`/CSS-правило) — грид подчиняется; (3) `colorMode`
переключает режим; (4) для light/dark — свои значения либо никаких; (5) любой
UI-фреймворк: привязка темы+режима через `style`/`colorMode`, перекраска на
обновлении (CSS-переменные живые).
