# 0205 — Размещение встроенных кнопок тулбара аргументом фабрики

- **Статус:** Принято (прожарка 2026-11-09)
- **Дата:** 2026-11-09
- **Слой:** плагины — аргумент `toolbar` у фабрик с кнопкой тулбара; ядро — раскладка
  `resolveToolbarGroups` (`core/toolbar.ts`) без изменений: она уже читает `group`, `order` и
  `align` слота. Тип `ToolbarPlacement` — из `/plugins`. Нового в ядре нет: аргумент меняет
  только запись слота, которую плагин и так отдаёт.
- **Изменяет:**
  - [ADR 0051](0051-toolbar-button-order.md) — «Переопределять порядок встроенных кнопок
    приложению не даём» снято: место встроенной кнопки задаёт аргумент её фабрики. Порядок по
    умолчанию и ранги групп — прежние.
- **Связано:**
  - [ADR 0035](0035-toolbar-and-column-visibility.md) — тулбар, группы, `toolbarSlot`.
  - [ADR 0046](0046-toolbar-and-status-bar-visibility.md) — тулбар по слотам, инертность без
    тулбара (`'noToolbar'`).
  - [ADR 0039](0039-reactive-plugin-arguments.md) — живые аргументы фабрик.
  - [ADR 0106](0106-flag-and-predicate-naming.md) — имена аргументов и контролов историй.
  - [ADR 0120](0120-model-and-interface-plugins.md) — настройки плагина — аргументами фабрики.
  - [ADR 0204](0204-hidden-column-transforms.md) — сводки «Сортировка» и «Группировка».

## Контекст

Порядок кнопок тулбара задан ADR 0051: левая сторона — поиск и «Фильтры» (группа `search`),
правая — «Колонки» (`view`), «Экспорт» (`data`), группы приложения, черновики (`drafts`) и журнал
отказов (`failures`). Приложение ставит только свои кнопки — полями `group`, `order`, `align` слота;
встроенные не двигаются. ADR 0051 отложил настройку «отдельной потребностью» — она появилась:
приложению нужно, например, вынести «Экспорт» влево или убрать сводку, которая ему не нужна.

Как у других: MUI X собирает тулбар из компонентов-кнопок, порядок — у приложения; у AG Grid
тулбара нет, порядок панелей боковой панели задаётся массивом (сверка — по памяти, в документацию
не заглядывали).

## Решение

- Фабрика плагина с кнопкой тулбара — `quickSearch`, `columnFiltering`, `columnSorting`,
  `rowGrouping`, `columnVisibility`, `dataExport`, `unsavedChanges`, `failureLog` — принимает
  `toolbar?: ToolbarPlacement | false`, где
  `ToolbarPlacement = { group?: string; order?: number | 'last'; align?: 'start' | 'end' }`.
- Заданное поле перекрывает размещение кнопки, незаданное — прежнее. Раскладка — по прежним
  правилам: ранги встроенных групп, группы приложения после них, внутри группы — по `order`
  (ADR 0051, TB9, TB16, TB19). Кнопка, перенесённая в группу приложения, стоит по её правилам.
- `toolbar: false` — кнопки нет. Плагин, у которого тулбар — единственный интерфейс, инертен с
  причиной `'noToolbar'`, как без тулбара (ADR 0046); у плагина с другими путями (кебаб «Скрыть
  колонку», кнопка фильтра в шапке) они остаются.
- Аргумент живой (ADR 0039): смена на лету переставляет кнопку без пересоздания таблицы.
- Порядок по умолчанию не меняется (решение автора 2026-11-09).

## Границы

- Проп порядка на таблице и функции отрисовки тулбара нет.
- Ранги встроенных групп приложение не меняет: переносится кнопка, а не группа.
- Кнопки внутри поповеров и нижней панели — вне решения.

## Отвергнутые альтернативы

- **Проп порядка на таблице** (`toolbarOrder`) — новый публичный проп, который должен знать id
  кнопок плагинов, подключённых не всегда.
- **Функция отрисовки тулбара** — полный контроль, но клавиатура тулбара (TB20) и сжатие на узкой
  ширине (TB17) переходят к приложению.

## Последствия

- **+** Приложение переставляет и убирает встроенные кнопки тем же языком, что ставит свои.
- **+** Типизировано: поле аргумента фабрики, без строковых id в пропе таблицы.
- **−** У восьми фабрик новый аргумент — по контролу историй на каждую (FN5).

## Требования

| ID  | Требование                                                                                                                                                   | Вид                 |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------- |
| TO1 | Фабрики с кнопкой тулбара принимают `toolbar: { group?, order?, align? }`: заданное поле перекрывает размещение кнопки, незаданное — прежнее                 | этап 1 · модульный  |
| TO2 | Перенесённая кнопка стоит по правилам раскладки ADR 0051: ранги встроенных групп прежние, в группе приложения — после встроенных, внутри группы — по `order` | этап 1 · модульный  |
| TO3 | `toolbar: false` — кнопки нет; плагин без другого интерфейса инертен с причиной `'noToolbar'`, у плагина с другими путями они остаются                       | этап 1 · модульный  |
| TO4 | Смена аргумента на лету переставляет кнопку без пересоздания таблицы                                                                                         | этап 1 · модульный  |
| TO5 | `←/→` и `Home/End` проходят кнопки в новом порядке; узкий тулбар сжимает поле поиска, стороны не наезжают                                                    | этап 1 · визуальный |
| TO6 | Тип `ToolbarPlacement` экспортируется из `/plugins`; у историй — контрол `<фабрика>Toolbar` по правилу ADR 0106, страж `storyControls`                       | этап 1 · модульный  |
