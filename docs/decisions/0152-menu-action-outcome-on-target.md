## Контекст

Пункт меню может вернуть промис (ADR 0078). У кебабов строки и заголовка и у инлайн-кнопок
ожидание и отказ показывает сама кнопка — дугой и отметкой с причиной (ADR 0127, ADR 0136).
У контекстного меню кнопки нет: после закрытия меню ни ожидание, ни отказ снаружи не видны.
Ожидание видно только в пункте при следующем открытии, отказ — значком в пункте и объявлением
для скринридера. Человек, который выбрал «Удалить» и закрыл меню, отказа не замечает.

Вспышку на цели (ADR 0134) встроенные носители зовут там, где знают цель: правка ячейки,
перенос, раскрытие. Для пунктов меню ADR 0134 §8 решил, что грид не знает, что изменило
действие, и оставил вспышку приложению (`table.flashOutcome`). Принцип ADR 0136 — итог
показывает то, на что повлияло действие. Без вспышки по умолчанию отказ пункта
контекстного меню остаётся невидимым там, где человек его запустил.

Вспышка и подсветка знают три формы цели — строку, ячейку и колонку. Выделение из многих
ячеек массивом ячеек не передать: «выделить всё» на 1000×1000 — миллион записей, а в
серверной модели строк id незагруженных строк неизвестны, выделение хранится индексами
(ADR 0146).

### Как у других

- **AG Grid** — `action` пункта контекстного меню синхронный, асинхронного состояния нет.
  Итог приложение показывает само: `api.flashCells({ rowNodes, columns })` вспыхивает
  произведение строк и колонок, массивами узлов строк.
- **MUI X** — готового контекстного меню ячейки нет, его пишет приложение; API вспышки нет.
- **Таблицы-редакторы** (Google Sheets, Excel в браузере) — итог долгого действия показывает
  тост внизу экрана. У Tessera тост — будущий плагин снекбара (ADR 0127 §9), принцип —
  итог на цели.

## Решение

### 1. Цель действия меню

У действия меню — новое поле:

```ts
target?: (
  ctx: TContext,
  defaultTarget: FlashTarget | readonly FlashTarget[] | undefined,
) => FlashTarget | readonly FlashTarget[] | false
```

- Поле принимают все меню и кнопки с `MenuAction`: кебабы строки и заголовка, их
  инлайн-кнопки и контекстное меню.
- `defaultTarget` — цель по умолчанию; приложение может вернуть её, сузить, расширить или
  заменить. `false` — без вспышки и без ожидания на цели.
- **Цель по умолчанию есть только у контекстного меню** — у него нет своей кнопки:
  - ячейка, на которой открыли меню;
  - если меню открыто на выделении из нескольких ячеек (`selection.isInSelection` и
    `isMultiple`) — выделение целиком: по диапазону на каждый прямоугольник выделения.
- У кебабов и инлайн-кнопок без `target` цель — объект их слота: строка у кнопок строки, колонка
  у кнопок заголовка, ячейка у кнопок ячейки ([ADR 0177](0177-pending-and-failure-on-the-object.md), §1). Пункты вложенных разделов
  берут слот кебаба, в котором открыт раздел.

### 2. Итог

- **Отказ** — `reverted` на цели (ADR 0134). У кебаба, инлайн-кнопки и контекстного меню —
  в кадре отказа промиса; на кнопке ни дуги, ни отметки (ADR 0177). Значок отказа в пункте, тултип с
  причиной и объявление остаются (ADR 0078 §5).
- **Успех** — без вспышки: грид не знает, на что повлияло действие, а результат действия виден
  сам; объявление «…: done» остаётся (как выгрузка и копирование, ADR 0136 §1).

### 3. Ожидание на цели

Пока промис ждёт, ячейки цели в окне несут `aria-busy="true"` и остаются рабочими — выделение,
копирование, меню; курсор обычный. Ячейки цели чуть темнеют (подложка `--tsr-comp-pending-bg`), и
по ним проходит светлый блик — общая волна ADR 0121: одна наклонная полоса на все ячейки цели, в
одной фазе, под текстом. Цвет блика — `--tsr-comp-pending-wave` от системного
`--tsr-sys-shine` (почти белый на светлой теме, слабее на тёмной), проход —
`--tsr-comp-pending-wave-duration` (1,5 с — чаще волны скелета), ширина и наклон — общие токены
волны. Итог снимает подложку, блик и `aria-busy`. Ожидание в пункте при открытии меню — как
раньше (ADR 0078 §4).

- **Уменьшенное движение** — блика нет, ячейки цели остаются под неподвижной подложкой (у скелета
  волна в этом режиме гаснет совсем — у ожидания знак остаётся).
- **Большая цель** — больше `--tsr-comp-pending-wave-limit` (60) занятых ячеек в окне: блика нет,
  только подложка. Блик — свой композитный слой у каждой ячейки; на всём теле 1000×1000 прокрутка
  с волной стоила 47–73 мс кадра против 16–23 мс без неё, с одной подложкой — 19–26 мс (замер
  2026-10-29, решение пользователя).
- **`forced-colors`** — ни подложки, ни блика: вокруг ячеек цели пунктирный контур `Highlight` на
  слое блика (`forced-color-adjust: none` наследуется — на ячейке он снял бы подмену цветов и с
  текста).
- **Решения 2026-10-29** (вопросы пользователя после внедрения): курсор `progress` виден только
  при наведении — ожиданию нужен видимый знак; курсор вернули обычным — ячейка рабочая.
  Свечение под шапкой (ADR 0094) отвергнуто: оно значит «обновляется вся таблица», приглушает
  тело и не говорит, что именно ждёт; для действий над всей таблицей у приложения уже есть
  `loading` и серверные действия (ADR 0116). Тёмная полоса на белой ячейке почти не видна —
  блик светлый по чуть затемнённой подложке, как у полоски скелета.

### 4. Цель «диапазон»

Новая форма цели вспышки и подсветки:

```ts
type RangeTarget = {
  range: {
    /** Углы по строкам: id в клиентской модели, индексы в серверной. */
    rows:
      | readonly [from: string, to: string]
      | { indexes: readonly [from: number, to: number] }
    columns: readonly [from: string, to: string]
  }
}
```

- Диапазон — прямоугольник между углами по текущему порядку строк и видимых колонок, как
  диапазон выделения ячеек. Одна запись при любом размере.
- В клиентской модели углы — id строк: после сортировки или фильтра диапазон — ячейки между
  теми же углами в новом порядке. Угол, ушедший из данных, снимает запись.
- В серверной модели углы — индексы (ADR 0146). Подсветка диапазона живёт долго, поэтому
  следует правилам выделения §6 ADR 0146: новая выборка снимает её, раскрытие и приход строк
  выше сдвигают, внутри — снимают. Вспышка гаснет за секунду и тем же правилам следует
  без отдельной проверки.
- Вид — как у вспышки и подсветки ячейки (ADR 0134 §5, ADR 0080 §2): слой фона под текстом,
  закреплённые ячейки залиты сплошной полосой, первенство ADR 0126. Ячейка диапазона несёт
  `data-flash` и `data-highlight`, как ячейка-цель.
- **Первенство в `forced-colors`.** Ячейка выделения под подсветкой или вспышкой отказа —
  `Mark` с текстом `MarkText`, как строка, выбранная и подсвеченная сразу (ADR 0126 §1).
  Раньше фон оставался цветом выделения, а текст брал `MarkText` — 1.39:1; пробел ADR 0126
  нашла матрица контраста на шаге отказа над выделением (решение по аналогии, 2026-10-29).
- **Без перехода фона в `forced-colors`.** Фон строк и ячеек в режиме — системный цвет
  состояния; переход фона провёл бы его через несистемный цвет, который браузер подменяет
  `Canvas`, — выделенная ячейка под вспышкой на миг теряла заливку. В режиме токен
  `--tsr-comp-row-transition` оставляет только переход контура: итог появляется сразу
  (ADR 0134, §4).
- Проверка «ячейка в диапазоне» — сравнение позиции строки и колонки с углами; цена
  отрисовки — TG11.

### 5. Доступность

Вспышка ничего не объявляет и `aria-*` не меняет (ADR 0134 §3): отказ объявляет пункт меню
или кнопка. `aria-busy` ожидания (§3) — единственный новый атрибут.

## Границы

- **Меню грипа ресайза** (ADR 0034) — без изменений: ожидание — `aria-busy` и курсор у грипа,
  отметки отказа нет; остаётся в «Известных проблемах» roadmap.
- **Вспышка успеха** — нет (§2).
- **Снекбар ошибок** — будущий плагин; этот ADR его не заменяет и не требует.
- **Мини-меню инлайн-кнопки** (`inlineAsMenu`) — пункты синхронны по контракту (ADR 0078 §6).

## Отвергнутые альтернативы

- **Только явный `target`, без цели по умолчанию** — честно к «грид не знает, что
  изменилось», но отказ пункта контекстного меню по-прежнему не виден снаружи, пока
  приложение не настроит каждое действие.
- **Всегда строка ячейки** — просто, но для действий над диапазоном и колонкой вспыхивает
  не то.
- **Выделение массивом ячеек** — миллион записей на «выделить всё», в серверной модели
  незагруженные строки без id.
- **Массив ячеек с пределом, сверх него — ячейка под курсором** — поведение зависит от
  размера выделения, его трудно объяснить.
- **Произведение строк и колонок, как `flashCells` в AG Grid** — массив строк растёт с
  выделением, та же проблема, что у массива ячеек.
- **Приглушить содержимое цели на время ожидания** — видно сразу, но на диапазоне в сотни
  ячеек — заметная цена прокрутки; дуга ожидания уже есть у пункта и у кнопок.
- **Свечение под шапкой на время ожидания** (ADR 0094) — значит «обновляется вся таблица»,
  приглушает тело вместе с целью, одно на несколько действий и не говорит, что ждёт.
- **Только курсор и `aria-busy`** — первое решение прожарки: без наведения ожидание не видно.
- **`target` только у контекстного меню** — кебаб строки не мог бы показать отказ на строке
  без ручного `flashOutcome`.

## Последствия

- **Ломающее изменение типов:** `HighlightTarget` и цель `flashOutcome` получают форму
  `range`. Приложение с исчерпывающим `switch` по форме цели получит ошибку TypeScript.
- Отказ пункта контекстного меню виден на месте вызова без настройки; приложение уточняет
  цель полем `target`.
- Приложение может подсвечивать и вспыхивать диапазоны своими вызовами.
- Из «Известных проблем» roadmap уходит часть про контекстное меню; меню грипа остаётся.
