# 0208 — Тонкая ячейка тела: один компонент на ячейку без смены DOM

- **Статус:** Принято (прожарка 2026-11-10)
- **Дата:** 2026-11-11
- **Слой:** грид — ячейка тела (`grid/BodyCell.tsx`, `grid/cellContent.tsx`) и обёртки содержимого
  ячейки (`grid/CellWrapperContent`, `grid/CellWrapperTitle`). Это не плагин: дерево ячейки
  принадлежит гриду, слоты плагинов в нём не меняются.
- **Связано:**
  - [ADR 0173](0173-body-channel-for-plugin-authors.md), [ADR 0195](0195-node-subscriptions-by-declared-slices.md)
    — вклад плагинов в ячейку и её подписки; здесь не меняются.
  - [ADR 0207](0207-one-head-layout.md) — одна раскладка; этот ADR — следующий пункт того же плана.
  - Замер `docs/research/tessera-vs-ag-grid-2026-11-09.md`.

## Контекст

Монтирование 1000 × 1000 на стенде против AG Grid — ~190 мс работы под ×4 CPU, из них JS ~165 мс
почти целиком внутри React (стенд 2026-11-10, 361 ячейка). На ячейку тела приходилось 7 компонентов
React: `BodyCell`, обёртка содержимого `CellWrapperContent` (memo), два `RenderSlot` (слева и справа —
рисуются и при пустом слоте и отдают `null`), `RenderCellSlot`, подпись `CellWrapperTitle` (memo) и
ячейка ядра `defaultCell` — `flexRender` делает из функции форматирования компонент. Хуки из них
есть только у `BodyCell`.

Опыт на стенде (A/B, 12 замеров): те же три изменения без смены DOM — монтирование 208 → 197 мс
(−5 %), JS 169 → 158 мс. Атрибуты со значением `false` и CSS-переменные ширин колонок выигрыша не
дали — отвергнуты замером.

### Как у других

- **AG Grid** рисует ячейку через React, но значение без своего рендерера — текст без компонента.
- **MUI X Data Grid** — компонент на ячейку с memo, без вложенных обёрток на каждую.

## Решение

1. **Обёртки — разметкой.** Ячейка тела рисует обёртку содержимого и подпись `div` с теми же
   классами и `data-testid`, что у компонентов (`cellWrapperClassName`, `cellTitleAttrs`). Компоненты
   `CellWrapperContent` и `CellWrapperTitle` остаются для шапки, футера, оверлеев и плагинов и берут
   классы из тех же функций.
2. **Слоты — только непустые.** `RenderSlot` слева и справа и `RenderCellSlot` владельца рисуются,
   когда в слоте есть записи; пустой слот — ни одного компонента.
3. **Ячейка ядра — вызовом.** Когда `columnDef.cell` — ячейка ядра (`defaultCell`), содержимое —
   её вызов, а не элемент: у неё нет хуков.

DOM ячейки прежний: классы, атрибуты и вложенность те же; пустое содержимое — без подписи, как у
`CellWrapperTitle`.

## Границы

- Шапка, футер и оверлеи не меняются: ячеек шапки — десятки, а не сотни.
- Вычисления колонки в ячейке (закрепление, выравнивание, номер колонки) — раз на ячейку, как
  прежде: их цену профиль не выделил отдельно, решение — после замера.

## Последствия

- **+** Одна ячейка тела ядра — один компонент вместо 6–7: меньше файберов на монтировании,
  прокрутке и смене списка строк.
- **−** Разметка обёрток в ячейке тела и в компонентах — из одних функций классов: две точки
  отрисовки одного вида.
- **Публичный API** не меняется: обёртки — внутренние, слоты работают как раньше.

## Требования

| ID  | Требование                                                                                                                                                           | Тест                 |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------- |
| TN1 | Ячейка тела ядра без слотов перерисовывается одним компонентом `BodyCell`: без компонентов обёрток, слотов и ячейки ядра — по счётчикам работы                       | визуальный           |
| TN2 | Слот ячейки с записями рисуется, как прежде: слева, справа и владелец получают контекст ячейки и её содержимое                                                       | модульный            |
| TN3 | DOM ячейки тела прежний: обёртка `.data-grid__cell-wrapper-content`, в ней подпись `.data-grid__cell-wrapper-title` с `data-testid`; пустое содержимое — без подписи | модульный            |
| TN4 | `perf:compare` монтирования 1000 × 1000 против ревизии до внедрения — без регрессии, итог записан в «Внедрение»                                                      | отчёт `perf:compare` |

## План внедрения

Один этап: решение §1–§3, TN1–TN3; TN4 — `perf:compare` по команде автора.

## Внедрение

2026-11-11. TN1–TN3 — красные мутацией (обёртки компонентами, слоты всегда, подпись без проверки
пустоты). TN4 — `perf:compare` против `a92bdd52` (рабочая копия с ADR 0209 и 0210), 15 раундов:
монтирование 1000 × 1000 без плагинов (P3) 29,4 → 25,1 мс (0,854, улучшение), со всеми плагинами
(P6) 31,1 → 28,3 мс (0,910, не определено); регрессий нет. Дописывание 100 строк при сортировке
(MS9-base, MS10-base) — −27…−30 %: смена списка перерисовывает меньше компонентов на ячейку.
