## Контекст

Иерархию строк грид показывает одним отступом: первая пользовательская колонка
получает отступ `шаг × глубина` (`getCellExpandingStyles`; шаг — ADR 0059), а тоггл раскрытия
живёт в отдельной служебной колонке. На глубоком дереве (и после асинхронного прихода
детей, ADR 0056) глазу не за что зацепиться: где кончается ветка и к какому родителю
относится строка, приходится считать по отступам.

Решено (прожарка 2026-10-07): вертикальные направляющие по уровням — как в
редакторах кода, — включаемые опцией `rowExpanding`, для раскрытых строк и групп.

## Решение

### 1. Вид: направляющие по уровням

Строка глубины `d` рисует `d` вертикальных линий в отступе первой пользовательской
колонки — по одной на уровень предков, по центру каждого шага отступа. Соседние строки
глубины ≥ `k` продолжают линию уровня `k` без разрывов, в том числе через границу
между строками. Получаются ровные «рельсы» через всех потомков ветки.

Уголков (`├─`, `└─`) нет: тоггл стоит в другой колонке, уголку не к чему подходить, а
знание «последний ли ребёнок» и «есть ли продолжение у предка» делает рендер строки
зависимым от соседей — дороже и хрупче при сортировке и фильтре.

### 2. Включение

Опция `rowExpanding({ treeLines: true })`, по умолчанию выключена — у существующих
гридов вид не меняется. Опция одна на всё дерево: строки-группы `rowGrouping`
раскрываются тем же плагином и получают линии по своей глубине.

### 3. Рендер: только CSS на ячейке отступа

Ячейка первой пользовательской колонки, у которой уже есть отступ, получает
декоративный псевдоэлемент цвета линии под маской: слой маски на каждый уровень, сдвинутый
на шаг, — изображение вчетверо шире линии с линией посередине. Список слоёв по глубине
строит ячейка. При дробном масштабе (браузерный масштаб 67–90 %, масштаб контейнера)
линия внутри изображения сглаживается, а прямоугольник, тень и стоп градиента шириной
в 1px Firefox и WebKit привязывают к пикселям экрана и схлопывают в ноль, Chromium —
стоп градиента (ADR 0084). Новых DOM-узлов нет, элементов через
несколько строк нет, поэтому линии не зависят от виртуализации, сортировки и
пагинации: каждая строка рисует свои. Псевдоэлемент выходит вверх на толщину границы
ячейки, чтобы линия не рвалась между строками, и не перехватывает указатель. Ячейку
отступа обрезает `clip-path: inset(0)` по внешнему краю границы, а не `contain: paint`:
та режет по внутреннему краю, а `overflow-clip-margin` нет в Safari.

Линии живут там же, где отступ, — в ячейке, которую выбирает ядро
(`getCellExpandingStyles`: первая пользовательская колонка по определению колонок).
Поэтому у закреплённой колонки они остаются на месте при горизонтальной прокрутке, а
куда отступ уходит при перестановке колонок, решает ядро отступа, а не линии — это
вне объёма. Узкая колонка теряет на линии ту же ширину, что сейчас на отступ.

| Токен                        | Смысл         | По умолчанию                      |
| ---------------------------- | ------------- | --------------------------------- |
| `--tsr-comp-tree-line-color` | цвет линий    | 5 % цвета текста (`--tsr-sys-fg`) |
| `--tsr-comp-tree-line-width` | толщина линий | 1px                               |

Цвет по умолчанию — 3 % цвета текста, а не цвет разделителей: разделитель (почти белый
на белом) на линии в 1px не читается; 3 % — едва заметная направляющая, не спорит с текстом.

### 4. Доступность

Линии декоративные: уровень строки в `treegrid` уже несёт `aria-level` (ADR 0015).
Скринридеры их не видят, axe-прогоны дерева в ролях `table` и `treegrid` остаются
чистыми.

## Границы

- **Уголки** `├─` / `└─` — не входят (§1).
- **Подсветка ветки** текущей строки при наведении — не входит, отдельная идея.
- **Линии в колонке тоггла** — не входят: колонка служебная, отступа в ней нет.
- **Шаг отступа** — не здесь: его задаёт токен `--tsr-comp-row-nesting-indent`
  ([ADR 0059](0059-row-nesting-indent.md)); шаг линий равен ему.

## Отвергнутые альтернативы

- **Классическое дерево с уголками** — §1.
- **Элемент-линия через несколько строк** (оверлей на ветку) — рвётся под
  виртуализацией и требует пересчёта геометрии на прокрутке.
- **Повторяющийся градиент на слое отступа** — линия в 1px из жёстких стопов градиента
  пропадает при дробном масштабе страницы (при шаге 16px — у строк первого уровня).
- **Тени псевдоэлемента со сдвигом на шаг** — прежний вариант этого ADR; в Firefox и
  WebKit прямоугольник в 1px при дробном масштабе схлопывается (ADR 0084).
- **Повтор маски `space`** — укладывает столько плиток, сколько влезает, а не по
  одной на уровень.
- **Линии через `background-image` самой ячейки** — им уже пользуется тинт выделения
  `cellSelection`; два слоя фона одной ячейки конфликтуют.
- **Включено по умолчанию** — меняет вид существующих гридов без запроса.

**Проверка видом.** Линии проверяются по пикселям скриншота. Скриншот снят не в масштабе
CSS-пикселей, поэтому линию ищут в окне ±1px, а перекрытие границы строки (тоньше
пикселя скриншота) дополнительно проверяется геометрией псевдоэлемента (RE54).

## Последствия

- **+** Принадлежность строки ветке видна без подсчёта отступов.
- **+** Цена — один псевдоэлемент на ячейку отступа, без JS на прокрутке.
- **−** Ядро ячейки знает об опции плагина (атрибут на ячейке отступа).
- **Публичный API:** опция `treeLines` у `rowExpanding`, токены
  `--tsr-comp-tree-line-*`. Ломающих изменений нет.

3. Тесты: визуальные — `row-expanding-tree-lines`, перф RE60 — в `scroll`.
