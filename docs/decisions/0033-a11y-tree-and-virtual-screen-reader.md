# 0033 — Проверка доступности: дерево AX Chromium и эмулятор скринридера

- **Статус:** Принято
- **Дата:** 2026-09-26
- **Изменён:** 2026-10-25 — стенды ручной проверки — в `Tessera/Common/Screen readers`
  (`*.dev.stories.tsx`, только в `npm run storybook`).
- **Связано:**
  - [ADR 0020](0020-accessibility.md), [ADR 0031](0031-wcag-keyboard.md),

  - [ADR 0034](0034-wcag-22-dragging-and-target-size.md) — WCAG 2.2: меню на

  - [ADR 0009](0009-test-coverage-visual-and-performance.md) — один тест на
    требование; префиксы `AX<n>` (дерево) и `SR<n>` (эмулятор).

## Контекст

axe проверяет правила ARIA, но не то, **что именно** получит и произнесёт
скринридер. Ручная проверка на NVDA / JAWS / VoiceOver остаётся эталоном, но её
нельзя гонять на каждое изменение. Нужны два автоматических уровня между ними.

## Решение

### Уровень 1 — снимки дерева доступности Chromium (`AX<n>`)

Серверная команда Vitest `axTree` (`stories/__tests__/a11y.commands.ts`) через
CDP берёт `Accessibility.getFullAXTree` дочернего iframe теста — то дерево,
которое браузер отдаёт скринридеру через платформенный API, а не вычисление
тестовой библиотеки. Поддерево от первого `grid`/`treegrid`/`table` сворачивается в
текст: строка на узел `роль "имя" свойства` (уровень, раскрытие, выбор, `invalid`,
`busy`, `live` и др.; у live-областей — их текст, у полей — описание), игнорируемые узлы, `generic`-обёртки и текстовые узлы
схлопываются. Сценарии сверяются со снимками (`toMatchSnapshot`); изменение
снимка — осознанное изменение того, что слышит пользователь, и проходит ревью.
Сценарии держат маленькими (3–5 строк), чтобы виртуализация не влияла на дерево.

### Уровень 2 — эмулятор скринридера (`SR<n>`)

`@guidepup/virtual-screen-reader` строит по DOM речь по спецификациям ACCNAME /
CORE-AAM / WAI-ARIA и слушает фокус и live-области. Тест ведёт грид реальными
клавишами (`userEvent`) и сверяет журнал фраз (`spokenPhraseLog`): что объявлено при
входе в грид, сортировке, выборе, правке с ошибкой, перестановке.

Ручной проход по настоящим скринридерам — по гайду
[docs/testing/screen-readers.md](../testing/screen-readers.md) (стенды «Screen readers — …»).

Эмулятор — приближение: реальные скринридеры различаются (режим фокуса и чтения,
озвучивание контекста строки). Он не заменяет ручную проверку, а ловит регрессии
того, что озвучивается при типовых действиях.

### Находки при внедрении

- Скрытая подпись колонки выбора дублировала имя чекбокса («Select all rows
  Select») — у колонки с именованным контролом подписи нет (ключ `selectColumn`
  удалён, [ADR 0032](0032-wcag-aa-remainder.md), W13).
- Ошибка `validate` не объявлялась: `role="alert"` вставлялся в DOM сразу с
  текстом. Теперь область ошибки есть всегда, меняется только текст (W11).
- При фокусе на ячейке `treegrid` состояние строки (уровень, раскрытие) не
  озвучивалось — добавлен фокус на строке ([ADR 0032](0032-wcag-aa-remainder.md), W16).
- Имя заголовка колонки включало текст кнопок («Country Sort descending») —
  теперь только текст заголовка (W17).

## Последствия

- **+** Регрессии того, что получает и произносит скринридер, ловятся в CI без
  установленных скринридеров.
- **−** Снимки дерева привязаны к версии Chromium: смена вычисления имён в
  браузере меняет снимки — это ожидаемое, ревьюируемое обновление.
- **−** Новая dev-зависимость и её транзитивные (`@testing-library/dom`,
  `dom-accessibility-api`, `html-aria`).
