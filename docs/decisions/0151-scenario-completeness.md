## Контекст

Стражи SN7–SN8 (ADR 0117) проверяют, что у каждого сценария из таблицы ADR есть история и
наоборот. Что в таблице записаны все сценарии фичи, не проверяет ничего: по §5 существующие
фичи дополняются «при аудите». Требование, шире сценария, доказывается визуальным тестом —
и показывать его в истории никто не обязан. VR14 требует, чтобы каждое состояние каталога
было показано хотя бы раз, и не видит, что то же состояние у другой фичи не показано нигде.

Разбор 2026-10-29 нашёл отказы без историй: фильтр колонки и страница (ADR 0116, SA18), выгрузка
(ADR 0044), новая выборка серверной модели строк (SD21), пункт контекстного меню (ADR 0078).
Их шаги добавлены (3c65e3f9), а сама история с выгрузкой нашла баг — отказ `onExport` не
отмечал кнопку (ec76528d). Причины пропусков:

1. Сценарий собирали из одного удобного пути, а не из всех исходов.
2. Отказ закрывали визуальным тестом — история не была обязательна.
3. Сквозные ADR 0127 и 0136 поменяли вид отказа во всех фичах, а истории старых фич
   обновлялись «при аудите», которого не было.
4. Ссылки на истории в тексте ADR никто не сверял: ADR 0078 ссылался на две несуществующие.

Отдельно: раздел «Data loading/Server row model» разросся до 21 истории в одном файле, и больше
половины из них — не о серверной модели, а о других фичах в серверном режиме.

### Как у других

- **AG Grid** — серверный режим одним разделом документации «Server-Side Row Model» с
  подстраницами по фичам: Sorting, Filtering, Row Grouping, Selection, Tree Data.
- **MUI X** — раздел «Server-side data» с подстраницами Lazy loading, Row grouping, Tree data,
  Aggregation.

## Решение

### 1. Правило: ответ и отказ

У действия с асинхронным итогом — колбэк вернул промис, запрос к серверу — истории показывают
и ожидание с ответом, и отказ: шагом своего гайда или соседнего. Если отказ по устройству
невозможен (действие не ждёт ответа) или его нет в демо, строка реестра (§2) называет причину.

### 2. Реестр исходов

Таблица «Реестр исходов» этого ADR — источник истины. Строка — одно асинхронное действие:

```md
| Действие | Колбэк | Где итог | Ответ | Отказ |
| -------- | ------ | -------- | ----- | ----- |
```

- **Колбэк** — `<фабрика>.<опция>` публичного API (`cellEditing.onCellEdit`).
- **Где итог** — по §1 ADR 0136: элемент, таблица или только кнопка.
- **Ответ** и **Отказ** — `` `<Экспорт истории>` › <Шаг гайда> `` или `— <причина>`.

Страж реестра (OC1–OC3) проверяет, что истории и шаги существуют, что каждый колбэк
публичного API, который может вернуть промис, в реестре есть, и что строка без шага несёт
причину. Реестр заполняется при внедрении; пробелы, найденные при заполнении, закрываются
шагами (OC7).

### 3. Сквозной ADR обновляет истории

ADR, который меняет вид или поведение чужих фич (как 0127 и 0136), перечисляет в
«Последствиях» затронутые истории и меняет их шаги в том же внедрении. Реестр исходов
подсказывает, какие истории затронуты. Это правило процесса; стража у него нет.

### 4. Ссылки на истории в документах

Ссылка на историю в тексте `docs` — «Раздел/… — Имя» в кавычках-ёлочках — указывает на
существующую историю (OC4). Расхождения на момент внедрения — в базе с причиной; база только
сокращается.

### 5. Подразделы серверной модели строк

«Data loading/Server row model» оставляет истории самой модели: `Playground`, «Jump to the
middle», «Block error», «Unknown total», «Sorting», «Open at record», «Million rows». Фичи в
серверном режиме — подразделами, файл на подраздел:

| Подраздел                                    | Истории                                                                                       |
| -------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Data loading/Server row model/Grouping       | Group by a column, Expand a group, Totals in the footer, Grouping refused                     |
| Data loading/Server row model/Selection      | Select all except, Select a group, Regrouping clears the selection, Count without group sizes |
| Data loading/Server row model/Cell selection | Select a range, Copy loads the rows, Copy over the limit, Copy refused by the server          |
| Data loading/Server row model/Editing        | Edit a cell                                                                                   |
| Data loading/Server row model/Lazy children  | Lazy children                                                                                 |

Каждый подраздел начинается своим `Playground` (SN31). Общий мок-сервер историй — в
`src/lib/stories/__mocks__`. Имена экспортов историй не меняются; ссылки «История» в таблицах
сценариев ADR 0138, 0139, 0144, 0146 и 0148 остаются верными, близнецы высокой контрастности
переезжают вместе со своими историями.

## Границы

- **Каждое визуальное требование в истории** — вне объёма: отклонено на прожарке.
- **Синхронные действия** реестром не охватываются: у них нет ожидания и отказа.
- **Сценарии этого ADR** — нет: он о правилах, а не о фиче.

## Отвергнутые альтернативы

- **Каждое видимое требование — шагом гайда** — сотни требований и историй.
- **Только чеклист прожарки** — полнота снова зависит от автора ADR.
- **Эвристика по словам «отказ», «ожидание» в требованиях** — хрупко, зависит от формулировок.
- **Сквозной ADR только перечисляет истории** — обновление снова откладывается.
- **Серверные сценарии — в разделы фич** («Rows/Grouping — Server …») — серверный режим
  рассыпан по каталогу; AG Grid и MUI X собирают его в один раздел.
- **Оставить раздел как есть** — один файл в 2700 строк и 21 история.

## Последствия

- **+** Новый асинхронный колбэк без историй ответа и отказа не пройдёт стража.
- **+** Пропуски вида и поведения видны в историях, а не только в тестах: история с выгрузкой
  нашла баг, который тесты пропускали.
- **−** Реестр — ещё одна таблица, которую держат в порядке вместе с историями.
- **−** У пяти подразделов серверной модели — свои `Playground`.

## Внедрение

Одним этапом, 2026-10-29.

- **Страж реестра** — `src/lib/__tests__/scenarioCompleteness.test.ts` (OC1–OC3, OC5–OC7):
  реестр читается из таблицы «Реестр исходов», истории и шаги гайдов — статическим разбором
  файлов историй (`__tests__/storyFiles.ts`), колбэки — по типам публичного API
  (`__tests__/publicTypes.ts`, признак `returnsThenable`; `ReactNode` с промисом React 19 не
  в счёт). Вне реестра — копии опций `<Фабрика>Hooks`, `RowSource` (его реализует таблица),
  `formAction` кнопок React DOM.
- **Страж ссылок** — `src/lib/__tests__/storyReferences.test.ts` (OC4): ссылки в ёлочках и
  обратных кавычках по `docs`; база — десять ссылок старых ADR на переименованные истории.
- **Пробелы, закрытые шагами:** «Export — Excel» — шаг «Файл не собран» (отказ формата больше
  не пишется в консоль, ADR 0073, XL7); новая история «Rows/Actions — Async action» (ADR 0078,
  S3) — ожидание и отказ на кнопке меню строки. **Причинами:** ответ действия меню колонки,
  строки и пункта контекстного меню — у успеха нет видимого итога; неудавшаяся проверка
  доступности и отказ загрузки панели — в демо не воспроизводятся, их проверяют визуальные
  тесты MI4 и AM30. Меню ручек и грипа ширины асинхронных действий приложения не несут.
- **Подразделы серверной модели** — пять файлов `DataGrid.DataLoading.ServerRowModel.<Подраздел>.stories.tsx`
  со своими `Playground`; общий «сервер» гайдов — `__mocks__/serverRowModelGuide.ts`;
  близнецы высокой контрастности названы по подразделам. Бюджет снимков (VR11) поднят до 850
  (ADR 0093).
