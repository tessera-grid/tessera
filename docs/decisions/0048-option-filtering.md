## Контекст

В CRM почти каждая таблица несёт поля с конечным набором значений: статус и этап
сделки, приоритет, теги, ответственный менеджер, компания. Сужают по ним чаще всего —
«мои сделки в работе», «теги VIP или Partner». Текстовый фильтр
([ADR 0045](0045-filtering.md)) здесь не годится: пользователь не знает точного
написания, а у ответственного в ячейке лежит id, а не имя.

Три вида таких полей различаются формой значения и источником вариантов:

- **select** — одно значение из короткого списка (статус);
- **multiselect** — массив значений (теги, роли);
- **lookup** — id записи справочника (менеджер, компания), справочник бывает большим и
  серверным.

Опора: TanStack Table v9 даёт faceting (`createFacetedRowModel`,
`createFacetedUniqueValues`) — уникальные значения колонки по строкам, прошедшим
остальные фильтры. В Base UI есть `Checkbox`; TanStack Virtual уже в стеке.

## Решение

### 1. Варианты — поле колонки (SF1–SF2)

Варианты описываются на уровне колонки, а не фильтра: от них зависят отрисовка ячейки,
быстрый поиск, экспорт и фильтр — и отрисовка работает без плагина фильтрации.

```ts
type OptionValue = string | number | boolean

interface ColumnOption {
  value: OptionValue
  label: string
  /** Серверный режим: число строк для счётчика варианта. */
  count?: number
}

{ accessorKey: 'status', header: 'Status',
  options: [{ value: 'lead', label: 'Lead' }, { value: 'won', label: 'Won' }],
  filter: 'select' }

{ accessorKey: 'tags', header: 'Tags', options: TAGS, filter: 'multiselect' }

{ accessorKey: 'managerId', header: 'Manager',
  getOptionLabel: id => managersById[id]?.name,
  filter: { type: 'lookup', loadOptions: (search, { signal }) => fetchManagers(search, signal) } }
```

- **`options`** и **`getOptionLabel(value) => string | undefined`** — поля описания
  колонки в ядре (аугментация `ColumnDef` ядром, а не плагином). Подпись значения
  ищется по порядку: `options` → `getOptionLabel` → кэш вариантов, загруженных
  `loadOptions` (§5) → само значение строкой. Ядро даёт помощник подписи; им
  пользуются отрисовка, `quickSearch`, `dataExport` и `columnFiltering` — без импорта
  друг друга (`check:tree-shaking`).
- **`loadOptions`** — в объекте `filter` у `lookup`: это способ искать варианты в
  панели, а не подписывать значения.
- **Без `options` и `loadOptions`** варианты фильтра — уникальные значения колонки
  (faceting TanStack); значение, которого нет в `options`, показывается сырым. В
  серверном режиме варианты из данных не собираются: на клиенте лишь страница данных.

### 2. Условия и значение фильтра (SF3–SF5)

| Тип           | Условия                                             | По умолчанию |
| ------------- | --------------------------------------------------- | ------------ |
| `select`      | любое из, ни одно из, пусто, не пусто               | любое из     |
| `lookup`      | то же                                               | любое из     |
| `multiselect` | любое из, содержит все, ни одно из, пусто, не пусто | любое из     |

- `select` / `lookup`: «любое из» — значение в выбранных; «ни одно из» — не в
  выбранных; «пусто» — `null`, `undefined`, `''`.
- `multiselect`: «любое из» — пересечение с выбранными не пусто; «содержит все» —
  выбранные все есть в ячейке; «ни одно из» — пересечения нет; «пусто» — `null`,
  `undefined`, `[]`.
- Значение в срезе — `{ operator, value: OptionValue[] }`; сериализуемо, серверу уходит
  как есть. Пустой выбор у условий со значением снимает фильтр.

### 3. Панель — чек-лист (SF6–SF11)

- Поповер кнопки заголовка (и пункт кебаба, [ADR 0045](0045-filtering.md), §4):
  выбор условия, поле поиска, «Выбрать все» / «Снять», список вариантов с галочками и
  счётчиками, «Сбросить».
- **Применение сразу:** галочка, «Выбрать все», «Снять», условие — без кнопки
  «Применить», как у булева фильтра и дат. Ввод поиска — через `debounceMs`.
- **Поиск** — по подписям, «содержит» без учёта регистра. «Выбрать все» и «Снять»
  действуют на варианты, видимые после поиска.
- **Счётчики фасетные:** число строк, прошедших остальные фильтры колонок и быстрый
  поиск, без фильтра этой колонки (как в каталогах магазинов). Отмеченный вариант со
  счётчиком 0 остаётся в списке. У `multiselect` строка учитывается в каждом своём
  значении. У вариантов из `loadOptions` счётчиков нет; в серверном режиме — только
  `option.count`.
- **Большие списки** виртуализируются (TanStack Virtual): в DOM — видимые варианты.
- **Клавиатура:** фокус в поле поиска при открытии; `Tab` — в список, стрелки — по
  вариантам, пробел — галочка; `Escape` закрывает и возвращает фокус на кнопку.
- **Ленивый модуль**, как у дат ([ADR 0047](0047-date-filtering.md), DF14): грид без
  таких колонок его не загружает.

### 4. Подписи вне панели (SF15–SF18)

- **Ячейка** колонки с `options` или `getOptionLabel` без своего `cell` показывает
  подпись; массив — подписи через «, ». Свой `cell` перекрывает.
- **Быстрый поиск** ищет по подписям таких колонок, а не по значениям (у `lookup` иначе
  искался бы id).
- **Экспорт** выгружает подписи (массив — через «, »). Это поправка к
  [ADR 0044](0044-export.md), EX17 («значения, а не отрисовка»), только для колонок с
  вариантами: подпись — данные, а не оформление. `formatValue` экспорта перекрывает.
- **Сводка «Фильтры»** называет условие и подписи: «Любое из: Lead, Won +2».

### 5. Асинхронный справочник (SF12–SF14)

```ts
filter: {
  type: 'lookup',
  loadOptions: (search: string, { signal }: { signal: AbortSignal }) =>
    Promise<ColumnOption[]>,
}
```

- Вызывается при открытии панели (пустой поиск) и при вводе поиска — через
  `debounceMs`; новый вызов отменяет прошлый (`signal`), устаревший ответ не
  показывается.
- **Ожидание** — индикатор в списке и `aria-busy`; **ошибка** — сообщение и «Повторить»
  (по образцу [ADR 0041](0041-async-business-callbacks.md)); выбранный фильтр при
  ошибке не снимается.
- Отмеченные значения показываются вверху списка даже вне ответа поиска.
- **Подписи выбранных** кэшируются из ответов `loadOptions` на время жизни таблицы;
  восстановленный срез без кэша подписывается через `getOptionLabel`, иначе — сырым
  значением.

### 6. Сервер, локализация, доступность (SF19–SF21)

- `server: true` ([ADR 0045](0045-filtering.md), §10): грид не фильтрует;
  `onFilterChange` получает срез как есть.
- Подписи (условия, «Выбрать все», «Снять», поиск, ожидание, ошибка, «Повторить») — из
  `localization`; иконки — из `icons`.
- Список — группа чекбоксов с доступным именем колонки; число найденных вариантов не
  объявляется live-областью (объявляется итог фильтрации, FL32). Панель проходит axe с
  `color-contrast` в обеих темах; зона нажатия не меньше 24×24.

## Границы

- **Цвета и чипы вариантов** в ячейке и в панели — не входят.
- **Создание варианта** из фильтра — не входит.
- **Иерархические справочники** (дерево вариантов) — не входят.
- **Редактор-селект в `cellEditing`** — не входит; `options` колонки к нему готовы.
- **Сортировка и группировка по подписи** — не входят: сортируется значение (у
  `lookup` — id). Записывается в «Известные проблемы» roadmap.
- **Счётчики у вариантов `loadOptions`** — не входят: их знает только сервер.

## Последствия

- **+** Самые частые фильтры CRM без знания написания и id.
- **+** Подпись значения задаётся один раз и согласована в ячейке, поиске, экспорте,
  сводке.
- **+** Новых зависимостей нет.
- **−** Расширение публичного API: поля колонки `options` / `getOptionLabel`, типы
  фильтра, `loadOptions`, ключи локализации; поправка к EX17.
- **−** Применение фильтра варианта на 100 000×10 не укладывается в INP: ~340–520 мс
  под ×4 CPU (с выбросами) — проход фильтра по 100 000 строкам и перерисовка, как у
  поиска FL35; фасеты в замере не видны (без счётчиков столько же). SF25 —
  `knownShortfall` с регресс-потолком 600 мс.
- **−** Ядро впервые описывает смысл значения колонки (подпись) — новая ответственность
  ядра, а не плагина.

## План внедрения

- **Фаза 1 — ядро.** Поля колонки `options` / `getOptionLabel`, помощник подписи,
  условия, фасеты, сериализуемый срез; ячейка, быстрый поиск, экспорт по подписям;
  поправка EX17 в ADR 0044 (SF2–SF5, SF8, SF14–SF17).
- **Фаза 2 — панель.** Ленивый модуль, чек-лист, поиск, «Выбрать все» / «Снять»,
  счётчики, виртуализация, клавиатура, сводка (SF1, SF6–SF11, SF18, SF22).
- **Фаза 3 — справочник.** `loadOptions`, ожидание, ошибка, кэш подписей (SF12–SF13).
- **Фаза 4 — сервер, вид, истории, перф.** SF19–SF21, SF23–SF26;
  `DataGrid.Filtering.stories.tsx`: «Filtering — select & multiselect» и
  «Filtering — lookup (server)».
