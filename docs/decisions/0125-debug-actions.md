## Контекст

Грид сообщает приложению бизнес-колбэками (`on*`) и срезами состояния, но не тем, какое
действие пользователь сделал: одна сортировка даёт колбэк, смену среза и пересборку
моделей, а несколько нажатий подряд неотличимы от одного. Консоль историй (ADR 0124)
склеивала записи по имени и времени и путала разные действия. Нужен источник правды о
действиях — у самого грида, единый для встроенных плагинов и плагинов автора.

### Как это сделано у других

- **MUI X** — шина событий `apiRef.current.subscribeEvent`: каждое действие грида —
  событие с именем и параметрами.
- **AG Grid** — события грида (`sortChanged`, `cellClicked`…) с `source`
  (`uiColumnSorted`, `api`).
- **TanStack Table** — нет: только колбэки срезов.

## Решение

### 1. Канал — в ядре

Опция ядра `useCreateTable({ onDebugAction })` получает действие:

```ts
interface DebugAction {
  id: number // порядковый номер у экземпляра таблицы
  plugin: string // id плагина-владельца; 'core' — ядро
  action: string // имя действия: 'toggleSort', 'resize', 'commit'…
  detail?: unknown // параметры действия
  source: 'pointer' | 'keyboard' | 'api' | 'auto'
  phase?: 'start' | 'end' // начало и конец жеста
  cause?: number // id исходного действия у отложенного итога
}
```

`commonFeature` (always-on) ставит в `constructTableAPIs` метод
`table.reportAction({ plugin, action, detail, source, phase, cause })` — рядом с
`reportPluginError` и `announce`. Он есть у таблицы при любом наборе плагинов; плагин
`definePlugin` вызывает его так же, как встроенный. Метод возвращает `id` действия —
его передают как `cause` в отложенный итог. Без `onDebugAction` метод сразу выходит:
событие не создаётся, `detail`-функция не вызывается. Канал работает и в продовой
сборке — без слушателя он ничего не стоит.

`source`: `pointer` — нажатие, касание или протяжка; `keyboard` — клавиша, в том числе
нажатие кнопки с клавиатуры; `api` — вызов метода приложением; `auto` — грид сам (порог
ленты). Ядро выводит его из события (`sourceOf(event)`).

### 2. Ядро сообщает само

О том, что исполняет само, ядро сообщает без кода в плагинах:

- **слот-действия** — кнопки шапки, кебабы, инлайн-кнопки и пункты меню (`runMenuAction`),
  с `id` плагина-владельца действия; их асинхронный итог — отдельным действием с `cause`;
- **клавиатурные действия** и **пункты контекстного меню**, **пункты меню ручек**;
- **клавиатурная навигация** — переход активной ячейки, вход и выход из режима действия;
- **серверные действия** (`runServerAction`) — запрос, ответ, отказ с откатом, замена
  новым запросом;
- **повтор загрузки** и закрытие плашки ошибки; **вызовы API** приложения
  (`scrollToRow`, подсветка; `exportData` — от `dataExportModel`) — с `source: 'api'`.

### 3. Плагин сообщает сам — только жесты и свои контролы

Явный вызов `table.reportAction` — в обработчиках контролов, которые плагин рисует сам
(флажок выбора, шеврон, поповер колонок, панель фильтра), и в жестах (протяжка ширины,
перетаскивание, выделение ячеек, сессия правки). Жест сообщает начало (`phase: 'start'`)
и конец (`phase: 'end'`); итог асинхронного колбэка плагина — общим помощником ядра
`reportOutcome(table, report, result)`: отдельное действие `<action>Resolved` или
`<action>Rejected` с `cause`.

## Отвергнутые альтернативы

- **Действия из событий DOM в историях** — точность ниже: не всякое нажатие — действие,
  а отложенные итоги не видны вовсе.
- **Подписка на экземпляре** (`table.subscribeDebugActions`) — новый императивный метод;
  опция ядра проще и следует правилу имён колбэков (ADR 0106).
- **Только в разработке** (`NODE_ENV`) — поведение зависело бы от бандлера потребителя;
  без слушателя канал и так бесплатен.
- **Итог внутри исходного действия** — группа «росла» бы задним числом, порядок перестал бы
  быть хронологическим; итог — своё действие с `cause`.
- **Логгер в каждом плагине** — хардкод в 20 плагинах; канал один, в ядре.

## Границы

- Детали действий — данные приложения: канал отдаёт их как есть, что отправлять дальше
  (аналитика), решает приложение.
- Частые промежуточные события жеста (движение указателя) — не действия: жест — начало и
  конец, промежуточное видно срезами.

## Последствия

- **Публичный API:** новая опция ядра `onDebugAction`, метод `table.reportAction`,
  помощник `reportOutcome`; ломающих изменений нет. Аугментация — `commonFeature.types.ts`.
- **Документация:** `docs/architecture/plugins-and-slots.md` (канал для автора плагина),
  `table-assembly.md` (опция ядра).
- **Перф (TQ6)** — требование AL26: слушатель не добавляет гриду работы.
- **Что вскрыли тесты перечня** (исправлено вместе с каналом):
  - причина итога по умолчанию терялась, когда плагину приходила копия таблицы (перенос
    строк и колонок) — ключ «последнего действия задачи» теперь сам метод
    `reportAction`, общий у экземпляра и копий (AL7, AL11, AL12);
  - кебаб и заглушки ленивых поповеров открываются вне обработки события — источник
    без события берётся из последнего ввода (`userSourceOf`), а не `api` (AL16);
  - отказ серверного `onExport` логируется и не пробрасывается — итог сообщается по
    исходному промису колбэка, иначе канал показывал успех (AL21);
  - «Повторить» на плашке ошибки терял событие нажатия — источник был `api` (AL25).
