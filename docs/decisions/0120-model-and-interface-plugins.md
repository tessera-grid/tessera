# 0120 — Плагины модели и плагины интерфейса; срезы плагинов — только в их аргументах

- **Статус:** Принято (решения — по итогам прожарки 2026-10-16; реализовано 2026-10-16)
- **Дата:** 2026-10-16
- **Изменяет:**

  - [ADR 0028](0028-define-plugin-authoring-api.md) — `controlled` в `definePlugin`

  - [ADR 0106](0106-flag-and-predicate-naming.md) — в правило имён добавляются плагин

  - [ADR 0044](0044-export.md) — оси выгрузки смотрят на модели, а не на плагины

## Контекст

Модели строк живут в плагинах (ADR 0010): плоский грид за них не платит. Но каждый плагин
модели строк приносит и свой интерфейс, и отдельно их не подключить:

| Состояние приложения   | Без плагина        | Плагин тянет за собой                   |
| ---------------------- | ------------------ | --------------------------------------- |
| `sorting`              | молча игнорируется | кнопки сортировки в заголовках, клавишу |
| `pagination`           | молча игнорируется | пейджер в нижней панели                 |
| `columnFilters`        | молча игнорируется | кнопку фильтра, сводку в тулбаре        |
| `globalFilter`         | молча игнорируется | поле поиска                             |
| `grouping`             | молча игнорируется | кнопку группировки в заголовках         |
| `rowSelection`         | молча игнорируется | колонку флажков, Space                  |
| `cellSelection`        | молча игнорируется | выделение мышью, копирование            |
| API `table.exportData` | метода нет         | кнопку выгрузки в тулбаре               |

Приложение со своими контролами (форма фильтров, пейджер в шапке страницы, вид из URL)
вынуждено подключать чужой интерфейс и прятать его обходными путями: свой пейджер —
`pagination()` плюс `enableStatusBar: false` (PB12), выбор без флажков — невозможен.

Вторая сторона той же проблемы — канал состояния. Срезы плагинов передаются через
`state` и `handlers` ядра, хотя применяет их только плагин: тип `state` выводится из набора
плагинов, а `handlers` — `Record<string, unknown>` без проверки. Срез без плагина
компилируется (переменная, `handlers`) и молча ничего не делает.

ADR 0119 уже разделил дерево: модель (сейчас `rowExpandingModel`) и интерфейс
`rowExpanding`. Колонки (порядок, видимость, закрепление, ширины) остаются в ядре — без них
нет раскладки, а их плагины и так только интерфейс. Этот ADR распространяет разделение
ADR 0119 на остальные модели и закрывает канал состояния.

Что показал код:

- `foldEntries` ([`core/features.ts`](../../src/lib/core/features.ts)) сливает опции **всех**
  присутствующих записей по порядку: выключенная запись отдаёт `enableSorting: false` и
  гасит модель, которую включила другая. Для дерева ADR 0119 уже решил это правилом «модель
  включена, если включена хоть одна несущая её запись».
- Фичи записей сливаются по ключу (`buildTesseraFeatures`): плагин интерфейса может нести
  фичи модели без механизма зависимостей.
- Бизнес-колбэки (`onToggleColumnSort`, `onPageChange`, `onFilterChange`, `onSearchChange`,
  `onSelectRow`) зовут только кнопки и действия интерфейса. Режим `server` (`manual*`),
  сужение среза, сброс страницы при смене порядка — свойства модели.
- `cellEditing` (`editing`/`onEditingChange`) и `keyboardNavigation`
  (`activeCell`/`onActiveCellChange`) уже принимают своё состояние аргументами через
  `controlled` `definePlugin` — образец для остальных.
- Межплагинные проверки почти все смотрят опции таблицы; по `id` плагина — только оси
  выгрузки (`dataExport/settings.ts`).

### Как это сделано у других

- **AG Grid** — модули модели и интерфейса раздельны: `RowGroupingModule` и
  `RowGroupingPanelModule`. Свой пейджер — `pagination` и `suppressPaginationPanel`;
  быстрый поиск `quickFilterText` не имеет встроенного поля; выгрузка — API.
- **MUI X** — всё встроено, модель — контролируемые пропы (`sortModel`, `paginationModel`,
  `filterModel`, `rowSelectionModel`); интерфейс прячут `hideFooterPagination`,
  `checkboxSelection: false`. Колонка с `sortable: false` или `filterable: false` не
  сортируется и не фильтруется из интерфейса, но программно — да.
- **TanStack Table** — только модель, интерфейса нет вовсе.

## Решение

### 1. Два уровня

**Плагин модели** приносит состояние и модель строк (или API) без единого контрола: фичи
TanStack, фабрику модели, режим данных, сужение среза, диагностику. **Плагин интерфейса**
включает свою модель и добавляет управление: кнопки, колонки, поля, клавиши, пункты меню,
бизнес-колбэки пользовательских действий.

### 2. Пары

| Модель                 | Интерфейс         | В модели                                                                                                                                              | В интерфейсе                                                                                      |
| ---------------------- | ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `columnSortingModel`   | `columnSorting`   | фичи, `sortFns`, сортировка по подписи вариантов, `server`, `multiSort: false` и `multiSort.max` (сужение)                                            | кнопка в заголовке, клавиша, `removal`, `multiSort.event`, `onToggleColumnSort`, `revertOnReject` |
| `paginationModel`      | `pagination`      | фича и модель, `initialPageSize`, `server`, `rowCount`, сброс страницы при смене порядка                                                              | пейджер в нижней панели, `pageSizes`, `onPageChange`, `revertOnReject`                            |
| `columnFilteringModel` | `columnFiltering` | фичи, типы `filter`, модель, фасеты, `server`, `timeZone`                                                                                             | кнопка фильтра, сводка в тулбаре, `filteredCount`, `debounceMs`, `dateLocale`, `onFilterChange`   |
| `quickSearchModel`     | `quickSearch`     | фича, функция поиска по видимым колонкам, `server`                                                                                                    | поле поиска, `debounceMs`, `filteredCount`, `onSearchChange`, повтор при смене колонок            |
| `rowGroupingModel`     | `rowGrouping`     | модель, агрегации; включает `rowExpandingModel` (§5)                                                                                                  | кнопка группировки в заголовке                                                                    |
| `rowSelectionModel`    | `rowSelection`    | фича, `subRows`, запрет при группировке, вид выбранной строки и `aria-selected` (§7)                                                                  | колонка флажков, Space, `selectedCount`, `onSelectRow`, `onSelectAllRowsOnPage`                   |
| `dataExportModel`      | `dataExport`      | `table.exportData`, `formats`, `filename`, `formatValue`, `allow`, `presets` (их требует `table.exportData(id)`), `server` и `onExport`, `onExported` | кнопка и панель                                                                                   |
| `cellSelectionModel`   | `cellSelection`   | фича, `canSelectCell`, подсветка диапазонов и `aria-selected`, `getSelectedCellRangesData`                                                            | мышь (`rangeSelection`, `dragSelection`, `multiRange`), копирование, пункт «Копировать»           |
| `rowExpandingModel`    | `rowExpanding`    | по ADR 0119                                                                                                                                           | по ADR 0119                                                                                       |

Свой пейджер теперь — `paginationModel()`: нижней панели нет, потому что нет её слотов
(ADR 0046); `enableStatusBar: false` для этого не нужен.

### 3. Включение модели интерфейсом и выключение

- Плагин интерфейса включает запись своей модели и передаёт ей свои аргументы модели:
  `columnSorting({ server: true })` работает, как сейчас. Подключать модель рядом не нужно.
- Включённая явная модель в наборе главнее включённой интерфейсом: её аргументы модели
  действуют, а аргументы модели у интерфейса — нет; если они расходятся, ядро в dev
  предупреждает. Выключенная явная модель рядом с включённым интерфейсом своих
  аргументов не навязывает: действует модель интерфейса с его аргументами.
  Сужения срезов (`narrow`) по-прежнему складываются от всех записей (так `maxDepth`
  `rowExpanding` ограничивает дерево и рядом с явной моделью — ADR 0119).
- Модель включена, если включена хоть одна присутствующая запись, которая её несёт.
  Опции модели (`enableSorting`, `manualSorting`…) выставляет только модель; интерфейс их не
  выставляет никогда. Порядок записей итог не меняет. Так правило ADR 0119 для дерева
  становится общим.
- Модель несут несколько интерфейсов без явной модели — действуют аргументы модели того
  интерфейса, который их задал, где бы он ни стоял в наборе (`rowGrouping()` включает
  модель дерева без аргументов, `rowExpanding({ initialExpanded })` после него — со своими).
  Задали двое и по-разному — действуют аргументы первого, ядро в dev предупреждает.
- Выключить интерфейс без модели: `columnSorting({ enabled: false })` рядом с явной
  `columnSortingModel()` — контролов нет, срез применяется. Без явной модели выключенный
  интерфейс гасит и модель, как сейчас.

### 4. Срезы плагинов — только в аргументах плагина

**Публичные `state` и `handlers` ядра несут только срезы колонок**: `columnVisibility`,
`columnOrder`, `columnPinning`, `columnSizing` и их `on…Change`. Их тип больше не зависит
от набора плагинов.

**Срез плагина задаётся аргументами его модели**, с именами как у среза TanStack:

```ts
const sorting = useSortingState() // { sorting, onSortingChange }
const rowSelection = useRowSelectionState() // { rowSelection, onRowSelectionChange }

useCreateTable({
  columns,
  data,
  plugins: [
    columnSorting({ ...sorting }),
    rowSelectionModel({ ...rowSelection }),
    paginationModel({ initialPagination: { pageIndex: 0, pageSize: 50 } }),
  ],
})
```

- Внешнее значение `<срез>` применяется до отрисовки кадра; изменения изнутри грида
  приходят в `on<Срез>Change`. Без внешнего значения срез живёт внутри грида; начальное
  значение — `initial<Срез>` (по образцу `initialPageSize`).
- Плагин интерфейса принимает те же аргументы среза и передаёт их своей модели; при явной
  модели действуют её (§3). Значение среза — не настройка ни у модели, ни у интерфейса: его
  смена не пересобирает набор плагинов, иначе каждый выбор строки в контролируемом срезе
  перерисовывал бы всю таблицу (MP19–MP20).
- Механизм — `controlled` `definePlugin` (ADR 0028), расширенный: ключом может быть срез
  TanStack, а не только локальный срез плагина, и срезов может быть несколько (фильтрам
  колонок — `columnFilters`; дереву — `expanded`).
- Срезы и колбэки, которые уходят из ядра в аргументы плагинов:

  | Срез и колбэк                            | Плагин                                        |
  | ---------------------------------------- | --------------------------------------------- |
  | `sorting`, `onSortingChange`             | `columnSortingModel` / `columnSorting`        |
  | `pagination`, `onPaginationChange`       | `paginationModel` / `pagination`              |
  | `columnFilters`, `onColumnFiltersChange` | `columnFilteringModel` / `columnFiltering`    |
  | `globalFilter`, `onGlobalFilterChange`   | `quickSearchModel` / `quickSearch`            |
  | `grouping`, `onGroupingChange`           | `rowGroupingModel` / `rowGrouping`            |
  | `expanded`, `onExpandedChange`           | `rowExpandingModel` / `rowExpanding` (§5)     |
  | `rowSelection`, `onRowSelectionChange`   | `rowSelectionModel` / `rowSelection`          |
  | `cellSelection`, `onCellSelectionChange` | `cellSelectionModel` / `cellSelection`        |
  | `onRowOrderChange`                       | `rowDragging`                                 |
  | `editing`, `activeCell` и их колбэки     | `cellEditing`, `keyboardNavigation` — уже так |

- Правило общее для всех плагинов, в том числе будущих: у ядра нет публичного канала для
  среза плагина.

**Защита от дурака.** Срез плагина, переданный в `state` или `handlers` ядра в обход
типов (приведением), ядро вырезает и не применяет; в dev — одно предупреждение на срез с
именем плагина и аргумента, куда его перенести. Источник среза один — аргумент плагина.

### 5. `expanded` — у модели дерева

Срез `expanded` принадлежит только `rowExpandingModel` (и `rowExpanding`, который её
включает). `rowGroupingModel` включает `rowExpandingModel`: группы раскрываются той же
моделью. Управлять раскрытием групп приложение будет аргументами `rowExpandingModel`,
подключив её явно.

### 6. Межплагинные проверки — по модели

Оси выгрузки (ADR 0044: значения `view`, `page`, `selected`) и любые другие проверки
«есть ли сортировка, страницы, выбор» смотрят на активную модель, а не на плагин
интерфейса: `paginationModel()` без `pagination()` даёт ось `page`. Проверки по опциям
таблицы (`infiniteScroll`, `keyboardNavigation`, `aria-multiselectable`) уже так работают.

### 7. Видимое состояние модели

Модель показывает своё состояние, но не даёт его менять: отсортированный порядок,
страница, отфильтрованные строки, группы, раскрытые подстроки — и **выбранные строки и
ячейки**: заливка выбора и `aria-selected` — у модели, без колонки флажков и мыши.
Клавиши, мышь, кнопки и пункты меню, меняющие состояние, — у интерфейса.

### 8. Имена (дополняет ADR 0106)

| Что                       | Правило                    | Примеры                                                        |
| ------------------------- | -------------------------- | -------------------------------------------------------------- |
| Плагин модели             | `<плагин интерфейса>Model` | `columnSortingModel`, `rowSelectionModel`, `rowExpandingModel` |
| Срез плагина в аргументах | имя среза TanStack         | `sorting`, `rowSelection`, `expanded`                          |
| Колбэк среза в аргументах | `on<Срез>Change`           | `onSortingChange`, `onRowSelectionChange`                      |
| Начальное значение среза  | `initial<Срез>`            | `initialSorting`, `initialPagination`, `initialPageSize`       |
| Тумблер модели в историях | `enable<Фабрика>`          | `enableColumnSortingModel`                                     |

Подопции истории `<фабрика><Опция>` различают фабрики, где одно имя — префикс другого
(`rowExpanding…` и `rowExpandingModel…`): маппер историй относит ключ к самому длинному
подходящему имени.

### 9. Код и сборка

Модель — свой модуль вне модулей интерфейса и экспорт из `/plugins`; интерфейс
импортирует модель, модель интерфейс — никогда (`check:tree-shaking`, IV3). Плоский грид
без моделей не платит ничего (ADR 0010, 0068).

### 10. Диагностика

`table.getPluginDiagnostics()` показывает явную модель отдельной записью; модель,
включённая интерфейсом, — часть записи интерфейса и отдельно не показывается.

## Миграция

Ломающее изменение публичного API (до 1.0 допустимо, отмечается в `CHANGELOG.md`):

| Было                                                                      | Стало                                                  |
| ------------------------------------------------------------------------- | ------------------------------------------------------ |
| `state: { sorting }`, `handlers: { onSortingChange }` + `columnSorting()` | `columnSorting({ sorting, onSortingChange })`          |
| `state: { rowSelection }` + `rowSelection()`                              | `rowSelection({ rowSelection, onRowSelectionChange })` |
| `state: { expanded: true }` + `treeData()`                                | `rowExpandingModel({ expanded: true })`                |
| `handlers: { onRowOrderChange }` + `rowDragging()`                        | `rowDragging({ onRowOrderChange })`                    |
| `pagination()` + `enableStatusBar: false` (свой пейджер)                  | `paginationModel()`                                    |
| `useSortingState()` → в `state`/`handlers`                                | `useSortingState()` → в аргументы плагина              |

README, истории, тесты и сайт документации переводятся вместе с реализацией.

## Отвергнутые альтернативы

- **Модели в ядре.** Ядро применяет все срезы без плагинов: модель и её проход по строкам
  вошли бы в каждый грид, против ADR 0010.
- **Интерфейс без модели, только парой.** `plugins: [columnSortingModel(), columnSorting()]`,
  как модули AG Grid: явно, но ломает каждый грид и многословно без пользы.
- **Короткие имена моделей** (`sorting()`, `selection()`): `pagination` и `rowSelection`
  уже заняты интерфейсом — пришлось бы переименовать существующие плагины.
- **Флаг интерфейса у плагина** (`columnSorting({ ui: false })`): плагин объявлен, но
  ничего не рисует — та же путаница ответственности, что `rowExpanding({ column: 'none' })`
  в ADR 0119.
- **Срезы плагинов в `state` ядра, типизированные по набору плагинов.** Тип уже выводится
  из набора, но переменная с лишним ключом и `handlers` проходят молча, а динамический
  набор плагинов расширяет тип; два канала одного среза путают источник истины.
- **Применять срез, переданный в ядро силой.** Мягче для миграции, но оставляет два
  канала одного среза.
- **`value`/`onChange` в аргументах.** Неоднозначно у плагина с несколькими срезами;
  помощники `use<Срез>State()` пришлось бы переделать.

## Границы

- Флаги колонки `columnDef.enableSorting` и подобные сохраняют семантику TanStack (ADR
  0106): колонка не сортируется вовсе, и программно тоже. Вариант MUI X «флаг гасит только
  кнопку» — отдельный ADR.
- Колонки (видимость, порядок, закрепление, ширины) остаются в ядре; их плагины — только
  интерфейс.
- `cellEditing`, `rowDragging`, `infiniteScroll`, `keyboardNavigation` на модель и
  интерфейс не делятся; их срезы и колбэки подчиняются §4.

## Последствия

- **Публичный API:** новые фабрики `columnSortingModel`, `paginationModel`,
  `columnFilteringModel`, `quickSearchModel`, `rowGroupingModel`, `rowSelectionModel`,
  `dataExportModel`, `cellSelectionModel`; аргументы срезов и `initial<Срез>` у моделей и
  интерфейсов. **Ломающие изменения:** срезы плагинов и их колбэки удалены из
  `state`/`handlers` ядра; `treeData` переименован в `rowExpandingModel`.
- **Ядро:** `foldEntries` выводит опции модели из всех её записей; `controlled`
  `definePlugin` — срезы TanStack и несколько ключей; вырезка чужих срезов из
  `state`/`handlers` с предупреждением; оси выгрузки — по моделям.
- **ADR 0119:** имя модели и канал `expanded` (§4, §5).
- **Документация:** `docs/architecture/plugins-and-slots.md` (два уровня плагинов, канал
  состояния), `table-assembly.md` (контракт `state`/`handlers`), README, roadmap.

## План внедрения

1. **Этап 1 — ядро.** Запись модели, включённая интерфейсом (`model` в `definePlugin`),
   явная модель главнее, включённая не видна в диагностике; опции модели — только от
   модели. Срезы TanStack в аргументах (`slices` в `definePlugin`): `<срез>`,
   `on<Срез>Change`, `initial<Срез>`. Дерево переходит на этот механизм: `rowExpanding`
   включает `rowExpandingModel`, срез `expanded` — их аргумент. Тесты MP4, MP5, MP8, MP9,
   MP16. Канал `state`/`handlers` ядра пока работает.
2. **Этап 2 — пары.** По одной: сортировка, пагинация, фильтры и поиск, группировка
   (включает модель дерева), выбор строк, выбор ячеек, выгрузка — модель, интерфейс,
   аргументы срезов, оси выгрузки по моделям. Тесты MP1–MP3, MP10–MP14, истории S1–S7.
3. **Этап 3 — канал ядра и миграция.** Срезы плагинов уходят из `state`/`handlers` ядра;
   истории, тесты, README и сайт — на аргументы плагинов. Тесты MP6, MP7, MP15, история
   S8. Документация: `docs/architecture/plugins-and-slots.md`, `table-assembly.md`,
   AGENTS.md, CHANGELOG.

## Требования

| ID   | Требование                                                                                                                                                                                                                                                   | Вид                                                  |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------- |
| MP1  | Каждая модель из §2 без своего интерфейса применяет свой срез (порядок, страница, фильтры, поиск, группы, выбор строк и ячеек) и даёт API TanStack (`table.exportData` — у выгрузки), а грид не рисует ни одного контрола интерфейса                         | визуальный, один тест обходит все модели             |
| MP2  | Плагин интерфейса без явной модели ведёт себя, как до разделения: строки, контролы и колбэки те же; меняется только канал состояния (MP8)                                                                                                                    | модульный, паритет                                   |
| MP3  | `enabled: false` у интерфейса при явной модели убирает контролы, а модель применяет срез; без явной модели выключенный интерфейс гасит и модель                                                                                                              | визуальный, один тест обходит все пары               |
| MP4  | Опции модели выставляет только модель: перестановка записей в наборе не меняет опции таблицы и строки                                                                                                                                                        | модульный                                            |
| MP5  | Включённая явная модель главнее модели, включённой интерфейсом: действуют её аргументы модели, расхождение — dev-предупреждение; выключенная явная рядом с включённым интерфейсом уступает его модели; сужения срезов складываются от всех записей           | модульный                                            |
| MP6  | Тип `state` и `handlers` `useCreateTable` содержит только срезы колонок и их колбэки; срез плагина или его колбэк там — ошибка компиляции                                                                                                                    | модульный, типовой                                   |
| MP7  | Срез плагина или его колбэк, переданный в `state`/`handlers` ядра в обход типов, не применяется; в dev — одно предупреждение на срез с именем плагина и аргумента                                                                                            | модульный                                            |
| MP8  | Модель и интерфейс принимают срез аргументами `<срез>` и `on<Срез>Change`: внешнее значение применяется до кадра, изменения изнутри уходят в колбэк (хелперов `use<Срез>State` нет — ADR 0164)                                                               | модульный                                            |
| MP9  | Без внешнего значения срез живёт внутри грида с начальным значением `initial<Срез>`, а без него — пустым; монтирование срез не меняет и его колбэк не зовёт                                                                                                  | модульный                                            |
| MP10 | `expanded` — аргумент только модели дерева (и включающего её `rowExpanding`); `rowGroupingModel` включает модель дерева, группы раскрываются по её срезу                                                                                                     | модульный                                            |
| MP11 | Импорт модели не тянет модули интерфейса                                                                                                                                                                                                                     | скрипт: `npm run check:tree-shaking` (после `build`) |
| MP12 | Оси выгрузки по сортировке, фильтрам, странице и выбору открываются по активной модели, без плагина интерфейса                                                                                                                                               | модульный                                            |
| MP13 | `rowSelectionModel()` без колонки флажков: выбранная строка залита выбором и несёт `aria-selected`; axe с `color-contrast` в обеих темах проходит                                                                                                            | визуальный                                           |
| MP14 | `cellSelectionModel()` подсвечивает диапазоны из среза; мышь, клавиши и копирование выделение не меняют и не копируют                                                                                                                                        | визуальный                                           |
| MP15 | Модели с пустыми срезами не дороже грида без них: монтирование и спокойная прокрутка 1000×1000 со всеми моделями §2 против того же грида без плагинов (база того же теста, ADR 0099)                                                                         | перф против базы                                     |
| MP16 | `table.getPluginDiagnostics()` показывает явную модель отдельной записью, а модель, включённую интерфейсом, — нет                                                                                                                                            | модульный                                            |
| MP17 | Смены контролируемого среза подряд, до перерисовки (сворачивание двух групп после отмены перетаскивания), складываются: колбэк получает значение от предыдущей смены, а не от прежнего значения приложения; после перерисовки — снова от значения приложения | модульный                                            |
| MP18 | Модель несут несколько интерфейсов без явной модели: действуют аргументы модели того, кто их задал, при любом порядке в наборе; разные аргументы у двух интерфейсов — действуют аргументы первого и dev-предупреждение                                       | модульный                                            |
| MP19 | Значение среза модели, заданное аргументом интерфейса, не входит в ключ аргументов интерфейса: его смена не пересобирает набор плагинов, как у самой модели (DP18)                                                                                           | модульный                                            |
| MP20 | Приложение ведёт выбор строк аргументом интерфейса: выбор строки перерисовывает только её, шапку и остальные строки — нет, по счётчикам работы                                                                                                               | визуальный                                           |
