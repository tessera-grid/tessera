## Контекст

«Применить» и «Применить всё» (`saveMode: 'manual'`) шлют черновики одним вызовом
`onCommitEdits`; ответ может отказать части (`refused`). Разбор кода 2026-11-14 показал:

- **Итога нет.** Сохранённые ячейки вспыхивают, отказанные получают треугольник и запись реестра
  отказов. Если отказанные ячейки вне окна, человек не видит ничего; журнал — отдельный плагин,
  без него признаков нет совсем.
- **Тысяча отказов — тысяча записей журнала** и тысяча отдельных записей в хранилище с вызовом
  `onFailure` на каждую.
- **Отказ запроса целиком** (сеть, ошибка сервера) размножается на все ячейки пакета с одной и
  той же причиной.
- **«Закрыть» в журнале молча сбрасывает правку** (`closeFailure` зовёт `discard`), «Очистить
  всё» — все отклонённые правки.
- **Переход к цели вспыхивает впустую**, когда строку найти не удалось: `scrollToRow` вернул
  `false`, вспышка всё равно запускается.
- **Строка, удалённая на сервере** (осознанное ограничение DR53): черновик висит в пульте,
  «Применить» получает обычный отказ с текстом сервера. Отличать его от прочих таблице и не
  нужно: почему сервер отказал, знает только сервер (§5).

### Как у других

- **AG Grid** (пакетное редактирование, 34+): отменяемый пакет правок, итог применения —
  событием приложению; сводной плашки и журнала отказов в гриде нет.
- **MUI X**: `processRowUpdate` по строке, отказ — `onProcessRowUpdateError`; пакетного
  применения и сводки нет.

Образца нет: итог и журнал — свои.

## Решение

### 1. Одна плашка на одно применение

Каждое применение пакета кончается одной плашкой в том же месте, где плашка серверного действия
(цель `'table'`, [ADR 0155](0155-pending-on-data.md)); новое применение заменяет плашку прежнего.

| Итог                     | Плашка                                                                  | Уходит                                                      |
| ------------------------ | ----------------------------------------------------------------------- | ----------------------------------------------------------- |
| Всё сохранено            | «Сохранено N изменений», тон успеха                                     | сама, через 3 с                                             |
| Часть отказана           | «Сохранено X из N», нейтральный тон; действие — см. ниже                | крестиком, новым применением или когда решены все её отказы |
| Ничего не сохранено      | «Ничего не сохранено: 0 из N», иконка отказа; действие — как у части    | крестиком, новым применением или когда решены все её отказы |
| Запрос не прошёл целиком | «Изменения не сохранены» и причина, иконка отказа; действие «Повторить» | крестиком, повтором                                         |

Вид плашки — по тому, провал ли итог (решение автора): сохранено всё — тон успеха; сохранена часть
— не провал, нейтральный тон (`tone: 'neutral'`, иконка «информация»); ничего не сохранено или
запрос не прошёл — провал, плашка без тона: иконка отказа `loadFailed` цветом ошибки, как у плашки
отказа загрузки.

Плашка называет только число сохранённых из общего числа: что и почему не сохранено, человек
смотрит в журнале отказов — там у каждого отказа причина из ответа сервера. Действие плашки
частичного итога: с плагином `failureLog` — «Показать» (открывает журнал и закрывает плашку:
разбор переходит в журнал, решение автора 2026-11-14), без него — «Повторить несохранённые». Сервер отказал всем правкам — плашка говорит «Ничего не сохранено: 0 из N»
(`cellEditing.applyNone`).

Плашка частичного итога уходит и сама, когда в реестре отказов не осталось ни одной записи с
`batch` её применения: все отказанные правки сброшены, сохранены повтором или исправлены в
ячейке — устаревший итог на экране не висит. Повтор начинает новое применение, поэтому плашка
уходит уже при его отправке.

Плашка успеха не уходит, пока на ней указатель или в ней фокус. Скринридеру — одно объявление на
применение с тем же текстом.

Плашка идёт общим каналом уведомления таблицы: запись `notice` среза `actionStatus`
(`TableNotice`, `showTableNotice`/`closeTableNotice`, чтение — `tableNotice`), которую грид рисует
`TableNoticeBanner` на месте плашки цели `'table'`. Приоритет на этом месте: плашка отказа
загрузки или серверного действия, затем плашка ожидания и вопрос перед записью, затем итог — пока
видна старшая, итог ждёт. `cellEditing` пишет итог одной записью по своему ключу: новое
применение её заменяет. Итог применения лежит и в срезе плагина `applied` (`ApplyOutcome`:
сохранено, отказано, причина отказа целиком, повтор); плашка «всё сохранено»
уходит через `APPLY_SAVED_HIDE_AFTER` (3000 мс). Действие «Показать» зовёт `table.showFailureLog()`
плагина `failureLog`.

### 2. Запрос не прошёл целиком — одна запись

Отклонённый промис `onCommitEdits` — отказ применения, а не ячеек: одна запись реестра с целью
`{ table: true }`, ключом `cellEditing:apply:<n>`, действием `cellEditing.commit`, причиной и
повтором (применить тот же набор черновиков), без `discard`. Ячейки остаются черновиками без
отметки отказа: ни одна из них не отклонена сама. Закрытие этой записи в журнале снимает и
плашку итога (`whenFailureGone`).

### 3. Запись реестра: применение и причина

Запись отказа получает необязательные поля:

```ts
interface Failure {
  /** Одно применение: отказы с одним `batch` и одной причиной журнал показывает группой. */
  batch?: string
  /** Действия над набором записей одного источника одним вызовом. */
  bulk?: {
    /** Источник: записи с одним `owner` принимают ключи друг друга. */
    owner: string
    retry?: (keys: readonly string[]) => void
    discard?: (keys: readonly string[]) => void
  }
}
```

Реестр остаётся плоским: `table.getFailures()` отдаёт запись на отказ, `onFailure` зовётся на
каждую. Отказы одного ответа пишутся в хранилище одной записью (`reportFailures(table, reports,
resolve?)`: `resolve` — ключи снятых отказов в той же записи). Вспышек итога — не больше предела
операции записи (`OUTCOME_FLASH_LIMIT`, ADR 0219).

Групповые действия журнала идут через `bulk`: журнал зовёт функцию первой записи один раз с
ключами всех записей того же `owner`; без поля — `retry`/`discard` каждой записи. `cellEditing`
даёт `bulk.retry` правкам применения: у них есть черновики.

`discard` у записи значит «за записью стоит несохранённая правка» (§6): у записей без правки —
отказа серверного действия, отказа применения целиком — поля нет, а то, что источник показывает
рядом, снимает подписка `whenFailureGone(table, key, done)`: `done` зовётся, когда запись ушла
из реестра или её заменил новый отказ.

В серверной модели строк снятие отказов по данным (`pruneFailures`) не снимает отказ строки,
которой нет в кэше: она не загружена или вытеснена (AO20).

### 4. Журнал: группы и второй уровень

Записи одного `batch` с одной причиной и одним видом цели (ячейки, строки, прочие
объекты) журнал показывает одной записью: подпись действия, «N ячеек» (или «N строк», «N
отказов»), причина (`plugins/failureLog/journal.ts`). Группа из одного отказа и запись с
уникальной причиной остаются обычными. Счётчик на кнопке журнала считает записи журнала, а не
отказы. Второй уровень — `PopupLevels` кита (ADR 0215).

Нажатие на группу меняет содержимое поповера на месте: заголовок группы с кнопкой «назад» и
виртуализированный список её отказов — у каждого цель, переход к ней, «Повторить» и «Сбросить
правку». Фокус при входе — на первой записи, при выходе — на группе; Escape на втором уровне
возвращает на первый.

Действия группы: «Повторить» — применить её правки одним пакетом; «Сбросить правки» — сбросить
все её правки одной записью в хранилище; у группы без правок вместо него — «Закрыть все в
группе». Действия журнала идут в канал действий: `retry`, `retryGroup`, `discard`,
`discardGroup`, `discardAll`, `close`, `clearAll`, `show`.

### 5. Строки больше нет

Признака «строки нет» в ответе пакета нет: таблица не знает, почему сервер отказал, —
единственный источник причины — текст отказа из ответа, и он зависит от сервера. Отказ правки
строки, которую удалили на сервере, — обычный отказ: таблица показывает причину из ответа как
есть, на ячейке — отметка отказа, в журнале — обычная запись с переходом к цели, «Повторить» и
«Сбросить правку».

Путь снять черновик исчезнувшей строки — применение: сервер отказывает правке своим текстом,
отказ встаёт записью в журнал, человек сбрасывает правку. Черновик таблица сама не снимает —
человек может переписать значение, прежде чем сбросить. Переход к строке, которую найти не
удалось, пишет «Не удалось найти строку» (§7). Транзакция `remove` снимает черновики, как
прежде (DR53).

### 6. Закрыть и сбросить — разные действия

- У записи, за которой стоит несохранённая правка (источник дал `discard`), крестика «Закрыть»
  нет: её действия — «Повторить» и «Сбросить правку» в тоне опасного действия. Запись уходит,
  когда правка сохранена, сброшена или значение исправлено в ячейке.
- У записи без правки (не удалась выгрузка, загрузка, отказ применения целиком, откатанный
  перенос) — «Повторить» и «Закрыть». Источник такой записи `discard` не даёт.
- Внизу журнала вместо «Очистить всё» — «Сбросить все правки» в тоне опасного действия: она
  сбрасывает правки всех записей и закрывает записи без правок. От десяти правок — вопрос с
  числом правок (вид вопроса — как перед большой записью, ADR 0223). Без записей с правками
  кнопка называется «Закрыть все» и не спрашивает. Вопрос — блок кита `ui/Question`: плашка
  `Alert` с текстом вопроса и двумя квадратными кнопками (галочка соглашается, крестик
  отказывается), опасная из них — в тоне опасного действия; он встаёт на место нижней кнопки,
  фокус — на «Оставить правки». Блок не экспортируется из `/ui`.

Сбрасывание из журнала идёт тем же путём, что сбрасывание из пульта: при подключённой истории
правок оно отменяется (ADR 0222, §14).

### 7. Переход к цели, которой нет

`showTarget` (`shared/objectTarget.ts`) вспыхивает цель только после удачной прокрутки и отдаёт
`Promise<boolean>`. Не удалась — журнал и пульт остаются открытыми и показывают у записи «Не
удалось найти строку» строкой ошибки записи (проп `error` у `PopupEntry` кита: значок и текст в
тоне ошибки под содержимым, кнопка перехода к цели ссылается на неё `aria-describedby`); скринридеру —
объявление.
Утверждения «удалена» нет: строка серверной модели может быть просто не загружена и не найдена
по подсказке места.

### 8. Плашка кита

`Alert` получает:

- `tone?: 'success'` — тон успеха несёт только иконка: `alertSuccess` (если своей нет) цветом
  `--tsr-comp-alert-success-color`; рамки у плашки нет, в `forced-colors` — обычный контур, как у
  любой плашки; без пропа — прежний вид. Цвет иконки — роль `--tsr-sys-success-strong`
  (`green-600` в светлой теме, `green-400` в тёмной, без моста к `--success`): значок на
  поверхности держит 3:1 (WCAG 1.4.11; 3,22:1 на белом, 8,51:1 на поверхности поповера тёмной
  темы), а роль заливки `--tsr-sys-success` (`green-500`) на белом даёт 2,22:1. Смесь роли с
  цветом текста в `oklch` не годится: ахроматический текст с оттенком 0° уводит оттенок смеси к
  ~90°, и иконка выходит жёлтой;
- `tone?: 'neutral'` — итог без провала, но и не полный успех: тон несёт только иконка —
  `alertNeutral` (если своей нет; по умолчанию `Info`, значок «информация») цветом
  `--tsr-comp-alert-neutral-color`; рамки нет, как у тона успеха. Цвет — роль приглушённых значков
  кнопок кита `--tsr-comp-control-color` (смесь цвета текста с фоном без оттенка, поэтому
  `oklch` её не окрашивает): 12,08:1 на поверхности поповера светлой темы, 8,14:1 — тёмной.
  Общий ключ `info` подсказки поиска (ADR 0053) не переиспользуется: иконку плашки
  переопределяют отдельно, как `alertSuccess`;
- `hideAfter?: number` и `onHide` — самостоятельный уход через столько миллисекунд; отсчёт стоит,
  пока на плашке указатель или в ней фокус.

## Границы

- **Узнать об удалении без применения** (запрос по `id`, поле ответа `getRows`) — не входит:
  ограничение DR53 остаётся, но у человека есть путь его снять.
- **Одиночные сохранения** (`saveMode: 'auto'`, `onCellEdit`) — без плашки итога: у них итог на
  ячейке.
- **Вставка, заполнение и массовая правка** (ADR 0219) — у них своя плашка отказа пакета; на
  новый вид итога не переводятся. Их отказы ячеек получают `batch` и группируются в журнале.
- **Счётчик «скрыто фильтром» в серверной модели строк** — отдельная прожарка.

## Отвергнутые альтернативы

- **Плашка на каждый отказ:** тысяча отказов — тысяча плашек.
- **Без плашки при успехе:** молча не ясно, произошло ли что-то (решение автора).
- **Журнал только группами, без второго уровня:** иногда нужна и сводка, и разбор каждой ошибки.
- **«Закрыть» прячет запись, правка остаётся:** запись — признак нерешённой проблемы; спрятанная
  проблема с живым черновиком путает сильнее.
- **Снимать черновик удалённой строки автоматически:** человек теряет набранное без своего
  действия.
- **Признак «строки нет» в ответе пакета и фраза словаря ядра:** таблица не может знать причину
  отказа, её знает только сервер и говорит своим текстом; детальный отчёт — в журнале, плашка
  называет только число сохранённых из общего числа (решение автора 2026-11-14).
- **Группа — одна запись реестра:** ломает `getFailures()` и `onFailure` для приложений, а
  отметке ячейки нужен свой отказ.

## Последствия

- **+** У применения есть итог в любом случае, в том числе без плагина журнала.
- **+** Журнал читается при тысяче отказов.
- **+** Правка не теряется нажатием на крестик.
- **Ломающее:** в журнале нет крестика у записей с правкой и кнопки «Очистить всё»; отказ запроса
  целиком — одна запись с целью-таблицей, а не запись и отметка на каждой ячейке; `discard` у
  записи реестра теперь значит «за записью стоит правка» — приложение, которое пишет свои записи
  с `discard` ради закрытия, получит «Сбросить правку».
- **Публичный API:** `batch` и `bulk` у записи реестра, срез
  `applied` в состоянии `cellEditing`, `table.showFailureLog()` плагина `failureLog`, ключ иконки
  `alertSuccess`, токен `--tsr-comp-alert-success-color`, роль темы `--tsr-sys-success-strong`
  (успех значком на поверхности), ключ иконки `alertNeutral`, токен
  `--tsr-comp-alert-neutral-color`, тон `'neutral'` у `TableNotice`, новые ключи словаря: `cellEditing.*`
  (`applySaved`, `applyPartly`, `applyFailed`, `applyNone`, `applyShow`, `applyRetry`), `failureLog.*` и `unsavedChanges.targetNotFound`. Кит: `tone`, `hideAfter` и `onHide` у
  `Alert`, `error` у `PopupEntry`, блок `Question` — из `/ui` они не экспортируются.
- **Перф:** AO17.

## Внедрение

1. **Кит:** `ui/Alert` — `tone`, `hideAfter`, `onHide`; история `UI/Alert`; AO19.
2. **Модель:** `core/failures` — поле `batch`; `plugins/cellEditing` — запись отказов ответа
   пачкой, одна запись при отказе запроса, предел вспышек, итог применения в срезе плагина для
   плашки, объявление, канал действий; запись отказа пакета операции записи — без `discard`
   (закрытие снимает статус при уходе записи); AO3, AO5, AO13–AO15, AO18, AO20–AO21.
3. **Журнал:** `plugins/failureLog` — группы, второй уровень, действия, нижняя кнопка с
   вопросом; `shared/objectTarget.ts` — переход без вспышки при неудаче, то же в пульте;
   AO6–AO10, AO12.
4. **Плашка итога:** показ итога применения в месте плашки цели `'table'`; AO1, AO2, AO4.
5. **Истории:** S1–S5 с гайдами на двух языках, близнецы высокой контрастности, состояния
   каталога; AO16; перф AO17 — в `interaction`.
6. **Документация:** ADR 0177 (JR2, JR3, JR8), ADR 0178 (DR17), ADR 0096; `ui-kit.md`,
   `plugins-and-slots.md`, `rendering.md` («Состояния загрузки»); roadmap — текст ограничения
   DR53; реестр исходов ADR 0151; карта наборов AGENTS.md.
