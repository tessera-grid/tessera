# 0069 — Словарь `rowsById` переходит новой модели

- **Статус:** Принято (решения — по итогам прожарки 2026-10-08)
- **Дата:** 2026-10-08
- **Связано:**
  - [ADR 0067](0067-incremental-lazy-core-row-model.md) — инкрементальная исходная
    модель ленивых детей. Здесь заменяется её решение «`rowsById` — честная копия»;
    остальное в силе.
  - [ADR 0064](0064-tessera-sorted-row-model.md) — своя модель сортировки копирует
    `rowsById` (вне объёма, см. «Границы»).

## Контекст

Инкрементальная модель (ADR 0067) собирает при приходе ответа новый словарь
`rowsById` на все строки: на 100 000 корней ~50 мс из ~66 мс сборки (IM8, ×4 CPU).

Читатели `rowsById` (2026-10-08):

- поиск по id — `getRow`, `getParentRow`, выделение (TanStack); `cellEditing`,
  `answerBatch`, `reconcileLoadedChildren`, `narrowExpanded`, `SelectedRowsCount`
  (Tessera);
- обход — `Object.values` при свёртывании строки из «раскрыто всё» (`expanded: true`,
  TanStack), копия
  в модели сортировки ([`sortedRowModel.ts`](../../src/lib/plugins/columnSorting/sortedRowModel.ts)).

Словарь между моделями никто не хранит: нижние модели TanStack передают его ссылку
дальше, но пересчитываются на каждую новую исходную модель. Цепочка прототипов
отпадает — её не видят ни `Object.values`, ни копия сортировки.

Решено (прожарка 2026-10-08):

- словарь переходит новой модели и правится на месте; прежней модели — ленивый снимок;
- копия в модели сортировки — вне объёма;
- порог IM8 — не дольше четверти полной сборки.

## Решение

### 1. Передача

При сборке из прежней модели (ADR 0067, §2) новая модель забирает словарь прежней и
правит его на месте: удаляет id строк изменённых поддеревьев, которых нет в новых, и
пишет новые объекты изменённых строк, их потомков и предков. Остальные ключи не
трогаются. Цена — O(изменённых строк).

### 2. Снимок прежней модели

У прежней модели свойство `rowsById` заменяется ленивым: при первом чтении словарь
собирается из её `flatRows` (которые не меняются) и запоминается. Прежняя модель
остаётся неизменной для любого, кто читает её `rowsById` после передачи; несколько
передач подряд дают каждой модели свой снимок, без цепочек.

## Границы

- **Копия `rowsById` в модели сортировки** (ADR 0064, SM5) при активной сортировке —
  отдельная задача в roadmap.
- **Полная сборка** (смена `data`, первая сборка) — без изменений.

## Отвергнутые альтернативы

- **Proxy поверх прежнего словаря** — прежний словарь не трогается, но каждое чтение
  идёт через ловушку, обход 100 000 ключей через неё медленнее копии, удалённым id
  нужны «надгробия».
- **Правка на месте без снимка** — прежняя модель меняется задним числом (ловушка,
  из-за которой ADR 0067 отверг правку `subRows`).
- **Цепочка прототипов** — `Object.values` и копия сортировки не видят
  унаследованные строки.

## Последствия

- **+** Приход ответа не копирует словарь на все строки: сборка модели ~20 мс против
  ~136 у полной (IM8, ×4 CPU, было ~66); в гриде RE38 ~290–360 → ~230 мс.
- **−** Ссылка на словарь, взятая у модели до прихода и сохранённая, видит правки.
  Сейчас так никто не делает; IM10 проверяет модель, но не такую ссылку.
- **Публичный API:** не меняется.

при приходе — не дольше четверти полной.
