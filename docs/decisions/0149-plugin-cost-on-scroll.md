## Контекст

Перф-матрица (ADR 0004) держит прокрутку без плагинов около цели RAIL, а со всеми плагинами
— втрое-вчетверо дороже. Замер 2026-10-28, спокойная прокрутка, ×4 CPU, prod-сборка, p95
работы на кадр:

| Выборка   | Без плагинов (P10, P11) | Все плагины (P12, P13) |
| --------- | ----------------------- | ---------------------- |
| 30×500    | Y 10 мс, X 17 мс        | Y 42 мс, X 49 мс       |
| 1000×1000 | Y 13 мс, X 19 мс        | Y 51 мс, X 62 мс       |

Разбор той же прокрутки 30×500:

- **Поодиночке плагины почти бесплатны.** Больше всех добавляют `rowActions` (+7 мс по Y) и
  `rowDragging` (+5 мс); прочие — 0–2 мс. Все вместе — +30 мс; без любого одного — всё ещё
  30–44 мс. Цена растёт быстрее суммы: с каждым плагином тяжелее каждая строка, а
  умножается это на все строки окна.
- **Кадр со всеми плагинами — на 57 % JavaScript**: React рисует пришедшие в окно строки и
  ячейки с кнопками всех плагинов, каждая ячейка держит свои подписки на store
  (`getSnapshot`, сравнение срезов — заметная доля профиля). Без плагинов — 23–34 %.
- **По горизонтали ещё 20 % — пересчёт стилей**: новые колонки приносят ячейки с кнопками и
  inline-стилями, браузер пересчитывает их стили каждый кадр.
- Скрытые кнопки ячеек и строк (ADR 0076) рисуются в каждой строке окна и прячутся стилем:
  платит каждая строка, хотя видны кнопки одной.
- Виртуализатор рисует окно синхронно в событии прокрутки (`flushSync` вендора TanStack
  Virtual): вся работа новых строк — в одной задаче кадра.

### Как это сделано у других

- **AG Grid** держит запас строк (`rowBuffer`) и дорисовывает строки и ячейки очередью по
  кадрам анимации: на слабой машине очередь отстаёт, но кадр не растёт. Рендереры ячеек
  создаются для каждой ячейки окна.
- **MUI X** обновляет окно состоянием React с запасом строк и колонок в пикселях
  (`rowBufferPx`, `columnBufferPx`); колонка действий рисуется в каждой строке.
- **Glide Data Grid** рисует ячейки на canvas — DOM на ячейку нет совсем.
- Монтирование кнопок по наведению — приём списков и таблиц приложений (почтовые клиенты,
  трекеры задач); у гридов общего назначения его нет, кнопки там рисуются всегда.

## Решение

Цель — прокрутка со всеми плагинами **не дороже двух прокруток без плагинов** на обеих
выборках по обеим осям. Гейт PS8 по итогам этапов — вдвое по Y и втрое по X (план внедрения,
этап 4). RAIL 16,7 мс остаётся целью дашборда, как сейчас: под ×4 CPU
её по горизонтали не держит и грид без плагинов.

Работа идёт четырьмя этапами — сначала без смены поведения. Каждый этап меряется
`perf:compare` против ревизии до него (ADR 0099); этап без выигрыша откатывается, причина
записывается сюда.

### 1. Одна подписка на строку

Ячейка не подписывается на store сама для каждого слота плагина: строка подписывается на
нужные срезы один раз и раздаёт ячейкам их часть. Смена среза, касающаяся одной строки
(выбор, наведение, правка), по-прежнему перерисовывает только её (ADR 0099, PF-счётчики).

### 2. Изоляция стилей и раскладки ячеек

Строка и ячейка тела изолированы от пересчёта соседей (`contain`). В inline-стилях ячейки —
только её размеры и место; вид — классами и переменными темы на строке или колонке, а не
на каждой ячейке.

### 3. Окно без синхронного рендера

Новые строки и колонки виртуализатора рисуются вне события прокрутки — без `flushSync`
(опция адаптера вендора). Пустых мест у края окна при спокойной прокрутке нет: запас окна
закрывает кадр задержки. Если цена запаса съедает выигрыш — этап откатывается.

### 5. Сдвиг окна — без перерисовки строк (до этапа 4)

Добавлен 2026-10-28 замером горизонтальной прокрутки (план внедрения, этап 5). Сдвиг окна
колонок перерисовывает у видимой строки только список её ячеек: компонент строки, её хуки и
обёртки плагинов (перетаскивание строк) не перерисовываются. Обёртки перетаскивания строки
не перерисовываются и при сдвиге окна строк — только при смене своей строки. Тулбар при сдвиге окна
не перерисовывается, ячейки футера перерисовываются только новые.

### 4. Значки скрытых кнопок — только там, где их видно

Скрытая кнопка ячейки и строки (действия, ручки, кебабы, инлайн-кнопки слотов) остаётся у
каждой строки: узел кнопки, её доступное имя и место в порядке фокуса не меняются. Её значок
монтируется только у строки:

- под указателем;
- с фокусом внутри;
- тронутой пальцем последней (ADR 0086);
- с открытым меню или панелью своей кнопки.

Включённая, ждущая, гаснущая и упавшая кнопка (ADR 0062, ADR 0127, ADR 0136) видна и без
наведения — её значок есть всегда. Появление — без сдвига раскладки и с прежним плавным
проявлением (ADR 0076): значок монтируется в том же событии, что включает `:hover`.

Замер этапа (план внедрения, этап 4) показал, что цена скрытой кнопки — в её значке SVG, а
не в кнопке: без значков кадр по X дешевле почти так же, как совсем без кнопок. Поэтому
монтируется значок, а не кнопка, и клавиатура, скринридер и касание остаются прежними.

Устройство: строку показывает хранилище грида на слушателях документа (`grid/rowReveal.ts`),
ячейка тела даёт место показа своей строки, обёртки скрытых кнопок кита — признак скрытой
кнопки, `IconButton` рисует значок через `RevealedIcon` (`ui/IconButton/iconReveal.tsx`).
Смена строки перерисовывает только значки двух строк.

## Границы

- **Быстрая прокрутка** (P7, P8) — скелеты (ADR 0008): её цена — другие требования.
- **Монтирование** — гейт по-прежнему P5–P6; этап 4 его только облегчает: значков при
  монтировании нет.
- **Сценарии и истории.** Видимое поведение не меняется: кнопки и сейчас видны только при
  наведении, его показывают истории разделов. Своей таблицы сценариев нет.
- **Canvas вместо DOM** — вне объёма.

## Отвергнутые альтернативы

- **Цель RAIL 16,7 мс сразу** — под ×4 CPU это почти цена грида без плагинов; потребовала
  бы всех мер разом без промежуточного замера.
- **Записать как осознанное ограничение** — грид для «highload» со всеми плагинами в
  50–60 мс на кадр не годится.
- **Кнопки по наведению только без клавиатурной навигации** — два поведения грида вместо
  одного; с навигацией фокус и так определяет строку.
- **Монтирование по наведению опцией приложения** — по умолчанию дорого всем, кто опцию не
  нашёл.
- **Скелет на кадр у края окна** — заметный мусор при спокойной прокрутке; запас окна дешевле.
- **Очередь дорисовки по кадрам, как AG Grid** — своя механика поверх виртуализатора; сначала
  — меры без неё.

## Последствия

- **+** Прокрутка со всеми плагинами в два раза дороже голой, а не вчетверо.
- **+** Меньше DOM на строку окна: память и стили дешевле и вне прокрутки.
- **−** Этап 4 меняет устройство: тесты, которые ищут значок скрытой кнопки без наведения,
  сначала наводят указатель или ставят фокус.
- **−** Этап 3 зависит от запаса окна: дороже монтирование строки — больше запас.
- **Публичный API** не меняется. Автор плагина: компонент слота ячейки монтируется у каждой
  строки, как прежде; значок кнопки кита в скрытой обёртке (`CellButton`, `RowButton`) — у
  строк из §4. Своя скрытая кнопка без обёртки кита рисует значок всегда.

## План внедрения

1. **Этап 1.** Подписки строки: срезы для слотов ячеек — одной подпиской строки; PS1;
   `perf:compare` до и после. **Отложен 2026-10-28** замером до переделки. Подписок на
   строку 26 без плагинов и 68 со всеми (из них почти две на ячейку — каналы `cellEditing`);
   при спокойной прокрутке store не меняется ни разу, подписки стоят только монтирования и
   размонтирования строк. Потолок выигрыша — грид совсем без подписок (значение читается
   один раз): P12 38,4 / 51,1 мс → 34,9 / 46,0 мс (Y / X), повтор базы — 44,5 / 54,4 мс.
   Не больше 13–16 % при шуме базы в 6 мс; одна подписка на строку дала бы меньше, а
   переделка задевает около десятка компонентов ячейки. PS1 ждёт, пока этапы 2–4 не
   покажут, хватает ли их.
2. **Этап 2.** `contain` строки и ячейки, inline-стили ячейки — размеры и место; PS2;
   `perf:compare`. **Отклонён 2026-10-28** замером. Строка и ячейка уже несут
   `contain: layout paint`; `contain: style` к ним — P12 44,8 / 53,3 мс против базы
   45,5 / 52,4 и 39,5 / 58,1 мс: в шуме. Пересчёт стилей по X — не сброс всего поддерева
   каждый кадр: 38 пересчётов на 60 кадров, около 350 элементов в каждом (треть DOM грида,
   1061 узел) — это ячейки новой колонки во всех строках, по 33 мкс на элемент под ×4 CPU.
   `contain` пересчёт новых элементов не уменьшает; его цену снижает число элементов в
   ячейке — этап 4. Inline-стили ячейки (ширина, место, отступ, заливки состояний) в
   профиле — меньше 1 %. PS2 снят.
3. **Этап 3.** Окно без `flushSync`, запас окна по замеру; PS3; `perf:compare`.
   **Отклонён 2026-10-28** замером. Без `flushSync` p95 задач P12 падает с 38–50 / 51–62 до
   24–27 / 28–30 мс (Y / X), но сумма работы главного потока та же (Y 644–810 против 786 мс,
   X 1972–2004 против 1840 мс): рендер окна ушёл из задачи события прокрутки в отдельную
   задачу React того же кадра. По кадрам выигрыша нет — средний интервал кадра под ×4 CPU
   Y 14,7–15,4 против 13,8 мс, X 25,1–25,2 против 24,9 мс, кадров длиннее 34 мс из 90 —
   16–17 против 15 и 35 против 37; пустых мест у края окна нет ни там, ни там. PS3 снят.
   **Вывод для гейта PS8:** p95 длительности задач обманывается дроблением работы; кадр
   измеряется интервалом кадра и долей длинных кадров, а не только p95 задач.
4. **Этап 5 — до этапа 4.** Добавлен 2026-10-28 замером горизонтальной прокрутки счётчиками
   работы (30 кадров, 30×500). Без плагинов — 14 коммитов, в каждом перерисованы все видимые
   строки (`BodyRow` ×120): ячейки мемоизированы, но строка заново выполняет свои хуки. Со
   всеми плагинами — 26 коммитов и 4512 компонентов: обёртки перетаскивания каждой строки
   (`DraggableBodyRow`, `ItemSortableContextProvider`) — в каждом коммите и по Y (×333 на 20
   коммитов), ячейки футера — в каждом коммите (`FooterCell` ×187), лишние коммиты от
   `columnPinning` (21) и `columnDragging` (22). Кнопки по наведению этого не снимают: без
   кнопок ячеек тела кадр по X 24,2 против 25,2 мс, без кнопок шапки — 24,0. PS10–PS13.
   **Сделан 2026-10-28.** Окно колонок строкам тела — контекстом `ColumnWindowContext`, его
   читает только список ячеек строки (PS10); список строк `SortableContext` тела вне
   перетаскивания — постоянный, строки окна — только идущему перетаскиванию, D34 (PS11);
   `Toolbar` и `FooterCell` — под `memo` (PS12, PS13). Отрисовано компонентов за 30 кадров со
   всеми плагинами: X 4512 → 2558, Y 4137 → 1503. Кадры под ×4 CPU (средний кадр, кадров длиннее
   34 мс из 90): Y 13,7–15,4 мс / 15–17 → 9,1 мс / 1, X 25,2 мс / 35–36 → 19,6 мс / 23; без
   плагинов — Y 6,9, X 8,0 мс. Остаток X — монтирование новых ячеек с кнопками слотов (этап 4).
   **Открыто:** со всеми плагинами коммитов при прокрутке больше, чем без них (X 26 против 14,
   Y 20 против 13); срезы таблицы при этом не меняются — коммиты от состояния компонентов (одна
   из причин — сессия проверок кебаба шапки на наведении, ADR 0078, под неподвижным указателем).
   PS12 сужено до тулбара. **Разобрано 2026-10-28** (после этапа 4, 30 кадров, начало каждого
   коммита — компонент, чей родитель не перерисован): X 25 против 14, Y 20 против 13; лишние —
   10 и 7 коммитов, начатых \`DndContext\` dnd-kit и одним \`MenuTrigger\` Base UI. Это
   регистрация новых перетаскиваемых узлов и триггеров эффектом после монтирования; в таком
   коммите около десяти компонентов (обвязка \`DndContext\`, \`SortableContext\`, кнопка
   триггера), строки и ячейки не перерисовываются. Ни один плагин отдельно их не даёт: без
   любого — на 0–2 коммита меньше. Цена — доли миллисекунды, код — upstream; не чиним.
5. **Этап 4.** Кнопки по наведению, фокусу, касанию и состоянию; PS4–PS7, гейт PS8 и PS9;
   перевод тестов, которые ищут кнопки без наведения; ADR 0004 и ADR 0076 — по факту.
   **Замер 2026-10-28** (30×500 со всеми плагинами, ×4 CPU, средний кадр / кадров длиннее
   34 мс из 90, вперемешку). Потолок — ячейки тела без слотов и зоны действий строки: Y
