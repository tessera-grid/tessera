# 0226 — Сквозные `aria-setsize` и `aria-posinset` строк верхнего уровня

- **Статус:** Принято (прожарка 2026-11-14, решения автора: строки верхнего уровня считаются
  сквозь страницы; неизвестный итог — `aria-setsize="-1"`; в объёме — клиентская и серверная
  пагинация, лента и ветки серверной модели строк; новой истории нет)
- **Дата:** 2026-11-14
- **Слой:** ядро — место строк верхнего уровня текущей страницы в списке и их итог
  (`rootWindowOf` в `core/pagination.ts`, рядом с `getRowWindow`): пагинация, лента и серверная
  модель строк — режимы ядра и его опций (`dataMode`, `rowCount`, `getTotalRowCount`), и тело
  читает одно место, а не каждый плагин; грид — атрибуты строк (`grid/treeAria.ts`, `Body`,
  `PendingRow`); плагин `serverRowModel` — известен ли размер набора строки (источник строк,
  `treeAria`) ([ADR 0163](0163-layer-boundaries-and-guards.md)).
- **Изменяет:**
  - [ADR 0032](0032-wcag-aa-remainder.md) — W10: соседи строки верхнего уровня — все строки
    верхнего уровня списка до разбивки на страницы, а не строки текущей страницы; неизвестный
    размер набора — `-1`.
  - [ADR 0065](0065-tree-aria-without-row-objects.md) — снимает границу «сквозные `setsize`/
    `posinset` корней через страницы не входят».
  - [ADR 0138](0138-server-side-row-model.md) — §14: у набора с неизвестным итогом
    `aria-setsize="-1"`.
- **Связано:**
  - [ADR 0038](0038-pagination-and-status-bar.md) — страницы по верхнему уровню (PG9), сквозной
    `aria-rowindex` (PG15).
  - [ADR 0081](0081-infinite-scroll.md) — лента, итог `rowCount` или неизвестен.
  - [ADR 0158](0158-ssrm-pagination.md) — страницы серверной модели строк.
  - [ADR 0169](0169-data-mode.md) — режимы данных, `rowCount` таблицы.
  - [ADR 0033](0033-a11y-tree-and-virtual-screen-reader.md) — эмулятор скринридера.

## Контекст

В `treegrid` (W10) строка несёт `aria-level`, `aria-setsize` и `aria-posinset`. Счёт идёт по
строкам модели, которые нарисует тело, — при клиентской пагинации это строки текущей страницы.
На второй странице по 25 строка верхнего уровня объявляется «1 из 25», хотя она 26-я из 1000.
При этом `aria-rowindex` и `aria-rowcount` уже сквозные (PG15): скринридер называет одну позицию
строкой таблицы и другую — элементом дерева.

Серверная модель строк считает строки верхнего уровня сквозь свои страницы (ADR 0158), но при
неизвестном итоге набора отдаёт в `aria-setsize` оценку по загруженным блокам: размер растёт по
мере прокрутки, и скринридер называет число, которого нет. Лента (ADR 0081) считает только
загруженные строки, хотя итог `rowCount` знает или знает, что он неизвестен: `aria-rowcount`
она уже ставит по нему.

По ARIA 1.2 `aria-setsize` и `aria-posinset` ставят именно тогда, когда в DOM есть не все
элементы набора, а неизвестный размер набора — `aria-setsize="-1"`.

### Как у других

- **MUI X** ставит `aria-setsize` и `aria-posinset` строкам дерева и группировки и пересчитывает
  их при фильтре; поведение при пагинации в документации и тестах не описано.
- **AG Grid** в документации доступности называет у строк `aria-rowindex`, `aria-selected`,
  `aria-expanded`; размер набора строк дерева не описан.

Готового образца нет — решение следует ARIA и уже сквозному `aria-rowindex`.

## Решение

### 1. Строки верхнего уровня — один набор на весь список

Набор строки верхнего уровня (и строки группы `rowGrouping`) — все строки верхнего уровня
списка после фильтра, поиска и группировки, до разбивки на страницы. На странице:

- `aria-posinset` = смещение страницы в строках верхнего уровня + место строки на странице;
- `aria-setsize` = число строк верхнего уровня в списке; неизвестно — `-1`.

Строки ниже верхнего уровня не меняются: страницы режутся по верхнему уровню (PG9), и ветка
целиком стоит на странице родителя.

### 2. Место страницы — от ядра

`rootWindowOf(table, source)` в `core/pagination.ts` отдаёт `{ offset, total }` строк верхнего
уровня текущей страницы; `total = -1` — итог неизвестен, `undefined` — счёт по строкам модели,
как прежде:

| Режим                                   | `offset`               | `total`                                                           |
| --------------------------------------- | ---------------------- | ----------------------------------------------------------------- |
| Без пагинации и ленты                   | 0                      | `undefined`                                                       |
| Клиентская пагинация                    | `pageIndex × pageSize` | строки верхнего уровня до нарезки (`getRowCount`)                 |
| Серверная пагинация (`data` — страница) | `pageIndex × pageSize` | `rowCount`                                                        |
| Лента                                   | 0                      | итог ленты (`getTotalRowCount`): `rowCount`, `-1` или `undefined` |
| Серверная модель строк                  | считает источник (§3)  | считает источник (§3)                                             |

Счёт `getTreeAria` по строкам модели не меняется (ADR 0065); тело прибавляет `offset` к
`aria-posinset` строк верхнего уровня и ставит `total` их `aria-setsize`. Цена — одно сложение на
строку окна.

### 3. Серверная модель строк

Источник строк отдаёт в `treeAria` строки ещё и `sizeKnown`: известен ли итог её набора —
строк верхнего уровня или ветки. Тело и `PendingRow` ставят `aria-setsize="-1"`, когда итог
неизвестен. Внутренние читатели размера набора — последняя подстрока ветки, линии дерева, перенос
и вложение строк — читают прежнюю оценку: `-1` — только в атрибуте; их поведение держат прежние
тесты (TL10–TL13, MV2–MV7, NT1–NT12). Незагруженная строка ветки до ответа теперь несёт `-1`, а не
размер блока (SD43).

`aria-posinset` строк верхнего уровня сквозной через страницы серверной модели уже (ADR 0158) —
требование это закрепляет.

### 4. Без клавиатурной навигации

Роль `table`: атрибутов уровня у строк нет (W10), решение их не касается.

## Границы

- **`aria-rowcount` при серверной пагинации с раскрытыми детьми** — не входит: итог строк
  таблицы там — `rowCount` строк верхнего уровня без детей других страниц; отдельный край.
- **Ручная проверка настоящими скринридерами** — остаётся открытой, как у ADR 0032.

## Отвергнутые альтернативы

- **Набор — строки страницы** (как было): позиция дерева расходится со сквозным
  `aria-rowindex`, «1 из 25» на 26-й строке.
- **Оценка размера при неизвестном итоге:** число, которое растёт по мере прокрутки, — неправда
  для скринридера; ARIA для этого случая даёт `-1`.
- **`-1` и во внутренних читателях размера:** линии дерева, перенос и вложение строк опираются
  на оценку загруженного; их поведение не должно меняться из-за атрибута.

## Последствия

- **+** Позиция строки дерева и позиция строки таблицы, которые называет скринридер,
  согласованы на любой странице и в любом режиме данных.
- **+** Неизвестный размер набора назван неизвестным.
- **Перф:** отдельного перф-требования нет — нового массового состояния нет, к счёту TA3
  прибавляется сложение на строку окна; цену счёта по-прежнему держит TA3.
- **Публичный API:** не меняется. Источник строк — внутренний контракт ядра: поле `sizeKnown`
  у `treeAria`.

серверной модели строк (`plugins/serverRowModel/tree.ts`, `source.ts`), `-1` в `Body` и
`PendingRow`. Тесты — модульный `treeAria.dom` (SZ1, SZ3–SZ4), визуальные `tree-aria-pages` (SZ2),
