# 0034 — Доступность: WCAG 2.2 AA — альтернатива перетаскиванию и размер целей

- **Дата:** 2026-09-26

## Контекст

WCAG 2.2 добавил к уровню AA два критерия про указатель.

**2.5.7 Dragging Movements.** Всё, что делается перетаскиванием, должно быть
доступно одним указателем без перетаскивания. Клавиатура альтернативой не
считается. В гриде перетаскиванием делаются три вещи:

- перестановка колонок — есть только `Alt+Shift+←/→` (KB3);
- перестановка строк и смена вложенности — только `Alt+Shift+стрелки` (KB4, W12);
- произвольная ширина колонки — двойной клик по грипу лишь сбрасывает её.

Выделение ячеек протяжкой уже имеет альтернативу — клик и `Shift+клик`.

**2.5.8 Target Size (Minimum).** Цель указателя — не меньше 24×24 CSS px, либо
круг диаметром 24 px с центром в цели не пересекает другие цели. Замер в Chromium
показал: чекбоксы выбора строк и ручки перетаскивания — 16×16 и стоят вплотную к
соседним целям. Кнопки (32–36 px) и зона грипа ширины (24 px × высота заголовка)
проходят. Правило axe `target-size` здесь не решает: ячейки грида с
`tabindex="-1"` оно считает возможными целями и отдаёт результат «incomplete».

## Решение

### Ручка перетаскивания — кнопка меню (2.5.7)

Клик по ручке без сдвига открывает меню команд перестановки. Шаблон тот же, что
у Atlassian и GitHub Projects: ручка остаётся местом перетаскивания и
одновременно даёт команды. Альтернатива есть везде, где есть перетаскивание: она
не зависит от плагинов меню `headerActionMenu` и `contextMenu`.

- **Порог старта DnD.** Сенсоры dnd-kit (`Pointer`, `Mouse`, `Touch`) в
  `DndHeadWrapper` и `DndBodyWrapper` получают `activationConstraint: { distance: 5 }`.
  Перетаскивание начинается после сдвига на 5 px. Короткое нажатие без сдвига —
  обычный клик и открывает меню.
- **Ручка колонки** (`columnDragging`) — меню «Move left» / «Move right».
- **Ручка строки** (`rowDragging`) — меню «Move up» / «Move down»; при раскрытии
  строк (`enableExpanding`) ещё «Indent» / «Outdent».
- **Одна логика с клавиатурой.** Команды меню и клавиатурные действия
  (`Alt+Shift+стрелки`) вызывают одни и те же функции (`moveColumn`,
  `moveRow`, `nestRow`, `unnestRow`). Ограничения общие: `getCanDrag`, закреплённые
  колонки не участвуют, группа не вкладывается в группу. Хуки тоже:
  `onColumnDragEnd` для колонок, `onRowOrderChange` для строк. Невыполнимая
  команда (край, закреплённый сосед) видна, но недоступна (`disabled`).
- **Семантика ручки.** Ручка — `role="button"` с именем из локализации
  («Move column» / «Move row»), `aria-haspopup="menu"` и `aria-expanded`. Открывается
  и с клавиатуры (`Enter` / `Space`). Инструкции dnd-kit (`aria-describedby`,
  `aria-roledescription="sortable"`) убраны: они описывают перетаскивание с
  клавиатуры через `KeyboardSensor`, которого в гриде нет.
- **Закрытие.** `Escape`, выбор пункта или клик мимо закрывают меню, фокус
  возвращается на ручку.
- **Ленивая загрузка.** Попап меню (Base UI `Menu`) грузится лениво и
  монтируется только открытым — как меню действий и контекстное меню.

### Грип ширины — кнопка меню (2.5.7)

Клик по грипу без сдвига (меньше 3 px между нажатием и отпусканием) открывает
меню «Wider» / «Narrower» / «Reset width». Шаг — 50 px (как `Shift+стрелка` у
сплиттера). Ширина ограничена `minSize` / `maxSize`, на границе пункт недоступен.
Итог сообщается хуком `onColumnResizeEnd`, как у перетаскивания и стрелок.

Сброс двойным кликом **убран**: первый клик теперь открывает меню. Сброс — пункт
«Reset width» (правка CR11 в [ADR 0013](0013-column-sizing.md)). С клавиатуры сброс
по-прежнему `Home` на сплиттере. Грип-обёртка — цель только для указателя, в
порядке фокуса её нет: клавиатура работает со сплиттером `role="separator"` внутри.

### Зона нажатия 24×24 (2.5.8)

Малые цели получают прозрачную зону нажатия 24×24 — псевдоэлемент `::before`,
выступающий за контрол до 24 px по центру. Вид не меняется: размеры рамки чекбокса
и иконки ручки прежние. Это касается чекбокса выбора строк (`SelectCheckbox`) и
ручки перетаскивания (`DragHandler`).

Ручка колонки прижата к левому краю заголовка (D19, [ADR 0006](0006-dnd-with-dnd-kit.md)),
а слева от неё — грип ширины соседней колонки. Поэтому в заголовке зона ручки
несимметрична: 24 px вправо от края ячейки, внутрь своей колонки
(`HeadCell.module.css`). Центрированная зона заходила бы на грип соседа на 4 px.

**Что считается целью.** Контролы внутри ячеек: кнопки, `role="button"`,
`role="checkbox"`, поля ввода и грип ширины. Сами ячейки грида целями не считаются:
это контейнеры контролов, и их фокус (`tabindex="-1"`) нужен клавиатурной
навигации. Зона нажатия проверяется по `document.elementFromPoint` на сетке точек
квадрата 24×24, содержащего цель (перебираются все положения такого квадрата).
Если ни один квадрат не принадлежит цели целиком, цель проходит по исключению об
отступе: круг диаметром 24 px с центром в цели не задевает соседние цели.

### Контур фокуса заголовка поверх контролов (2.4.7, 2.4.11)

Контур активной ячейки заголовка был `outline` с отрицательным отступом, то есть
рисовался по краю самой ячейки. Грип ширины лежит у правого края поверх
содержимого (`z-index: 1`, непрозрачный фон) и срезал правую сторону контура.
Теперь контур заголовка рисует псевдоэлемент `::after` поверх содержимого ячейки
(`z-index: 2`, `pointer-events: none`) тем же токеном `--tsr-comp-focus-ring`.

### Находки при внедрении

- **Меню в портале закрывалось с `keyboardNavigation`.** Base UI переводит фокус
  на пункт меню при наведении и стрелками. Событие фокуса из портала всплывает по
  React-дереву до корня грида, и перенаправление «вход в грид извне» уводило фокус
  на активную ячейку. Меню закрывалось. Теперь перенаправляется только фокус
  внутри DOM грида (`onFocusCapture` в `core/keyboardNavigation.ts`). Это касалось
  и кебаба заголовка, и контекстного меню при навигации по пунктам.
- **Соседние колонки не сдвигались при смене ширины без протяжки.** Колоночный
  виртуализатор пересчитывал смещения только в конце протяжки. Стрелки сплиттера
  (KB2), `Home` и меню грипа меняли ширину колонки, а следующая оставалась на
  месте и накрывала её. Теперь пересчёт идёт и при смене среза `columnSizing` вне
  протяжки (`core/virtualization/columnVirtualizer.ts`).
- **У ручек перетаскивания не было имени.** `role="button"` из dnd-kit был
  безымянным, а `aria-describedby` вёл на инструкции `KeyboardSensor`, которого в
  гриде нет.
- **axe `target-size` не решает 2.5.8 для грида.** Ячейки с `tabindex="-1"`
  правило считает возможными целями и отдаёт «incomplete», поэтому замер — свой
  (TS1).

## Последствия

- **+** 2.5.7 выполняется без условий на конфигурацию: где есть перетаскивание,
  там есть и меню на той же ручке.
- **+** Ручки перетаскивания получили доступное имя — раньше `role="button"` был
  безымянным.
- **+** Пункты меню — видимая подсказка к `Alt+Shift+стрелкам` (закрыт пункт
  roadmap).
- **−** Перетаскивание стартует после сдвига на 5 px, а не сразу по нажатию.
- **−** Двойной клик по грипу больше не сбрасывает ширину — сброс в меню.
- **−** Вложение строк из меню, как и с клавиатуры, требует `onRowOrderChange`:
  без него пунктов перестановки нет — как и DnD, перестановка не работает.
