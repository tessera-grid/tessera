# 0175 — Редакторы по типу данных

- **Статус:** Принято (решения — по итогам прожарки 2026-11-01)
- **Дата:** 2026-11-01
- **Слой:** `plugins/cellEditing` — встроенные редакторы по базовому типу, выбор редактора и
  разбор ввода: правку ячейки ведёт плагин, ядру редакторы не нужны. Поле `editor` у типа плагин
  объявляет сам, дополняя `DataTypeFields` (как `*Feature.ts` дополняют типы TanStack), — ядро о
  редакторах не знает. Календарь и список вариантов с флажками — в `shared/`: их берут и
  `cellEditing`, и `columnFiltering`, а плагин не импортирует другой плагин

- **Изменяет:**

    `onCellEdit`, `validate` и `onEditCancel` получают значение в типе колонки, черновик сессии —

  - [ADR 0139](0139-saved-row-and-column-data-type.md), «Границы» — разобранное значение в
    коммите клиентского режима: разбор при сохранении в обоих режимах, серверная модель пишет в
    кэш то же значение.
  - [ADR 0172](0172-column-data-type.md), «Границы» — у определения типа поле `editor`.
  - [ADR 0047](0047-date-filtering.md), [ADR 0048](0048-option-filtering.md) — календарь панели
    даты и список вариантов панели вариантов переезжают в `shared/`, вид и поведение фильтров не

- **Связано:**

## Контекст

Тип колонки (ADR 0172, 0174) задаёт вид, сортировку, фильтр, поиск и выгрузку, но правка
ячейки о нём не знает. Встроенный редактор — одно текстовое поле на любой тип: число в `ru`
открывается с точкой, хотя ячейка показывает запятую; дату, булево и вариант приходится набирать
текстом. `onCellEdit` получает строку, и разбирает её приложение — кроме серверной модели, где
разбор по типу уже есть (ADR 0139). Свой редактор задаётся одним аргументом плагина на все
колонки и сам ветвится по колонке.

### Как у других

- **AG Grid** — `cellDataType` выбирает редактор: `agNumberCellEditor`, `agDateCellEditor`,
  `agCheckboxCellEditor`, `agSelectCellEditor` и `agRichSelectCellEditor` (поиск, асинхронные
  значения, несколько значений); `valueParser` колонки; значение в `onCellValueChanged` — в типе
  колонки.
- **MUI X** — `type` колонки: `number`, `date`, `dateTime`, `boolean`, `singleSelect` (список без
  поиска); `renderEditCell` колонки; `processRowUpdate` получает строку со значением в типе.

В обеих свой редактор задаётся у колонки, значение правки — в типе колонки.

## Решение

### 1. Значение в типе колонки

`onCellEdit` получает `value` в типе колонки — число, `Date`, запись, массив — и `text`,
введённый текст. `validate` получает то же значение и текст, `onEditCancel.draft` — черновик в
типе колонки. Ввод разбирается по базовому типу при сохранении в обоих режимах; `parseValue` типа
или колонки главнее встроенного разбора. Серверная модель пишет в кэш то же значение, второго
разбора нет (ADR 0139).

### 2. Встроенные редакторы по базовому типу

| Базовый тип                  | Редактор                                                                                                                                                                                                                                                                  |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `text`                       | Текстовое поле, как сейчас.                                                                                                                                                                                                                                               |
| `number`, `numberString`     | Поле с текстом числа по языку таблицы («1 234,5» в `ru») и вводом по нему же. Не число — ошибка поля из словаря, как у `validate`, сохранения нет. Пустое поле — `null`. `numberString` не проходит через float.                                                          |
| `boolean`                    | Без поля: действие правки — кнопка, Enter, F2, двойной щелчок, Space — сразу переключает значение и сохраняет его.                                                                                                                                                        |
| `date`, `dateString`         | Поповер с календарём фильтра даты: пояс таблицы, язык календаря. Значение — `Date` или строка формата типа.                                                                                                                                                               |
| `dateTime`, `dateTimeString` | Тот же календарь и поле времени.                                                                                                                                                                                                                                          |
| `select`, `object`           | Поле с поиском (Combobox Base UI): набор сужает список, стрелки и Enter. Варианты — `options` колонки, справочник — `loadOptions` с ожиданием, отказом и повтором. `object` выбирает запись по `getKey`, подписывает по `getLabel`. Значение очищается отдельным пунктом. |
| `multiSelect`                | Поповер со списком флажков и поиском — общий модуль с панелью фильтра вариантов. Сохраняет массив.                                                                                                                                                                        |

В поповерах Enter сохраняет, Escape отменяет, фокус возвращается в ячейку. Календарь и список
вариантов грузятся ленивыми модулями при первой правке своего типа (ADR 0061), длинный список
виртуализирован.

### 3. Свой редактор

Редактор выбирается по порядку: `editor` колонки, затем `editor` типа (наследуется по `extends`),
затем аргумент `editor` плагина, затем встроенный по базовому типу. `CellEditor` получает
черновик в типе колонки, `commit(value)`, `setDraft(value)`, введённый текст, подпись, ошибку и
контекст ячейки.

## Границы

- Ввод своего варианта, которого нет в списке (creatable), — вне объёма.
- Массовая правка, протяжка значения и правка строки целиком — вне объёма (roadmap).
- Редакторы будущих типов вида ячейки (`url`, `rating` и др.) — с ADR «вид ячейки по типу».
- Типы `time` и `duration` — свои прожарки.
- Ввода даты текстом без календаря нет.

## Отвергнутые альтернативы

- **Строка в `onCellEdit`, как сейчас** — разбор по типу дублируется в каждом приложении, а
  серверная модель уже разбирает сама: два правила для одного ввода.
- **Выпадающий список без поиска для `select`** — справочник с сервера и длинный список так не
  правятся.
- **Поле с чипами для `multiSelect`** — в узкой ячейке чипы не помещаются.
- **`input type="number"`** — разряды и запятая языка таблицы работают не во всех браузерах.
- **Свой редактор только аргументом плагина** — один редактор на все колонки ветвится по
  колонке сам, а тип из реестра не может принести свой редактор.

## Последствия

- **+** Правка в типе колонки: число по языку таблицы, календарь, выбор варианта и записи.
- **+** Одно правило разбора для клиентского и серверного режимов.
- **−** Ломающее изменение `onCellEdit`, `validate` и `onEditCancel`: истории и тесты правки
  переводятся на значение в типе.
- **−** Календарь и список вариантов переезжают из фильтров в `shared/` — тесты DF и SF остаются
  страховкой.

## Внедрение

- **Этап 1** (ED1–ED5, ED11; S1, S2, S7): значение в типе колонки, разбор при сохранении, выбор
  редактора, поля числа и `numberString`, булево одним нажатием; истории и тесты правки
  переводятся на значение в типе.
- **Этап 2** (ED6–ED7; S3): календарь фильтра даты — в `shared/`, редактор даты и даты со
  временем.
- **Этап 3** (ED8–ED10, ED12–ED14; S4–S6): список вариантов фильтра — в `shared/`, поле с поиском
  для `select` и `object`, список с флажками для `multiSelect`; доступность, касания и перф всех
  редакторов.
