# 0192 — Номера страниц и переход на страницу

- **Статус:** Принято (решения — по итогам прожарки 2026-11-07), внедрено 2026-11-07
- **Дата:** 2026-11-07
- **Слой:** плагин `pagination` — кнопки номеров и поле, расчёт ряда в `pagination/model.ts`. Ядро и грид
  не меняются: переход идёт прежним `changePageByUser`, вид панели отдаёт `[data-status-bar-layout]`.

  - [ADR 0116](0116-async-server-actions.md) — откат страницы при отказе.
  - [ADR 0153](0153-cancel-long-operations.md) — отмена перехода.

## Контекст

Пагинация умеет «первая/назад/вперёд/последняя» (ADR 0038). Чтобы попасть на страницу 37 из 40, нужно
нажать «последняя» и трижды «назад», а на странице 500 из 1000 способа быстрее нет. Текущую страницу
пользователь вычисляет по диапазону «1201–1225 из 2500». Переход на страницу есть только в API.

Логика готова: контрол знает число страниц и известен ли итог, переход проходит через
`changePageByUser` с `onPageChange`, откатом и объявлением. Не хватает элемента, который этим
пользуется.

### Как у других

|                     | По умолчанию                           | Номера страниц                  | Поле перехода     |
| ------------------- | -------------------------------------- | ------------------------------- | ----------------- |
| AG Grid             | «первая/назад/вперёд/последняя» и поле | опцией `pageNumbers`            | да, по умолчанию  |
| MUI X Data Grid     | подвал с размером страницы             | нет, только своя замена подвала | нет, `setPage`    |
| DevExtreme DataGrid | адаптивный пейджер                     | да, компактный режим при узости | —                 |
| Ant Design          | кнопки номеров                         | да                              | `showQuickJumper` |

При неизвестном итоге MUI даёт только стрелки и флаг «есть следующая». Узость DevExtreme решает
компактным режимом, AG Grid прячет части панели.

## Решение

### 1. Режимы

`pagination({ pageNumbers })`, значение по умолчанию — `'buttons'`:

| Значение    | Вид                                                            |
| ----------- | -------------------------------------------------------------- |
| `'buttons'` | «назад», ряд номеров, «вперёд»                                 |
| `'input'`   | «первая», «назад», поле номера и «из N», «вперёд», «последняя» |
| `false`     | четыре кнопки, как в ADR 0038                                  |

При `'buttons'` кнопок «первая» и «последняя» нет: номера первой и последней страницы стоят в ряду.
При `'input'` их нет в ряду, поэтому кнопки остаются.

### 2. Ряд номеров

Всегда первая и последняя страница, текущая и её соседи, между ними многоточие. Мест — не больше семи;
при семи страницах и больше их ровно семь, поэтому ряд не прыгает при смене страницы:

```
1 2 3 4 5 … 40        у начала
1 … 6 7 8 … 40        в середине
1 … 36 37 38 39 40    у конца
```

Многоточие — не кнопка: оно ничего не делает и скрыто от скринридера. Расчёт — чистая функция,
цена не зависит от числа страниц.

### 3. Кнопка номера и текущая страница

Кнопка номера — `Button` кита, вариант `ghost`; имя — «Go to page N» из `localization`, номер — на
языке таблицы. Текущая страница несёт `aria-current="page"` и выглядит как выбранный сегмент
`ui/Segments`, новых токенов нет: заливка, тень и цвет. Она остаётся в порядке фокуса, повторное нажатие
ничего не делает. Если `Button` не даст нужного вида, решение выносится к автору (ui-kit.md).

### 4. Поле номера

Поле кита `Field` с текущим номером и подписью «из N», с отступами кита и шириной под номер
последней страницы на языке таблицы. Enter и уход фокуса переходят; значение вне
диапазона приводится к границе; не число возвращает прежний номер; Escape отменяет ввод. Переход на ту
же страницу не вызывает `onPageChange`.

### 5. Узкая панель

В компактном и двухстрочном виде панели (ADR 0038, SB7–SB8) номера и поле скрыты, видны четыре кнопки.
Оба набора живут в DOM, вид переключает CSS по `[data-status-bar-layout]`, поэтому смена вида ничего не
перемонтирует (SB13). Скрытый набор вне дерева доступности и порядка фокуса.

### 6. Неизвестный итог

Пока итог неизвестен («1–25 из многих», ADR 0158), номера и поле скрыты, видны четыре кнопки. Пришёл
итог — появляются номера. Переход на произвольный номер мог бы уйти за конец данных.

### 7. Серверный режим

Переход идёт прежним путём: `onPageChange`, плашка «Загрузка страницы…», откат при отказе и отмена
(ADR 0116, ADR 0153). Пока запрос ждёт, ряд показывает новую страницу; откат возвращает прежнюю. Своего
ожидания на кнопке номера нет, как у кнопок пагинации (ADR 0177, §1).

## Границы

- **Число кнопок не настраивается**: семь мест одинаковы у всех таблиц. Запрос приложения — отдельным ADR.
- **Многоточие не переходит** на пять страниц вперёд, как у Ant Design.
- **Свой пейджер приложения** — через `statusBarSlot` и `table.setPageIndex`, отдельного API нет.
- **Поле не появляется в узкой панели** вместо номеров.

## Отвергнутые альтернативы

- **Только кнопки, без поля** — проще, но со страницы 1 не попасть на 500 из 1000.
- **Умолчание как сейчас, всё опцией** — вид не меняется, но пользователь грида номеров не увидит, пока о
  них не вспомнит разработчик приложения.
- **Поле по умолчанию, как у AG Grid** — постоянная ширина, но текущая страница не видна рядом с соседними.
- **Оставить «первую» и «последнюю» рядом с номерами** — кнопки дублируют номера и расширяют панель.
- **Номера в узкой панели** (`1 … 7 … 40`) — панель чаще уходит в две строки ради меньшей пользы.
- **Номера при неизвестном итоге** (`1 2 3 4 …`) — вторая раскладка ряда ради возврата к пройденному.

## Последствия

- **Ломающее изменение вида до 1.0:** по умолчанию вместо «первой» и «последней» — ряд номеров.
  Прежний вид — `pageNumbers: false`.
- Ряд шире четырёх кнопок: панель раньше переходит в компактный вид.
- Вид историй с пагинацией меняется, снимки Chromatic нужно принять.
- Новый аргумент фабрики — запись в базе паритета моделей (ADR 0187).

## Внедрение

Ряд и кнопки — `pagination/PageNumbers.tsx`, расчёт — `pagination/model.ts`, вид по панели — CSS
`Pagination.module.css`. PG2 и остальные тесты ADR 0038 идут с `pageNumbers: false`.

Тесты: визуальный `page-numbers` (PJ2–PJ10, PJ12, PJ14–PJ16), модульный `pageNumbers` (PJ1, PJ11), перф
PJ13 — в `interaction`. Истории S1–S5 с гайдами и близнецами высокой контрастности.
