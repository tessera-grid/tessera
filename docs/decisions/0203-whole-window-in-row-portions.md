# 0203 — Первый рендер и смена всего окна по кускам

- **Статус:** Принято (прожарка 2026-11-09)
- **Дата:** 2026-11-09
- **Слой:** ядро — виртуализатор строк и колонок (`core/virtualization`), адаптер TanStack
  Virtual в вендоре (`tessera.patch`); грид — корень `DataGrid` и тело (`grid/Body`,
  `grid/rowPortions.ts`). Это не плагин: первый рендер грида и его окно принадлежат ядру и гриду.
- **Изменяет:**
  - [ADR 0107](0107-row-motion.md) — RM22: без `startViewTransition` — при выключенном
    `enableIncrementalRender` (§5).
- **Связано:**
  - [ADR 0202](0202-window-band.md) — полоса окна; синхронность после уведомления виртуализатора.
  - [ADR 0143](0143-tanstack-virtual-fork.md) — правка адаптера в `tessera.patch` (§3).
  - [ADR 0099](0099-perf-gates-and-ab-compare.md) — гейт против базы того же теста.
  - [ADR 0091](0091-environment-compatibility.md) — серверный рендер и гидратация (EV5).
  - [ADR 0021](0021-keyboard-navigation.md) — активная ячейка и фокус.
  - Замер против AG Grid — `docs/research/tessera-vs-ag-grid-2026-11-09.md`, пункт 4.

## Контекст

Монтирование 1000×1000 у Tessera дольше, чем у AG Grid, по стене (256 мс против 164), при
почти равной работе JS (218 мс против 206). Самая длинная задача — 180 мс, у AG Grid — 51 мс.

Разбор трассы (2026-11-09, ×4 CPU, данные заранее):

- Корень грида рендерится одной задачей: оболочка, шапка, тулбар, конвейер моделей строк,
  подписки срезов. Со всеми плагинами это 250 мс и больше. Окна ещё нет: размер области
  виртуализатор узнаёт только после коммита.
- Замер области в layout-эффекте будит виртуализатор, и React синхронно перерисовывает всё
  окно — шапку и строки — в той же задаче коммита (обновления из layout-эффектов в React
  синхронны). Одна нарезка строк этого не снимает: со всеми плагинами самая длинная задача
  576 → 382 мс.

Как устроено у других:

- **AG Grid** — своя очередь задач в кадрах анимации: сначала строки, затем ячейки, бюджет
  60 мс на кадр; и при монтировании, и при прыжках. Оболочка без React — лёгкая.
- **MUI X Data Grid, react-window, Handsontable, Glide** — окно за один проход.

## Решение

### 1. Первый рендер — переходом React

- Корень `DataGrid` при монтировании на клиенте сначала рисует пустую рамку того же размера
  (класс корня, высота по `height` и `maxHeight`, `className` и `style` приложения), а сам грид —
  переходом React (`startTransition`). Рендер перехода React режет на куски: самая дорогая часть
  оболочки идёт кусками, а не одной задачей.
- Первое окно после замера области виртуализатор ставит тоже переходом: функция `useFlushSync`
  отвечает `'transition'`, пока окно ни разу не нарисовано (§3).
- Серверный рендер и гидратация — сразу грид: разметка клиента совпадает с серверной.

### 2. Смена всего окна строк — порциями

Окно строк меняется целиком, когда ни одна видимая строка нового окна не была нарисована:
монтирование, первый приход данных, прыжок за полосу, смена страницы, `scrollToRow` вдаль.

- **Монтирование** — порциями с первой: строка активной ячейки, видимые сверху вниз, затем
  запас окна, ближние раньше. На экране до этого ничего не было.
- **Прыжок** — видимые строки сразу, в событии (ADR 0202, §2), запас окна — порциями: пустых
  мест на экране нет.
- Размер порции — по бюджету времени: цена строки замеряется на прошлой порции, первая берёт
  оценку по числу ячеек строки. Порция ставится в кадре анимации переходом React: её рендер
  режется на куски, целиком идёт только коммит.
- Новая смена окна посреди нарезки отменяет недорисованные строки, которых в новом окне нет.

### 3. Адаптер вендора

`useFlushSync` — булево или функция от виртуализатора, ответ — `true`, `false` или
`'transition'`; `'transition'` ставит перерисовку в `React.startTransition`.

### 4. Что остаётся прежним

- `aria-rowcount`, `aria-rowindex` и высота тела не зависят от нарезки.
- Фокус, `scrollToRow` и клавиши не ждут остальных порций: их строка — в первой.
- Смена окна на шаг прокрутки нарезкой не управляется — это ADR 0202.

### 5. Опция `enableIncrementalRender`

Переход React внутри `<ViewTransition>` приложения (React 19.3) запускает
`document.startViewTransition`: снимок страницы и анимацию, которые могут оборвать анимацию
самого приложения. Граница `<ViewTransition default="none">` вокруг грида вызов не снимает.
Поэтому возможность ядра `enableIncrementalRender` (ADR 0106), по умолчанию включена:
`false` — первый рендер и смена всего окна одним проходом, как до этого ADR, без рамки,
переходов и порций. Так же у AG Grid `suppressAnimationFrame`; MUI X, react-window и
Handsontable всегда рисуют за один проход.

### 6. Готовность грида после монтирования

Пока грид за рамкой первого рендера, в DOM нет ни контейнера прокрутки, ни строк — кадр-два
после монтирования. Решение автора — рамку оставить; следствия:

- `table.scrollToRow`, `table.scrollToRowIndex` и докрутка к колонке, вызванные до готовности
  грида (например, из эффекта монтирования приложения), ждут его окна и прокручивают, а не
  отвечают `false`. Таблица без грида отвечает `false` сразу, как прежде.
- Признак готовности для приложения и тестов — атрибуты: рамка первого рендера несёт
  `data-tsr-grid-pending`, тело, пока режет окно, — `data-portions-pending`. Грид дорисован,
  когда в его корне нет ни того, ни другого. Помощники тестов и `settle` каталога ждут этого.

## Отвергнутые альтернативы

- **Только порции строк.** Самая длинная задача со всеми плагинами 576 → 382 мс: остаётся
  оболочка и синхронная перерисовка после замера.
- **Откладывать части оболочки вручную** (шапку, тулбар, панели — после тела). Режет то же, что
  переход React, но вручную и с порядком появления частей на экране.
- **Скелеты, затем содержимое.** Длинную задачу не убирает: содержимое после скелетов — тот же
  проход.
- **Прыжок порциями, как у AG Grid.** Кадр с пустой полосой посреди экрана при явном действии
  человека.

## Последствия

- **+** Самая длинная задача монтирования 1000×1000: без плагинов 111 → 27 мс, со всеми
  плагинами 526 → 51–62 мс; работы не больше, первая строка — не позже.
- **−** Первый кадр монтирования — пустая рамка; грид появляется через кадр-два, строки —
  порциями.
- **−** Тесты, которые читают грид сразу после монтирования, ждут его.
- **−** Бюджет ядра (LB3–LB4) вырос вместе с ADR 0202 до 210 590 байт gzip: рамка первого
  рендера и порции строк — в `DataGrid` без плагинов.
- **Публичный API:** новая опция ядра `enableIncrementalRender` (§5); по умолчанию грид рисует
  по кускам, приложению с `<ViewTransition>` над гридом её выключают.
- **Ломающее изменение публичного поведения:** DOM грида (контейнер прокрутки, строки)
  появляется кадром-двумя позже монтирования, а не в том же коммите. Код приложения, который
  сразу берёт контейнер или строки, ждёт, пока в корне грида не останется
  `data-tsr-grid-pending` и `data-portions-pending` (§6); вызовы прокрутки ждут сами.
  `enableIncrementalRender: false` возвращает прежнее поведение (§5).
