# 0023 — Сквозные (межплагинные) взаимодействия: слой тестов с префиксом `X<n>`

- **Статус:** Принято
- **Дата:** 2026-09-08
- **Изменён:** 2026-11-06 — X6: выбор не гаснет и при активной группировке (ADR 0185).
- **Связано:**
  - [ADR 0001](0001-spec-driven-development.md) — spec-driven: требование → тест;
    здесь заводится **новый класс** требований, не принадлежащих одному плагину.
  - [ADR 0009](0009-test-coverage-visual-and-performance.md) — правило «один тест =
    одно требование одного плагина» расширяется на межплагинные требования, не
    размывая однокомпонентные спеки: они живут в отдельном файле со своим префиксом.
  - [ADR 0022](0022-plugin-compatibility-contract.md) — контракт совместимости
    (`PC<n>`) покрывает **тихие отключения и владение** через чистую логику
    (`getCan*`). Этот ADR — про **наблюдаемое поведение связки** двух включённых
    плагинов (интеграционный сценарий в реальном DOM), а не про гейты.
  - [ADR 0006](0006-dnd-with-dnd-kit.md), [ADR 0014](0014-row-selection.md) —
    первая связка (`rowSelection × rowDragging`) переиспользует DnD-хореографию
    (`rowDragging.dnd.ts`) и DOM-контракт выбора.

## Контекст

Часть корректности живёт **между** плагинами и не принадлежит ни одному в
отдельности. Пример из roadmap: при перетаскивании выбранной строки выбор должен
быть привязан к **идентичности строки** (`getRowId: row => row.id`), а не к слоту —
то есть после переупорядочивания выбранной остаётся та же строка, а не та, что
заняла её позицию. Однокомпонентные спеки (`RS<n>`, `D<n>`) это не проверяют: каждая
гоняет свой плагин изолированно.

Нужен отдельный слой тестов на **связки включённых плагинов**, с собственным
префиксом требований, чтобы не смешивать их с однокомпонентными спеками и держать
правило ADR 0009 честным.

## Решение

Заводим класс сквозных требований с префиксом **`X<n>`**. Тесты живут в
`src/lib/stories/__tests__/visual/cross-plugin.test.tsx` (vitest-browser, реальный
Chromium), гоняют существующие истории с включёнными **несколькими** плагинами
(override args) и **переиспользуют общую механику** — DnD-хореографию из
`rowDragging.dnd.ts`, DOM-контракт выбора (`data-selected`, `.row-select-checkbox`),
— читая состояние из контракта DOM, а не из литералов мока
([ADR 0009](0009-test-coverage-visual-and-performance.md)).

Разграничение с [ADR 0022](0022-plugin-compatibility-contract.md):

- **`PC<n>`** — «плагин инертен/кто владеет» (гейт `getCan*`, чистая логика).
- **`X<n>`** — «два включённых плагина корректно работают вместе» (поведение в DOM).

## Требования и покрытие тестами

По конвенции ([ADR 0001](0001-spec-driven-development.md),
[ADR 0009](0009-test-coverage-visual-and-performance.md)) каждое требование — один
именованный тест с ID-префиксом `X<n>:`.

| ID  | Требование                                                                                                                                                                                                           | Тест                                 |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| X1  | Выбор строки переживает её перетаскивание: выбранной остаётся та же строка (по `id`), а не занявшая слот                                                                                                             | `visual/cross-plugin.test.tsx` `X1:` |
| X2  | Кебаб заголовка и кебаб строки схлопываются независимо; оба меню открываются и работают ([ADR 0024](0024-slot-action-descriptor-and-menu.md))                                                                        | `visual/cross-plugin.test.tsx` `X2:` |
| X3  | columnPinning × columnSizing: ресайз закреплённой колонки пересчитывает sticky-offset следующей закреплённой (единая цепочка смещений; offset задан `calc()` от переменных ширины)                                   | `visual/cross-plugin.test.tsx` `X3:` |
| X4  | columnPinning × rowSelection: лидирующая колонка выбора входит в левый pin-блок (CP14b) и смещает пользовательский пин на свою ширину (одна цепочка offset)                                                          | `visual/cross-plugin.test.tsx` `X4:` |
| X5  | columnDragging × columnSorting: заголовок сортируется по клику (drag не съедает клик) и сохраняет сортировку после переноса в новую позицию (привязка к идентичности колонки)                                        | `visual/cross-plugin.test.tsx` `X5:` |
| X6  | rowSelection × rowGrouping: выбор работает при включённом плагине группировки, при активной группировке (флажки и «выбрать все» на месте, [ADR 0185](0185-selection-with-client-grouping.md)) и после разгруппировки | `visual/cross-plugin.test.tsx` `X6:` |

## Последствия

- **+** Появился дом для межплагинных требований — новые связки добавляются как
  `X7`, `X8`, … в тот же файл, без засорения однокомпонентных спек.
- **+** Механика переиспользуется (DnD, DOM-контракты) — тесты не дублируют
  choreography.
- **−** Слой наполняется постепенно, по мере реальных связок (см.
  [roadmap](../roadmap.md)). Ортогональные пары без общего состояния тестами не
  покрываются осознанно — проверять нечего.
