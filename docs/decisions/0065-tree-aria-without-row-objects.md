# 0065 — `aria-*` дерева без объекта на строку

- **Статус:** Принято (решения — по итогам прожарки 2026-10-08)
- **Дата:** 2026-10-08
- **Связано:**
  - [ADR 0032](0032-wcag-aa-remainder.md) — W10: в `treegrid` строки несут
    `aria-level`, `aria-setsize`, `aria-posinset` среди соседей того же родителя в
    текущей модели строк. Смысл не меняется.
  - [ADR 0054](0054-lazy-row-children.md) — RE38: приход ленивых детей; этот ADR —
    первый шаг плана «Дешёвый приход ленивых детей» в roadmap.
  - [ADR 0038](0038-pagination-and-status-bar.md) — пагинация по верхнему уровню.

## Контекст

Профиль RE38 (2026-10-08): после SC11 пересборка моделей TanStack занимает ~25 мс, а
крупнейшая доля в профиле — `getTreeAria` в теле грида. На каждую смену списка строк она группирует
все строки по `parentId` в `Map` и создаёт объект атрибутов на каждую строку — на
100 000 строк это 100 000 объектов, хотя рисуются десятки. Объект на строку ещё и
передаётся мемоизированной строке пропсом.

Решено (прожарка 2026-10-08):

- один проход по строкам в типизированные массивы, а не счёт только для видимых
  строк: тот же смысл без краёв фильтра, групп и копий строк при сортировке;
- смысл W10 не меняется: у корней счёт — в пределах страницы; сквозной счёт корней —
  отдельный вопрос в roadmap;
- доказательство — паритет с прежним алгоритмом и перф против него.

## Решение

### 1. Счёт

Строки модели идут в порядке обхода дерева: родитель, затем его потомки. Соседи
строки глубины `d` — дети последней перед ней строки глубины `d − 1`; у корней группа
одна. Проход ведёт по уровням «последнюю строку» и «открытую группу её детей»,
номер в группе и размер группы пишутся в `Int32Array` по индексу строки — без
объектов и строковых ключей.

Совпадение группы проверяется по `parentId`: если родитель строки — не последняя
строка уровня выше (родителя нет среди строк, порядок не древесный), счёт уходит на
запасной путь — прежнюю группировку по `parentId`. Результат одинаков в обоих путях.

Читается минимум: у корня — только глубина (у строк глубины 0 в модели TanStack нет
родителя, включая строки групп), `id` — только у родителя проверяемой строки. Чтение
поля у сотен тысяч строк разных таблиц мегаморфно и дорого: `parentId` у каждого
корня утраивал цену счёта.

### 2. Передача в строку

Тело передаёт строке два числа — `aria-setsize` и `aria-posinset`; `aria-level`
строка берёт из глубины. Числа не ломают мемоизацию строки, объект бы ломал.

## Границы

- **Сквозные `setsize`/`posinset` корней через страницы** — не входят (roadmap).
- **Счёт только для видимых строк** — не входит: выигрыш против одного прохода мал,
  краёв больше.

## Отвергнутые альтернативы

- **Только видимые строки через `subRows` родителя** — поиск родителя и счёт корней,
  края фильтра, групп и копий строк при сортировке.
- **Оставить `Map` объектов, но мемоизировать дольше** — список строк меняется при
  каждом раскрытии, сортировке и приходе детей.

## Последствия

- **+** Счёт на 100 000 строк модели TanStack ~45 → ~5 мс под ×4 CPU (TA3): `id`
  читается только у родителя проверяемой строки; строка не получает новый
  объект.
- **−** RE38 почти не изменился (~270–280 мс): сэмплирующий профиль завысил долю счёта
  — без профилировщика он стоил ~25 мс из ~280. Цена прихода — перерисовка тела и
  корня.
- **−** Запасной путь хранит прежний алгоритм.
- **Публичный API:** не меняется.
