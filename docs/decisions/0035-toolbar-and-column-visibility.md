## Контекст

Видимость колонок в ядре уже есть: `columnVisibilityFeature` всегда включена, грид,
виртуализация, пиннинг, DnD и клавиатурная навигация работают с видимыми
колонками, а потребитель управляет ими через `state.columnVisibility` и
`handlers.onColumnVisibilityChange`. Не хватает **пользовательского контрола**:
скрыть или вернуть колонку сейчас можно только кодом.

Все существующие слоты привязаны к колонке, ячейке или строке
(`left/rightHeaderSlot`, `left/right/cellSlot`, `actionRowSlot`). Табличного места
для контролов, которые относятся ко всей таблице (колонки, в будущем экспорт,
плотность, фильтры), нет. Своей внешней рамки у грида тоже нет: есть только
разделители строк, а рамку в сторис рисует обёртка потребителя.

## Решение

### 1. Рамка грида (требования TB1–TB2)

Библиотека вводит **внешнюю рамку** вокруг всего блока «тулбар + таблица»:
`border` и скругление углов на корневой обёртке грида, на токенах
`--tsr-comp-frame-border-color`, `--tsr-comp-frame-border-width`,
`--tsr-comp-frame-radius` (выводятся из `--tsr-sys-border` и `--tsr-sys-radius`).
Содержимое обрезается по скруглению (`overflow: hidden` на обёртке, скролл остаётся
у контейнера таблицы). Рамка — переопределяемая тема: ширина `0` её убирает.

### 2. Тулбар (требования TB3–TB12)

> **Уточнено [ADR 0046](0046-toolbar-and-status-bar-visibility.md):** по умолчанию тулбар
> показывается по наличию активного `toolbarSlot`; `enableToolbar: true` оставляет пустой
> тулбар, `false` запрещает его. Абзац ниже — исходное решение.

**Включение.** Ядровый флаг `enableToolbar` у `useCreateTable` (по аналогии с
`enableFooter`). Тулбар рисуется, когда флаг включён, даже если ни один плагин не
добавил кнопку: раскладка не прыгает при подключении плагинов, а левая часть
позже получит контент потребителя.

**Раскладка.** Тулбар — строка **над таблицей, вне её скролл-контейнера**: не
скроллится ни по горизонтали, ни по вертикали. Сверху, слева и справа его
ограничивает рамка грида, снизу — горизонтальный разделитель с таблицей
(`--tsr-comp-toolbar-divider-color`); двойной линии со шапкой нет: собственной
верхней линии у шапки больше нет ни в одной раскладке — сверху её ограничивает рамка
или разделитель тулбара. Кнопки прижаты
к **правому** краю; левая часть зарезервирована под контент потребителя (вне этого
ADR) и слоты с `align: 'start'` (поле быстрого поиска, [ADR 0045](0045-filtering.md)). Высота, отступы и фон — `--tsr-comp-toolbar-height`,
`--tsr-comp-toolbar-padding-x`, `--tsr-comp-toolbar-gap`, `--tsr-comp-toolbar-bg`.
Полосу загрузки (`LinearProgress`) тулбар не трогает: она остаётся под шапкой.

**Слот `toolbarSlot`.** Новый табличный слот записи плагина:

```ts
interface ToolbarSlot {
  id: string // ключ дедупликации, как у остальных слотов
  slot: 'toolbarSlot'
  order?: number | 'last' // порядок внутри группы
  group?: string // подгруппа; по умолчанию 'default'
  component: (props: { table: Table }) => ReactNode
}
```

Компонент получает `table` целиком (контекста колонки нет); бизнес-колбэки плагина
читает через `table.getHooks()`. Слот регистрируется декларативно (`slots` в
`definePlugin`), дедуплицируется по `id` и собирается реактивно из активных
записей — как остальные слоты.

**Подгруппы и разделители.** Кнопки объединяются по `group`. Порядок групп —
по наименьшему `order` среди их кнопок; внутри группы — по `order`. Между
соседними непустыми группами рендерится вертикальный разделитель
(`Toolbar.Separator` Base UI, `role="separator"`, `aria-orientation="vertical"`).
Пустая группа разделителя не даёт.

**Доступность.** Тулбар — Base UI `Toolbar.Root` (`role="toolbar"`,
`aria-label` из локализации `toolbar`), в DOM перед гридом. Один tab-stop:
`Tab` входит в тулбар, `←`/`→` ходят по кнопкам (с зацикливанием), `Home`/`End` —
к первой/последней; следующий `Tab` уходит в грид. Не зависит от плагина
`keyboardNavigation`.

**Кнопка тулбара — семейство F4.** Компонент `ToolbarButton` на
`Toolbar.Button` Base UI: иконка с тултипом (подпись — `aria-label`), **квадратная
со скруглёнными углами** (`--tsr-comp-toolbar-button-radius`, по умолчанию
`--tsr-comp-control-radius`), размер `--tsr-comp-toolbar-button-size` (не меньше
24×24, [ADR 0034](0034-wcag-22-dragging-and-target-size.md)). Цвета и состояния —
как у action-кнопок ячеек (плоская, без тени): `control-color`, hover —
`control-hover-bg`, **активное** состояние (открыт поповер кнопки или
`active`-признак) — `control-active-color` + `control-active-hover-bg`, disabled —
`control-disabled-color`, фокус — `focus-ring`, переход — `action-button-transition`.
F4 вносится в контракт семейств [ADR 0017](0017-ui-components.md); общий с F1/F2
disabled-цвет и transition (TC-1/TC-2) распространяется на F4, радиус (TC-3) —
нет: у F4 свой.

### 3. Плагин `columnVisibility` (требования CV1–CV19)

Presence-based плагин `columnVisibility()` на `definePlugin`, без сервисной
колонки. Контрибьютит кнопку «Колонки» в `toolbarSlot` (группа `view`) и
действие «Скрыть колонку» в кебаб заголовка.

**Состояние — общее, у таблицы.** Видимость хранит стоковый срез
`columnVisibility` (фича ядра, включена всегда), а не локальный state плагина:
её читают грид, виртуализация, пиннинг, DnD и навигация, и второй источник правды
рядом со срезом TanStack разошёлся бы с ним. Контролируемость и сохранение — как
у остальных срезов: `state.columnVisibility` + `handlers.onColumnVisibilityChange`.

**Бизнес-колбэк — в аргументах плагина** (как `onToggleColumnSort`,
`onTogglePin`, [ADR 0027](0027-plugin-hooks-in-factory-args.md)):

```ts
columnVisibility({
  onToggleColumnVisibility?: (columnIds: string[], visible: boolean) => void,
})
```

Вызывается на **действие пользователя** (галочка, группа, «Показать все»,
«Сбросить», «Скрыть колонку»), а не на любое изменение среза; для группы — одним
вызовом со всеми затронутыми листьями.

**Меню колонок.** Кнопка открывает поповер (Base UI `Popover`,
`aria-label` из локализации `columns`), выровненный по правому краю кнопки:

- **Поиск** сверху: фильтр по подписи заголовка без учёта регистра. Совпала
  группа — видна со всеми потомками; совпал лист — виден вместе с цепочкой
  родителей. Нет совпадений — текст из локализации `noColumnsFound`.
- **Дерево колонок** в порядке отображения (с учётом пиннинга и перестановки):
  группы — узлы с отступом по глубине, листья — галочки (Base UI `Checkbox`).
  Галочка группы — **трёхсостоянная**: все потомки видимы — отмечена, ни одного —
  снята, часть — `indeterminate`. Клик по группе показывает всех её потомков,
  если хоть один скрыт, иначе скрывает всех.
- **Служебные колонки** (выбор строк, ручка перетаскивания, раскрытие, действия
  строки) в меню не попадают: их видимостью владеют плагины.
- **Защищённые колонки:** `enableHiding: false` в `columnDef` — галочка видна,
  отмечена и заблокирована. Последнюю видимую колонку скрыть можно — таблица покажет
  заглушку «все колонки скрыты» ([ADR 0133](0133-hide-all-columns.md)).
- **Флажок «Все колонки»** — корень дерева над списком ([ADR 0133](0133-hide-all-columns.md)).
- **Разделители** меню (и других поповеров грида: кебаб, панель экспорта) — мягкий токен
  `--tsr-comp-popup-divider-color` (по умолчанию `--tsr-sys-border`), а не более
  контрастная граница контролов `--tsr-comp-control-border`.
- **Подвал:** подпись «Выбрано N колонок» и «Сбросить» (к
  `initialState.columnVisibility`, стоковый `resetColumnVisibility`, ADR 0133).
- Клавиатура и фокус — Base UI: `Escape` закрывает поповер и возвращает фокус на
  кнопку тулбара; `Tab` ходит по полю поиска, галочкам и кнопкам.

**Скрытие из заголовка.** Действие «Скрыть колонку» в кебабе заголовка
(`rightHeaderSlot`) дублирует галочку для удобства. Видно, если колонку можно
скрыть (`getCanHide()`), в том числе у последней видимой (ADR 0133). Для заголовка группы
вложенной шапки — «Скрыть группу» (все листья группы). Подача — **только в меню**
(см. ниже): иконка-глаз в каждом заголовке не появляется.

**Без тулбара плагин инертен** (с [ADR 0046](0046-toolbar-and-status-bar-visibility.md) — только при явном `enableToolbar: false`). Кнопка «Колонки» — единственное место, где скрытую
колонку можно вернуть. Поэтому без `enableToolbar` «Скрыть колонку» в кебабе тоже
не показывается (иначе колонку можно скрыть без возврата), `diagnose` отдаёт
причину `'noToolbar'`, а ядро один раз предупреждает об этом при монтировании
([ADR 0036](0036-plugin-contract-diagnostics-and-a11y.md)).

**Скрытая закреплённая колонка** сохраняет закрепление и при показе возвращается
в свой закреплённый блок.

### 4. Подача «только в меню» для `SlotAction` (требования AM22–AM23)

`SlotAction` получает признак `placement?: 'auto' | 'menu'` (по умолчанию
`'auto'` — нынешнее поведение). Действие `'menu'` никогда не рендерится инлайн:
если в слоте есть хотя бы одно применимое `'menu'`-действие, кебаб показывается, и
в нём — `'menu'`-действия плюс схлопнутые по порогу. Сам такой кебаб занимает место
в ряду, поэтому **в пороге считается одной кнопкой** (сколько бы `'menu'`-действий
в нём ни было): пин + сортировка + кебаб = 3 — при пороге 3 всё уходит в кебаб, и
в заголовке не оказывается трёх кнопок, которые не помещаются в колонку. Без
плагина-меню (`headerActionMenu`) у такого действия нет поверхности — оно не
показывается (скрыть колонку остаётся через тулбар).

## Границы

- **Левая часть тулбара** (заголовок, поиск по данным) — позже, отдельной
  потребностью; здесь только резерв места. Счётчики и прочие сведения о данных —
  не в тулбаре, а в нижней панели ([ADR 0038](0038-pagination-and-status-bar.md)):
  сверху контролы, снизу сведения.
- **Другие кнопки тулбара** (экспорт, плотность, фильтры, полноэкранный режим) —
  своими плагинами поверх `toolbarSlot`.
- **Сохранение видимости** между сессиями — у потребителя через контролируемый
  `state` + `handlers`.
- **Перестановка колонок из меню** (drag в списке) — не в этом ADR.

## Последствия

- **+** Табличное место для контролов: следующие плагины (экспорт, плотность)
  добавляют кнопку одним слотом, без правок ядра.
- **+** Видимость остаётся одним срезом TanStack — нет второго источника правды.
- **+** Base UI уже содержит `Toolbar`, `Popover` и `Checkbox` с `indeterminate`;
  новых зависимостей нет.
- **−** **Видимое изменение для всех гридов:** появляется внешняя рамка со
  скруглением (O1). Потребитель со своей рамкой получит двойную — снимает её
  токеном `--tsr-comp-frame-border-width: 0`.
- **−** Новые чанки Base UI (`toolbar`, `popover`) добавляют вес; поповер меню
  грузится лениво (как кебаб, [ADR 0024](0024-slot-action-descriptor-and-menu.md)),
  тулбар — только при `enableToolbar`: отдельный чанк (около 6.5 KB gzip), пока он
  грузится, стоит заглушка той же высоты. Основной вход без тулбара не тяжелеет.
- **−** Расширение публичного API: `enableToolbar`, слот `toolbarSlot`,
  `SlotAction.placement`, плагин `columnVisibility`, новые ключи локализации и
  иконок, токены рамки и тулбара.

## Открытые вопросы

- **O1. Рамка без тулбара — РЕШЕНО.** Рамка рисуется **всегда**, с тулбаром и без:
  это рамка грида, тулбар её продолжает. Убрать — токеном ширины `0` (TB1).
- **O2. Индикатор на кнопке «Колонки» — РЕШЕНО.** Когда скрыта хотя бы одна
  колонка, кнопка в активном состоянии F4 (CV18).
- **O3. Кнопки без иконки — РЕШЕНО.** F4 — только иконка с тултипом; подача
  «иконка + подпись» заводится отдельно, если понадобится.
- **O4. «Скрыть колонку» без кебаба — РЕШЕНО.** Без плагина-меню заголовка пункта
  нет, скрыть колонку можно только из тулбара (AM23). Обратное — кебаб без
  тулбара — тоже запрещено: пункта нет, плагин инертен (CV19).

**Производительность**

| ID  | Требование                                                                                                                                     | Вид  |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| I4  | Скрытие/показ колонки из меню на выборке 1000×1000 со всеми плагинами — замер против цели Response (INP ≤ 100 мс) пишется в дашборд (ADR 0099) | perf |
| I5  | Открытие меню при 1000 колонках — замер против цели Response (INP ≤ 100 мс) пишется в дашборд (ADR 0099)                                       | perf |
| I6  | Ввод в поиск меню при 1000 колонках — замер против цели Response (INP ≤ 100 мс) пишется в дашборд (ADR 0099)                                   | perf |

Список меню виртуализирован (рисуются только видимые строки): без этого I4 и I5
занимали 4–6 с. **I4 — известный недостиг** (`knownShortfall`, регресс-потолок
320 мс, замер ~200–250 мс под ×4 с выбросами до ~310). CPU-профиль показал две квадратичные траты, обе
убраны: проверка «не последняя видимая колонка» в каждой строке меню и в каждом
заголовке сортировала все листья (`getIsPinned` в компараторе) — теперь это счётчик
по мемоизированному `getVisibleLeafColumns`; `getDraggableIndex` в каждом заголовке
фильтровал все колонки — теперь индекс кэшируется на массив листьев. Остаток размазан
по согласованию React и мемо TanStack: перерисовка видимых строк и ячеек с новым
набором колонок. Цель INP 100 мс остаётся (см. «Известные проблемы» в
[roadmap](../roadmap.md)).

## План внедрения

- **Фаза 1 — рамка и тулбар.** Токены рамки/тулбара, обёртка грида, флаг
  `enableToolbar`, слот `toolbarSlot` (типы, свёртка, дедуп), группы и
  разделители, `ToolbarButton` (F4) и его место в контракте семейств
  (TB1–TB15).
- **Фаза 2 — плагин.** `columnVisibility`: кнопка, поповер, дерево, поиск,
  «Показать все»/«Сбросить», колбэк, локализация и иконки (CV1–CV13, CV16–CV18).
- **Фаза 3 — заголовок.** `SlotAction.placement`, «Скрыть колонку/группу» в кебабе,
  пиннинг скрытой колонки (AM22–AM23, CV14–CV15).
- **Фаза 4 — перформанс.** Кейсы I4–I6 в перф-матрице.

Новые ключи локализации: `toolbar` («Table toolbar»), `columns` («Columns»),
`searchColumns` («Find column»), `noColumnsFound` («No columns found»),
`showAllColumns` («Show all»), `resetColumns` («Reset»), `hideColumn` («Hide
column»), `hideGroup` («Hide group»). Новая иконка: `columns` (по умолчанию —
`Columns3` из lucide).
