# 0186 — Перенос строки между группами клиентской группировки

- **Статус:** Принято и внедрено (решения — по итогам прожарки 2026-11-05)
- **Дата:** 2026-11-05
- **Слой:** плагин `rowDragging` — бросок, меню ручки и запись итога; плагин `rowGroupingModel` —
  стадия в модели группировки, потому что значение группы читает только она; общий срез переносов

## Контекст

На клиенте активная группировка гасит перетаскивание (ADR 0022, B2), а в серверной модели лист
переносится между группами (ADR 0159, §5). Перенос между группами — привычный способ сменить
значение: перевести задачу на другого исполнителя, сделку на другую стадию.

### Как у других

- **AG Grid** — `rowDragManaged` с `refreshAfterGroupEdit`: грид сам меняет значение колонки группы и
  перестраивает группировку.
- **MUI X** (Premium) — `rowReordering` меняет поле группы, для вычисляемых значений нужен
  `groupingValueSetter`, сохранение — `processRowUpdate`. При сортировке перестановка выключена.

## Решение

### 1. Когда активно

`rowDragging` при клиентской группировке активен, если задан `onRowDragEnd`: значение пишет
приложение, и без колбэка ему нечем его получить. Без колбэка плагин инертен с причиной `grouping`,
как прежде. При сортировке, фильтре и поиске инертен с их причинами. Строки-группы не переносятся.

### 2. Бросок

Лист бросается в другую группу того же уровня. `onRowDragEnd` получает `parentId`, `previousParentId`,
`groupValues`, `previousGroupValues` — тот же контракт, что в SSRM. `index` — место среди строк группы
по порядку данных: порядок внутри группы задают данные, а не бросок.

Значение в `data` пишет приложение: данные принадлежат ему, а колонка не обязана уметь записывать
значение обратно (вычисляемый `accessorFn`).

### 3. Промис

Пока промис ждёт, строка стоит в новой группе — стадия модели группировки. Успех снимает стадию,
значение к этому моменту пишет приложение. Отказ снимает стадию: строка возвращается, вспышка
`danger` и объявление (ADR 0112, 0114). Ячейка колонки группировки до итога показывает значение
новой группы: строка не расходится сама с собой.

Для плоского входа постановка и снятие стадии используют инкрементальное обновление
группировки. Стадия пересобирает затронутые группы, сохраняя остальные вместе с их
агрегатами, пока сохраняется место этих групп в списке.

### 4. Недопустимые места

Место внутри своей группы недопустимо: облако в тоне ошибки (ADR 0137). Перестановки внутри группы
нет. Уровень групп листу недоступен. Свёрнутая группа раскрывается паузой (ADR 0109), бросок в неё
раскрывает её.

### 5. Меню ручки

Замена перетаскиванию (ADR 0034): раздел «В группу» со списком групп того же уровня, в разделе — как
в меню действий (ADR 0079): шеврон, стрелки и строка «назад». Пунктов «вверх» и «вниз» при группировке
нет: перестановки внутри группы нет.

## Границы

- **Перестановка внутри группы** — нет: нужен устойчивый порядок внутри группы (ADR 0022, B2).
- **Перенос групп целиком** — нет.
- **Порядок групп** идёт по первой строке данных, как у TanStack: перенос первой строки группы может
  поднять другую группу выше. Сортировка групп — отдельная потребность.
- **`revertOnReject: false`** при переносе между группами не действует: значение в данных не менялось,
  и оставить строку в новой группе нечем.
- **Раздел «В группу» в серверной модели** — нет: группы известны не все.

## Отвергнутые альтернативы

- **Запись значения гридом, как в AG Grid.** Понадобился бы `groupingValueSetter` и правило для
  вычисляемых колонок, а `data` в Tessera принадлежит приложению.
- **Правка значения ячейки как замена перетаскиванию.** Ячейка может быть нередактируемой.
- **Без стадии: строка стоит на месте до итога.** Отличалось бы от серверной модели и выглядело бы как
  неудавшийся бросок.

## Последствия

- **+** Перенос между группами работает в обеих моделях с одним контрактом колбэка.
- **−** Стадия опирается на кэши значений строки TanStack: при смене их поведения она сломается;
  внесено в перечень [upstream-foundations.md](../architecture/upstream-foundations.md#движок-строк-поверх-tanstack).
- **Публичный API:** `rowDragging` с `onRowDragEnd` при группировке больше не инертен, ручки видны.
  `HandleMenuItemModel` и `HeaderMenuItem` получают необязательные `items`.

## Внедрение

Этап один.

- **Стадия.** Запись `rowMoves` несёт `group` — значения колонок группировки цели. Модель
  группировки кладёт их в кэши значений строки (`_valuesCache`, `_groupingValuesCache`), которые
  TanStack читает первыми, снимает при уходе записи и пересобирается при смене набора таких записей
  (`groupedRowModel`): подмена метода прототипа не работает, TanStack зовёт статические функции.
- **Колбэк.** `rowDragReportsMoves`: хуки дополнены пустым `onRowDragEnd` (`resolveHooks`), поэтому
  задан ли он приложением, плагин узнаёт из своих аргументов.
- **Перенос.** `groupMove.ts` в `rowDragging`: цели, значения по пути группы, `commitRowMove` без
  записи в данные. Бросок и меню ручки идут этим путём.
- **Меню.** `HandleMenuPopup` рисует раздел видом кита `MenuSections` на своём коротком состоянии: уровни
  известны сразу, загрузки нет.
