## Контекст

Highload-таблицы CRM — сотни тысяч и миллионы строк. Сейчас серверный режим умеет
сортировку, фильтр, поиск, страницу и раскрытие с промисами (ADR 0116, ADR 0054) и ленту
(ADR 0081). Ленту нельзя открыть в середине списка и прыгнуть ползунком в конец, а
загруженные строки копятся без предела.

Три ограничения архитектуры мешают разреженным блокам:

1. **Данные целиком у приложения.** Грид получает `data` и считает её всеми строками;
   ADR 0081 и 0116 закрепили это принципом и отвергли `getRows`.
2. **Список строк только сплошной.** Виртуализатор берёт число строк из длины массива
   модели (`core/virtualization/rowVirtualizer.ts`); около двадцати модулей читают
   `getRowModel().rows[i]` и `rowsById` напрямую: клавиатура, раскрытие, перетаскивание,
   выбор, выгрузка, `scrollToRow`, скелет, «наверх», правка, футер.
3. **Каждый ответ пересобирает модель целиком.** Цепочка моделей TanStack на новую
   `data` пересобирается по всем строкам. Свои инкрементальные модели (ADR 0064,
   0067–0072) опираются на непубличное поведение TanStack и работают только при
   неизменной `data`.

Предел высоты элемента в браузере (в Chrome v118 — 32 млн px) AG Grid обходит
растяжкой: строки едут быстрее ползунка. В TanStack Virtual штатного решения нет.
Выгрузка в AG Grid SSRM — только загруженные строки.

## Решение

### 1. Плагин модели `serverRowModel`

```ts
serverRowModel<TData>({
  enabled?: boolean,
  /** Загрузить строки [start, end) под текущее состояние. */
  getRows: (request: ServerRowsRequest) =>
    Promise<ServerRowsResponse<TData>> | ServerRowsResponse<TData>,
  /** Всего строк, если известно до первого ответа. Живой аргумент. */
  rowCount?: number,
  /** Строк в блоке; договор на время жизни. */
  blockSize?: number, // 100
  /** Сколько блоков держать в кэше. Живой аргумент. */
  maxBlocks?: number, // 100
})

interface ServerRowsRequest {
  start: number
  end: number
  sorting: SortingState
  columnFilters: ColumnFiltersState
  globalFilter: string
  signal: AbortSignal
}

interface ServerRowsResponse<TData> {
  rows: TData[]
  /** Итог, если сервер его знает. */
  rowCount?: number
}
```

- Плагин модели по ADR 0120: контролов нет, плоский грид без него не платит, импорт не
  тянет других плагинов (IV3).
- **Данные держит грид** — кэш блоков. Проп `data` в этом режиме не читается.
  Источник правды — сервер; приложение сообщает об изменениях методами §7.
- `getRowId` обязателен: id по индексу после перезапроса бессмысленны.
- Отказ — промис отклоняется; текст причины — по правилу AS10 (ADR 0041).

### 2. Источник строк ядра

Ядро получает источник строк — метод `table.getRowSource()` из `commonFeature`:

```ts
interface RowSource<TRow> {
  count(): number // всего строк в списке (с незагруженными)
  at(index: number): TRow | undefined // undefined — нет или не загружена
  byId(id: string): TRow | undefined // строка данных, в том числе не в списке
  indexOf(id: string): number // -1 — её нет в списке
  rows?(): readonly TRow[] // весь список, если он загружен целиком
  observe?(window: { first: number; last: number; fast: boolean }): void
}
```

- Источник — один объект, а не четыре метода таблицы: имя `table.getRowCount` занято
  пагинацией TanStack (итог всех страниц).
- По умолчанию источник — модель строк TanStack: список — `getRowModel().rows`, `byId` —
  как `getRow(id, true)` TanStack (строки групп и других страниц), но без исключения.
  Клиентский режим ведёт себя как прежде: тот же порядок, те же индексы.
- `serverRowModel` подставляет свой источник — хранилище блоков — опцией таблицы
  `getRowSource`, только при заданном `getRows`.
- `rows` есть только у источника, загруженного целиком: по нему тело считает `aria-*`
  дерева, линии, движение строк и место броска. У серверного его нет — эти функции
  выключены.
- `observe` — окно тела: видимые строки с запасом виртуализатора (без закреплённых
  далёких строк) и флаг быстрой прокрутки ADR 0008. Грид сообщает его при смене окна и
  при входе в быструю прокрутку и выходе из неё; у источника без `observe` работы нет.
- Тело берёт строку у источника по индексу; незагруженная — строка скелета ADR 0060 на
  своём месте, ключ виртуализатора — индекс.
- Через источник строки читают виртуализатор строк, клавиатура, правка, выбор,
  `scrollToRow` (индекс), скелет, «наверх», футер, подсветка и вспышки (уход цели) и
  первая и последняя строка у `commonFeature`.
- Модели строк TanStack мимо источника читают только модули списка стража SD2, каждый с
  причиной: фабрики моделей клиентского режима, алгоритмы над массивом строк тела
  (`aria-*` дерева, линии, движение строк, место броска), ленивые дети, перетаскивание,
  обход данных выгрузки и счётчики строк данных. В SSRM эти функции инертны или серверные
  (§13, §10) либо переходят на источник в своём этапе. Список только сокращается.

### 3. Движок серверного режима

- Строки блока собираются публичной `constructRow` TanStack один раз при приходе блока;
  `index` строки — её позиция в списке.
- Цепочка моделей TanStack в этом режиме простаивает: модели сортировки, фильтров и
  поиска работают в серверном режиме (`manual*`), страниц нет. Приход блока не обходит
  строки других блоков.
- Свои модели клиентского режима (ADR 0064, 0067–0072) не меняются; замена их своим
  движком — отдельная задача roadmap, источник строк — её шов.

### 4. Блоки, кэш и запросы

- Блок — `blockSize` строк подряд от кратного ему начала.
- Нужны блоки, пересекающие окно виртуализации строк с его запасом.
- **Во время быстрой прокрутки** (ADR 0008) блоки не запрашиваются; после неё — блоки
  окна.
- Не больше двух запросов одновременно; остальные ждут очереди в порядке близости к
  окну.
- Блок, ушедший из окна до ответа, отменяется: его `signal` прерван, поздний ответ
  игнорируется.
- **Вытеснение — LRU** по `maxBlocks`. Не вытесняются блоки окна, блок активной ячейки,
  блок строки в правке. Возврат к вытесненному блоку — новый запрос.
- Свежесть без TTL и опроса: блок живёт до вытеснения или обновления (§7).

### 5. Незагруженные строки, итог и предел высоты

- Незагруженная строка — строка скелета по раскладке колонок ADR 0060 (`skeletonCell`,
  полоска по колонке), статичная, без волны, с закреплёнными и служебными колонками.
- **Итог известен** (`rowCount` в аргументах или в ответе): высота тела — на весь итог
  с первого кадра; ползунок можно протянуть в любое место.
- **Итог неизвестен**: высота растёт по блокам — за последним загруженным блоком один
  блок скелета; блок короче `blockSize` — конец списка, итог становится известен.
- Новый `rowCount` из ответа меняет высоту без сдвига прокрутки и фокуса.
- **Предел высоты браузера.** Если `rowCount × высота строки` больше предела, измеренного
  при монтировании, — dev-warn с советом о пагинации; растяжки нет (вне объёма). Предел
  меряется один раз блоком заведомо огромной высоты (браузер обрезает её до своего
  предела) и только для тела выше 10 млн px; предупреждение — у любого грида, не только
  серверного (`core/scrollHeightLimit.ts`).

### 6. Сортировка, фильтры и поиск

- `columnSorting`, `columnFiltering`, `quickSearch` и их модели в режиме SSRM серверные
  без `server: true`; клиентский режим не включается.
- Смена любого из трёх срезов: кэш сбрасывается, тело прокручивается в начало, `signal`
  всех запросов прерван. Прежние строки остаются на экране под свечением обновления
  (ADR 0094) до прихода блоков нового окна.
- Перезапрос — ожидающее серверное действие ADR 0116: свет у причины, отказ откатывает
  сортировку к подтверждённой, оставляет черновик полей и показывает плашку с повтором.
  Колбэки `onToggleColumnSort`, `onFilterChange`, `onSearchChange` зовутся как
  уведомления; их промис в этом режиме не ждётся.

### 7. Обновление данных приложением

- `table.refreshRows({ purge?: boolean })` — перезапрос блоков окна под текущим
  состоянием. Без `purge` строки остаются на экране до ответа (свечение обновления), с
  `purge` — сначала скелет. Остальные блоки кэша сбрасываются.
- `table.setRowData(id, updater)` — меняет строку в кэше (после правки, push с сервера)
  и перерисовывает только её. Для незагруженной строки вызов игнорируется.
- Правка ячейки (`cellEditing`): успех промиса `onCellEdit` пишет значение в кэш.

### 8. Клавиатура и доступность

- Активная ячейка может стоять на незагруженной строке: фокус стоит, строка `aria-busy`;
  пришедший блок рисует содержимое без сдвига фокуса.
- `Ctrl+End`, `Ctrl+Home`, `PageDown`, `PageUp` двигают по всему итогу и загружают
  нужный блок.
- `aria-rowcount` — итог (плюс строки шапки) или `-1`. Незагруженные строки в окне — в
  дереве доступности: `role="row"`, сквозной `aria-rowindex`, `aria-busy="true"`.
- Незагруженная строка (`grid/PendingRow`) — скелет для глаз (скрыт от вспомогательных
  технологий) и одна ячейка во всю строку с подписью «Loading». Под клавиатурной
  навигацией она становится активной в колонке активной ячейки; пришедший блок убирает
  её, и фокус берёт настоящая ячейка той же позиции — тем же путём, что фокус,
  потерянный вместе с размонтированной строкой. `Ctrl+Home` ведёт в шапку (KN5), как без
  серверной модели.
- Копирование диапазона ячеек (ADR 0029) с незагруженными строками отказывается с
  объявлением.

### 9. Выбор строк

- Режим «выбрано всё, кроме»: «Выбрать всё» в шапке выбирает весь итог без загрузки
  строк; снятые флажки — исключения. Флажки строк остаются живыми, счётчик
  `selectedCount` — `rowCount − исключения`.
- Срез выбора отдаёт приложению `{ all: true, except: id[] }` или выбранные id —
  аргументами `rowSelectionModel` (ADR 0120, §4).
- Смена сортировки, фильтра или поиска выбор не сбрасывает.
- Выбор вложенных групп — вне объёма.

### 10. Выгрузка

- В режиме SSRM выгрузка только серверная: `dataExport({ server: true })` получает в
  `onExport` состояние запроса и состояние выбора (§9).
- Без `server: true` — dev-warn, значения `all`, `view`, `selected` недоступны с причиной.

### 11. Ошибки

- **Отказ блока**: на месте блока — строка ошибки ADR 0081 с причиной и «Повторить»;
  она прилипает к верху видимой части блока. Остальные строки блока — пустые рамки
  строк: границы ячеек и чередование полос как у строк, без полосок скелета (скелет
  обещает ответ, а его не будет до повтора), скрыты от вспомогательных технологий. При
  быстрой прокрутке вид тот же. Повтор перезапрашивает только этот блок. Плашки нет:
  загруженные строки целы. Отказ объявляется.
- **Автоповтор**: отказавший блок, ушедший из окна и вернувшийся в него, запрашивается
  сам один раз — не во время быстрой прокрутки. Отказ автоповтора оставляет строку
  ошибки, и этот блок дальше повторяется только кнопкой. Так строки ошибки не копятся по
  списку после временного сбоя, а при стойком отказе сервер не получает запрос на каждый
  возврат.
- **Отказ первого запроса** при пустом кэше — заглушка ошибки ADR 0096 с повтором.
- Строка ошибки — общий компонент `grid/LoadMoreError`, тот же, что у ленты ADR 0081;
  подпись — `rowsLoadFailed` («Couldn't load these rows»), кнопка — `loadMoreRetry`.
  Источник отдаёт отказы методом `failures()`, тело рисует обёртку во весь блок, а строку
  ошибки в ней — липкой под шапкой, а строки блока под ней — пустыми рамками.
- Отказ списка целиком — `loadError()` источника: `DataGrid` показывает его как отказ
  загрузки ADR 0096 (ошибка приложения главнее), а строк в списке на это время нет
  (`count()` — 0), чтобы заглушка встала под шапкой. Объявляет такой отказ заглушка, а не
  строка ошибки.

### 12. Прокрутка к строке

- `table.scrollToRowIndex(index, options)` — загрузить блок и прокрутить к строке по
  индексу; опции — как у `scrollToRow` (ADR 0104).
- `table.scrollToRow(id, { index })` — строка не загружена: прокрутка по подсказке
  индекса; после прихода блока строка с этим id должна стоять там, иначе `false`.
- Открыть список на записи (ссылка, результат поиска) — индекс записи сообщает сервер.

### 14. Ленивые дети (этап 5)

- У раскрытой строки — своё хранилище блоков: `getRows` получает `parentId`, `start` и
  `end` в пределах детей; число детей — из ответа или `hasChildren`.
- Вытеснение, отказ блока и скелет — те же, что у корней.

## Границы

- Серверная группировка и агрегаты (`groupKeys`) — отдельный ADR.
- Растяжка высоты сверх предела браузера — отдельный ADR при потребности.
- TTL, опрос, push-подписки — приложение вызывает `refreshRows` и `setRowData`.
- Двунаправленная лента без итога (чаты, курсорный API) — вне объёма.
- SSRM вместе с пагинацией, перетаскивание строк в SSRM — вне объёма.
- Замена клиентских моделей ADR 0064, 0067–0072 своим движком — отдельная задача.

## Отвергнутые альтернативы

- **Разреженная `data` у приложения** (AG Grid Viewport Row Model). Каждый блок — новая
  `data` и пересборка модели на все строки; разреженный массив TanStack не
  поддерживает.
- **SSRM как фабрика `coreRowModel` из загруженных строк.** Индексы модели не совпадают
  с позицией в списке, и движок снова опирается на внутренности TanStack.
- **Свой движок и для клиентского режима сразу.** Удваивает объём и риск; серверному
  режиму не нужен.
- **Режим ядра вместо плагина.** Плоский грид платил бы за кэш блоков (против ADR 0010).
- **Кэш без предела** (AG Grid по умолчанию). Долгая прокрутка миллиона строк держит
  весь набор в памяти.
- **Склейка запросов диапазоном** (MUI X). Ключ кэша — диапазон, а не блок; частичные
  попадания усложняют вытеснение.
- **Скелеты сразу при смене сортировки.** Экран пустеет на время запроса; прежние строки
  под свечением сохраняют контекст (как `keepPreviousData` MUI X).
- **`isAllRowsSelected` для «выбрать всё».** Блокирует флажки строк: «все, кроме» —
  типичная массовая операция CRM.
- **Выгрузка загруженных блоков.** Разрозненные блоки — не осмысленный набор строк.

## Последствия

- **+** Миллион строк с прыжком в любое место, ограниченная память, ошибки по блокам,
  клавиатура и `aria-*` на всём итоге.
- **+** Серверный режим не зависит от внутренностей TanStack; источник строк — шов для
  своего движка клиентского режима.
- **−** Источник строк сделан не у всех: алгоритмы над массивом строк тела, ленивые
  дети, перетаскивание и выгрузка читают модели TanStack по списку стража SD2 и
  переходят на источник в своём этапе.
- **−** Незагруженные строки — новый вид строк в дереве доступности.
- **−** Предел высоты: при строках 40px Firefox ограничивает список примерно 440 000
  строк, Chrome — 800 000.
- **Публичный API:** плагин `serverRowModel` и его типы (`ServerRowsRequest`,
  `ServerRowsResponse`); метод `getRowSource` и тип `RowSource`;
  `refreshRows`, `setRowData`, `scrollToRowIndex`; опция `index` у `scrollToRow`; срез
  выбора «все, кроме»; причина инертности `'serverRowModel'`; подписи локализации.
  Ломающих изменений нет.

## План внедрения

1. **Этап 1 — источник строк.** `table.getRowSource()`, перевод потребителей по индексу
   и id, страж чтения моделей, без смены поведения. SD1–SD2.
2. **Этап 2 — плоский `serverRowModel`.** Блоки, кэш, запросы, скелеты, итог, ошибки,
   клавиатура, доступность, перф и утечки, инертность без загрузчика и канал действий.
   SD3–SD19, SD31–SD34, SD37–SD39.
3. **Этап 3 — серверные действия и обновление.** Сортировка, фильтр, поиск, `refreshRows`,
   `setRowData`, правка, прокрутка к строке, сочетания. SD20–SD27.
4. **Этап 4 — выбор и выгрузка.** SD28–SD30.
5. **Этап 5 — ленивые дети.** SD35–SD36.

Документация: `docs/architecture/table-assembly.md`, `virtualization.md`,
`upstream-foundations.md`, `plugins-and-slots.md`, roadmap, AGENTS.md, CHANGELOG — по этапам.
