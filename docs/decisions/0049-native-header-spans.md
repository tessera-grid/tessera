## Контекст

Вложенная шапка рисуется CSS-гридом (`layout = 'grid'`): ячейка заголовка ставится в
`gridRow` и `gridColumn: span colSpan`. Вертикальное объединение сейчас задаёт
собственное поле Tessera `columnDef.rowSpan`:

- `rowSpan > 0` — ячейка в `gridRow: 1 / span rowSpan`, иначе — строка
  `column.depth + 1` (`grid/layout.ts`, `useGridStyles`);
- `rowSpan: 0` — заголовок не рисуется (`HeadCell`), как и плейсхолдеры TanStack.

Чтобы это работало, потребитель выравнивает дерево колонок до одной глубины
группами-прокладками и вручную считает спаны:

```ts
group({
  id: 'countryGroup',
  header: '',
  rowSpan: 2,
  columns: [
    group({
      id: 'countryNestedGroup',
      rowSpan: 0,
      columns: [accessor('country')],
    }),
  ],
})
```

Служебные колонки (`rowSelection`, `rowExpanding`, `rowDragging`, `rowActions`) делают
то же автоматически — оборачивают себя в `depth − 1` групп `*-group-level-N`.

Недостатки:

1. **Контракт протекает к потребителю.** Нужно знать про прокладки, выдумывать им `id`
   и пересчитывать все `rowSpan` при изменении глубины любой ветки.
2. **Ошибка беззвучна.** Без прокладки мелкий лист встаёт в строку `column.depth + 1`
   (наверх), под ним — пустота; диагностики нет.
3. **Прокладки — настоящие `Column`.** Они участвуют в id, порядке и пиннинге групп;
   знание «`rowSpan: 0` — призрак» продублировано в `layout.ts`, `HeadCell.tsx`,
   `keyboardNavigation/header.ts`, `commonFeature.ts` (через приведения типов).
4. **Конфликт имён с upstream.** В v9 у заголовка есть свой `header.rowSpan` с другой
   системой отсчёта.
5. **Нет `aria-rowspan` / `aria-colspan`.** В гриде на `div` скринридер не сопоставляет
   объединённую ячейку с колонками и строками, которые она покрывает.

TanStack Table v9 сам считает вертикальный спан (`buildHeaderGroups` →
`updateHeaderSpans`). Лист мельче максимальной глубины получает плейсхолдеры в
строках над собой; верхний плейсхолдер цепочки несёт `header.rowSpan` — высоту всей
цепочки, а каждый покрытый им заголовок (включая настоящий заголовок листа в нижней
строке) — `rowSpan = 0`. Остальные заголовки — `rowSpan = 1`. Группа всегда стоит в
строке своей глубины, прямо над подзаголовками; плейсхолдеры бывают только у листьев.

## Решение

### 1. Спан шапки — только из `header.rowSpan` v9 (HS1–HS5)

- Заголовок с `header.rowSpan === 0` не рисуется. Остальные ставятся в
  `gridRow: (header.depth + 1) / span header.rowSpan` и
  `gridColumn: span header.colSpan`.
- Верхний плейсхолдер цепочки рисуется как обычный заголовок своей колонки
  (`header.column` — лист): подпись, сортировка, слоты, ресайз. Колонки задаются как
  есть, без прокладок: мелкий лист сам растягивается до низа шапки.
- Вид: **группа — одна строка над подзаголовками; лист под ней растягивается** на
  оставшиеся строки (`Name` наверху, `First Name` — на две строки ниже). Лист без
  групп занимает всю высоту шапки (`Country`).
- Содержимое растянутого листа **прижато к низу**: подписи и иконки всех листьев стоят
  на одной нижней линии независимо от высоты ячейки.
- Спаны пересчитывает TanStack при каждой смене `getHeaderGroups()` (видимость,
  порядок, пиннинг), поэтому скрытие самой глубокой ветки уменьшает число строк шапки
  без дыр.

### 1a. Вершина цепочки — это заголовок листа (HS13)

Пустой заголовок — тот, у которого `header.rowSpan === 0`, а не любой с
`header.isPlaceholder`. Верхний плейсхолдер цепочки ведёт себя как заголовок своего
листа везде, где решается «есть ли у ячейки содержимое и действия»: слоты и
кебаб-меню, регистрация в клавиатурной навигации, пункт «Скрыть колонку». Проверки
`isPlaceholder` в `HeadCell` (навигация) и `hideHeaderAction` (скрытие) заменяются
этим правилом. Набор действий растянутого листа — тот же, что у листа обычной высоты.

### 2. Служебные колонки без групп-прокладок (HS6, HS14)

`rowSelection`, `rowExpanding`, `rowDragging` и `rowActions` вставляют свою колонку
листом без обёрток `*-group-level-N` и без зависимости от глубины шапки. Под вложенной
шапкой полную высоту им даёт цепочка плейсхолдеров v9.

Глубина шапки служила только обёрткам, поэтому она убрана из API колонки плагина:
`ServiceColumn.make` — `() => ColumnDef`, а `make` в `definePlugin` получает только
компоненты: `make({ cell, header })` вместо `make(depth, { cell, header })`. Результат
`make` кэшируется один раз на запись. Ломающее изменение API автора плагина (ADR 0028).

### 3. Публичный API (HS7–HS8)

- `columnDef.rowSpan` **удалён** из `CommonColumnDef` — ломающее изменение (до 1.0).
  Поле не переводится в устаревшее: молча игнорируемое поле хуже ошибки компиляции.
  Миграция: убрать `rowSpan` и группы-прокладки из определений колонок.
- `header.getIsFullHeightHeader()` сохраняется и выводится из v9:
  `header.rowSpan === table.getHeaderGroups().length`. Покрытые заголовки
  (`rowSpan = 0`) возвращают `false`.

### 4. Доступность (HS9, HS12)

Объединённая ячейка шапки получает `aria-rowspan={rowSpan}` при `rowSpan > 1` и
`aria-colspan={colSpan}` при `colSpan > 1`. В DOM она лежит в строке своей вершины
(`aria-rowindex = headerGroup.depth + 1`) — строка ARIA совпадает с визуальной верхней.
Дерево доступности Chromium (CDP) спаны ячеек не отдаёт, поэтому требование
проверяется сверкой атрибутов с боксом ячейки.

### 5. Клавиатура и пиннинг (HS10–HS11)

- Сетка владельцев шапки (ADR 0031, KB5) строится из v9: заголовок владеет строками
  `header.depth … header.depth + rowSpan − 1` во всех колонках своих листьев;
  `rowSpan = 0` ничем не владеет. Стрелки проходят объединённую ячейку за один шаг,
  фокус — на видимой ячейке. Идентификатор ячейки фокуса — id видимого заголовка
  (у растянутого листа это id верхнего плейсхолдера).
- Объединённая ячейка закреплённого листа липнет вместе с листом во всех строках,
  которые занимает.

### 6. Что меняется в принятых ADR

- **ADR 0006:** служебная колонка `rowDragging` не оборачивает себя в группы — под
  вложенной шапкой полную высоту даёт v9 (HS6).
- **ADR 0011:** группы-прокладки в историях и тестах исчезают; CP13–CP19 и LP-тесты
  перепроверяются на новых колонках `groupedColumns`, ожидания по прокладкам
  (если есть) переписываются. Под групповым пиннингом мелкий лист верхнего уровня
  (`Country`) закрепляется кнопкой на собственной ячейке, а не на пустой прокладке.
- **ADR 0035, CV3:** в дереве меню «Колонки» больше нет групп-прокладок; вложенность
  проверяется на настоящих группах (`info` → `more-info` → `age`).
- **ADR 0031, KB5:** сетка владельцев — по `header.depth` и `header.rowSpan` (HS10),
  а не по `columnDef.rowSpan`.

## Границы

- **ColumnDragging под вложенной шапкой** — по-прежнему инертен (ADR 0022). Если его
  когда-нибудь включат, проверки «лист — это `header.subHeaders.length === 0`» в
  `ColumnDraggingComponent` и `keyboardActions` придётся пересмотреть: у вершины
  цепочки есть подзаголовок — покрытый ею лист.
- **Виртуализация колонок под вложенной шапкой** — по-прежнему выключена.
- **Подвал** не меняется: он рисует только строку листьев.
- **Pivot** — отдельный ADR (roadmap).
- **Режим «группа обнимает листья»** (группа растягивается вниз, листья в одну нижнюю
  строку) — не поддерживается, см. «Отвергнутые альтернативы».

## Отвергнутые альтернативы

- **Оставить `columnDef.rowSpan`.** Ручной контракт с прокладками, беззвучные ошибки,
  дублирование знания о «призраках» в четырёх модулях — при наличии готового спана в
  upstream.
- **Группа растягивается вниз, листья — одна нижняя строка** (текущий вид без ручной
  разметки: группа поглощает плейсхолдеры под собой). Требует своего прохода поверх
  `getHeaderGroups()`, расходится с моделью v9 и рецептом из её типов. Близкий вид
  даёт прижатие подписей к низу (§1): все подписи на одной линии, отличается только
  положение горизонтальной границы.
- **Переводить `columnDef.rowSpan` в устаревшее с dev-предупреждением.** Внешних
  потребителей до 1.0 нет; удаление поля из типа покажет все места компилятором.
- **`aria-*` спанов отдельной задачей.** Модель спанов меняется здесь же; атрибуты
  читают те же `rowSpan` и `colSpan`.

## Последствия

- **+** Колонки описываются как данные, без разметки раскладки; служебные колонки
  проще и не зависят от глубины шапки.
- **+** Спаны верны при любой видимости и порядке колонок — их считает TanStack.
- **+** Скринридер получает спаны шапки.
- **−** Ломающее изменение: `columnDef.rowSpan` удалён, группы-прокладки в чужих
  определениях колонок станут видимыми пустыми группами.
- **−** Ломающее изменение API автора плагина: `make` колонки больше не получает
  глубину шапки — `make(depth, parts)` превращается в `make(parts)`.
- **−** Меняется вид: группа над мелкими листьями — одна строка, а не во всю
  оставшуюся высоту.
- **−** Видимая ячейка растянутого листа — плейсхолдер с собственным `header.id`;
  всё, что опирается на `header.id` (ячейка фокуса, `--header-<id>-size`,
  sticky-смещения), обязано работать с ним (HS10–HS11).
- **Перф (TQ6)** — неприменимо: нового массового состояния нет, спаны считает
  `buildHeaderGroups` за тот же проход; колонок и заголовков становится не больше,
  а меньше (без прокладок).

## План внедрения

- **Ядро.** `useGridStyles` (`grid/layout.ts`) — из `header.depth`, `header.rowSpan`,
  `header.colSpan`; `HeadCell` пропускает `rowSpan === 0`, рисует плейсхолдер вершины
  с контентом колонки, прижимает содержимое к низу, ставит `aria-rowspan` /
  `aria-colspan`, регистрирует вершину цепочки в навигации (`rowSpan !== 0` вместо
  `!isPlaceholder`). `getIsFullHeightHeader` в `commonFeature.ts` — из `header.rowSpan`.
  `CommonColumnDef.rowSpan` удалён.
- **Клавиатура.** `getHeaderRows` в `core/keyboardNavigation/header.ts` — диапазон
  `depth … depth + rowSpan − 1`; `NavHeader` без `columnDef.rowSpan`.
- **Плагины.** Обёртки `*-group-level-N` удалены из `rowSelectionColumn`,
  `rowExpandingColumn`, `rowDraggingColumn`, `rowActionsColumn`. `hideHeaderAction`
  скрывает пункт только у заголовка с `rowSpan === 0`. `ServiceColumn.make` и `make`
  в `definePlugin` — без глубины; `getMaxColumnsDepth` удалена.
- **Тесты.** Модульные HS1, HS7–HS8, HS14; визуальный набор `visual/header-spans`
  (HS2–HS6, HS9, HS11–HS13); HS10 — в `keyboard-wcag`. Переписываются тесты, которые
  опираются на прокладки или `columnDef.rowSpan` (`core-roles`, `keyboard-wcag`,
  CV3 в `column-visibility`, модульные `HeadCell`/`gridLayout`, при необходимости
  CP/LP).
- **Истории.** `groupedColumns` — без прокладок и `rowSpan`; новая история
  «Header Groups — shallow leaves» со смешанной глубиной листьев и служебными
  колонками (логики нет —
  дымовой тест не нужен).
- **Документация.** `docs/architecture/rendering.md`, `table-assembly.md`
  (служебные колонки), правки ADR 0006, 0011, 0031 (§6); статус → «Принято».
