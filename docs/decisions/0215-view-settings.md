## Контекст

ADR 0204 поставил в тулбар по кнопке-сводке на преобразование: «Фильтры» (ADR 0045), «Сортировка»,
«Группировка», рядом — «Колонки». Автор счёл это лишним: кнопок много, а у грида без своего тулбара
сводки сами создавали тулбар.

Как у других (сверка 2026-11-11): по кнопке на фичу — у приложений-баз (Airtable, Baserow, NocoDB,
monday); одно меню настроек вида — у Notion («View settings»: фильтр, сортировка, группировка,
свойства) и Linear («Display options»); грид-библиотеки (AG Grid, MUI X, DevExtreme) сортировку не
сводят вовсе, группировку показывают своей полосой. Автор выбрал вариант Notion.

## Решение

### 1. Что попадает в «Настройки вида»

Раздел «Настроек вида» — то, что меняет состав, порядок или структуру строк либо набор колонок и не видно
на месте. Встроенные разделы, в порядке рангов:

| Раздел      | Владелец           | Ранг |
| ----------- | ------------------ | ---- |
| Фильтр      | `columnFiltering`  | 10   |
| Сортировка  | `columnSorting`    | 20   |
| Группировка | `rowGrouping`      | 30   |
| Колонки     | `columnVisibility` | 40   |
| Поиск       | `quickSearch`      | 50   |

Раздел «Поиск» есть, только когда поиск активен, а поля поиска в тулбаре нет
(`quickSearch({ toolbar: false })`): иначе текст виден в поле. Разделы авторов — после встроенных,
по своему `order`. Не входят: закрепление, ширины и порядок колонок, перестановка строк, раскрытие,
пагинация, выбор, правка, итоги — видны на месте; опции ядра (высота строк, тема, язык) — решения
приложения.

### 2. Кнопка

- Кнопка «Настройки вида» (`icons.viewSettings`, по умолчанию lucide `SlidersHorizontal`) — в группе `view` справа,
  на месте «Колонок». Бабл — число активных разделов; подпись и доступное имя — с ним.
- Появляется, когда в наборе есть хоть один раздел; тулбар с ней — по ADR 0046. Опция ядра
  `viewSettingsToolbar?: ToolbarPlacement | false` задаёт группу, порядок и сторону, `false` — кнопки нет.
- Кнопку рисует грид в ленивом модуле тулбара: базовый `DataGrid` без плагинов не растёт.
- Кнопка подписана только на срезы своих разделов (`slices`): выбор строки её не будит.

### 3. Поповер

- **Первый уровень** — строка на раздел: значок, имя, короткое значение справа, шеврон у
  открываемого. Неактивный раздел без своей панели приглушён и не открывается. Общего «Сбросить
  всё» нет (решение автора 2026-11-11): оно снимало бы настройки, которые пользователь не трогал.
- **Простой раздел** — строка «назад», уровни по порядку: колонка, описание («по убыванию,
  приоритет 1 из 2»), значок скрытой колонки у её имени (перечёркнутый глаз с тултипом «Колонка скрыта» — фокусируемый `StatusIcon` кита обычного тона, ADR 0183, PK16), снятие уровня; внизу справа «Сбросить <раздел>» —
  `ghost`, не опасный (ADR 0206). Снятие и сброс — путями плагина: канал действий, серверное
  действие с откатом. Рисует ядро по уровням раздела.
- **Раздел со своей панелью** — ядро даёт рамку со строкой «назад», содержимое — ленивый
  компонент раздела. «Колонки» — прежнее меню колонок (поиск, «Все колонки», дерево, ластик),
  открывается всегда, даже когда ничего не скрыто.
- Фокус: вход в раздел — на первый элемент раздела (поле поиска у «Колонок»), «назад» — на строку
  раздела, снятие уровня — на соседний уровень или сброс (как ADR 0204, HT10).
- Переход между уровнями — сдвигом, как у разделов меню (ADR 0079): раздел въезжает справа,
  уходящий уровень уезжает влево, «назад» — наоборот; окно подстраивает размер переходом. Общая
  механика — примитив кита `PopupLevels` (`ui/Popup`), им же пользуются разделы меню. Строка раздела — пункт перехода кита `PopupNavItem` (значок, подпись, короткое значение справа многоточием с тултипом, шеврон; без перехода — без шеврона и нажатия); строка «назад» — он же без шеврона. Пока грузится панель раздела — строки-скелеты кита `PopupSkeletonRows`, те же, что у разделов меню и списка вариантов. Модуль панели не загрузился — на их месте блок ошибки кита с причиной и повтором, как отказ списка вариантов (ADR 0175, ED24); повтор грузит модуль заново (VW17). У первого
  уровня — заголовок «Настройки вида», у раздела — строка «назад»: одним видом — кеглем и жирностью подписей групп (ADR 0183, PK4), без разделителя.
  Тот же заголовок — у всех поповеров-панелей (`PopupPanel title`): журнал отказов, пульт, отметка
  ячейки (ADR 0183, PK33).

### 4. Короткие значения

Короткое значение — счётчик, а не имена колонок (решение автора 2026-11-11): так строка читается
сразу и не обрезается.

| Раздел        | Нет         | Есть     | С черновиками     |
| ------------- | ----------- | -------- | ----------------- |
| Фильтр        | none        | 2 active | 2 active, 1 draft |
| Сортировка    | none        | 2 active | —                 |
| Группировка   | none        | 2 active | —                 |
| Колонки       | all visible | 3 hidden | —                 |
| Поиск         | —           | active   | —                 |
| Раздел автора | своё        | своё     | своё              |

«draft» — неприменённое условие фильтра (черновик ADR 0178). У колонок — «hidden»: «active» про
колонки прочиталось бы как «показаны». Имена колонок, порядок уровней и отметка «колонка скрыта» —
внутри раздела. Доступное имя строки — полное: имя раздела и его уровни.

### 5. Договор раздела

Плагин вкладывает разделы полем `viewSettingsSections` записи (`definePlugin`), тип `ViewSettingsSection` — из
`/plugins`:

- `id`, `order`, `plugin` — владелец в канале действий;
- `label(labels)`, `icon` — ключ `icons`;
- `slices` — срезы состояния, на которые подписаны кнопка и строка;
- `visible?(table)` — строка есть; `active(table)` — раздел в бабле;
- `value(table, labels)` — короткое значение (помощник `countViewSettingsValue`),
  `description?(table, labels)` — полное значение для доступного имени;
- простой раздел — `levels(table, labels)`: `{ id, label, description, hidden, removeLabel,
remove(source) }` и `reset?: { label(labels), run(table, source) }`;
- раздел со своей панелью — `panel`: ленивый компонент (`preloadable`) с `{ table }`.

## Границы

- **Этап 2 — управление из «Настроек вида»** (`docs/roadmap.md`, «Запланировано»): добавить условие
  фильтра, уровень сортировки и группировки из раздела — для приложений, у которых нет кнопок в
  заголовках (модель без интерфейса, ADR 0120). Договор раздела тогда получает действие
  «добавить»; раздел такого грида вкладывает модель.
- Перестановки колонок в «Настройках вида» нет (решение автора 2026-11-11).
- Пользовательских предпочтений отображения (плотность, перенос, линии дерева) во встроенном
  «Настройках вида» нет; автор или приложение добавляет их своим разделом.

## Отвергнутые альтернативы

- **Кнопка-сводка на фичу** (ADR 0204 §5) — много кнопок, у грида без тулбара появлялся тулбар.
- **Плагин `viewSettings()`** — без него «Настроек вида» нет, автору надо помнить его подключить.
- **Общий слот из `shared/`** — автору плагина недоступен: `shared/` не публичный API.
- **Всё на одной панели без разделов** — длинно при многих уровнях; у Notion — разделы.

## Последствия

- **+** Одна кнопка вместо четырёх; разделы авторов — тем же договором.
- **+** Скрытое состояние таблицы видно в одном месте.
- **−** Ломающее изменение: нет кнопок `filter-summary-button`, `column-visibility-button`,
  сводок сортировки и группировки; снят аргумент `toolbar` у четырёх фабрик.
- **−** «Колонки» — на шаг дальше: открыть «Настройки вида», затем раздел.

## План внедрения

Один этап: факт `viewSettingsSections` и опция `viewSettingsToolbar` в ядре, кнопка и поповер в гриде, разделы пяти
плагинов, снятие сводок и кнопки «Колонки», истории S1–S4, перевод гайдов, открывавших «Колонки» и
сводки, на «Настройки вида». Вид — на приёмку автора; тесты VW1–VW15 — после приёмки.

## Внедрение

- **По виду** (2026-11-11), тесты VW1–VW15 — после приёмки вида автором. Факт `core/viewSettingsSections.ts`,
  кнопка и поповер — `grid/ViewSettings` (кнопка — в ленивом модуле тулбара, поповер — свой ленивый
  модуль), разделы — `viewSection.ts` у `columnFiltering`, `columnVisibility` (панель — ленивый
  `ColumnVisibilitySection`), `quickSearch`; сортировка и группировка — общий
  `shared/transformSection.ts`. Сводки ADR 0204 и кнопки «Фильтры» и «Колонки» удалены, гайды историй
  открывают «Настройки вида» (`__mocks__/viewSettings.ts`). Бюджет `DataGrid` без плагинов (LB3–LB4): 221 742 байт
  против 212 973 — прирост в ленивых модулях тулбара и поповера; бюджет поднят решением автора 2026-11-11.
