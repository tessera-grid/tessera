# 0063 — Сортировка колонок с вариантами по подписи

- **Статус:** Принято (решения — по итогам прожарки 2026-10-08)
- **Дата:** 2026-10-08
- **Связано:**
  - [ADR 0048](0048-option-filtering.md) — варианты колонки (`options`,
    `getOptionLabel`, кэш `loadOptions`); пункт «Сортировка и группировка по подписи —
    не входят» из «Границ» снимается этим ADR.
  - [ADR 0012](0012-column-sorting.md) — плагин `columnSorting`: функция сортировки
    колонки с вариантами по умолчанию меняется.
  - [ADR 0016](0016-row-grouping.md) — строки-группы упорядочиваются той же функцией.
  - [ADR 0010](0010-invert-core-plugins-registry.md) — tree-shaking: сортировка по
    подписи живёт в плагине, ядро даёт только поиск подписи.

## Контекст

Подпись значения колонки с вариантами видна в ячейке, быстром поиске, экспорте,
фильтре и сводке (ADR 0048), но сортировка идёт по самому значению. У `lookup` это id:
менеджеры «Bob Reed», «Alice Moss» с id `m2`, `m1` встают в порядке id, а не имён. У
`select` значение — служебный ключ (`lead`, `won`), и порядок ключей не совпадает ни с
алфавитом подписей, ни с порядком вариантов.

Решено (прожарка 2026-10-08):

- порядок — как у чек-листа панели фильтра: есть `options` — их порядок, иначе —
  алфавит подписи;
- включено по умолчанию; свой `sortFn` колонки перекрывает;
- значение без подписи — после известных вариантов, как оно видно в ячейке (строкой);
  массив — поэлементно; пустые — последними.

## Решение

### 1. Порядок значений

Ключ значения колонки с `options` или `getOptionLabel` — группа и место внутри неё.
По возрастанию группы идут так:

1. **Вариант из `options`** — по индексу в `options`.
2. **Значение с подписью вне `options`** (`getOptionLabel`, кэш `loadOptions`) — по
   подписи, `Intl.Collator` по умолчанию (тот же порядок, что `localeCompare` у
   чек-листа фильтра).
3. **Значение без подписи** — по строке значения, тем же сравнением.
4. **Пустое** (`null`, `undefined`, `''`, `[]`).

По убыванию порядок обратный целиком. Массив (`multiselect`) сравнивается поэлементно
по ключам элементов; массив-префикс — раньше более длинного.

### 2. Где живёт

Плагин `columnSorting` добавляет фичу с `initColumnInstanceData`: колонке с `options`
или `getOptionLabel`, у которой `sortFn` остался `'auto'`, она ставит функцию
сортировки по подписи. Подставляется в уже слитое описание колонки (свежий объект на
каждую колонку), исходное описание приложения не меняется. `createSortedRowModel`
TanStack берёт функцию из описания колонки (`column_getSortFn`), поэтому метод
прототипа для этого не годится.

Ядро даёт `knownOptionLabel` — подпись или `undefined` (тот же порядок поиска, что у
`optionLabelOf`, без запасного «значение строкой») и `extraOptionLabel` — подпись вне
`options` (`getOptionLabel`, затем кэш `loadOptions`).

### 3. Группировка

Строки-группы `rowGrouping` при сортировке по колонке группировки упорядочиваются той
же функцией: значение строки-группы — значение группировки. Без сортировки порядок
групп прежний — по первому появлению.

### 4. Серверный режим

При `columnSorting({ server: true })` (`manualSorting`) модель не сортирует, порядок
задаёт сервер — по подписи ли, решает он.

## Границы

- **Порядок групп без сортировки** — не входит: по первому появлению, как раньше.
- **Серверная сортировка по подписи** — не входит: это договор приложения с сервером.
- **Направление первого клика** — не меняется: общее для таблицы (`sortDescFirst`,
  ADR 0012).

## Отвергнутые альтернативы

- **Всегда алфавит подписи** — теряется смысловой порядок `options` (воронка
  статусов), и сортировка расходится с чек-листом фильтра.
- **Включение флагом колонки** — сортировка по видимому тексту — ожидаемое поведение;
  флаг оставил бы неверный порядок по умолчанию.
- **Метод `getAutoSortFn` на прототипе колонки** — `createSortedRowModel` вызывает
  внутреннюю функцию, а не метод, и переопределение не срабатывает.
- **Функция в ядре (`getDefaultColumnDef`)** — ядро платило бы за сортировку без
  плагина, а `'auto'` TanStack пришлось бы повторить для всех колонок.

## Последствия

- **+** Порядок совпадает с тем, что видно в ячейке и в чек-листе фильтра.
- **+** Новых зависимостей и опций нет.
- **−** Сравнение ищет подписи на каждой паре строк; цена на 100 000 строк — OS11.
- **Ломающее изменение поведения:** колонки с `options` или `getOptionLabel`
  сортируются по подписи, а не по значению. Прежний порядок возвращает свой `sortFn`
  колонки (например, `'basic'`).
