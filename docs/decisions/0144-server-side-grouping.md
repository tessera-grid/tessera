## Контекст

Серверная модель строк (ADR 0138) держит миллионы строк, но группировать их не умеет:
`rowGrouping` в её режиме инертен, клиентская модель TanStack группирует только загруженные
строки. Для «highload» группировка с агрегатами на сервере — базовая операция: сводка по
странам, менеджерам или статусам по всей выборке, а не по одному блоку.

### Как у других

- **AG Grid SSRM** — запрос несёт `rowGroupCols`, `valueCols` с `aggFunc` и путь `groupKeys`;
  сервер отвечает строками-группами текущего уровня с агрегатами, число детей —
  `getChildCount(data)`; итог — `grandTotalRow`. Дерево данных и группировка не совмещаются.
- **MUI X Premium** — `getRows` получает `groupFields` и `groupKeys`, агрегаты — по
  `aggregationModel`, итог — `aggregateRow` ответа; число детей — `getChildrenCount(row)`.

## Решение

### 1. Тот же загрузчик

`getRows` получает три новых поля запроса:

```ts
interface ServerRowsRequest {
  // …прежние поля (ADR 0138, §1)
  /** Колонки группировки по уровням; без группировки — пусто. */
  grouping: string[]
  /** Значения групп от корня до уровня запроса; у корня — пусто. */
  groupKeys: unknown[]
  /** Колонка → имя её `aggregationFn` (`sum`, `count`, `mean`…); только строковые. */
  aggregations: Record<string, string>
}

interface ServerRowsResponse<TData> {
  // …прежние поля
  /** Итоги колонок по всей выборке; читаются из ответа корня. */
  totals?: Record<string, unknown>
  /** Строк данных во всей выборке при группировке (корень — это группы). */
  leafCount?: number
}

serverRowModel({
  // …прежние опции
  /** Строк в группе — из строки-группы ответа; без неё — после раскрытия. */
  getGroupChildCount?: (row: TData) => number | undefined,
})
```

Пока `groupKeys` короче `grouping`, ответ — строки-группы уровня `groupKeys.length`; на
последнем уровне — строки данных. Уровни групп — ветки дерева хранилищ §14 ADR 0138: у
раскрытой группы своё хранилище, запрос несёт её путь `groupKeys` и `parentId` — id группы.

### 2. Строка-группа

- **Значение группы** — значение сгруппированной колонки этого уровня в строке ответа
  (её `accessorKey` или `accessorFn`).
- **Id** грид строит сам из пути: `group:` и JSON значений от корня. С id строк данных
  (`getRowId` приложения) он не пересекается, пока приложение не даёт строкам такой префикс.
- Строка — `constructRow` TanStack с `groupingColumnId` и `groupingValue`: `getIsGrouped()`
  истинно, ячейка сгруппированной колонки — ячейка группы, прочие — агрегаты.
- **Агрегаты** — значения полей колонок в строке ответа: сервер кладёт их туда, где у строки
  данных лежит значение колонки. Ячейку рисует `cell` колонки, как у клиентской группировки:
  `aggregatedCell` TanStack грид не рисует ни там, ни здесь.
- **Путь** `groupKeys` — JSON-значения: строки, числа, булевы, `null`.
- **Число строк** — `getGroupChildCount(row)`: подпись в ячейке группы и итог хранилища
  ветки — скелеты на всю её высоту при раскрытии. Без числа — один блок скелетов (§14).

### 3. Смена группировки — серверное действие

Срез `grouping` входит в выборку, как сортировка (ADR 0138, §6): новая выборка — с начала
списка, прежние строки — под свечением, отказ — откат среза и плашка с повтором (ADR 0116).
Раскрытие групп сбрасывается: id групп другой группировки не совпадают. Смена сортировки,
фильтра или поиска раскрытие сохраняет, как у веток §14.

### 4. Итог в футере

`totals` ответа корня — итоги колонок выборки. Футер (ADR 0118) показывает их: колонка без
`footer` — значение итога, своя функция `footer` читает его методом таблицы
`table.getColumnTotal(columnId)` (контекст заголовка TanStack не расширяется). Новая выборка —
новый итог.

### 5. Выбор и выгрузка

- Флажки — только у строк данных; у строки-группы флажка нет. «Выбрать всё, кроме» выбирает
  строки данных выборки; счётчик — `leafCount − исключённые`, без `leafCount` — «все, кроме k».
- Серверная выгрузка получает `grouping` и `aggregations` в `query`.

### 6. Совместимость

- `rowGrouping` в SSRM работает: кнопка в шапке, срез `grouping`, строки-группы — из
  источника. Клиентская модель группировки в режиме SSRM не строится.
- `rowGroupingModel` отдельно в SSRM инертен с причиной `'serverRowModel'`: модели без
  интерфейса группировать нечем.
- При группировке строки данных детей не раскрывают (`hasChildren` не читается), dev-warn.
- Клавиши, кнопка раскрытия, отступ уровня и `aria-*` `treegrid` — те же, что у веток §14.

## Границы

- Выбор группы целиком (с незагруженными детьми) — [ADR 0148](0148-group-selection-in-ssrm.md).
- Группировка вместе с деревом данных (`hasChildren`) — вне объёма, осознанное ограничение
  (roadmap).
- Клиентские агрегаты в SSRM, сводные таблицы, «раскрыть всё», липкие строки групп — вне
  объёма.

## Отвергнутые альтернативы

- **Отдельный `getGroups`** — два пути запросов в движке и у приложения; ветки §14 уже
  несут уровни.
- **Сервер сам решает агрегаты** — смена `aggregationFn` колонки не доходила бы до сервера.
- **Число строк только после раскрытия** — подпись «US (1 234)» — норма у AG Grid и MUI X.

## Последствия

- **+** Группировка и агрегаты по всей выборке на миллионах строк; итог списка в футере.
- **−** Строки-группы — новый вид строк в движке SSRM; их id строится на каждый блок.
- **Публичный API:** не ломается — новые поля запроса и ответа, опция
  `getGroupChildCount`, метод `table.getColumnTotal`.

## Внедрение

- **Тесты:** модульный `serverGrouping.dom` (GS1–GS2, GS10–GS11), визуальный `server-grouping`
  (GS3–GS9), перф GS12 — в `interaction` (раскрытие группы 28 против 32 мс у ветки при 100 000
  корней), GS13 — в `scroll` (p95 11,2 против 11,1 мс у плоского списка). TQ1 — мутациями:
  пустой путь `groupKeys`, `aggregations` с `'auto'` — GS1; id группы по индексу, без
  `groupingColumnId` — GS2; выгрузка без `grouping` — GS10; клиентская модель активна,
  ленивые дети при группировке — GS11; кнопка мимо серверного действия, без сброса раскрытия,
  без начала списка — GS3; без числа строк — GS4; ветка без итога — GS5; группа не
  раскрывается — GS6; раскрытие теряется на смене выборки — GS7; футер без значения итога,
  `getColumnTotal` без итога — GS8; выбор выключен группировкой, без `leafCount` — GS9; работа
  в ветке группы и в проходе по веткам — GS12 и GS13.
- **Найдено по ходу:** смена группировки не возвращала список к началу —
  `rowSourceWindow` следил только за сортировкой, фильтрами и поиском; раскрываемость
  строки-группы — `getRowCanExpand` плагина `rowExpanding` (TanStack проверяет её функцией
  `row_getCanExpand`, а не методом строки).
