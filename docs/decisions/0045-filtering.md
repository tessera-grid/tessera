## Контекст

Фильтрация — разрыв №1 с рынком (roadmap, «Паритет с рынком»): таблицу без фильтра в
большинстве сценариев не рассматривают, а Tessera затевалась ради highload-таблиц CRM,
где пользователь сужает тысячи строк до нужных. Потребитель — конечный пользователь
грида (сужает выборку), приложение (держит фильтры в своём состоянии, в серверном
режиме перезапрашивает данные) и соседние плагины (экспорт `view`, нижняя панель).

Опора есть: TanStack v9 даёт `columnFilteringFeature` (срез `columnFilters`,
`createFilteredRowModel`, `filterFns`, `filterFromLeafRows`, `manualFiltering`) и
`globalFilteringFeature` (срез `globalFilter`, `manualFiltering`). Работы — в UI, типах
фильтров, контрактах с другими плагинами и сервером.

Срезы по типам данных — решение автора:

1. **Этот ADR** — строка, число, булево; быстрый поиск.
2. Дата и дата со временем — [ADR 0047](0047-date-filtering.md).
3. Справочник и селект — [ADR 0048](0048-option-filtering.md).

## Решение

### 1. Два плагина (FL1–FL2)

Presence-based и tree-shakeable ([ADR 0010](0010-invert-core-plugins-registry.md)), как
разделены фичи TanStack:

- **`columnFiltering(options)`** — фильтры колонок: кнопка в заголовке, поповер
  условия, кнопка-сводка «Фильтры» в тулбаре, «показано N из M» в нижней панели.
- **`quickSearch(options)`** — поле поиска в тулбаре по значениям всех подходящих колонок.

Выключенный плагин (`enabled: false`) сужает свой срез до пустого (`narrow`,
[ADR 0039](0039-reactive-plugin-arguments.md), §4): строки не фильтруются, сохранённые
фильтры возвращаются при включении. Ради этого ядро собирает сужения и у
выключенных записей.

Оба работают по отдельности и вместе; фильтры разных колонок и быстрый поиск
объединяются через **И**. Общий код (дебаунс, заглушка пустого результата, сравнение
значений) живёт вне папок плагинов (`check:tree-shaking`).

```ts
columnFiltering({
  server?: boolean,            // договор на время жизни (ADR 0039)
  debounceMs?: number,         // по умолчанию 200
  onFilterChange?: (filters: ColumnFilter[]) => void,
  // серверный режим: числа для «показано N из M»
  filteredRowCount?: number,
  totalRowCount?: number,
})

quickSearch({
  server?: boolean,
  debounceMs?: number,
  onSearchChange?: (search: string) => void,
})
```

Бизнес-колбэки — в аргументах фабрики ([ADR 0027](0027-plugin-hooks-in-factory-args.md)),
живые ([ADR 0039](0039-reactive-plugin-arguments.md)); `server` — в `lifetime`.

### 2. Тип фильтра колонки — явно (FL3)

Колонка фильтруется, только если в `columnDef` задан `filter`:

```ts
{ accessorKey: 'name', header: 'Name', filter: 'text' }
{ accessorKey: 'age', header: 'Age', filter: 'number' }
{ accessorKey: 'active', header: 'Active', filter: { type: 'boolean', nullable: true } }
```

Без `filter` нет ни кнопки в заголовке, ни участия колонки в фильтрах колонок. Поле
дополняет тип `ColumnDef` через аугментацию плагина. Фильтруются **значения** ячеек
(`cell.getValue()`), а не отрисовка, как в экспорте.

### 3. Условия и значение фильтра (FL4–FL8)

Значение фильтра — `{ operator, value }`; срез — стоковый `columnFilters`
(`{ id, value }[]`), контролируемый через `state.columnFilters`.

| Тип       | Условия                                                               | По умолчанию |
| --------- | --------------------------------------------------------------------- | ------------ |
| `text`    | содержит, равно, начинается с, заканчивается на, пусто, не пусто      | содержит     |
| `number`  | =, ≠, <, ≤, >, ≥, между (границы включительно), пусто, не пусто       | =            |
| `boolean` | переключатель «Все / Да / Нет»; «Пусто» — только при `nullable: true` | Все          |

- **Текст:** без учёта регистра, ввод обрезается по краям. «Пусто» — `null`,
  `undefined` или `''`. Пустой ввод у условий со значением — фильтра нет.
- **Число:** поле принимает только число; ввод, который не разбирается как число, не
  применяется, поле помечено ошибкой (`aria-invalid` и текст). У «между» — два поля;
  пустая граница — открытый интервал.
- **Булево:** «Все» снимает фильтр.
- Условия без значения («пусто», «не пусто») применяются сразу.

### 4. Кнопка в заголовке и поповер (FL9–FL11)

- Кнопка-воронка в заголовке фильтруемой колонки — дескриптор действия слота
  ([ADR 0024](0024-slot-action-descriptor-and-menu.md)): при `headerActionMenu`
  становится пунктом кебаба. Дескриптор — **действие с панелью**: новое поле
  `SlotAction.panel(ctx, { close, initialFocusRef })` расширяет контракт слота —
  инлайн-кнопка и пункт кебаба открывают поповер с этим содержимым (у кебаба — у его
  кнопки), `onSelect` не вызывается. Поле общее: им может пользоваться любой плагин. Активный фильтр виден по индикации кнопки (и в
  доступном имени), когда кнопка схлопнута — по пункту меню.
- Поповер: выбор условия, поле значения, «Сбросить». Вид — общий `ui/Popup`
  ([ADR 0017](0017-ui-components.md), PP1–PP7).
- **Применение сразу, с дебаунсом** `debounceMs` (200 мс) после ввода; выбор условия
  и булева значения — без дебаунса. Кнопки «Применить» нет. В серверном режиме — кнопка
  «Применить» и черновик условия по колонке ([ADR 0154](0154-server-filter-apply-and-draft.md)).
- Клавиатура и фокус: фокус в поле при открытии, `Escape` закрывает и возвращает
  фокус на кнопку (ADR 0021/0031).

### 5. Сводка фильтров в тулбаре (FL12–FL13)

Факты о **фильтрах** — наверху, рядом с поиском.

- Кнопка «Фильтры» — кнопка тулбара (F4, ADR 0035), есть при включённом плагине. При
  активных фильтрах — «Фильтры · N»; без фильтров — `disabled` (раскладка не прыгает).
- Поповер-сводка: список активных фильтров — подпись колонки, условие, значение,
  кнопка сброса этого фильтра; внизу «Сбросить все». Быстрый поиск в сводку не входит:
  его поле на виду.
- **Фильтр на скрытой колонке остаётся активным** и в сводке помечен значком и подписью
  «колонка скрыта». Сводка — единственное место, где такой фильтр видно.
- Доступное имя кнопки называет числа текстом: «Фильтры, активно 3, из них 1 на
  скрытой колонке».
- Без `enableToolbar` сводки нет, а фильтры колонок работают — поэтому плагин
  **активен** (`diagnose` двоичен: инертный плагин ничего не делает, а здесь работает
  главное). Фильтр на скрытой колонке тогда виден только по меню «Колонки».

### 6. Быстрый поиск (FL14–FL15, FL42)

- Поле в тулбаре (левая сторона), с кнопкой очистки. Сторону задаёт новое значение
  `align: 'start'` у слота тулбара (по умолчанию `'end'`, ADR 0035).
- Кнопки внутри поля (подсказка колонок ADR 0053 и очистка) не прижаты к рамке: от
  правого края поля их отделяет токен `--tsr-comp-quick-search-button-inset` — тот же
  зазор, что сверху и снизу; текст поля не заходит под кнопки.
- Условие — «содержит», без учёта регистра, тот же дебаунс.
- Ищет по **видимым** колонкам — по показанному тексту: формат типа, подписи вариантов,
  даты в виде `2026-10-31` ([ADR 0172](0172-column-data-type.md), DT15); колонку исключает
  `enableGlobalFilter: false` (стоковое поле v9). Служебные колонки не участвуют.
  Булевы колонки (значок, а не текст) не участвуют; список колонок поиска виден в тултипе
  поля и уходит серверу в `onSearchChange` ([ADR 0053](0053-quick-search-columns-hint.md)).
- Срез — стоковый `globalFilter`, контролируемый через `state.globalFilter`.
- Без тулбара поля нет, но поиск работает программно (`globalFilter`), плагин активен
  ([ADR 0046](0046-toolbar-and-status-bar-visibility.md), PB9).

### 7. Сведения о строках в нижней панели (FL16–FL18)

Факты о **данных** — внизу ([ADR 0038](0038-pagination-and-status-bar.md)).

- **«Показано N из M»** — слот `columnFiltering` (или `quickSearch`) в левой части
  панели при активном фильтре или поиске; без них элемента нет. Включается опцией
  `filteredCount: true`, как счётчик выбора `selectedCount`: иначе любой грид с
  фильтрами получил бы нижнюю панель. N — строки после
  фильтрации (все страницы), M — все строки. Слот один на таблицу (дедупликация по
  `id`), даже если подключены оба плагина.
- **«Скрыто фильтром»** — продолжение счётчика выбора
  (`rowSelection({ selectedCount })`, RS19): «3 выбрано, 1 скрыта фильтром». Часть про
  скрытые появляется, только когда выбранные строки не проходят фильтр. Без
  `selectedCount` её нет. Новый ключ локализации `selectedRowsHidden(count)` —
  существующий `selectedRows` не меняется.
- Числа в панели не являются live-областью (RS22); об итоге фильтрации сообщает §9.

### 8. Взаимодействие с другими плагинами (FL19–FL26)

| Плагин             | Поведение при активном фильтре                                                                                                         |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| `pagination`       | смена фильтра или поиска возвращает на первую страницу; число страниц — по отфильтрованным строкам                                     |
| `rowSelection`     | выбор строк, скрытых фильтром, **сохраняется** и виден в счётчике (§7); «выбрать все» в шапке — только отфильтрованные                 |
| `rowDragging`      | при **непустом** фильтре или поиске инертен: ручки скрыты (порядок в отфильтрованном виде ненастоящий), как при группировке (ADR 0022) |
| `rowExpanding`     | в дереве родитель виден, если подходит потомок (`filterFromLeafRows`)                                                                  |
| `rowGrouping`      | группы собираются из отфильтрованных строк                                                                                             |
| `cellEditing`      | строка, переставшая проходить фильтр после сохранения, уходит из выборки сразу; открытая сессия правки жива (ADR 0040)                 |
| `dataExport`       | `view` учитывает фильтры и поиск; подпись — «С учётом фильтров» / «С учётом сортировки и фильтров» (ADR 0044, EX10)                    |
| `columnVisibility` | скрытие колонки не снимает её фильтр (§5)                                                                                              |

Само подключение плагинов фильтрации ничего не блокирует — гейт по **непустому**
фильтру, как гейт группировки по активной группировке.

### 9. Пустой результат (FL27–FL28, FL41)

Своя заглушка, отдельно от `stub` (пустые данные, решение автора 2026-09-05 остаётся в
силе). В отличие от `stub`, она встаёт **поверх пустого тела**, а шапка с кнопками
фильтров остаётся — иначе пользователю нечем менять условия:

- Показывается, когда строк нет **и** активен фильтр колонки или поиск — и в клиентском,
  и в серверном режиме (сервер вернул пусто при активных фильтрах).
- По умолчанию: текст `noRowsMatchFilters` («No rows match the filters») и кнопка
  `resetFilters` («Reset filters»), которая сбрасывает фильтры колонок и поиск.
- Переопределяется `stubs.filtered` грида ([ADR 0123](0123-empty-state-stubs.md)):
  `ReactNode` или `({ action }) => ReactNode`, `action` — сброс фильтров и поиска.
- Без активных фильтров при пустых данных — заглушка `noData` (ADR 0123).
- Встаёт под шапкой во всю видимую ширину и при колонках уже грида: контейнер прокрутки
  на это время — колонка (`data-filter-empty`), как у заглушки ошибки загрузки (ADR
  0096); исправлено 2026-10-12 (FL41).

### 10. Серверный режим (FL29–FL31)

- **Режим данных общий.** `manualFiltering` в v9 — один флаг на таблицу: если `server`
  задан хотя бы у одного из плагинов, не фильтрует грид ни по колонкам, ни по поиску.
  Задавайте `server` обоим плагинам одинаково.
- `server: true` → `manualFiltering`: грид не фильтрует; `onFilterChange` /
  `onSearchChange` получают состояние после действия пользователя (после дебаунса),
  программная смена среза колбэк не зовёт (как PG6). Приложение перезапрашивает `data`.
- «Показано N из M» — из аргументов `filteredRowCount` / `totalRowCount`; без них
  элемента нет. «Скрыто фильтром» в серверном режиме не показывается: какие выбранные
  строки скрыты, знает только сервер.
- Смена `server` после монтирования не применяется (ADR 0039, договор на время жизни).
- Серверный режим без колбэка — `diagnose` → `'noOnFilterChange'` / `'noOnSearchChange'`.

### 11. Доступность и локализация (FL32–FL34)

- После применения фильтра или поиска число строк объявляется вежливой live-областью
  грида («120 rows»), один раз на применение (после дебаунса); пустой результат
  объявляется тем же числом, а не подписью «нет данных». В серверном режиме
  результата ещё нет — о нём сообщает окончание загрузки (`enableLoading`).
- Подписи — из `localization` (условия, кнопки, сводка, заглушка, «показано N из M»),
  иконки — из `icons` (`filter`, `filterActive`, `search`, `clear`).
- Кнопки, поповеры, поле поиска и заглушка проходят axe с `color-contrast` в обеих
  темах; зона нажатия кнопок не меньше 24×24 (ADR 0034).
- Панель фильтра — ленивые модули (сама панель; календарь и чек-лист — отдельно,
  DF14, SF22). Поповер открывается, когда модули панели этой колонки уже загружены
  (`SlotAction.preload`, ADR 0024): пустой поповер, а затем содержимое, — это вспышка,
  которую видно при первом открытии. Загрузка начинается при наведении и фокусе
  кнопки, поэтому к клику модуль обычно готов, а ожидание после клика короче.
  Добавлено 2026-10-07 багфиксом.

## Границы

- **Дата и дата со временем** — второй срез, [ADR 0047](0047-date-filtering.md).
- **Справочник и селект** (set-фильтр, значения с сервера) — третий срез, [ADR 0048](0048-option-filtering.md).
- **Несколько условий на колонку** (И/ИЛИ внутри колонки) — не входит.
- **Строка фильтров под шапкой** (floating filters) — возможно позже, тем же состоянием.
- **Чипы активных фильтров** под тулбаром — возможно позже, как вид той же сводки.
- **Подсветка совпадений** в ячейках — не входит.
- **Фильтр по отрисовке** или по произвольной функции колонки — не входит; свой
  `filterFn` TanStack остаётся доступен в `columnDef`, но без UI.
- **Server-Side Row Model** — отдельный ADR; здесь сервер получает только состояние.

## Последствия

- **+** Пользователь сужает выборку в самой таблице; приложение получает одно
  состояние для клиента и сервера.
- **+** Фильтр, который не видно (скрытая колонка), и выбор, которого не видно
  (скрытые строки), не теряются и не действуют незаметно.
- **+** Новых зависимостей нет; стоковые фичи TanStack.
- **−** Расширение публичного API: два плагина, поле `filter` в `columnDef`, проп
  `filterStub`, ключи локализации и иконки, новые причины `diagnose`.
- **−** Ещё одна кнопка заголовка и ещё один гейт `rowDragging` — новые связки в
  контракте совместимости (ADR 0022).
- **−** Фильтрация на 100 000 строк может не уложиться в INP — тогда `knownShortfall`
  с регресс-потолком, как I7.

## План внедрения

- **Фаза 1 — ядро фильтров.** Фабрики условий текст/число/булево, поле `filter`,
  объединение через И, быстрый поиск без UI (FL2, FL4–FL6, FL14, FL26).
- **Фаза 2 — UI колонки.** Кнопка заголовка, поповер, дебаунс, кебаб, клавиатура
  (FL3, FL7–FL11).
- **Фаза 3 — тулбар и панель.** Поле поиска (и с ним FL1 — оба плагина по
  отдельности), сводка, скрытые колонки, «показано N из M», «скрыто фильтром»,
  `diagnose` (FL1, FL12–FL13, FL15–FL18).
- **Фаза 4 — сочетания.** Пагинация, выбор, перетаскивание, дерево, группировка,
  правка, экспорт (FL19–FL25).
- **Фаза 5 — пустой результат, сервер, доступность.** FL27–FL34.
- **Фаза 6 — перформанс и истории.** FL35–FL36; `DataGrid.Filtering.stories.tsx`:
  «Filtering», «Filtering — tree», «Filtering — with pagination, selection and export»,
  «Filtering — empty result», «Filtering — Server» (FL37); тумблеры
  `enableColumnFiltering` / `enableQuickSearch` в `argsToPlugins` и `StoryProps`.
