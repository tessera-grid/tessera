# 0161 — Линии дерева в серверной модели строк

## Контекст

Линии дерева считает обратный проход по всей модели строк (`grid/treeBranches.ts`): маска
строки — есть ли ниже сестра у неё и у каждого предка. В SSRM всех строк нет, и `treeLines`
там инертен (SD44): серверное дерево и серверные группы остаются без линий.

### Как у других

У AG Grid и MUI X линий дерева нет — это фича Tessera (ADR 0058, 0102).

## Решение

### 1. Линии по раскладке

`treeLines` в SSRM активен. Раскладка дерева SSRM (`serverRowModel/tree`) знает место строки в
её ветке и размер ветки; признак «ниже есть сестра» у строки и каждого предка — место меньше
размера ветки без единицы. Счёт — O(глубины) на строку, без прохода по строкам списка; на
одинаковом дереве маски совпадают с клиентским проходом.

### 2. Незагруженные строки и неизвестный размер

Незагруженные строки ветки — с линиями, как скелет дерева (SL24); приход блока линии не
сдвигает. Размер ветки неизвестен — у последнего загруженного ребёнка линия идёт вниз к блоку
скелетов за ним; короткий блок ставит «конец ветки».

### 3. Группы, перенос, обновление

Серверные группы — с линиями, как клиентские (ADR 0058). Превью броска в SSRM (ADR 0108, 0159) — линии по проекции окна на раскладке; после броска — линии нового места. Раскрытие,
приход блока и транзакция перерисовывают только строки окна, чьи линии изменились.

## Границы

- Линии строк за окном не считаются — их нет на экране.

## Отвергнутые альтернативы

- **Проход по загруженным строкам.** Между блоками — незагруженные строки: признак «ниже есть
  сестра» был бы неверен у последней строки блока.
- **Конец ветки у последнего загруженного ребёнка при неизвестном размере.** Под ним виден
  блок скелетов — линия обрывалась бы перед строками той же ветки.

## Последствия

- SD44 и тест инертности `treeLines` в SSRM меняют ожидания.
- Маску строки считают два модуля — паритет держит TL9.

## Внедрение

**Внедрён 2026-10-31.**

- **Маска по раскладке** — `BlockTree.linesAt` (`serverRowModel/tree.ts`): от места строки в её
  ветке вверх по предкам, у каждого уровня — место меньше размера ветки без единицы. Размер
  ветки — `count()` её хранилища: без итога это загруженное и блок впереди, короткий блок делает
  его точным. Линии к детям — следующая строка глубже. Строк счёт не читает.
- **Источник** отдаёт `treeLines(index)` (`RowSource`) в индексах страницы: за концом страницы
  детей нет. `Body` строит из него индекс линий (`treeLinesOf` в `grid/treeBranches.ts`) вместо
  прохода по массиву строк; незагруженной строке — линии её места, как у скелета дерева.
- **Проекция броска** (ADR 0108) берёт глубины и состояние прохода из индекса линий, а не из
  массива строк — одна функция для клиента и серверной модели.
- **`treeLines` в SSRM активен** (`neverInert`); SD44 ADR 0138 и его тест переписаны.
- **Требования:** TL14 уточнён — строки, у которых сменилось место, перерисовываются тоже; вид
  теста — визуальный (счётчики работы в браузере, как SD19).
- **Тесты:** модульный TL9 (`serverTreeLines`), визуальные TL10–TL13 (`server-tree-lines`),
  TL14 — в `work-counters`, перф TL15 — в `scroll`; история S1 `ServerTreeLines` с гайдом и
  близнецами. Линии включены во всех историях серверной модели с вложенными строками: ленивые
  дети (и липкие ветки S4 ADR 0160), группировка, выбор, выделение, пагинация, перетаскивание,
  транзакции.
