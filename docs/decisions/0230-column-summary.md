# 0230 — Сводка колонки: выбор функции агрегата пользователем

- **Статус:** Принято и внедрено 2026-11-15 (прожарка 2026-11-15, решения автора: название «Сводка»; выбор — в меню колонки
  и разделом «Настроек вида», как сортировка и фильтр; кнопки на ячейке итога, контекстного меню
  итога и своих контролов тулбара нет; режим «все строки дерева» остаётся решением разработчика;
  список функций по типу колонки; «Без сводки»; на каждый сценарий — история с гайдом)
- **Дата:** 2026-11-15
- **Слой:** плагин `columnAggregation` (`plugins/columnAggregation`) — выбор пользователя поверх
  `aggregationFn` колонки: без плагина выбора нет в сборке, поэтому он не в ядре. Живое поле
  `aggregationFn` и ключ пересчёта значений групп — `shared/aggregation.ts`: их читают модель
  группировки и итог колонок, общий код плагинов живёт в `shared/`. Ядро — подпись функции у
  итога (опция `columnTotalLabel`, футер — возможность ядра), целое число у счётных функций
  (форматирование итога — ядра) и вид серверного действия `aggregation` (серверные действия —
  ядра, ADR 0116) ([ADR 0163](0163-layer-boundaries-and-guards.md)).
- **Изменяет:**
  - [ADR 0184](0184-column-totals-and-group-row-count.md) «Границы» — «настройка метода агрегации
    человеком — нет» снимается: её даёт плагин `columnAggregation`.
  - [ADR 0215](0215-view-settings.md) §1, §4 — раздел «Сводка» с рангом 35; итоги колонок по-прежнему

  - [ADR 0116](0116-async-server-actions.md) — вид серверного действия `aggregation`, его срез
    откатывается при отказе.
- **Связано:**
  - [ADR 0229](0229-tree-totals-over-all-nodes.md) — режим `aggregationScope` (не входит в выбор).
  - [ADR 0172](0172-column-data-type.md) — тип колонки задаёт список функций.
  - [ADR 0079](0079-nested-menu-sections.md) — вложенный раздел меню.
  - [ADR 0062](0062-active-action-indicator.md) — точка включённого действия на кебабе.
  - [ADR 0221](0221-value-change-flash.md) — смена функции не вспыхивает (VC22).

## Контекст

Функцию итога и значений строк-групп задаёт разработчик полем `aggregationFn` колонки (ADR 0184).
Человек, который разбирает данные, хочет переключать её сам: средний чек вместо суммы, максимум
вместо количества. Сейчас для этого приложение пишет свой интерфейс и меняет колонки.

### Как это сделано у других (проверено 2026-11-15)

- **AG Grid** — выбор функции в меню колонки и на боковой панели колонок; включается у колонки
  (`enableValue`), список ограничивает `allowedAggFuncs` — только для интерфейса, не для API.
  Заголовок показывает функцию: «sum(Bank Balance)», `suppressAggFuncInHeader` её прячет.
- **MUI X Premium** — пункт «Aggregation» в меню колонки, итог — строкой внизу или в строке
  группы; состояние `aggregationModel` контролируемо; `availableAggregationFunctions` колонки
  ограничивает список; по умолчанию выбор есть у числовых и строковых колонок.
- **DevExtreme** — в DataGrid встроенного выбора нет; для PivotGrid документация советует своё
  контекстное меню. Грид WinForms DevExpress — контекстное меню строки итогов.
- В AG Grid и MUI одна выбранная функция задаёт и итог внизу, и значения строк-групп.

## Решение

### 1. Плагин `columnAggregation` и срез

```ts
useCreateTable({
  columns: [
    { accessorKey: 'amount', dataType: 'number', aggregationFn: 'sum' },
  ],
  plugins: [columnTotals(), columnAggregation()],
})
```

- Срез `columnAggregations` — колонка → имя функции или `null` («Без сводки»). Нет ключа —
  действует `aggregationFn` колонки, как без плагина. Аргументы фабрики — `columnAggregations`,
  `onColumnAggregationsChange`, `initialColumnAggregations` (ADR 0120, §4); метод таблицы
  `setColumnAggregations` — выбор из кода.
- Выбор главнее `aggregationFn`: фича плагина делает поле `aggregationFn` описания колонки живым —
  его читают TanStack, итог колонок, стадия группировки и запрос сервера, ничего не зная о
  плагине. Новых колонок смена выбора не создаёт: хост таблицы на срезы не подписан (ADR 0196).
- Значения строк-групп стадия группировки пересобирает по ключу выбора из `shared/aggregation.ts`;
  итог TanStack сверяет функцию сам.
- Один выбор задаёт и итог внизу, и значения строк-групп — с одной группировкой, без строки
  итогов, тоже.

### 2. Какие функции доступны

- Список задаёт тип колонки — поле `aggregationFns` записи реестра `dataTypes` (ADR 0172): новый тип
  объявляет свои функции сам. Встроенные:

  | Тип                                                                                                  | Функции                                                |
  | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
  | `number`                                                                                             | сумма, среднее, медиана, минимум, максимум, количество |
  | `date`, `dateTime`                                                                                   | минимум, максимум, количество                          |
  | `text`, `select`, `multiSelect`, `boolean`, `object`, `numberString`, `dateString`, `dateTimeString` | количество, число разных значений                      |

  Строковые даты и десятичная строка — только счёт: минимум и сумма TanStack строки пропускают.

- Поле колонки `aggregationFns` задаёт свой список. Функция по умолчанию (`aggregationFn`) входит в
  список всегда.
- Свои функции регистрируются по имени: `columnAggregation({ functions: { p90: { aggregate,
label, dataTypes: ['number'] } } })`; `label` — текст приложения. Функция входит в список
  колонок типов `dataTypes` и колонок, чей список её называет. Имя уходит серверу, как имена
  встроенных.
- Новая встроенная функция `uniqueCount` — число разных значений — в общем наборе
  `shared/aggregation.ts`.

### 3. Меню колонки

- Пункт «Сводка» в кебабе заголовка (`placement: 'menu'`), подсказка справа — текущая функция,
  шеврон открывает вложенный список (ADR 0079): функции по порядку списка с отметкой текущей и
  «Без сводки» последним. Выбор закрывает меню.
- Пункт есть, когда результат виден: строка итогов включена или идёт группировка. Колонка без
  функций, служебная колонка и колонка, для которой `canSummarizeColumn(column)` ответил
  `false`, пункта не имеют.
- Выбор не по умолчанию зажигает точку на кебабе колонки (ADR 0062).

### 4. Подпись функции у итога

- Ячейка итога с плагином показывает перед числом имя функции: «Среднее 420». Подпись — отдельный
  элемент, `…` сокращает сначала её, число не обрезается. Ядро берёт подпись из опции
  `columnTotalLabel(table, columnId)`, которую ставит плагин.
- В строках-группах подписи нет: она повторялась бы в каждой строке.

### 5. Счётные функции — целым числом

`count` и `uniqueCount` дают число строк, а не значение колонки: итог и значение строки-группы
показываются целым числом по языку таблицы, а не по типу колонки (иначе количество в денежной
колонке вышло бы «$12.00», в колонке дат — датой). Это правило ядра, оно действует и без плагина.

### 6. «Настройки вида»

Раздел «Сводка», ранг 35 — после «Группировки», перед «Колонками». Уровни — колонки с выбором в
срезе, в порядке колонок; описание — имя функции. Снятие уровня возвращает функцию по умолчанию,
«Сбросить» — все. Короткое значение — «N active». Раздел есть, когда есть пункт меню хоть у одной
колонки.

### 7. Серверная модель

Имя выбранной функции уходит в `aggregations` запроса (ADR 0144, §1): смена выбора начинает новую
выборку. Это серверное действие вида `aggregation` (ADR 0116): свечение, при отказе срез
откатывается к выбору до цепочки и появляется плашка. `revertOnReject: false` оставляет новый
выбор. На клиенте выбор применяется сразу.

### 8. Выгрузка и вспышка

Запрос серверной выгрузки несёт выбранную функцию в `aggregations`, как запрос строк; клиентская
выгрузка строк-групп и итогов не пишет (ADR 0044). Смена функции не вспыхивает итогом — сменился
смысл числа (ADR 0221, VC22).

## Границы

- Несколько сводок одной колонки, итоги групп отдельной строкой — нет (ADR 0184).
- Режим `aggregationScope` — решение разработчика, в меню его нет (ADR 0229).
- Кнопки на ячейке итога, контекстного меню итога, контролов тулбара кроме «Настроек вида» — нет.
- Сумма и среднее десятичных строк (`numberString`) — нет, пока нет точной арифметики строк.

## Отвергнутые альтернативы

- **Опция `columnTotals`.** Без строки итогов функцию групп было бы не поменять.
- **Новые колонки на смену выбора.** Хост таблицы пришлось бы подписать на срез, и выбор будил бы
  приложение (ADR 0196).
- **Обёртка функций реестра с выбором по колонке.** Колонка без `aggregationFn` выбора бы не
  получила, кэши TanStack сверяют имя функции, а не выбор.
- **Функция в заголовке колонки, как в AG Grid.** Подпись нужна там, где число.
- **Раздел только в меню колонки.** Без строки итогов изменённую функцию не видно на месте.

## Последствия

- У каждой колонки с плагином поле `aggregationFn` — свойство с геттером на её описании.
- Смена выбора пересобирает значения строк-групп целиком.
- Новый вид серверного действия и его снимок в ядре.

## План внедрения

1. Ядро: живое `aggregationFn`, ключ выбора для стадии группировки, `uniqueCount`, целое число
   счётных функций, опция `columnTotalLabel`, вид серверного действия `aggregation`.
2. Плагин: срез, списки, меню, точка, подпись, «Настройки вида», факт преобразования.
3. Серверная модель и выгрузка.
4. Тесты SU1–SU18 и истории S1–S8 с гайдами и близнецами высокой контрастности.
