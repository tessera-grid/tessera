# 0141 — Пределы браузера: высота тела и липкая шапка

- **Статус:** Принято (решения — по итогам прожарки 2026-10-26)
- **Дата:** 2026-10-26
- **Связано:**
  - [ADR 0138](0138-server-side-row-model.md) — §5 «предел высоты», SD18 (снято этим ADR).
  - [ADR 0004](0004-core-on-tanstack-table.md) — R17, липкая шапка.
  - [ADR 0118](0118-column-footer.md) — футер вне области прокрутки отвергнут.
  - [ADR 0036](0036-plugin-contract-diagnostics-and-a11y.md) — логгер грида.

## Контекст

Тело грида — один блок высотой «строк × высота строки» внутри области прокрутки, шапка
прилипает к её верху (`position: sticky`). У браузеров два предела, которые длинный
список задевает (замер пробником, Firefox 155, Chromium и WebKit из Playwright):

| Предел                                          | Firefox                                            | Chromium, WebKit              |
| ----------------------------------------------- | -------------------------------------------------- | ----------------------------- |
| Высота элемента                                 | 17 895 697 px (2^30/60); **выше — высота 0**       | 33 554 428 px; выше — обрезка |
| Прокрутка, до которой держится `sticky; top: 0` | 8 947 848 px (2^29/60); глубже шапка уезжает вверх | без предела                   |
| `sticky; bottom: 0`, `sticky; left`             | держатся                                           | держатся                      |

При строках по 50px шапка Firefox перестаёт прилипать после строки ~179 000, тело
выше ~357 000 строк получает высоту 0 — список схлопывается. Замер ADR 0138 (§5, SD18) —
блок `1e9px` — в Firefox даёт 0: предупреждение печатало «(0px)», а порог фактически был
константой 10 млн px. Шапка Firefox на глубокой прокрутке нашлась на гайде S5 ADR 0138 в
`test:engines`.

### Как у других

- **AG Grid** — шапка в отдельном контейнере над областью прокрутки; тело выше
  измеренного предела «растягивается»: высота не выше предела, строки сдвигаются на
  долю прокрутки (`divStretchOffset`).
- **MUI X DataGrid** — пределы браузеров описаны в документации, растяжки нет.
- **TanStack Virtual** — предел высоты открыт с 2023 года
  ([#616](https://github.com/TanStack/virtual/issues/616)); PR со встроенным сжатием
  прокрутки ([#1172](https://github.com/TanStack/virtual/pull/1172), `maxScrollSize`, по
  умолчанию 33 млн px) не принят. Пределы Firefox нигде не описаны.

## Решение

1. **Замер предела высоты.** Пробный блок высотой `1e9px`: обрезанная высота — предел
   (Chromium, WebKit); высота 0 — бинарный поиск наибольшей высоты, которую блок
   получает (Firefox). Без определения браузера по `userAgent`.
2. **Замер предела липкости.** Скрытая область прокрутки высотой в предел высоты с
   блоком `sticky; top: 0`: держится на последней прокрутке — предела нет, иначе
   бинарный поиск по прокрутке.
3. **Один раз на документ и только для тела выше 8 млн px** — ниже обоих пределов в
   любом из движков. Предел высоты меряется и в продакшене (он нужен обрезке), предел
   липкости — только когда предупреждение будет напечатано.
4. **Обрезка тела.** Тело выше предела высоты грид обрезает сам: в Firefox список не
   схлопывается — строки до предела видны и прокручиваются, как в Chromium. Обрезка по
   пределу высоты, а не липкости: доступно больше строк, о шапке предупреждает п. 5.
5. **Два предупреждения разработчику** (логгер грида, ключи — по одному на сессию), оба с
   советом о пагинации:
   - `stickyHeaderLimit` — тело выше предела липкости: «шапка перестаёт прилипать после
     строки N»;
   - `scrollHeightLimit` — тело выше предела высоты: «строки после N недоступны
     прокрутке», в тексте — настоящий предел.

## Границы

- **Растяжка высоты** — следующий ADR: тело не выше меньшего из двух пределов, позиция
  прокрутки сжимается (как AG Grid и PR #1172), через публичные `scrollToFn` и
  `observeElementOffset` TanStack Virtual.
- `scrollToRow`, `scrollToRowIndex`, `Ctrl+End` к строке за пределом высоты — как было:
  строка за пределом не видна («Известные проблемы» roadmap до растяжки).
- Предел ширины (колонки) — нет: таблицы шириной в миллионы пикселей не бывает.

## Отвергнутые альтернативы

- **Шапка вне области прокрутки** (AG Grid) — чинит только шапку, предел высоты
  остаётся; синхронизацию горизонтальной прокрутки отверг ADR 0118 для футера.
- **Предел по `userAgent`** — сломается при смене предела в Firefox, врёт для форков.
- **Одна константа 8,9 млн px для всех** — ложное предупреждение в Chromium и WebKit.
- **Обрезка по пределу липкости** — шапка держится всегда, но в Firefox доступна только
  половина строк.
- **Свой ползунок прокрутки** — заново доступность, касания, колесо и инерция.

## Последствия

- **+** Список выше 17,9 млн px в Firefox не схлопывается; предупреждение называет
  настоящий предел и номер строки.
- **+** Замер — основа растяжки: её граница — меньший из двух пределов.
- **−** Пробник — синхронные раскладки (около 2 мс под Firefox, один раз на документ, только
  для тела выше 8 млн px).
- **−** В Firefox строки после ~179 000 (по 50px) — без липкой шапки, до растяжки.
- **Публичный API:** без изменений; новое предупреждение `stickyHeaderLimit` в консоли
  разработчика.

| BH1 | Предел высоты — наибольшая высота, которую блок получает: в Firefox около 17,9 млн px (не 0), в Chromium и WebKit — 33,5 млн px                                                | визуальный |
| BH2 | Предел липкости — наибольшая прокрутка, на которой `sticky; top: 0` у верха области: в Firefox около 8,9 млн px, в Chromium и WebKit предела нет                               | визуальный |
| BH3 | Замеры — один раз на документ и только для тела выше 8 млн px: у таблицы ниже пробник в DOM не появляется; предел липкости не меряется, когда предупреждение не печатается     | визуальный |
| BH4 | Тело выше предела высоты обрезано до предела: в Firefox список не схлопывается — первая строка видна, прокрутка до предела показывает строки                                   | визуальный |
| BH5 | Тело выше предела липкости — предупреждение `stickyHeaderLimit` с номером строки, после которой шапка перестаёт прилипать, и советом о пагинации; без предела липкости — нет   | визуальный |

| BH7 | Монтирование списка на 1 000 000 строк с замером обоих пределов — не дороже базы того же монтирования с измеренными пределами: потолок — больше из базы × 1,3 и базы + 10 мс   | перф       |
