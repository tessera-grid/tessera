# 0008 — Fast-scroll: скелетоны ячеек при быстрой прокрутке

- **Статус:** Принято
- **Дата:** 2026-08-02

## Контекст

Даже при виртуализации ([ADR 0005](0005-virtualization-tanstack-virtual.md)) при
быстрой прокрутке JS-стек рендеринга захлёбывается: за короткое время монтируется и
отрисовывается огромное число ячеек с полным содержимым (форматирование, слоты,
инжектируемый контент), кадры проседают, прокрутка дёргается.

Это **обособленная проблема рендеринга**: она возникает на любом виртуализированном
гриде из-за стоимости монтирования содержимого ячеек и не зависит ни от версии
TanStack, ни от того, как пересчитывается модель данных.

## Решение

Ввести **fast-scroll**: пока прокрутка идёт быстро, монтировать вместо полного
содержимого ячейки лёгкий скелетон; реальное содержимое рендерится, когда прокрутка
успокаивается. Механизм состоит из трёх частей: детектор скорости
([`useFastScroll`](../../src/lib/core/fastScroll/useFastScroll.ts)), раздача
состояния через контекст
([`FastScrollProvider`](../../src/lib/core/fastScroll/fastScrollContext.tsx)) и
подавление содержимого на уровне ячейки
([`BodyCell`](../../src/lib/ui/BodyCell/BodyCell.tsx)).

### Детектор скорости (`useFastScroll`)

`useFastScroll({ getScrollElement })` вешает **пассивный** слушатель `scroll` на
скролл-контейнер грида (`DataGrid` передаёт `getScrollElement`) и оценивает скорость
по скользящему окну:

- на каждом событии копится сэмпл `{ time, |Δleft|, |Δtop| }`; сэмплы старше
  `VELOCITY_WINDOW = 250 мс` отбрасываются;
- скорость по оси = сумма пройденного за окно / окно, приведённая к **px/сек**;
- считается отдельно по X и Y — горизонталь и вертикаль имеют разную стоимость и
  разные пороги.

**Гистерезис входа/выхода** (пороги в px/сек), чтобы режим не «дребезжал» на границе:

| | Y (вертикаль) | X (горизонталь) |
| --- | --- | --- |
| Вход (`ENTER_VELOCITY`) | `2000` | `4500` |
| Выход (`EXIT_VELOCITY`, 25% от входа) | `500` | `1125` |

Вход по любой оси `≥ ENTER` включает режим; падение по любой оси `≤ EXIT`
запрашивает выход. Между порогами состояние сохраняется как есть.

**Тайминги стабилизации** гасят мерцание на коротких рывках и остановках:

- `MIN_DURATION = 250 мс` — минимальное время в режиме. `requestExit` откладывает
  фактический выход на остаток до `MIN_DURATION`, если он ещё не истёк, — один
  быстрый флик не даёт цикл «включился → тут же выключился».
- `IDLE_DELAY = 300 мс` — если события `scroll` прекратились, выйти из режима через
  этот таймаут (прокрутка просто остановилась, а не замедлилась плавно).

### Состояние и его раздача

Детектор отдаёт `FastScrollState = { isFastScrolling, sessionId }`:

- `isFastScrolling` — активен ли режим сейчас;
- `sessionId` — счётчик, **инкрементируемый при каждом входе** в режим. Это ключ ко
  всему решению (см. ниже). Текущее значение хранится в ref, чтобы обработчик
  скролла не пересоздавался, а наружу отдаётся через `setState`.

`FastScrollProvider` кладёт это состояние в React-контекст; ячейки читают его через
`useFastScrollState()`. Один провайдер на грид — состояние вычисляется в одном месте,
а не в каждой ячейке.

### Подавление содержимого в ячейке (`BodyCell`)

Наивная реализация «если `isFastScrolling` — рисуй скелетон» дала бы неприятный
артефакт: ячейки, **уже видимые** в момент начала быстрой прокрутки, мигнули бы
содержимое → скелетон → содержимое. `sessionId` решает это:

```ts
const { isFastScrolling, sessionId } = useFastScrollState()
const mountedInSession = useRef(sessionId).current // фиксируется при монтировании

const isSuppressed = isFastScrolling && mountedInSession === sessionId
const showSkeleton = isSuppressed && !isActionsColumn && !isPinnedColumn
```

`mountedInSession` захватывает `sessionId` на момент монтирования ячейки и больше не
меняется. Заглушка показывается **только** у ячеек, смонтированных в **текущую**
сессию быстрого скролла (`mountedInSession === sessionId`), — то есть у тех, что
вылетают под курсор во время рывка. Ячейки, отрисованные до входа в режим, имеют
меньший `mountedInSession` и продолжают показывать реальное содержимое, не мигая.

Дополнительно из подавления **исключены** колонки действий (`isActionsColumn`) и
закреплённые колонки (`isPinnedColumn`) — они дёшевы и важны как визуальные якоря во
время прокрутки. Сам скелетон — статичный `Skeleton` фиксированного размера
(`width="50%"`, `height={16}`) **без анимации** (`animation={false}`): анимировать
плейсхолдеры, которые живут доли секунды, — только тратить кадры, ради которых всё и
затевалось.

## Последствия

- **+** Плавная быстрая прокрутка на больших наборах данных: под курсор монтируются
  дешёвые скелетоны, объём работы на кадр ограничен независимо от сложности ячеек.
- **+** Трюк с `sessionId` убирает мерцание уже-видимых ячеек — заглушки получают
  только вновь появляющиеся строки.
- **+** Механизм полностью ортогонален модели данных: он смотрит только на скорость
  DOM-скролла и переживёт смену версии TanStack.
- **+** Гистерезис + `MIN_DURATION`/`IDLE_DELAY` дают стабильный режим без дребезга
  на границах и коротких рывках.
- **−** Во время активной прокрутки пользователь видит скелетоны, а не содержимое, —
  сознательный размен точности отображения на плавность.
- **−** Пороги входа/выхода подобраны эмпирически под типичный «вес» ячейки; на
  экстремально лёгких или тяжёлых ячейках их, возможно, придётся калибровать.
