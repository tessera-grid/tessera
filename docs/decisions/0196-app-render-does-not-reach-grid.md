# 0196 — Перерисовка приложения не доходит до грида

- **Статус:** Принято (прожарка 2026-11-08), внедрено 2026-11-08
- **Дата:** 2026-11-08
- **Слой:** `core/useCreateTable` — компонент приложения не подписан на срезы, ссылка `table`
  по входам отрисовки; грид (`DataGrid`) — `memo` по пропам. Не в плагине: на что подписано
  приложение и когда меняется `table` — договор ядра со всеми потребителями.
- **Изменяет:**
  - [ADR 0026](0026-migrate-to-tanstack-v9.md) — `useTable` получает селектор: компонент
    приложения не подписан на срезы состояния; поле `table.state` убрано из результата
    `useCreateTable` — ломающее изменение до 1.0.
  - [ADR 0040](0040-action-sessions.md) — `reconcile` зовётся после рендера приложения и после
    каждой смены состояния таблицы, а не только после рендера.
- **Связано:**
  - [ADR 0027](0027-plugin-hooks-in-factory-args.md) — колбэки читаются живо, их новые ссылки
    перерисовок не требуют (H7).
  - [ADR 0039](0039-reactive-plugin-arguments.md) — сигнатура аргументов плагинов решает, сменился
    ли набор плагинов.
  - [ADR 0171](0171-effective-state-in-atoms.md) — эффективное состояние и контролируемые срезы
    живут атомами.
  - [ADR 0195](0195-node-subscriptions-by-declared-slices.md) — узлы тела уже подписаны только на
    свои срезы; этот ADR закрывает остаток клика выбора строки.
  - [ADR 0149](0149-plugin-cost-on-scroll.md), [ADR 0099](0099-perf-gates-and-ab-compare.md) —
    счётчики работы и сравнение ревизий.

## Контекст

`useCreateTable` вызывает `useTable` TanStack без селектора. Без селектора компонент
приложения подписан на все срезы состояния: выбор строки, сортировка, раскрытие перерисовывают
его, и `useTable` отдаёт новый объект `table`. Когда приложение держит срез у себя (выбор строк в
`useState`, чтобы показать «выбрано N» вне грида), оно перерисовывается и так — на каждый клик.

В обоих случаях `DataGrid` получает новую ссылку `table` и перерисовывается. Строки, ячейки и
заголовки обёрнуты в `memo` и отсекаются (H7, ADR 0027); тулбар, поле поиска, кнопка «Колонки» с
деревом колонок, зоны кнопок шапки и нижняя панель — нет. Профиль клика выбора строки под ×4 CPU
(2026-11-07, все плагины, выбор у приложения): 20–25 % клика — эта перерисовка. Та же цена — у
любой перерисовки приложения, не связанной с гридом.

### Как у других

- **AG Grid** — выбор — внутреннее состояние грида; обёртка React сверяет пропы, перерисовка
  родителя с теми же пропами внутрь не проходит.
- **MUI X Data Grid** — состояние во внутреннем хранилище; при контролируемом
  `rowSelectionModel` перерисовывается корень грида, компоненты внутри — `memo` с селекторами.
- **TanStack Table v9** — рекомендует узкий селектор в `useTable` и `table.Subscribe` ниже по
  дереву.

Tessera берёт поведение AG Grid: перерисовка приложения с теми же входами до грида не доходит,
а значения срезов приходят атомами, как в TanStack.

Что держалось за перерисовку приложения на смену среза:

- **`reconcile` плагинов** (ADR 0040, §2) звался layout-эффектом после рендера приложения;
- **следование за `data`** (ADR 0194) запоминало прежний список строк только при слушателях, а
  они подписываются после первого рендера.

## Решение

### 1. Приложение не подписано на срезы

`useCreateTable` передаёт `useTable` селектор без срезов: смена среза, которым владеет таблица,
компонент приложения не перерисовывает. Состояние приложение читает публичными `useSlice` и
`useTableState` — точечно, в том компоненте, которому оно нужно. Поле `table.state` из результата
`useCreateTable` убрано.

`reconcile` записей ядро зовёт после рендера приложения и после каждой смены состояния
таблицы — микрозадачей после записи, которая её сделала: запись плагина не прерывается
посреди. Список строк для следования за `data` помнится с первого рендера.

### 2. Ссылка `table` — по входам отрисовки

`useCreateTable` возвращает ту же ссылку `table`, пока не сменился ни один вход отрисовки. Входы
отрисовки — все опции, кроме двух:

- **значения контролируемых срезов** (`state` ядра и срезы в аргументах плагинов) — доходят до
  грида атомами (ADR 0171) до отрисовки кадра;
- **колбэки** (`handlers`, `on*` в аргументах фабрик) — читаются живо (ADR 0027).

Набор плагинов и их аргументы сравниваются сигнатурой ADR 0039; прочие опции — по ссылке каждой.
Новые `columns`, `data`, язык, `loading`, флаги панелей и другие опции дают новую ссылку `table`.

### 3. `DataGrid` — `memo` по пропам

`DataGrid` обёрнут в `memo`: при той же ссылке `table` и тех же пропах он не перерисовывается.
Пропы-объекты (`icons`, `localization`, `stubs`, `style`) приложение держит стабильными — иначе
каждая перерисовка приложения снова доходит до грида. Это правило — в
`docs/architecture/rendering.md`.

## Границы

- Узлы тела — ADR 0195, не меняются.
- Пропы-объекты, созданные в рендере приложения, грид сам не сравнивает по содержимому: глубокое
  сравнение на каждой перерисовке дороже пользы.
- Своих историй нет: изменение не видно, клиентских сценариев у него нет.

## Отвергнутые альтернативы

- **Только селектор хоста.** Снимает перерисовку при срезе у таблицы, но не при срезе у
  приложения — а именно так приложения обычно держат выбор, и так мерят I1–I2.
- **`memo` на каждом компоненте тулбара, панелей и шапки.** Семантика `table` не меняется, но
  каждый новый компонент снова течёт, пока ему не добавят `memo` со стабильными пропами.
- **Опция `useCreateTable({ select })`, как селектор TanStack.** Ещё одна опция ядра ради
  случая, который покрывают `useSlice` и `useTableState`.
- **Глубокое сравнение пропов `DataGrid`.** Цена на каждую перерисовку приложения, а пропы
  меняются редко.

## Последствия

- Клик выбора строки и любая перерисовка приложения с теми же входами не перерисовывают тулбар,
  панели и шапку.
- **Ломающее изменение** до 1.0: из результата `useCreateTable` убрано поле `table.state`.
- Код Tessera, который полагался на перерисовку приложения от смены среза, переходит на подписку
  атомов; такой зависимости в коде быть не должно — её ловят тесты HR6–HR7 и полный набор.
- Ошибка в правиле входов отрисовки — грид не увидит смену опции. Поэтому правило обратное:
  новая ссылка на всё, кроме значений срезов и колбэков.

## Внедрение

Этап 1 — весь объём: селектор `useTable`, ссылка `table` по входам отрисовки, `memo` у
`DataGrid`, удаление `table.state` из типа, тесты HR1–HR8, правило стабильных пропов в
`docs/architecture/rendering.md`, поправки `reactivity.md` и `table-assembly.md`, `perf:compare`
против ревизии до внедрения.

Отчёт HR9 (2026-11-08): `perf:compare -- HEAD --cases I1,I2`, A — `ad73fea2`, B — рабочая копия с
ADR 0195–0198, пять раундов вперемешку, порог ±10 %. Самая долгая задача I1 — 88,3 → 29,5 мс (×0,34,
95 % — 0,27–0,39), I2 — 89,5 → 29,3 мс (×0,33, 0,31–0,44): улучшение, регрессии нет. Вклад ADR 0196
отдельно от ADR 0195 этот замер не разделяет.
