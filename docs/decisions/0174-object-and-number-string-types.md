# 0174 — Типы данных `object` и `numberString`

- **Статус:** Принято (решения — по итогам прожарки 2026-11-01)
- **Дата:** 2026-11-01
- **Слой:** `core/` — два встроенных типа в `core/dataTypes.ts`, текст записи и десятичной строки
  в `core/dataTypeFormat.ts`, разбор правки в `core/columnDataType.ts`: ядро уже владеет
  системой типов (ADR 0172). Плагины — каждый своё по базовому типу: сортировка
  (`columnSortingModel`), фильтр и фасеты по ключу (`columnFilteringModel`), группировка по ключу
  (`rowGroupingModel`), выгрузка (`dataExportModel`); десятичное сравнение строк — `util/`
  (листовая утилита без импортов `src/lib`, её берут ядро и плагины).
- **Изменяет:**
  - [ADR 0172](0172-column-data-type.md) — к девяти встроенным типам добавляются `object` и
    `numberString` (DT1).
  - [ADR 0048](0048-option-filtering.md) — фильтр-список записи хранит в срезе ключи, варианты и

  - [ADR 0016](0016-row-grouping.md) — колонка записи группирует по ключу.

  - [ADR 0139](0139-saved-row-and-column-data-type.md) — разбор правки `numberString` в десятичную
    строку; запись — только своим `parseValue`.
- **Связано:**
  - [ADR 0063](0063-option-label-sorting.md) — сортировка по подписи.
  - [ADR 0084](0084-cross-browser-support.md) — `Intl.NumberFormat` со строкой есть с Safari 15.4,

## Контекст

ADR 0172 дал таблице девять встроенных типов. Два частых вида данных из API в них не
укладываются.

- **Запись** — менеджер, город, категория приходят объектом `{ id, name }`, а не значением
  варианта. Сейчас приложение пишет `formatValue` и свой `sortFn`, но фильтр, поиск, группировка
  и выгрузка о записи не знают: фильтр-список сравнивает объекты по ссылке, группировка делит
  одинаковые записи разных экземпляров, CSV пишет `[object Object]`.
- **Десятичное число строкой** — бэкенды отдают деньги строкой (`"1234.50"`), чтобы не терять
  точность. Тип `number` переводит её во float: после 15 значащих цифр порядок и фильтр неверны.

### Как у других

- **AG Grid** — тип `object` есть, но без `valueFormatter` и `valueParser` не работает; ключ для
  группировки и фильтра-списка — `keyCreator`. Десятичной строки нет: `number` с переводом в
  число и потерей знаков.
- **MUI X** — ни записи, ни десятичной строки: `valueGetter` и `valueFormatter` колонки, фильтр и
  группировка о записи не знают.
- **Handsontable** — ни того ни другого.

## Решение

### 1. `object` — запись с ключом и подписью

Значение — объект. `getKey(value)` и `getLabel(value)` задаются у типа или колонки; по умолчанию
ключ — поле `id`, подпись — `label`, иначе `name`, иначе ключ строкой. Подпись видят ячейка,
строка группы, тултип, сводка фильтров, поиск и выгрузка; сортировка — по подписи через
`Intl.Collator` языка. Фильтр — список с флажками по подписям: варианты и счётчики — по ключу,
справочник — `loadOptions`, срез хранит ключи и остаётся сериализуемым. Группировка — по ключу.
Правку записи пишет только свой `parseValue`: редакторы по типу — следующий ADR.

### 2. `numberString` — десятичное число строкой

Значение — десятичная строка (`"-1234.50"`, без экспоненты). Сортировка и фильтр сравнивают
строки десятично, без перевода во float. Показ — как есть или `Intl.NumberFormat` по `format`
строкой, без потери знаков; выравнивание — вправо, как у `number`. Разбор правки — по языку
таблицы в десятичную строку. CSV — строкой как есть; xlsx — числом до 15 значащих цифр, длиннее —
текстом, чтобы Excel не округлил.

### 3. Этапы

1. `object`: TY1–TY8, TY15; сценарии S1, S2.
2. `numberString`: TY9–TY14; сценарии S3, S4.

## Границы

- Агрегаты (сумма, среднее) по `numberString` — вне объёма: нужна десятичная арифметика.
- Редактор записи (выбор из справочника) — в ADR редакторов по типу.
- `time` и `duration` — следующим ADR по сценариям (roadmap).
- Экспонента, разделители разрядов и пробелы в данных `numberString` — не число: сортировка
  ставит такие значения к пустым.

## Отвергнутые альтернативы

- **Только функции без умолчаний** (как AG Grid) — каждая колонка записи повторяла бы
  `getKey`/`getLabel` для типичного `{ id, name }`.
- **Имена полей `keyField`/`labelField`** — не покрывают составную подпись
  (`${first} ${last}`).
- **`numberString` через `Number`** — проще, но теряет знаки после 15-го: ради этого тип и нужен.
- **`time` и `duration` в том же ADR** — дольше до первого результата; сценарии для них ещё не
  собраны.

## Последствия

- **+** Запись и десятичная строка работают во всех фичах по типу без своего кода приложения.
- **+** Срез фильтра записи сериализуем и уходит серверу ключами.
- **−** Фасеты по ключу дороже фасетов по значению — перф-гейт TY15.
- **−** Своё десятичное сравнение: знак, ведущие нули, `"-0"` — покрыть модульными тестами.

## Внедрение

- **Этап 1** (TY1–TY8, TY15; S1, S2): тип `object` и поля типа `getKey`/`getLabel` —
  `core/dataTypes.ts`; ключ и подпись записи — `objectKeyOf` и `objectLabelOf` в
  `core/dataTypeFormat.ts` (запись без ключа предупреждает и при показе, и при расчёте ключа —
  раз на колонку). Сортировка по подписи — ветка `object` в `columnSortingModel/typedSort.ts`.
  Фильтр: вид `select` из базового типа, `optionKeyOf` и `filterOptionLabelOf` в
  `columnFilteringModel/options.ts` — варианты, счётчики и условие по ключу, подписи из записей,
  в том числе в сводке фильтров. Группировка по ключу — `rowGroupingModel/objectGrouping.ts`
  ставит колонке `getGroupingValue`, если своего нет. Выгрузка подписью — `exportData.ts`. Разбор
  правки текст в запись не превращает: её пишет только свой `parseValue`, иначе — совет в
  консоли (`cellEditing:objectNotWritten`). Изменено требование DT1 ADR 0172 — список встроенных
  типов. Тесты: модульные `dataTypes` (TY1, TY3, TY4, TY6, TY7) и `cellEditWrite.dom` (TY8),
  визуальный `data-types` (TY2, TY5), перф TY15 — в `interaction`; гайды S1 `DataTypesObject` и
  S2 `DataTypesObjectLabel`, колонка менеджера — в `DataTypesPlayground`.
- **Этап 2** (TY9–TY14; S3, S4): тип `numberString`; десятичная арифметика без float —
  `util/decimal.ts` (`parseDecimal`, `compareDecimal`, `significantDigits`, `decimalText`), ввод
  по языку в десятичную строку — `parseLocaleDecimal` в `util/parseNumber.ts`. Показ — строка как
  есть или `Intl.NumberFormat` по `format` строкой; выравнивание и цифры одной ширины — у обоих
  числовых типов (`isNumericBase`). Сортировка — ветка `numberString` в `typedSort.ts`. Фильтр —
  вид `number`; граница числового условия — `NumberBound` (`number | string`): панель колонки
  `numberString` кладёт в срез десятичную строку, сравнение со строкой с любой стороны —
  десятичное; строковые границы «между» — даты, только если это не десятичная строка. Разбор
  правки — десятичная строка, как набрана. xlsx — число до 15 значащих цифр (`EXCEL_DIGITS`),
  длиннее — текст. Требование DT1 ADR 0172 дополнено. Тесты: модульные `dataTypes` (TY10, TY11,
  TY13) и `cellEditWrite.dom` (TY12), визуальный `data-types` (TY9), перф TY14 — в
  `interaction`; гайды S3 `DataTypesNumberString` и S4 `DataTypesNumberStringExport`, колонка
  остатка — в `DataTypesPlayground`.
