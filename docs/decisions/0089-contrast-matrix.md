# 0089 — Матрица контраста: WCAG-пороги по отрисованным состояниям грида

- **Статус:** Принято (решения — по итогам прожарки 2026-10-11); с
  [ADR 0093](0093-visual-state-catalog.md) сценарии матрицы — истории каталога (VR14).
- **Дата:** 2026-10-11
- **Связано:**
  - [ADR 0043](0043-honest-test-coverage.md) — TQ5: axe нового состояния с
    `color-contrast`.
  - [ADR 0032](0032-wcag-aa-remainder.md) — W5–W7: контраст флажка, кольца фокуса, края
    выделения.
  - [ADR 0019](0019-token-architecture.md) — токены темы; `theming-matrix` (TT-*)
    проверяет привязку «элемент = токен», но не контраст.
  - [ADR 0087](0087-forced-colors.md), [ADR 0088](0088-increased-contrast.md) — режимы
    контраста.

## Контекст

Контраст сейчас проверяется точечно — там, где есть требование:

- **axe `color-contrast`** (WCAG 1.4.3) — включается для нового состояния по TQ5; в общих
  прогонах доступности (A5, A7) выключен.
- **Свой расчёт** (`contrast()`, `toRgba` в `a11y-helpers.ts`) — нетекстовое по
  WCAG 1.4.11, которое axe не проверяет: флажок, кольцо, край выделения, индикаторы.
- **Режимы** — `forced-colors` (HC) и повышенный контраст (MC).

Слепые зоны:

1. **Нет сплошной матрицы.** Сочетания состояний (подсветка поверх закреплённой ячейки
   выбранной строки под указателем) не проверены: новое сочетание может просесть молча.
2. **`incomplete` у axe.** На градиентах, псевдоэлементах и перекрытых слоях axe не
   считает контраст и помечает узел `incomplete`, а тесты смотрят только `violations`.
3. **Одна палитра.** Тесты идут с палитрой историй (`global.css` задаёт роли shadcn);
   запасные цвета Tessera — то, что получит приложение без своей палитры, — не
   проверяются.

### Как это сделано у других

- **Дизайн-системы** (по памяти — Primer; подходы из обзоров) проверяют пары токенов
  «текст на фоне», «граница на фоне» в CI для каждой темы. Прозрачность, псевдоэлементы,
  наложения и `forced-colors` меняют фактический цвет — пары токенов этого не видят.
- **Syncfusion** по своим словам гоняет axe-core и accessibility-checker на гриде в
  автотестах.
- **AG Grid, MUI X** — публичных сведений о проверке контраста нет.

## Решение

Один визуальный набор `contrast-matrix` в `npm test` (Chromium) проверяет WCAG-пороги
по **отрисованному** DOM: состояния создаются в настоящем гриде, цвета —
`getComputedStyle`, фон — наложение полупрозрачных слоёв до непрозрачного
(`effectiveBg`, переезжает в `a11y-helpers.ts`).

### 1. Пороги

- **Обычный режим — WCAG AA:** текст не ниже 4,5:1 (крупный — 3:1); иконки контролов и
  границы полей не ниже 3:1 (1.4.11).
- **Повышенный контраст (ADR 0088):** текст не ниже 7:1; нетекстовое — 3:1.
- **Отличие состояния от покоя** (наведение, выбор) в обычном режиме не проверяется:
  WCAG его не требует (выбор виден по флажку), а наведение по умолчанию — ~1,1:1 по
  замыслу. В режиме повышенного контраста его проверяет MC3.
- **Выключенное** (`disabled`, `aria-disabled`) WCAG освобождает — пропускается.

### 2. Матрица

| Ось          | Значения                                                                                  |
| ------------ | ----------------------------------------------------------------------------------------- |
| тело         | покой, нечётная строка, наведение, выбор, выбор с наведением, активная ячейка             |
| ячейка       | обычная, закреплённая слева, закреплённая справа, служебная (флажок, грип, действия)      |
| наложения    | подсветка трёх тонов (ADR 0080), диапазон ячеек, ожидание и ошибка ячейки (ADR 0041/0057) |
| шапка, футер | покой, наведение, активная сортировка, закрепление                                        |
| панели       | тулбар, быстрый поиск, пагинация, счётчик выбранного                                      |
| поповеры     | пункт в покое, под указателем, выбранный; тултип                                          |
| тема         | светлая, тёмная                                                                           |
| режим        | обычный, повышенный контраст                                                              |
| палитра      | запасные цвета Tessera (без ролей shadcn), палитра историй (`global.css`)                 |

Гарантии на произвольную палитру приложения нет: её задаёт приложение.

### 3. Что проверяется в узле

- **Текст** — каждый элемент с непустым собственным текстовым узлом внутри грида и его
  поповеров: цвет текста к `effectiveBg`.
- **Нетекстовое** — иконки кнопок (`currentColor` SVG) и границы полей и флажков к
  фону под ними.
- **Слой на градиенте** (подсветка, блик) — цвет слоя берётся из его токена и
  накладывается как обычный слой.

### 4. axe — второй сигнал

На каждой комбинации идёт axe с `color-contrast` (в повышенном режиме —
`color-contrast-enhanced`). Нарушение — падение. `incomplete` на текстовом узле грида —
тоже падение, кроме причин из короткого списка в наборе, у каждой — обоснование
(например, «фон — градиент подсветки, проверен своим расчётом»).

### 5. Найденные нарушения

Нарушение, которое чинится правкой токена, чинится в той же работе. Нарушение, которому
нужно решение по дизайну, — запись в базе известных нарушений
(`contrast-baseline.json` рядом с набором) с причиной и строкой в roadmap «Известные
проблемы». База только сокращается: исправленное нарушение, оставшееся в базе, роняет
тест — как `requirements-baseline.json` (ADR 0043).

## Границы

- Только Chromium: цвета между движками почти не расходятся; `test:engines` набор не
  включает.
- `forced-colors` — своя проверка HC (палитру задаёт система, пороги — по ней).
- Пиксели скриншота — только там, где они уже есть (линии дерева): матрица читает
  вычисленные цвета; сглаживание тонких линий она не видит.
- Живые контрастные темы и экранные лупы — нет.

## Отвергнутые альтернативы

- **Пары токенов.** Проще и быстрее, но не видят наложений — именно там грид проседает.
- **Пары токенов и DOM вместе.** Двойная работа: DOM-матрица покрывает пары как частный
  случай.
- **Отличие состояний 3:1 в обычном режиме.** Требует перерисовки вида грида — решение по
  дизайну, а не проверка; режим для этого — ADR 0088.
- **Только свой расчёт без axe.** axe знает правила «крупного текста» и скрытого текста;
  второй независимый сигнал дешёвый.
- **Чинить всё до слияния.** Часть нарушений может потребовать решений по дизайну;
  база с причиной не даёт им потеряться и не блокирует проверку остального.

## Последствия

- **+** Любое новое сочетание состояний проверяется на контраст без нового теста.
- **+** Запасные цвета Tessera проверены так же, как палитра историй.
- **+** `incomplete` axe больше не проходит молча.
- **−** Время `npm test` растёт — цель не больше ~30 с на набор.
- **−** Переходы цвета требуют дожидаться конечных значений (как в MC).
- Публичный API не меняется.

| CX2 | Наложения — подсветка трёх тонов, диапазон ячеек, ожидание и ошибка ячейки: текст поверх не ниже порога CX1                                                         | visual |

| CX6 | Матрица идёт на двух палитрах: запасной (без ролей shadcn) и палитре историй                                                                                        | visual |
| CX7 | axe на каждой комбинации: нарушение — падение; `incomplete` на текстовом узле грида — падение, кроме причин из списка с обоснованием                                | visual |
| CX8 | База известных нарушений только сокращается: исправленное нарушение, оставшееся в базе, роняет тест                                                                 | visual |

**Тесты.** Набор `visual/contrast-matrix`; хелперы `effectiveBg` и выбор текстовых
узлов — в `a11y-helpers.ts`. Режим повышенного контраста — пропом `contrast="more"`;
запасная палитра — `--border` и прочие роли shadcn на `<html>` сброшены в `initial`.
Перф-требования нет: изменение касается только тестов (TQ6 неприменим).

## Внедрение

Матрица сразу нашла то, что точечные проверки пропускали:

- **axe молчал.** Chromium пишет серые смеси `color-mix(in oklch, …)` как
  `oklch(L C none)`; axe-core 4.13 такой цвет не разбирал и на первом же узле снимал
  правило `color-contrast` целиком — 0 проверенных узлов, 0 нарушений, тест зелёный.
  Проверки TQ5 во всех наборах на таких фонах шли вхолостую. axe-core обновлён до 4.14
  (разбирает `none`); ошибка axe (`error-occurred`) в CX7 — падение, разобранных причин
  `incomplete` сейчас нет.
- **Строки смешивались со страницей.** Наведение и выбор строки — полупрозрачные слои, а
  под строками до страницы ничего не было: тёмный грид на светлой странице давал белый
  текст на белом (1,04:1). Грид теперь красит свой фон токеном `--tsr-comp-bg`
  (= `--tsr-sys-bg`, ADR 0018, TH11). Расчёт фона (`effectiveBg`) идёт до холста
  страницы, а не останавливается на корне темы — иначе он прятал ту же ошибку.
- **Ожившие axe-проверки** (WCAG 2.5.3, видимый текст входит в доступное имя): имя дня
  календаря начинается с видимого числа («1, Sunday, March 1st, 2026»); заглушка выбора
  размера страницы подписана подписью и значением (`aria-labelledby`), как настоящий
  список. Тесты SG3 и SF21 проверяли состояние посреди перехода или примитив без
  поверхности — исправлены сами тесты.

Палитра историй совпадает с запасной, кроме рамки в режиме повышенного контраста, —
CX6 проверяет именно это различие. Иконка — SVG внутри контрола; декоративная
графика (стрелка поповера) не проверяется. Подсветки сценария CX2 ставятся после того,
как история подала данные, и стоят на строках без отправленных правок. База известных
нарушений пуста.
